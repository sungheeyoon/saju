# 사주 서비스 PRD — 출시 범위 · 다음 단계 · 미정

색인은 `docs/prd.md` 다 — 표시(선다 · 없다 · 다르다)의 뜻과 절마다 사는 파일이 거기 있다.

## 7. 다음 단계 — 하기로 정했으나 **아직 없는 것**

감사에서 「다름」으로 나오는 것이 맞다. 여기 적힌 것은 **무엇을 만들지 정했다**는 뜻이다.

### 7.0 출시 범위 — 세 단계 (2026-09-22)

**「출시」를 단독 명칭으로 쓰지 않는다** — 둘째와 셋째 단계를 함께 가리켜 모호하다. 단계는 셋이고
이름으로 부른다. **지금은 운영 베타다.**

| 단계 | 무엇 | 끝났다고 말하는 조건 |
| --- | --- | --- |
| **운영 베타** (지금) | 테스트 코드로 들어온 사람이 §1~§6 전부를 쓴다 | — |
| **채팅 안전 베타** | §7.1 채팅 + §7.2 접속 상태. 테스트 코드는 그대로다 | 아래 여섯을 **지정한 운영 테스트 계정으로 프로덕션에서 밟는다** |
| **공개 출시** | 테스트 코드 없이 받는다. §7.3 본인확인 · PG 결제 · 공개 모집에 견딜 보안 점검 · 확장된 관리자·제재 화면 · 개인정보·약관·고객 대응 · 외부 알림 | 항목마다 크기가 아직 안 정해졌다 — 정해지면 여기 적는다 |

**채팅 안전 베타는 짧게 간다.** §7.1·§7.2 의 줄을 다 만들어야 끝나는 것이 아니라, 다음 여섯을
**운영자가 지정한 테스트 계정으로** 프로덕션에서 한 번씩 밟으면 끝난 것이다. 실제 사고를 기다리지 않는다.

1. 매칭된 두 계정이 대화를 주고받는다
2. 차단이 방을 닫고, **닫힌 뒤 두 쪽이 §7.1 의 열람 규칙대로 본다**
3. 이용 정지가 방을 닫고, 열람 규칙대로 본다
4. 탈퇴 신청이 방을 닫고, 열람 규칙대로 본다
5. 신고 한 건이 **고른 메시지와 앞뒤 문맥의 스냅샷**과 함께 남는다
6. 전송 한도에 걸린 한 건이 거절된다

**운영자 확인 수단은 이 단계에서 화면이 아니다.** runbook 의 SQL 절차로 둔다 — 화면은 공개 출시의
「확장된 관리자」에 속한다. **그 1차판이 섰다(2026-09-24, ADR 0103)** — 신고 증거 열람대 `/ops/reports`. 운영자가 현재
계정에 연결된 신고를 목록(최신부터 30건씩, 처리 상태 · 사유 · 대화 근거로 거른다)에서 찾아 열면, 신고 내용과 신고 당시의
불변 스냅샷(고른 메시지 하나가 「신고한 메시지」로 강조되고 앞뒤 문맥이 시간순)을 읽는다. 읽기 전용이다 — 화면에 쓰는
누름은 없고, 검토 기록(검토한 운영자 · 결과 — 조치 없음 · 경고 · 이용 정지 결정 · 추가 확인 필요 · 판단 근거 · 당시 제재 대상)은
운영자가 CLI 로 부르는 검토 문 하나가 적어 상세가 읽는다(ADR 0107). **처리 필요**는 안 봤거나 추가 확인 필요인 신고이고, 나머지가
**처리 완료**다. 경고 · 이용 정지 결정에는 제재 대상이 있어야 하고 조치 없음 · 추가 확인 필요에는 없다. 이용 정지 결정을 적으면
같은 자리에서 그 계정이 정지된다 — 나중에 해제해도 결정 기록은 그대로 남는다. 경고는 경고받은 사람에게 앱 안 안내로 간다 —
아래 「경고와 누적」. 운영자는 목록에서 **안내번호**로 경고를 찾고, 상세에서 안내번호 · 경고 갈래 · 이용자가 확인했는가를 본다. 신고한 사람은 그 기록을 못 읽는다. 이메일 · 출생정보 · 풀이 · 저장한 사람은 안 보이고, 두 계정은
닉네임과 내부 UUID 로 가른다. 떠난 사람의 신고(ADR 0098)는 화면에 없다 — runbook 의 SQL 로 읽는다.

**경고와 누적(2026-09-24, ADR 0108).** 경고는 **앱 안 안내와 이메일 둘 다**로 알린다 — **앱 안 안내는 섰고, 이메일은 외부
알림(G-26)의 제공자를 기다린다.** 싣는 것은 **사유의 갈래 · 경고한 날 · 이의 제기의 길 · 안내번호**뿐이다 — 운영자의 판단 근거와
신고한 사람 · 신고 시각 · 고른 메시지 · 대화 상대 · **경고 횟수**는 싣지 않는다(신고한 사람을 지킨다). 갈래는 신고 사유 넷 중 운영자가
경고에 붙이는 값이고(고르지 않으면 신고 사유), 안내번호는 경고마다 붙는 `W-` 와 네 글자다. 안내는 경고받은 사람이 로그인한
화면(`/me` 아래)의 맨 위에 서서 화면을 옮겨도 남고, 「확인했습니다」를 누르면 확인한 시각이 남고 내려간다 — 안 읽은 경고가 여럿이면
오래된 것부터 하나씩이다. 이용이 정지된 계정 · 탈퇴 대기에는 안 서고(제 상태만 본다), 신고한 사람이 떠나 따로 보관된 신고의 경고도
안 선다. 문구는 이렇다(운영자 승인 2026-09-24):

| 자리 | 문구 |
| --- | --- |
| 제목 | 운영정책 위반으로 경고를 받았습니다 |
| 첫 줄 — 괴롭힘이나 위협 · 사칭이나 거짓 정보 · 부적절한 내용 | {날짜}에 {갈래}에 해당하는 이용이 확인되어 경고를 드립니다. |
| 첫 줄 — 그 밖 | {날짜}에 운영정책에 어긋나는 이용이 확인되어 경고를 드립니다. |
| 둘째 줄 | 같은 일이 반복되면 이용이 제한될 수 있습니다. |
| 이의 제기 줄 | 이 경고에 이의가 있으면 {고객 문의 이메일}로 알려 주세요. 3영업일 안에 답을 드립니다. |
| 안내번호 줄 | 문의하실 때 안내번호 {번호}를 함께 적어 주세요. |
| 버튼 | 확인했습니다 |

고객 문의 이메일은 사업자등록 뒤에 선다 — 그때까지 자리 표시다(G-25 ㉡). **최근 12개월의 경고가 3회째가 되는 검토부터** 운영자가
이용 정지 결정을 검토한다 — 자동 정지는 없다. **중대한 위반은 횟수와 상관없이 즉시 검토**하고, 무엇이 중대한가는 운영자가
판단한다(신고 사유에는 무게가 없다 — 보기는 약관의 금지 행위에 맞췄다). 이의 제기와 이용 정지의 소명은 고객 문의 이메일로 받고
(G-25 ④ · ㉤, 첫 답 3영업일 안), 운영자는 메일의 안내번호로 경고를 찾는다. 이의 제기를 받아들이면 결과를 조치 없음으로 고쳐 셈에서
빼고, 확인 전이던 안내도 내려간다. 이메일과 고객 문의 이메일 주소는 G-57 이 든다.

**운영 통제(2026-09-24, ADR 0105).** 이용자 개인정보는 `/ops/**` 화면으로만 읽는다 — 화면의 문이 읽을 때마다(거절도) 누가 ·
언제 · 무엇을 읽었는지를 추가만 되는 접속기록에 남기고, 기록은 매일 지울 수 없는 저장소(S3 Object Lock, 400일)로 나간다(AWS
계정이 서면 켜진다). 운영 SQL 은 개인을 가리키지 않는 것만 보내고 목적과 해시가 남는다. 개인정보를 SQL 로 읽는 것은 장애 ·
수사기관 요청 때 사람만 한다. 신고는 접수 뒤 3영업일 안에 1차 판단하는 것이 **내부 목표**이고(추가 확인 필요로 보류해도 접수부터 센다, ADR 0107) 이용자에게 약속하지 않는다.
운영자가 3영업일 넘게 자리를 비우면 새 가입을 닫는다 — 닫힌 동안 새 사람은 틀린 코드와 같은 「사용할 수 없는 코드예요. 코드를 다시 확인해 주세요.」를 보고,
이미 가입한 사람은 그대로 쓴다.

**공개 출시 준비는 채팅 안전 베타와 나란히 간다.** 다만 둘은 코드에서 겹친다 — 접점 넷을 먼저 적는다.

| 공개 출시 항목 | 채팅과 닿는 자리 |
| --- | --- |
| 본인확인 | 채팅 참여 자격 — 인증이 가입의 문이라(§7.3) 인증 안 된 계정은 방을 열 자리까지 오지 못한다 |
| 관리자·제재 화면 | 신고 근거 스냅샷을 읽는 자리 — 1차판(읽기 전용 열람대)이 섰다(ADR 0103) |
| 외부 알림 | 새 메시지 통보 — 웹 푸시로 섰고 운영에 켜기 전이다(§7.1, G-26) |
| 개인정보 정책 | 메시지 보존·삭제 기간 — §7.1 에 정했고, 정책 문서가 그 수를 옮겨 적는다 |

공개 출시가 긴 쪽이므로 채팅을 짧게 해도 공개가 앞당겨지지는 않는다.

**PG 결제와 판매 단위는 다른 결정이다.** PG 는 결제 수단이고, 무엇을 파는지는 **풀이권 묶음**으로
정했다(2026-09-23, §8.7, ADR 0100) — 1회 · 3회 · 5회 · 20회, 유효기간 없음, 무료 몫은 1개, 인연 요청도
같은 풀이권. 산 몫은 한도 위에 얹힐 뿐이라 「세는 것이지 갖는 것이 아니다」(ADR 0021)와 「요청 때
예약한다」(ADR 0038)는 그대로 선다.

**장부는 섰다 — 판매는 닫혀 있다(2026-09-24, ADR 0106).** 결제 주문 · 산 묶음 · 환불 · 제공자 알림 · 사용 이력 다섯 표가 PG 에
중립으로 서 있고, 한도는 무료 + 예외 + 산 묶음(걷은 것을 뺀)이다. 사용 이력은 어느 풀이 · 인연 요청이 어느 몫을 썼는지를
**무료 → 예외 → 산 때가 이른 묶음** 차례로 적는다 — 잔액이 아니라 환불 셈에만 든다. 환불은 산 묶음의 안 쓴 회차만이고
예약 중인 것은 풀릴 때까지 아니다. 떠난 사람의 결제 기록은 따로 5년 두고 앱은 못 읽는다.

**환불 기준은 정했다(2026-10-07, ADR 0148).** 산 풀이권은 자동 만료가 없고, 7일 안이든 뒤든 요청하면 안 쓴 유료 회차를
**결제액 × 안 쓴 유료 회차 ÷ 산 유료 회차**로 공제 없이 돌려준다. 정상 제공한 풀이는 결제 전 고지와 무료 1개의 체험을 갖춘
경우 단순 변심으로 돌려주지 않고, 생성 실패 · 계약과 다른 제공은 다시 제공하거나 돌려준다. 탈퇴 뒤에도 결제 기록이 남은 동안
청구할 수 있고, 서비스를 끝내면 30일 전에 알리고 안 쓴 유료분을 정산한다. 약관 문장은 `docs/legal/terms-draft.md`, 이용자에게
보이는 글은 `docs/legal/refund-policy.md` 다. 금액은 여전히 사람이 PG 콘솔에서 돌려준 뒤 장부에 적는다.
주문을 승인으로 만드는 것은 서버뿐이고, 판매를 여는 스위치는 꺼져 있다.

| 묶음 | 가격(부가세 포함) | 화면에 서는 말 |
| --- | --- | --- |
| 1회 | 4,900원 | 할인 표시 없음 |
| 3회 | 12,900원 | 1회권 대비 12% 할인 |
| 5회 | 19,900원 | 1회권 대비 18% 할인 · **추천** |
| 20회 | 59,000원 | 1회권 대비 39% 할인 · **최대 할인** |

- 할인율은 **1회권을 같은 횟수만큼 살 때와 견준 값을 정수로 내린 것**이다(실제 12.2 · 18.8 · 39.8%, 운영자 결정 2026-09-24) —
  표시가 실제보다 커지지 않게 한다. 값은 `src/lib/reading/bundle.ts` 의 `discountAgainstSingles` 하나가 든다. 화면은 기준을 함께 적는다(「12% 할인」만 쓰지 않는다).
  추천과 최대 할인은 서로 다른 까닭을 달아 하나만 강조되게 한다. 가격은 사람이 정한 값이다 — 재어 보고 정한 값이
  아니다(가격 설문 제출 1건)
- **판매는 결제 전 고지가 서고 G-25 의 판매 조건이 풀린 뒤 연다** — 철회 · 일부 쓴 묶음의 환불 기준은 정했다(ADR 0148).
  이용약관 · 환불정책을 공개 주소에 게시하는 것은 판매가 아니고 변호사 검토를 기다리지 않는다(운영자 결정 2026-10-07)
- **저장 자리 10명은 공개 출시에서 걷는다**(ADR 0102) — 20회권이 「자리 > 풀이권」을 깨므로
- 결제수단은 **국내 카드 먼저**, 간편결제는 심사가 끝나는 대로 더한다. 구독 · 해외결제 · 가상계좌 · 휴대폰 소액결제 ·
  계좌이체는 두지 않는다
- 연동은 PortOne V2, PG 와 휴대폰 본인확인은 NHN KCP 가 **후보**다. 점술 · 동의 기반 매칭 업종의 입점 가능 여부와
  본인확인의 CI 제공 여부를 확인한 뒤 확정하고, 안 맞으면 같은 PortOne 연동 안에서 다른 PG 를 본다

**2026-09-15 의 새 기능 보류는 채팅에 한해 풀린다.** 프롬프트 실험 보류는 그대로다.

§7.1 앱 내 채팅 · §7.2 접속 상태는 `docs/product/prd/chat.md` 에 있다.

### 7.3 본인인증이 가입의 문이다 — **없다** (2026-09-23 에 고쳐 정했다, ADR 0101)

- **가입 폼은 PASS 휴대폰 본인인증 → 닉네임(중복 확인) → 안내 확인 순이다.** 인증이 끝나야 다음으로
  넘어가고, 인증 전의 계정은 가입이 안 끝난 계정이다. 공개 출시에서 테스트 코드 자리를 인증이 대신한다.
  한 폼 · 한 번의 누름은 그대로다(§5.0)
- **만 19세 이상만 가입한다**
- **사람은 CI 로 가린다** — 전화번호가 아니다. 같은 사람이 계정 둘을 동시에 둘 수 없다
- **인증 생년월일은 나이 확인에만 쓴다.** 사주는 사용자가 넣은 생년월일시로 계산하고, 둘은 따로 산다.
  **사주 입력은 성별 · 년까지 지금처럼 고칠 수 있다** — 인증값으로 잠그지 않는다. 등록된 생일과 실제
  생일이 다른 사람이 흔하기 때문이다
- **무료 풀이권은 한 사람에게 평생 한 번이다.** 탈퇴 뒤 같은 사람이 다시 가입할 수는 있지만 무료 몫은
  0 이다. 그래서 떠난 뒤에도 **CI 원문이 아닌 HMAC 식별값과 무료 몫을 받은 사실 · 시각만** 따로 남고,
  앱은 그것을 읽지 못한다. 보관의 적정성과 고지는 G-25 가 든다
- **베타 계정은 공개 출시 때 인증만 받는다** — 코드와 닉네임은 다시 묻지 않는다. 이미 받은 무료 5 가
  그 사람의 평생 한 번이다

### 7.4 화면 정리 — **반영**

원래 묶어서 검토하던 네 항목 중 메뉴와 매칭 진입은 반영했고, 나머지는 아래처럼 닫혔다.

**7.4.1 메뉴는 홈 · 궁합 · 인연 · 채팅 넷과 종 · 톱니 — 반영(2026-09-29, ADR 0126 — ADR 0109 의 홈 · 매칭 · 풀이 · 채팅을 이었다.)**

| 탭 | 누르면 | 켜지는 화면 |
| --- | --- | --- |
| **홈** | `/me` | `/me` · `/me/people/**` · 풀이 보관함 `/me/readings` · 한 사람 계산 `/saju`(ADR 0144) |
| **궁합** | `/compat` | `/compat` |
| **인연** | `/me/matching` | `/me/matching/**`(인연 기록 포함) |
| **채팅** | `/me/chat` | `/me/chat/**` |

- **결과 화면 셋은 온 곳의 탭을 켜고 ← 도 온 곳으로 간다**(ADR 0134, 운영자 결정 2026-09-29 u2). 사주풀이(`/me/readings/*`) ·
  직접 궁합(`/me/compat`) · 인연 궁합(`/me/match/*`)으로 가는 링크가 `?from=` 을 싣는다 — 홈 탭 · 보관함(칩과 함께)에서 연 것은
  홈, 궁합 탭은 궁합, 인연 탭 · 인연 기록은 인연, 채팅방은 채팅, 소식은 종이 켜진다. ← 의 글자는 가는 곳의 이름이다(「홈」 ·
  「풀이 보관함」 · 「궁합」 · 「인연」 · 「인연 기록」 · 「채팅」 · 「소식」). 온 곳이 없거나 모르는 값이면 결과 종류의 탭과 그 탭
  첫 화면이다 — 사주풀이는 홈, 직접 궁합은 궁합, 인연 궁합은 인연. ← 는 같은 사이트의 정해진 경로로만 간다

- **주소는 하나도 안 바뀌었다.** 탭 이름과 켜지는 화면만 바뀐다. 결과 화면은 위처럼 온 곳으로 켜고, 온 곳을 모를 때만
  **무엇인가**로 켠다 — 한 사람 풀이는 홈, 두 사람을 고른 궁합은 궁합, 동의로 열린 궁합은 인연
- 「풀이」 탭은 없다. **풀이 보관함**(`/me/readings`)은 홈 탭의 전체 기록이고(ADR 0133 · 0134) 홈 탭 「내가 받은 사주풀이」 머리의 **풀이 보관함** ·
  궁합 탭 · 인연 탭의 「모두 보기」가 그리로 간다
- 탭의 그림은 집 · **태극**(로그인 전 첫 화면 「궁합 보기」 입구와 같은 그림) · 사람 · 말풍선이다. 궁합을 가리키는 그림은 앱 어디서나 태극이고, 하트는 인연 쪽(오늘의 인연 · 요청)에만 남는다
- 폰에서는 아래에 떠 있는 둥근 독이다. 안 읽은 채팅 수는 채팅 탭에, **답할 받은 요청 수는 인연 탭에** 붙는다(ADR 0130)
- 머리글 오른쪽: **풀이권 잔액** · **종**(소식 `/me/requests`, 요청이 왔다는 소식을 뺀 안 읽은 알림 수) · **톱니**(프로필 · 계정 관리 · 서비스 설문 · 로그아웃).
  종 · 톱니 안의 화면은 어느 탭도 안 켠다
- 옛 탭 「사주·궁합」 · 「사람」은 홈 안의 길이 됐다(2026-09-24). 「소식」은 탭이 아니라 종이다 — 답해야 할 요청은
  **인연 탭의 수**가, 지나간 일은 종의 수와 **홈의 안 읽은 소식 띠**가 든다(ADR 0130)
- 관문이 되돌리는 자리(`/signup` · `/closed`)에서는 탭 · 종 · 풀이권을 안 세우고 톱니만 남는다
- 「인연 설정」 내비게이션은 없앴다. 상대 조건과 참여 관리는 계정 관리에 있고, 옛 `/me/discovery` 주소는 거기로 잇는다

**7.4.2 「보기」를 한 화면으로 — 궁합의 두 입구만 합쳤다(2026-09-09), 나머지는 안 한다(2026-09-23)**

**궁합의 두 입구는 합쳐졌다**(ADR 0054). 「직접 입력」과 「저장한 사람」이 화면 둘이 아니라
한 화면의 **칸마다 고르는 토글**이 됐고, 섞어 고를 수 있다. `/compat` 은 두 사람을 정하는
자리이고 `/me/compat` 은 그 결과다 — 하나로 합친 것이 아니라 **걸음으로 갈랐다.**

**사주 보기와 궁합 보기는 한 화면의 토글로 합치지 않는다**(2026-09-23). 둘은 지금처럼 따로 가는
흐름이고, 섞어 고르는 것은 궁합 화면 안에서 저장한 사람과 직접 입력을 칸마다 고르는 것까지다.
지난 판이 적은 값 — 저장된 사람의 출생 원문이 브라우저로 내려가고, 계산이 양쪽에서 돌고, 토글 하나가
로그인 요구를 켰다 껐다 한다 — 을 치르지 않는다
## 8. 미정 — 무엇을 할지 **아직 안 정한 것**

1. ~~탈퇴를 신청할 때 **상대에게 이미 보인 내 결과**는 어떻게 되나~~ — **답했다**(2026-09-23, ADR 0094).
   신청하면 함께 보던 궁합이 상대의 목록에서 내려가고, 처분 때 내 여덟 글자와 그 궁합풀이가
   지워진다. 대화는 상대에게 닫힌 날부터 90일 남는다(§5.3 · §7.1)
2. ~~두 관리 Person 끼리의 사이를 언제 묻나~~ — **답했다**(2026-09-23). 지금 동작이 결정이다 — 궁합을 볼 때마다
   두 사람의 관계를 보여 주고, 저장한 관계가 있으면 미리 골라 둔 채 보여 주며, 바꾸면 새 값을 남긴다
3. ~~하루 100회가 맞는 수인가~~ — **답했다**(2026-09-23). 서비스 전체 500회로 올리고 80% 알림은 400회로 따른다.
   운영 검증 계정의 호출은 따로 센다 — 올리는 일은 G-03 이 든다
4. ~~프롬프트 판을 여럿 두고 고를 것인가~~ — **고르지 않는다**(2026-09-23). 사용자도 운영자도 판을 고르지 않고,
   실험판은 선택지가 아니다. 나가는 것은 `CONTROL` **하나**이고, 검산 화면(`/me/reading/inspect`)도
   그 판만 보여 준다 — 나란히 서 있던 실험판은 운영판처럼 읽혀 걷었다(G-32). 실험판(`PROMPT_VARIANTS`
   · `PAIR_VARIANTS` · `MATCH_INPUT_VARIANTS`)은 시험과 실호출 도구로만 남는다
5. **모델 입력에 자리 색인을 더한다** — 2026-09-23 에 다시 열어 **더했다**(G-33, ADR 0099, `reading-prompt-v13` — 지금 판본은 개인 풀이
   `reading-prompt-v15` · 두 궁합 `reading-prompt-v17`).
   이것은 아래 9/1 실험의 결과가 아니라 사람의 새 결정이다.

   **지금 모양.** 모든 kind(개인 · 저장한 사람 · 비공개 궁합 · 인연 궁합)의 프롬프트에 「자리가 붙은 사실」이 선다 —
   원본 사실 하나가 번호 달린 한 줄이고(`[R1] A 월지 丑 → B 년지 戌 : 축술형`, 신살 · 공망은 `[S1]`), 맨 아래
   **자리 색인**이 자리마다 걸린 번호만 모은다(`- A 월지 巳 : R1 · R4 · S5`). 색인은 사실을 다시 적지 않고, 판정 기준
   글자는 걸린 자리가 아니라 색인에 안 선다. 자리는 사람 · 기둥 · 천간/지지를 갈라 적고(v11 그대로), 목록은 자료가 든
   만큼만 싣는다 — 인연 궁합 자료에는 원국 안 관계와 신살이 없으므로 두 사람 사이 관계만 선다(`WITHHELD_PATHS`).
   실호출 시험이 사용자가 읽는 본문을 자리 검사 넷(틀린 자리 · 번호 누설 · 천간 신살과 지지 관계 묶기 · 시간 미상
   합 단정)으로 잰다 — 2026-09-23 두 차례 열 편 모두 0 이었다(ADR 0099).

   **그 전의 기록 — 9/1 실험.** 원문은 저장소 밖 로컬 `.ab-overlaps/run-2026-09-01T04-38-24-525Z/`
   에만 있다(`manifest.json`·`rescored.json`·`key.json`). 자기 풀이 한 kind, 명식 다섯 ×
   세 팔 × **한 번씩**(15콜). A 는 색인 자료·지시 없음, B 는 색인과 선택 예산 지시, C 는 색인은
   있고 예산 지시만 없음. 15건 모두 저장 검사를 지났고, hard 게이트 실패는 **C 만 2건**이었다
   (천간 신살과 지지 관계를 묶은 것 1 · 시간 미상의 반방합을 단정한 것 1). A·B 는 0건.
   그 실험이 보인 것은 **「그 자료·그 지시로는 색인의 실익이 확인되지 않았다」까지였다.** 그 색인은 자리마다 사실을
   풀어 적었다 — 지금 색인은 번호만 든다. 그 뒤 2026-09-15 에 목록(`v11` · `v12`)을 두 궁합에만 실었다

6. ~~인연 궁합에 각자의 판정을 넣을 것인가~~ — **넣지 않는다**(2026-09-23). 제한형 입력을 그대로 둔다(ADR 0067). 제한형과 확장형을 같은 조건으로 견주는 도구가
   섰고(`docs/analysis/match-input-comparison.md`), 1~5라운드를 부른 뒤 **제한형을 운영으로 올렸다**(2026-09-15).
   - 확장형은 동의 화면이 「열리지 않는다」고 적은 신강신약·억부를 모델에 넣는다. 넣은 판정은
     두 사람이 함께 읽는 글에 드러날 수 있다 — 결과가 좋아도 **동의 문구를 먼저 고쳐야** 올린다
   - 운영은 제한형 A 와 읽는 법 4판이다. 옛 컷은 원복용으로만 남는다(`LEGACY_PAIR_ASSEMBLY`)
   - 옛 컷이 넣던 각자의 억부 후보·가중 세력은 새 인연 궁합 입력에서 빠졌다. 저장된 옛 풀이는 그대로다
   - 9/1 자리 색인 실험은 이 물음의 근거가 아니다
7. ~~PG 에서 무엇을 파는가~~ — **풀이권 묶음**(2026-09-23, ADR 0100). 1회 · 3회 · 5회 · 20회 넷을 팔고,
   산 풀이권에 유효기간은 없다. 무료 몫은 공개 출시부터 **1개**다. 인연 요청은 지금처럼 같은 풀이권을
   예약한다. 산 몫은 한도에 더해질 뿐이라 ADR 0021 · 0038 은 그대로 선다. 가격 · PG 는 G-21 이 든다
8. ~~실시간 접속 표시를 할 것인가~~ — **안 한다**(2026-09-23). 최근 활동 구간 셋을 화면을 다시 읽을 때
   갱신하는 지금 방식을 둔다(§7.2)
