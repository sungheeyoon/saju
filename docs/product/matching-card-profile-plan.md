# 매칭 카드와 공개 프로필 확장안

상태: 공개 프로필 추가 항목은 제안. 2026-09-18 소스 리뷰 반영.

매칭의 제품 기준·지나친 인연 정책은 [PRD §6.1](../prd.md#61-추천은-스냅샷이다--선다)을 따른다.
현재 실제 후보 카드와 지나치기 저장·보관 조회는 연결되어 있다. 보관함 복원과 실제 사진·
예시 표시 구분은 같은 날 후속 구현에서 연결했다([리뷰](matching-review-2026-09-18.md)).
직업·거주 지역·관심사 입력과 아래 프로필 확장 동선은 아직 구현된 기능이 아니다.

## 제품 기준

“내 귀인은 내가 찾는다.” 나의 사주를 기준으로 인연을 발견하고, 궁합의 근거와 상대의 소개를 읽은 뒤 내가 선택한다.
카드의 주 정보는 사진·닉네임, 예측 궁합 점수와 근거다. 직업·지역·취향은 상대를 알아가는 보조 정보이며 궁합 점수의 계산 재료가 아니다.

## 현재 데이터와 처리 방침

| 항목 | 현재 상태 | 이번 확장안 |
| --- | --- | --- |
| 닉네임 | 가입 시 입력, 프로필에서 수정, 후보 응답 제공 | 기존 사용 |
| 프로필 사진 | 프로필에서 1장 등록·교체·삭제, 후보 사진 조회 구현 | 기존 사용. 처음 매칭에 들어오면 등록 안내 |
| 소개 | 선택 입력, 최대 300자, 후보 응답 제공 | 입력 하나 유지. 카드 2줄, 상세 전체 |
| 예측 궁합 점수 | `CandidateCard.previewScore` 제공 | 기존 서버 결과 표시. 프런트 재계산 금지 |
| 점수 해석·추천 이유 | `verdict`, `reason`, `highlights`, `balanceLabel` 제공 | 기존 문구 사용. 카드와 상세의 역할만 나눔 |
| 직업 | 예시만 존재 | 선택 공개 정보로 추가, 최대 20자 자유 입력 |
| 거주 지역 | 예시만 존재. 사주 입력에는 출생지가 있음 | 거주 지역을 별도 입력. 출생지와 분리 |
| 관심사 태그 | 예시만 존재 | 정해진 목록에서 직접 최대 3개 선택 |
| 나이 | 사주 출생 정보는 있으나 후보 공개 응답에 없음 | 1차 카드에서 제외. 공개 범위 결정 전 나이 추출·노출 안 함 |
| 카드 제목·소개 본문 | 예시에 각각 존재 | 기존 소개 하나로 통합. 제목을 따로 받지 않음 |
| 질문형 자기소개 | 질문·답변 예시만 존재 | 1차에서 제외. 소개와 태그로 충분한지 확인 후 검토 |
| ‘푸른 나무의 기운’ 등 대표 기운 | 예시 문구. 후보의 대표 오행을 제공하는 필드는 없음 | 제거. 보완 오행 설명으로 대체 |

## 입력 시점과 이동 흐름

1. 가입: 기존 테스트 코드·닉네임·안내 확인 유지. 직업·지역·취향을 추가하지 않는다.
2. 내 사주 등록: 기존 출생 정보 입력 유지. 이 입력은 궁합 계산용이며 공개 프로필과 별개다.
3. 첫 매칭 진입: 비차단 안내 카드 ‘나를 소개하면 인연이 더 가까워져요’와 ‘내 카드 꾸미기 / 나중에’를 보여준다. 나중에를 누르면 바로 탐색한다.
4. 내 카드 꾸미기: 별도 가입 화면 대신 `/me/profile?returnTo=matching`에서 기존 프로필 폼을 확장한다. 저장 후 매칭으로 돌아온다. 복귀 목적지는 앱 내부의 정해진 값만 허용한다.
5. 재수정: 매칭 화면의 ‘내 카드 수정’, 기존 계정 메뉴의 ‘프로필’ 모두 같은 편집 화면으로 연결한다.

새 안내는 선택 입력을 돕는 것이며, 현행 사주 등록 후 인연 찾기 참여 정책을 자동으로 바꾸지 않는다. 필수 사진·심사·별도 참여 동의 관문은 이번 범위에 추가하지 않는다. 기존 사용자에게 재가입을 요구하지 않는다.

## 프로필 편집 화면

위에서 아래로 다음 순서로 구성한다.

- **나의 첫인상:** 사진 1장, 닉네임. 사진 선택 시 얼굴 중심으로 카드에 잘리는 영역을 미리 확인한다. 저장·삭제는 현재 사진 처리 방식 유지.
- **나를 소개하는 글:** 기존 소개 300자. ‘함께 어떤 시간을 보내고 싶은가요?’를 입력 도움말로 제공. 카드 미리보기에서는 2줄, 상세에서는 전체를 보여준다.
- **나의 일과 생활:** 직업, 공개 거주 지역. 모두 선택이며 빈칸으로 저장하면 해당 항목은 공개 카드에서 사라진다.
- **좋아하는 것:** 선택형 태그 최대 3개. 저장 전 실제 카드 배치로 확인.

편집 화면에 ‘입력한 공개 프로필은 매칭과 요청 화면에 표시됩니다’를 안내한다. 정보별 미입력·지우기를 지원하며, 미입력 값을 ‘회사원’·‘서울’ 등으로 채우지 않는다.

### 직업

‘브랜드 디자이너’, ‘대학원생’, ‘자영업’, ‘쉬어가는 중’ 같은 자기표현을 받는다. 최대 20자, 줄바꿈 제외, 앞뒤 공백 정리. 회사명·직장 주소는 별도로 받지 않는다. 처음에는 직업 선택 분류와 자유입력을 함께 운영하지 않는다.

### 거주 지역

‘현재 생활하는 지역’이라는 이름으로 받는다. 시·도 선택 → 원하면 시·군·구 선택. 시·도만 고르면 ‘서울’, 구까지 고르면 ‘서울 · 성동구’로 공개될 것을 저장 전에 보여준다. 언제든 구를 지워 광역 지역만 공개하거나 전체를 비울 수 있다.

주소·동·GPS·출생지 자동 채우기는 사용하지 않는다. 지역을 받는 것과 지역 필터·거리 추천을 만드는 것은 별도 범위다. 이번에는 소개 정보로만 쓴다.

### 관심사 태그

태그는 사주 분석 결과가 아니라 사용자가 직접 고른 취향이다. 시스템이 소개에서 추출하거나 사주로 추정하지 않는다.

초기 목록 예시:
- 일상: 동네 산책, 카페, 요리, 반려동물
- 문화: 독립서점, 독서, 전시, 영화, 공연
- 기록: 필름 사진, 글쓰기, 여행 기록
- 활동: 러닝, 등산, 여행, 운동
- 음악: 음악 감상, 재즈

운영자가 관리하는 고정 목록과 고유 ID를 사용한다. 화면에 선택 개수 ‘2 / 3’를 표시하고, 3개 선택 시 나머지는 비활성화한다. 선택한 항목은 다시 눌러 해제할 수 있다. 미선택도 저장 가능하다. 카드에는 선택 순서로 최대 3개 표시한다. 태그를 눌러 검색·필터로 이동시키지 않는다.

궁합 점수나 추천 순서에 반영하지 않으며, 별도 비교를 구현하기 전 ‘공통 관심사’라고 표시하지 않는다. 1차에는 자유 태그 입력을 받지 않는다.

## 작은 카드의 정보 우선순위

```text
[ 프로필 사진                       ]
[ 닉네임                            ]
[ 직업 · 공개 거주 지역  (있을 때만) ]

나와의 예측 궁합 점수
79 / 100       아주 좋은 궁합일 수 있어요.
木 내 사주에서 적은 목 기운을 보완해 줘요.

소개 최대 2줄
[동네 산책] [독립서점] [필름 사진]
궁합의 이유와 프로필 보기 →

되돌리기       다음 인연       궁합 요청
```

사진 위에 대표 기운 배지와 나이를 추가하지 않는다. 궁합 정보는 사진 아래 한 영역으로 모은다. 직업·지역 중 하나만 있으면 구분점을 빼고 하나만 표시한다. 둘 다 없으면 해당 줄 전체를 생략한다.

소개·태그가 비어도 사진·닉네임·점수·추천 이유만으로 카드가 완성된다. 소개가 비면 ‘자기소개 없음’을 표시하고 가짜 예시 소개로 채우지 않는다. 사진이 없는 실제 회원은 닉네임 기반 기본 이미지를 사용하며 AI 예시 얼굴을 대신 배정하지 않는다.

## 궁합 문구의 규칙

- 점수와 판정은 기존 `previewScore`, `verdict`를 사용한다.
- 카드에는 `highlights` 중 첫 항목 1개만 표시한다. 서버가 주는 기존 순서를 유지하며 ‘가장 강한 보완’이라고 해석하지 않는다. ‘외 1개’ 문구는 빼고, 상세 진입에서 모든 보완 항목을 읽게 한다.
- 내 해당 오행이 0개인 경우와 적게 있는 경우의 ‘부족한 / 적은’ 구분은 기존 `cardTextFor`가 정한다. 새 화면에서 문구를 다시 만들지 않는다.
- 보완 오행이 없으면 `reason`을 표시한다. 긍정적인 보완 문장을 만들어 넣지 않는다. 이 상태에서는 소개를 접어도 궁합 이유는 끝까지 읽을 수 있게 한다.
- 특정 오행이 있다고 성격·경제력·연애 결과를 단정하지 않는다. 취향 태그도 분석 근거에 포함하지 않는다.
- ‘귀인’은 인연을 스스로 찾는 제품 메시지다. 현재 데이터가 판정하지 않는 ‘천을귀인’ 등 특정 신살 판정을 부여하지 않는다.

## 상세 보기

상세는 ‘왜 나와 맞는지’부터 보여준다. 점수·판정 → 모든 보완 항목 → 기존 `reason` → 사진·소개 전체·직업·지역·태그 → 상세 궁합 요청 순서다.

원국 전체·오행 전체 분포·출생 입력·상세 궁합 분석을 미리 열지 않는다. 상호 동의 전에는 기존 후보 공개 범위까지만 보여준다. 실제 매칭의 하트는 확인 창을 거쳐 기존 요청·동의 절차로 이어진다. 예시 화면의 하트는 실제 요청을 보내지 않는다.

## 실제 구현에 필요한 변경

1. 기존 `app_user` 공개 프로필에 선택 직업, 거주 시·도 코드, 거주 시·군·구 코드를 추가한다. 태그는 관리용 목록과 사용자 선택 관계로 저장하고 최대 3개·선택 순서를 검증한다. 생년월일 테이블과 분리한다.
2. 프로필 입력 타입·서버 저장 함수·DB 검증·폼을 함께 확장한다. 기존 사용자는 새 항목이 비어 있어도 정상 동작한다.
3. 후보용 `my_discovery_board()`와 `BoardRow`·`CandidateCard`에 승인된 공개 항목만 추가한다. 새 필드를 보여주려고 클라이언트가 상대 계정 테이블을 직접 조회하지 않는다.
4. 점수 스냅샷·점수 계산과 공개 프로필 정보를 분리한다. 닉네임·사진·직업·소개·태그 수정은 기존 후보 조회 권한 안에서 다음 조회에 반영하고 점수 재계산을 요구하지 않는다. 사용자 정보를 계속 이전 값으로 보여주는 캐시가 남지 않게 갱신한다.
5. 내가 보는 프로필 미리보기는 사진·소개·선택 정보의 배치만 보여준다. 상대에 따라 달라지는 궁합 점수를 ‘나의 점수’처럼 넣지 않는다.
6. 모든 선택 정보의 삭제, 사진 없음, 소개 300자, 긴 직업명, 태그 0~3개, 보완 항목 없음/복수, 좁은 화면, 기존 계정의 첫 진입을 검증한다.

## 권장 구현 순서

- **현재:** 기존 사진·닉네임·소개·궁합 데이터로 실카드를 연결했다. 보관함의 복원·사진·표시와 되돌리기를 연결했다. AI 예시 프로필은 미리보기 경로에 유지한다.
- **다음:** 기존 프로필에 관심사 태그, 직업, 공개 거주 지역을 추가. 입력·저장·후보 응답·표시를 항목별로 끝까지 연결한 뒤 공개.
- **마지막:** 첫 매칭 안내, 내 카드 미리보기, 편집 후 복귀 흐름을 다듬는다.

나이 공개, 복수 사진, 질문형 소개, 거리 필터, 태그 기반 추천은 이번 1차 범위에서 제외한다. 필요성이 확인되면 공개 범위와 입력 흐름을 별도로 기획한다.

## 확인한 코드

- `app/signup/form.tsx`: 가입 입력
- `app/me/profile/page.tsx`, `form.tsx`, `actions.ts`: 사진·닉네임·소개 편집
- `src/lib/profile/index.ts`: 소개 300자, 사진 1장과 크기·형식 제약
- `app/me/candidates.ts`: 후보 공개 데이터
- `src/lib/discovery/index.ts`: 점수·보완 오행 문구·공개 범위
- `app/me/matching/matching-experience.tsx`: 실후보·미리보기 공용 카드
