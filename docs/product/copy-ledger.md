# 화면 문구 대장

**규칙의 원본은 `CONTEXT.md` §8 이다. 이 대장은 운영자가 확정한 화면 문구와 예외만 든다.**
에이전트는 대장을 임의로 늘리지 않는다 — 새 후보는 PR · 보고에 표로만 낸다. 확정되면 그 PR 이
대장에 줄을 더하고 PR 번호 · 날짜를 적는다.

**UI 변경 요청이 오면 문구는 여기서 먼저 찾는다** — 순서는 `docs/agents/code-rules.md` 「화면 문구」가 든다.
시안 · 외부 리뷰 · 에이전트가 쓴 문구는 이 대장에 들기 전까지 확정이 아니다.

서비스 이름은 **점점**이다(2026-09-24 확정, `src/lib/brand`). 「만세력」은 서비스 이름이 아니라 「만세력 엔진」처럼
사주 계산 기능을 가리킬 때만 쓴다.

2026-09-29 에 claude.ai 아티팩트(<https://claude.ai/code/artifact/263b0f15-c2f5-48a1-a327-d747a58ed639>)에서
옮겼다. 그 아티팩트는 이제 보기용이고 원본은 이 파일이다. **옛 판(2026-09-03, 서비스 이름이 「만세력」이던 때)은
아티팩트의 「과거 기록」에 있다 — 기준이 아니다.**

## 01 규칙 — 버튼은 결과를 말하고, 닫는 것은 「취소」다

운영자 결정, 2026-09-28. 본문은 `CONTEXT.md` §8 이고 아래는 그 요지다.

- 실행 버튼은 결과를 말하는 동작명 — 「확인」 같은 추상어 대신 「목록에서 빼기」 · 「요청 보내기」 · 「차단하기」 · 「신고하기」 · 「탈퇴 신청하기」.
- 목록 관계를 없앨 때는 「목록에서 빼기」. 파괴 여부가 불분명한 곳에 「삭제」를 쓰지 않는다.
- 확인창을 닫는 버튼은 「취소」.
- 「그만두기」는 입력 내용이 사라지는 작성 중단에만, 「작성 그만두기」처럼 구체적으로.
- 화면 이름은 「저장한 사람」. 「사람 탭」 · 「자리 비우기」를 쓰지 않는다.
- 말투 — 앱의 대부분은 합쇼체(「~습니다」)이고, 오류 화면 · 404 · 매칭 참여 오류는 해요체로 정했다. 이름 뒤 「님」은 띄어 쓴다(「{이름} 님」, 국립국어원 기준).

## 03 확정 문구 — 버튼, PR #299 (2026-09-28)

운영자가 표를 확정했다. 「그만두기」는 닫을 때 입력이 실제로 사라지는지 코드로 확인해 갈랐다.

## 04 따로 남긴 것 — DB 가 내는 문장

DB 가 내는 닉네임 중복 거절 「이미 쓰고 있는 닉네임입니다.」(`save_my_profile` · `complete_signup`)는 옛 표기다.
마이그레이션이 드는 일이라 따로 한다.

## 06 확정 문구 — 말투 (PR 대기)

조율자가 전한 운영자 확정 목록이다(2026-09-29). 말투 PR 이 머지되면 그 본문 표로 이 절을 맞추고 「PR 대기」를 번호로 바꾼다.

| 자리 | 확정 | PR |
| --- | --- | --- |
| 받은 요청 띠 | 수락하면 인연 궁합이 열려요 | PR 대기 |
| 알림 — 완성 | 인연 궁합이 완성됐어요 | PR 대기 |
| 알림 — 실패 | 인연 궁합을 만들지 못했어요. 인연 궁합 화면에서 다시 시도해 주세요. | PR 대기 |
| 빈 표지 | 내 사주 등록하기 · 사주풀이 받기 | PR 대기 |
| 저장한 사람으로 가는 링크 | 저장한 사람 관리 | PR 대기 |
| 생성 중 | 작성 중… · 검토 중… | PR 대기 |

「답하면 궁합이 열린다」처럼 쓰지 않는다 — 거절도 답이고 궁합은 수락해야 열린다(실제 버튼 `수락하고 궁합 열기`).
