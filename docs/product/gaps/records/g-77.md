# G-77 기록

표의 줄: [간극 대장 「채팅 안전 베타」의 G-77](../../gaps.md#채팅-안전-베타)

2026-10-08 리뷰가 고쳤다 — 마이그레이션 `20261120090000` 이 새 읽음 문 `mark_chat_read(p_match_id, p_up_to_seq)` 를 세우면서
옛 한 칸 서명을 같은 자리에서 지웠다. 그러면 `db push` 와 앱 배포의 어느 순서에도 떠 있는 옛 앱 · 열린 브라우저 · 롤백의 읽음이
실패하는 창이 선다. 그래서 옛 것을 남겼다(넓히기, `docs/ops/runbook/deploy.md` 「규약 넷」 3). 동작은 옛것(그 순간 방의
마지막까지), 권한 판정은 새것과 같다(볼 수 없는 방은 `42501`).

## 닫는 길

1. 새 앱이 운영에 오른다.
2. **잰다** — 배포 뒤 하루 넘게, `pg_stat_statements` 에서 `mark_chat_read` 를 든 문 가운데 `p_up_to_seq` 가 없는 것의
   `calls` 가 늘지 않는다(개인정보 없는 집계 — `npm run db:remote`).
3. 좁히기 마이그레이션이 `drop function public.mark_chat_read(uuid)` 를 하고, 두 벌을 든 시험 줄을 뺀다 —
   `supabase/tests/74_authenticated_doors.test.sql` 의 옛 서명 한 줄, `82_live_channel.test.sql` 의 「문의 모양」 넷.
