# G-25 기록

표의 줄: [간극 대장 「공개 출시」의 G-25](../../gaps.md#공개-출시)

표의 「G-25」 줄 메모 칸에 쌓였던 실행 기록이다 — 문장은 그대로 옮겼다(2026-10-05). 줄을 닫으면 이 절도 함께 걷는다.

**정한 것(2026-09-23):** ① 메시지 보존은 §7.1 의 90일을 처리방침이 옮겨 적는다 ② 결제 · 청약철회 기록 **5년**, 소비자 불만 · 분쟁 처리 기록(환불 요청 · 중복결제 · 취소 이의 ·
미제공 신고) **3년** — 탈퇴 3일 처분의 예외로 따로 두고 앱은 못 읽는다(전자상거래법 시행령 제6조) ③ 개인정보처리시스템에 접속한 운영자의 접속기록 **1년 이상**(안전성 확보조치 기준 제8조) —
이용자 5만 명 이상이 되거나 고유식별정보 · 민감정보를 받게 되면 2년으로 다시 본다 ④ 고객 문의는 이메일과 앱 안 문의, **3영업일 안 첫 답**. 1372 안내는 문의 대응 절차에 두지 않는다 ⑤
결혼중개업법은 지금 비해당으로 판단하고 제품 구조를 바꾸지 않는다 — 요청 때 예약 · 수락 때 자동 생성 그대로(ADR 0038 · 0100). 지키는 경계: 결혼 상대 · 성혼 · 결혼 상담이라 광고하지 않는다
· 결혼 의사나 혼인 조건을 받지 않는다 · 교제나 성혼을 보장하지 않는다 · 약관의 서비스 정의에 결혼 알선이 아님을 적는다 **변호사 검토로 정하는 것:** ⑥ 환불 산식 — 「쓴 회차를 1회권 가격으로 공제」와
「7일 뒤 10% 공제」가 유효한지. 무료 · 예외 몫은 환불하지 않는다는 것과 예약 중인 몫은 풀릴 때까지 대상이 아니라는 것은 정했다(G-21 ③). 묶음별 결제 · 사용 이력은 어느 산식이든 필요하므로 먼저
만든다 — **섰다(2026-09-24, ADR 0106)**: 운영자 문 `operator_reading_refund_basis` 가 묶음마다 산 수 · 쓴 수 · 예약 중 수 · 안 쓴 수 · 결제 금액 · 결제
시각 · 환불한 것을 한 번에 내고 접속기록에 남긴다. 떠난 사람의 결제 기록은 `retention.reading_payment` 에 마지막 결제 사건부터 5년(②) — 로그인 이메일은 옮기지 않는다. 승인된 적
없는 주문의 거절 알림은 `retention.refused_reading_payment` 에 최소 칸으로 마지막 거절 알림부터 5년(G-23 ⑥, 2026-09-24 — 5년 대상인지는 변호사 검토 B-8) ⑦ 탈퇴
때 남은 유료 풀이권 — 바로 소멸시킬지는 환불 기준과 함께 본다. 그때까지는 탈퇴 판에 남은 수량과 환불 신청 길을 분명히 보인다 ⑧ 무료 지급 HMAC 식별값의 보관 기간 · 목적 · 근거(개인정보 보호법
제21조, ADR 0101) — 기한 없음이 어렵다면 5년, 기한이 생기면 ADR 0101 을 다시 연다 ⑨ 이용자 IP · 접속 시각 3개월 — 통신비밀보호법(시행령 제41조②) · 전기통신사업자 해당 여부를 본
뒤 확정한다(G-52 에서 넘어옴, ADR 0098) ⑩ 이용약관 전문 — 공정위 디지털콘텐츠 이용 표준약관을 바탕으로 쓰고, 분쟁 해결 조항에 1372 · 분쟁조정기관을 넣을지도 여기서 정한다 ⑪ 결혼중개업법 적용
여부 — 서비스 구조를 보이고 짧게 확인한다. 신고 · 보증보험을 전제로 문서를 만들지 않는다 ⑫ **운영자 접속기록 1년인가 2년인가**(ADR 0105) — 「개인정보의 안전성 확보조치 기준」 제8조는 원칙
1년, 정보주체 5만 명 이상 · 고유식별정보 · 민감정보 처리 등은 2년이다. **본인확인에서 받는 CI 가 고유식별정보에 해당하는지**(ADR 0101 은 CI 원문을 안 남기고 HMAC 식별값만 둔다)와 그래서
2년인지를 묻는다 — 단정하지 않았다(요청서 `docs/legal/counsel-request.md` 에 이미 든 물음). 2년이면 S3 기본 보존을 730일로 올리고 이미 있는 객체의 보존을 만료 전에
늘린다(`docs/ops/runbook/security.md` 「반출」 4) **선행:** 사업자등록 · 통신판매업 신고(PG 신청 조건, G-21). **변호사 검토는 공개 출시 전 운영자가 한 번에 처리한다 — 다른 구현을 막는 blocker 가
아니다. 다만 결제 판매(G-21)와 본인확인(G-20)을 실제로 여는 일은 검토가 끝날 때까지 하지 않는다.** 묶음의 입구는 `docs/legal/README.md`(요청서 · 약관 초안 · 처리방침 v8 ·
미결 질문 열여덟 · 빈칸), 표지는 `[출시 전 운영자·변호사 확인]`. **운영자 승인(2026-09-24):** 운영자 CLI 기록은 SQL 원문이 아니라 목적 · SHA-256 이다(ADR 0105 추기) **초안이
섰다(2026-09-24):** 이용약관 초안 `docs/legal/terms-draft.md`(과기정통부 고시 제2022-66호 「디지털콘텐츠 표준약관」의 조 구성 — 공정위 판 원문은 못 찾았다) · 처리방침
v8 `docs/legal/privacy-v8-draft.md` — **2026-09-24 에 구현과 맞춘 완성본으로 다시 썼다**(법인 소재와 처리 위치를 가름 — Supabase 서울
`ap-northeast-2` · Vercel 서버 `icn1` · 전송망은 세계, AWS 반출 서울 기본안 · OpenAI 로 가는 것 · 본인확인의 받는 것과 남기는 것 · 결제 장부 칸 그대로 · 접속기록 칸
· 쿠키와 저장소 · 보존과 크론, 부록 A 구현 대조 · B v6 대조표 · C 재확인 지점 · D 빈칸) · 변호사 검토 요청서 `docs/legal/counsel-request.md`(⑥~⑪ + CI
고유식별정보 여부 · 접속기록 1년/2년 · 서울 리전의 국외 이전 여부 · 본인확인기관의 지위). **화면은 그대로 `notice-v6` 다** — v7 반영(`NOTICE_VERSION` ·
`NOTICE_ACK_FLOOR` 를 `notice-v8` 로, 확인한 사람 전원이 다시 읽는 내용 개정)과 가입 폼의 약관 확인 칸은 **변호사 검토와 한글 문구 승인 뒤**다. **남은 것:** ㉠ 변호사 검토
1회 ㉡ 빈칸 — **사업자등록 뒤**(상호 · 대표자 · 주소 · 전화 · 사업자등록번호 · 통신판매업 신고번호 · 개인정보 보호책임자 · 고객 문의 이메일 · 시행일)와 **계약 뒤**(PortOne · PG ·
본인확인기관의 이름 · 소재 · 처리 위치 · 넘기는 항목)뿐이다 — AWS 리전은 서울(`ap-northeast-2`) 기본안으로 채웠다 ㉢ v6 이 구현과 어긋난 자리 — 안전성 확보조치 절 · 자동 수집 장치
절이 없다, Supabase · Vercel 을 「미국」으로만 적는다, **궁합풀이가 OpenAI 에 두 사람을 부르는 이름과 사이를 싣는데 「여덟 글자와 사실만」이라 적는다**, 닉네임 · 소개 · 사진 · 메시지
· 신고를 받는 항목으로 안 적는다, 닫힌 방 메시지를 「90일이 지나면 지웁니다」라 하나 지우는 손은 달마다 도는 SQL 이다 — 전부 v7 에서 바로잡았고 v6 은 따로 고치지 않는다(v6.1 없음, 운영자 결정
2026-09-24) ㉣ 출시 전 운영 결정 — 이전 방침의 열람 경로 · 선택 항목 「다음 테스트 소식 받기」의 이름 · 문의 메일함의 3년 보관 · 접속기록 DB 원본의 파기 시점 ㉤ 앱 안 문의 창구 · 결제
내역의 철회 신청 칸이 아직 없다. 이용 정지의 소명과 경고의 이의 제기는 고객 문의 이메일로 받는다(운영자 결정 2026-09-24, ADR 0108 추기) — 새 창구를 만들지 않는다 **약관 · 처리방침 본문의
「만세력 서비스」 · 「만세력 이용약관」은 다음 판에서 「점점」으로 바꾼다**(G-58 에서 넘어옴, 2026-09-28) — 고지한 판의 글자라 상수를 안 읽고, 처리방침은 판을 올리면 안내 확인이 다시 돈다 **정지된
계정은 스스로 탈퇴 · 동의 철회를 못 한다**(2026-09-30 에 잼) — `request_account_deletion()` 이 「이용이 정지된 계정입니다.」로 거절하고(main 의 기존 동작), 동의 두
문도 같은 문장으로 거절한다(#384). 법무 검토 때 함께 본다
