# G-106 기록

표의 줄: [간극 대장 「채팅 안전 베타」의 G-106](../../gaps.md#채팅-안전-베타)

2026-10-11, #648(방 머리의 궁합 단추가 생성 상태와 점수를 든다) 머지 전 검토가 「뒤에 고쳐도 됨」으로 남긴 것이다.

- 방 머리의 단추는 `app/me/chat/[matchId]/room-compat.ts` 가 `my_reading` · `my_last_reading_run` 으로 읽고, 방이 다시 그려질 때만
  새로 읽힌다. 다시 그리는 신호는 계정 채널의 `requests` 다(`app/live/changes.ts` 의 `redrawsOn`).
- 인연 궁합 시도의 신호는 `tell_match_reading_settled`(`supabase/migrations/20261120090000_the_app_hears_what_changed_on_one_private_channel.sql`
  「7. 인연 궁합」) 하나뿐이고, `reading_run` 의 **UPDATE 로 `running` 에서 벗어날 때만** 보낸다. 새 시도의 INSERT 에는 신호가 없다.
- 그래서 실패 뒤 상대가 인연 궁합 화면의 「궁합풀이 받기」로 새 시도를 열면, 내 방 머리는 그 시도가 끝날 때까지 「다시 받기」로
  남는다. 「만드는 중」을 건너뛸 뿐이다.

틀린 동작이 되지 않는 까닭:

- 시도가 끝나면 UPDATE 신호가 와 단추가 점수나 「다시 받기」로 맞게 선다.
- 그 사이 말이 한 통이라도 오가면 방이 다시 그려져 「만드는 중」이 선다.
- 「다시 받기」를 눌러도 가는 곳은 인연 궁합 화면이고, 그 화면은 마지막 시도를 읽어 만드는 중임을 말한다(`app/me/reading/current.ts`).

닫는 길은 둘이다 — `reading_run` 의 match 갈래 INSERT 에 두 사람에게 `requests` 를 보내는 트리거를 하나 더하거나(db 역할,
새 마이그레이션), 이대로 둔다.
