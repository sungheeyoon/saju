## 운영자가 정한 범위 (2026-10-16)

| 자리 | 필요한 동작 | 처리 기준 |
| --- | --- | --- |
| 회원 상세 | 풀이권 추가 지급 | 수량 · 사유 입력. 장애 보상인지 운영 지급인지 기록 |
| 회원 상세 | 지급한 풀이권 회수 | 미사용분만 회수. 유료 구매분 환불과 구분 |
| 회원 상세 | 풀이권 이력 | 구매 · 사용 · 환불 · 운영 지급 · 회수를 한곳에서 확인 |
| 신고 상세 | 조치 없음 · 추가 검토 · 경고 · 이용 정지 | 판단 근거를 남기고 화면에서 바로 처리 |
| 신고 상세 | 대상 회원 열기 | 현재 상태 · 이전 경고 · 처분 이력 확인 |
| 회원 상세 | 이용 정지 해제 | 해제 사유와 실행자 기록 |

- 신고 처리는 목록에서 급한 건 확인 → 신고 당시 근거 확인 → 같은 화면에서 처분 → 반영 결과 확인으로 끝난다. 지금은
  UUID 를 복사해 `review_report` SQL 을 돌린다(`app/ops/reports/[reportId]/page.tsx`, `docs/ops/runbook/moderation.md`).
- 풀이권 보상은 신고 화면에 붙이지 않고 대상 회원을 열어 사유를 이어 지급한다 — 신고 처분과 피해 보상을 따로 정확히 적는다.
- 차례: ① 풀이권 지급 · 회수 · 이력 → ② 신고 처분 → ③ 정지 · 해제.
- **지급 · 회수 · 처분 · 정지 · 해제 모두 사유와 실행자 이력이 남는다**(운영자 2026-10-16).
- 회원 화면의 경고 수는 `public.report` 만 센다 — 탈퇴한 신고자의 `retention.report` 경고는 범위를 밝히고 따로 확인한다(G-110
  결정). 처분 이력도 같은 경계를 지킨다(운영자 2026-10-16).
- 참고(외부 리뷰, 2026-10-16): 제재 화면은 통지 · 소명 · 해제까지 잇는다 — 카카오 비즈니스 운영정책
  <https://kakaobusiness-policy.kakao.com/OPERATIONPOLICY/>.

## 이 범위 밖으로 남긴 것

- 웹훅이 오지 않았거나 처리되지 못한 결제를 찾는 결제 대조 — G-110 ④ 는 웹훅이 온 결제의 이상만 알린다. [G-112](g-112.md) 로 뗐다.
- 탈퇴 대기의 해제 — 런북 「이용 정지와 해제」의 SQL 그대로다(탈퇴의 흐름은 `docs/ops/runbook/erasure.md`).
- 떠난 사람의 신고(`retention.report`)의 처분 — 목록에 서지 않으므로 지금처럼 런북 SQL 이다.
- 기한이 있는 정지 — 해제는 사람이 누른다(정한 것 G-111-8).
- 운영자 권한의 회수 — 지금 절차(`docs/ops/runbook/operators.md`) 그대로다. 화면은 운영자 계정을 정지하지 않는다(정한 것 G-111-10).

## 요구사항 (2026-10-16, 구현 전)

G-110 의 PR 넷(#725 오늘의 숫자 · #726 결제 이상 알림 · #727 주문 · 환불 · #729 회원)이 같은 DB 함수 · 접속기록 동작 목록을
고치는 중이라 **이 절과 아래 「화면 설계」는 요구사항만 적는다** — 마이그레이션 · 문 · 앱 코드는 그 넷이 머지된 뒤다. 그 PR 들의
지금 모양(회원 화면 `/ops/members?q=`, #729 의 ADR · 환불의 확보 → 확정 → 준비 취소, #727 의 ADR)에 맞췄다. ADR 은 구현 PR 이
쓴다(번호가 G-110 과 겹치지 않게).

### 모두에 걸리는 것

- **운영자만 한다.** 화면은 지금 운영 화면과 같은 경계다 — 자료를 청해 거절당하면 404(ADR 0103). 쓰는 문은 `authenticated` 에
  열고 안에서 `is_operator()` 로 닫는다(#727 의 ADR 의 4 와 같은 모양). 운영자가 아니면 `42501` 이고 앱이 `note_operator_denial` 로
  같은 동작 이름을 따로 적는다. **서버 열쇠(`service_role`)에는 열지 않는다** — 열쇠가 새도 풀이권을 나눠 주거나 계정을 세우는
  문이 되지 않게(ADR 0043 의 까닭 그대로).
- **실행자는 부른 사람이다.** 문이 `auth.uid()` 를 실행자로 적는다 — 인자로 받지 않는다(지금 `review_report` 는 운영자 UUID 를
  인자로 받는다). 내부 기록은 운영자 UUID, 화면은 운영자 닉네임이다(G-111-9).
- **사유는 갈래 하나 + 메모.** 갈래는 DB 가 받는 닫힌 목록이고, 메모는 짧은 자유 글(지급 · 회수 · 정지 · 해제 200자, 판단 근거는
  지금처럼 500자)이다. 메모에는 이메일 · 실명 · 연락처를 적지 않는다 — 칸 아래 한 줄로 말한다. 이용자에게는 갈래만 간다.
- **같은 요청은 한 번만 반영한다.** 쓰는 문(지급 · 회수 · 처분 · 정지 · 해제)은 화면이 폼을 열 때 만든 **요청 고유 번호**를 받고,
  DB 가 그 번호에 유일 제약을 건다. 응답이 끊겨 다시 눌러도 두 번째는 첫 번째의 결과를 돌려줄 뿐 새 줄을 만들지 않는다. 같은 번호에
  다른 내용(수량 · 갈래 · 대상)이 오면 거절한다(#727 의 「같은 취소 번호로 다시 눌러도 한 번만」과 같은 모양).
- **이력은 지우지 않는다.** 지급 · 회수 · 정지 · 해제는 덮어쓰지 않고 줄이 쌓인다. 신고 처분만 신고 한 건의 결과를 덮어쓰되(이의
  제기 인정 등, ADR 0107), 덮어쓰기 전 결과도 이력 줄로 남긴다.
- **접속기록에 남는다** — 쓰는 문마다 같은 트랜잭션에 한 줄. 거른 조건 칸에는 **id 만**(계정 · 신고 · 이력 줄) 적는다 — 메모 ·
  판단 근거 · 닉네임은 적지 않는다(반출본은 지울 수 없다, ADR 0105 결정 2). 거절된 시도는 줄과 함께 되감기고 거절 기록이 따로 남는다.
- **경고 · 처분의 경계는 G-110 그대로다** — 회원 화면이 세는 경고 · 처분 이력은 지금 계정의 신고(`public.report`)뿐이다. 신고한
  사람이 떠나 옮겨진 경고(`retention.report`)는 화면이 읽지 않고, 「탈퇴한 신고자의 분리 보관 경고는 런북 SQL 로 따로 셉니다」 한 줄이
  늘 선다(#729 의 ADR 의 3). 이 판의 처분 이력 · 신고 상세의 대상 회원 요약 · 「이번이 N회째」 문장도 **「현재 신고 기준」** 을 단다.

### ① 풀이권 지급 · 회수 · 이력 — 회원 상세

자리는 회원 화면(`/ops/members?q=<계정 id>`, #729)의 찾은 결과다. 다른 화면에서 회원을 열 때도 이 주소로 간다 — 계정 id 로 찾으면
한 명이라 새 주소를 세우지 않는다. 지급 · 회수의 수량은 「장」, 실제 풀이에 쓴 것은 「회」로 부른다.

| 동작 | 처리 기준 | 남는 칸 |
| --- | --- | --- |
| 지급 | 수량 1 ~ 10장(G-111-1). 사유 갈래 `outage`(장애 보상) · `operator`(운영 지급). 메모 필수. 신고 화면에서 넘어왔으면 그 신고가 「관련 신고」로 따라온다. 요청 고유 번호로 한 번만. 지급마다 장애 알림 한 줄(계정 id · 수량 · 갈래만). 이용자에게 「풀이권 N장이 지급됐어요 — <갈래>」(G-111-3) | 계정 · 수량 · 갈래 · 메모 · 관련 신고(없으면 비움) · 요청 고유 번호 · 실행자 · 시각 |
| 회수 | **지급분의 안 쓴 것만** — `지급 합 − 회수 합 − 지급 몫의 살아 있는 쓰임(확정 + 예약)`. 예약 중인 지급 몫은 풀린 뒤에 걷는다(환불과 같은 규칙). 무료 몫 · 산 몫(묶음)은 건드리지 않는다 — 유료 구매분은 주문 화면의 환불이다. 갈래 `mistake`(잘못 지급) · `duplicate`(중복 지급) · `other`(기타, G-111-4). 메모 필수. **사람 자물쇠(`reading:user:<id>`) 안에서** 셈하고 적는다 — 풀이 시작 · 인연 요청이 같은 자물쇠를 잡으므로(ADR 0106) 회수와 마지막 한 장을 다투면 한쪽만 이긴다. 요청 고유 번호로 한 번만. 이용자에게 「풀이권 N장이 회수됐어요 — <갈래>」 | 계정 · 수량 · 갈래 · 메모 · 요청 고유 번호 · 실행자 · 시각 |
| 이력 | 구매(승인된 주문) · 사용(쓰임 장부의 확정 · 예약 · 풀림, 몫은 무료 · 지급 · 묶음 · 몫 밖) · 환불(주문 환불) · 지급 · 회수를 한 목록에 시각 차례로 | 읽기 — 접속기록 한 줄 |

- 쓰는 순서는 지금 그대로다 — 무료 → 예외(지급) → 산 때가 이른 묶음(ADR 0106). 그래서 「지급분에서 쓴 것」은 장부의 `grant` 몫이다.
- **사용 줄은 차감인 것만 「−1회」다.** 확정은 「−1회 사용」, 예약은 「1회 예약 중」(차감 아님), 풀림(실패 · 유효시간 넘김 · 요청
  거절 · 만료)은 「반환 · 차감 없음」으로 적고 수에 부호를 달지 않는다.
- 이력의 사용 줄은 **무엇을 풀었는지 적지 않는다** — 날짜 · 몫 · 상태만(풀이 대상 · 출생정보는 회원 화면의 경계 밖, #729 의 ADR 의 2).
- 구매 · 환불 줄은 수량과 주문 번호 링크만, 금액은 주문 화면(G-111-5).
- 지급 · 회수로 바뀐 잔액은 이용자 화면에 곧 선다 — 풀이권 표 셋의 변화가 이미 그 계정의 `credits` 갈래로 간다(ADR 0155).

### ② 신고 처분 — 신고 상세

흐름: **목록에서 급한 건 → 신고 당시 근거 → 같은 화면에서 처분 → 반영 결과.** 신고 id 복사 단추와 「검토 문(`review_report`)으로
적습니다」 줄을 걷는다.

**지금 `review_report` 는 결과를 조건 없이 덮어쓴다**(2026-10-16 코드로 확인 — 마지막 정의는 `20261020090000`). 신고 행을 id 로만
골라 `reviewed_at` · `reviewed_by` · 결과 · 근거 · 제재 대상을 그대로 새 값으로 바꾸고, 앞 결과를 어디에도 남기지 않는다 — 두
운영자가 같은 신고를 나란히 처리하면 늦게 누른 쪽이 말없이 이긴다. 경고에서 다른 결과로 바꿔도 안내번호는 남고(`warning_ref` 는
유지), 이용 정지 결정에서 다른 결과로 바꿔도 **계정 정지는 풀리지 않는다**(정지는 결과가 `suspension` 일 때 거는 것만 있다).
**정지가 남는 것은 이 판도 그대로 둔다 — 고칠 결함이 아니다.** 처분을 바꿔도 자동으로 해제하지 않고, 남은 정지를 반영 결과에
보이며, 해제는 ③ 의 회원 화면에서 사유 · 실행자와 함께 따로 한다(해제가 제 이력 줄을 갖게). 고치는 것은 덮어쓰기와 앞 결과가
안 남는 것(아래 버전 검사 · 이력 줄)뿐이다. 지금 운영의 런북에도 이 한 줄을 경고로 두었다(`docs/ops/runbook/moderation.md`
「신고와 차단」).

| 동작 | 처리 기준 | 남는 칸 |
| --- | --- | --- |
| 목록의 급한 건 | 처리 필요(`report_is_open`)를 먼저. 그 안의 차례는 **괴롭힘 · 위협 사유 → 3영업일 넘김 → 접수가 오래된 것**(G-111-6). 줄에 「괴롭힘 · 위협」 · 「기한 지남」 딱지 | — |
| 처분 넷 | `no_action`(조치 없음) · `needs_more`(추가 확인 필요) · `warning`(경고) · `suspension`(이용 정지 결정). 지금 `review_report` 의 판정을 그대로 쓴다 — 경고 · 정지에는 제재 대상(신고의 두 계정 중 하나, 기본은 신고받은 계정)이 있어야 하고, 경고의 갈래는 기본이 신고 사유다. **판단 근거는 넷 모두 필수**(G-111-7) | 신고 · 결과 · 판단 근거 · 제재 대상 · 경고 갈래 · 실행자(`reviewed_by` · `sanctioned_by`) · 시각, 경고면 안내번호 |
| **버전 검사** | 신고마다 처리 버전(처음 0, 적을 때마다 +1)을 둔다. 화면은 읽은 버전을 함께 보내고, **DB 의 지금 버전과 같을 때만** 적는다 — 다르면 거절하고 화면이 지금 결과를 다시 그린다(「다른 운영자가 먼저 처리했습니다」). 「처분 바꾸기」도 같은 검사를 거친다. 적을 때 앞 결과(버전 · 결과 · 근거 · 제재 대상 · 실행자 · 시각)를 이력 줄로 남긴다 | 이력 줄 |
| 이용 정지 결정 | 기록과 계정 정지가 한 트랜잭션(ADR 0107). 탈퇴 대기 계정은 거절된다. 제재 대상이 운영자 계정이면 거절(G-111-10). 「처분 바꾸기」로 정지 결정에서 다른 결과로 바꿔도 **자동으로 해제하지 않는다** — 반영 결과에 남은 정지(「계정은 여전히 이용 정지 — 해제는 회원 화면」)를 보이고, 해제는 회원 화면에서 따로 한다 | 위 칸 + 계정 상태 이력 한 줄(③ 과 같은 표) |
| 대상 회원 열기 | 신고 상세에 대상 요약 — 지금 상태 · 「현재 신고 기준 최근 12개월 경고 N회」 · 처분 이력 최근 셋 — 과 「회원 열기」. 경고를 고르면 「현재 신고 기준 이번이 N회째 경고」를 보인다(3회째부터 정지 검토, ADR 0108). **이 신고에 이미 경고가 적혀 있으면 N 에서 그 건을 한 번만 센다**(바꾸는 건을 두 번 세지 않는다) | 읽기 — 접속기록 한 줄 |
| 보상 | 신고 화면에는 지급 단추를 두지 않는다. 「회원 열기」가 신고 id 를 들고 가 ① 의 지급 폼에 「관련 신고」로 이어진다 | ① 의 칸 |

- 분리 보관 경고까지 센 수는 런북 「경고를 적기 전에 — 셈과 무게」 질의다.

### ③ 정지 · 해제 — 회원 상세

| 동작 | 처리 기준 | 남는 칸 |
| --- | --- | --- |
| 정지 | **신고와 무관한 정지만** — 신고로 정지하는 것은 ② 의 처분이다(기록과 정지가 함께). 이용 중인 계정만, 운영자 계정은 거절(G-111-10). 갈래 `policy`(운영정책 위반) · `payment`(결제 부정) · `eligibility`(이용 자격 — 만 19세 미만 정황 등) · `other`. 메모 필수. 이용자에게는 정지 안내에 사유 갈래와 소명 경로(고객 문의 이메일)를 보인다(G-111-8) | 계정 · 바뀌기 전 · 뒤 상태 · 갈래 · 메모 · 관련 신고 · 요청 고유 번호 · 실행자 · 시각 |
| 해제 | 이용 정지인 계정만. 갈래 `appeal`(소명 인정) · `mistake`(잘못 정지) · `other`. 메모 필수. 「이용 정지 결정」 신고 기록은 그대로 남는다 | 같은 칸 |
| 처분 이력 | 신고 처분(경고 · 이용 정지 결정 — 지금 「경고 이력」 칸)과 계정 상태 이력(정지 · 해제)을 한 목록에 | 읽기 — 접속기록 한 줄 |

- **계정 상태를 바꾸는 길은 공통 처리 함수 하나다.** 화면의 문 · `review_report` 의 정지 · 런북의 정지 · 해제가 모두 사유 갈래 · 메모 ·
  실행자를 받는 같은 함수를 부른다. 런북의 `update public.app_user set status …` 는 그 함수 호출로 바꾼다(실행자는 운영자 UUID 인자,
  break-glass 대장 번호를 메모에).
- **트리거는 안전망이다.** `app_user.status` 가 바뀔 때마다 계정 상태 이력 한 줄을 적는다 — 공통 함수를 거치지 않은 변경(직접
  UPDATE)은 실행자 · 사유가 빈 줄로 남고, 화면은 그 줄에 「실행자 · 사유 없음」 딱지를 달며, 장애 알림 길로 한 줄을 보낸다. 탈퇴
  흐름(탈퇴 신청 · 취소)의 변경은 그 흐름이 제 갈래로 적어 알림을 보내지 않는다.

### 데이터 모양 — 구현 때 정할 것 (스케치)

- **지급 · 회수 장부** — 지금 예외 표(`reading_credit_grant`)는 계정당 한 줄(`extra` · `note`)이라 이력이 없다. 줄이 쌓이는 표
  (계정 · `grant`/`revoke` · 수량 · 갈래 · 메모 · 관련 신고 · 요청 고유 번호(유일) · 실행자 · 시각)를 세우고, 한도의 「예외 몫」은
  그 합으로 읽는다(`reading_credit_shares` 한 자리). 지금 예외 표의 줄은 「기록 이전」 지급 한 줄로 옮긴다(실행자 비움). 떠난 계정의
  이 줄을 함께 지울지 분리 보관할지는 그때 정한다.
- **처분 문** — `review_report` 를 감싸는 운영자 문(실행자 = `auth.uid()`, 읽은 버전 · 요청 고유 번호를 받는다). 신고 두 표에 처리
  버전 칸, 앞 결과를 남길 이력 표. 런북의 `review_report` 호출도 버전을 받게 할지(받지 않으면 「지금 것을 덮어쓴다」를 명시)는 구현 때.
- **계정 상태 이력** — 공통 처리 함수 + 트리거(위 ③). 문은 같은 트랜잭션의 설정 값으로 갈래 · 메모 · 실행자를 건넨다.
- **이력 읽기** — 회원 화면의 문이 다섯 갈래(구매 · 사용 · 환불 · 지급 · 회수)를 한 목록으로 내준다. 사용 줄이 많을 수 있어 30줄씩.
- **알림** — 지급 알림은 `notify_ops` 의 새 갈래(계정 id · 수량 · 갈래만). 이용자 알림은 앱 안 소식의 새 갈래 둘(지급 · 회수) — 문구는
  구현 PR 이 표로 묻는다.
- **시험** — pgTAP: 운영자만 · 같은 요청 고유 번호는 한 줄 · 회수가 지급분의 안 쓴 것을 넘지 못함 · 회수와 풀이 시작이 마지막 한 장을
  다툴 때 한쪽만 · 산 몫은 회수로 줄지 않음 · 버전이 다르면 처분 거절 · 처분과 정지가 한 트랜잭션 · 직접 UPDATE 가 빈 실행자 줄을
  남김 · 접속기록 줄 · 거절의 되감김. 화면은 단위 시험(갈래 · 셈)과 그림.

## 화면 설계 (2026-10-16)

시안 그림(390 · 1280)은 저장소 밖에 두었다 — 경로는 PR 본문. 문구는 운영자 전용 설명(`/ops/**`, ADR 0103)이고 이용자에게 가는
글자(지급 · 회수 · 정지 안내)는 구현 PR 이 표로 묻는다.

### 회원 상세 (`/ops/members?q=<계정 id>`)

차례: 계정 → 풀이권 → 풀이권 이력 → 처분 이력.

- **계정 칸** — 닉네임 · 상태 딱지 · 계정 id(지금 그대로). 상태에 따라 단추 하나: 이용 중이면 「이용 정지」(붉은 글자 단추),
  이용 정지면 「정지 해제」. 탈퇴 대기면 단추 없이 「탈퇴 대기 — 해제는 런북」 한 줄. 운영자 계정이면 정지 단추 없이 「운영자 계정」 딱지.
  - 누르면 칸 안에 폼이 펼쳐진다 — 사유(갈래 고르기) · 메모(필수, 200자) · 관련 신고(신고에서 넘어왔을 때만, 딱지) · 실행 단추.
  - 확인 창: **「<닉네임> 님을 이용 정지할까요?」** 본문 「대화방이 닫히고 모든 이용이 막힙니다. 이용자에게 사유 갈래가 안내됩니다.」
    단추 「이용 정지」(위험) · 「취소」. 해제는 **「<닉네임> 님의 정지를 풀까요?」** 본문 「닫힌 대화방은 다시 열리지 않습니다.」(방의
    닫힘은 상태라 해제가 되살리지 않는 것으로 읽힌다 — ADR 0091, 구현 때 재어 문구를 맞춘다) 단추 「정지 해제」 · 「취소」.
  - 결과: 상태 딱지가 바뀌고 칸 아래 완료 줄 「이용 정지했습니다」, 처분 이력 맨 위에 새 줄이 강조되어 선다.
- **풀이권 칸** — 지금의 넷(산 · 환불로 걷은 · 산 것에서 쓴 · 쓴 풀이권)에 **지급분** 줄: 「지급 N장 · 회수 N장 · 지급분에서 쓴
  N회 · 회수할 수 있는 N장」. 단추 둘: 「풀이권 지급」(주 단추) · 「지급분 회수」(보조). 회수할 것이 0 이면 회수 단추를 잠그고 곁에
  「회수할 지급분이 없습니다」(예약 중이 있으면 「예약 중 N장은 풀린 뒤 회수」).
  - **지급 폼** — 수량(1 ~ 10장, 고르기) · 사유(「장애 보상」 · 「운영 지급」 마디 둘) · 메모(필수, 「이용자에게는 보이지 않습니다」) ·
    관련 신고 딱지(신고에서 왔을 때). 단추는 수를 말한다 — 「3장 지급」. 누르는 동안 단추를 잠근다. 확인 창 **「<닉네임> 님에게
    풀이권 3장을 지급할까요?」** 본문 「사유: 장애 보상 · 이용자에게 수량과 사유가 안내됩니다.」 단추 「지급」 · 「취소」.
  - **회수 폼** — 수량(1 ~ 회수할 수 있는 수) · 사유(「잘못 지급」 · 「중복 지급」 · 「기타」) · 메모(필수). 폼 위 한 줄 「지급분만
    회수합니다. 구매분 환불은 주문 화면에서.」(주문 화면 링크). 확인 창 **「지급분 2장을 회수할까요?」** 단추 「회수」(위험) · 「취소」.
  - 결과: 수가 바뀌고 완료 줄 「지급했습니다」, 이력 맨 위에 새 줄. 끊겼다 다시 눌러 같은 요청이면 「이미 지급했습니다」로 같은 결과를 보인다.
  - 실패: 폼 아래 실패 줄 — 「회수할 수 있는 지급분보다 많습니다.」(그 사이 이용자가 썼을 때) · 「지급하지 못했습니다. 다시 시도해
    주세요.」. 운영자가 아니면 404.
- **풀이권 이력 칸** — 거르기 마디 넷: 「전체」 · 「구매 · 환불」 · 「지급 · 회수」 · 「사용」. 줄마다 시각 · 종류 딱지 · 수(지급 +3장 ·
  회수 −1장 · 구매 +5장 · 사용 −1회, 반환 · 예약은 부호 없이) · 내용(주문 번호 링크 · 사유 · 메모 · 몫) · 실행자(지급 · 회수 · 환불만).
  30줄씩, 아래 「더 보기」. 빈 상태 「풀이권 이력이 없습니다.」 · 실패 「이력을 읽지 못했습니다.」(다시 시도).
- **처분 이력 칸** — 지금 「경고 이력」 칸의 자리. 제목 곁 「현재 신고 기준 최근 12개월 경고 N회」, 아래 분리 보관 한 줄(그대로).
  줄마다 시각 · 종류(경고 · 이용 정지 결정 · 이용 정지 · 정지 해제) · 갈래 · 메모(정지 · 해제만) · 실행자 · 「신고 내용 보기」(신고에서
  온 줄만). 실행자가 빈 줄은 「실행자 · 사유 없음」 딱지. 빈 상태 「현재 신고와 계정에 적힌 처분이 없습니다.」.

### 신고 목록 (`/ops/reports`)

- 기본 거르기를 「처리 필요」로, 차례를 「급한 순」(괴롭힘 · 위협 → 기한 지남 → 오래된 순)으로. 줄에 딱지 「괴롭힘 · 위협」 ·
  「기한 지남」(접수 뒤 3영업일 넘김, 주말만 뺀 어림 — 런북과 같은 셈).
- 머리에 「처리 필요 N건 · 기한 지남 N건」. 빈 상태 「처리할 신고가 없습니다.」.

### 신고 상세 (`/ops/reports/[reportId]`)

넓은 화면은 두 열 — 왼쪽 근거(신고 칸 · 신고 당시 대화), 오른쪽 처분(대상 회원 요약 · 처분 폼, 스크롤해도 붙어 선다). 폰은 신고 →
근거 → 대상 회원 → 처분 차례로 한 열. 머리의 신고 id 복사 · 검토 문 안내 줄은 걷는다.

- **대상 회원 요약** — 신고받은 계정: 닉네임 · 지금 상태 · 「현재 신고 기준 최근 12개월 경고 N회」 · 처분 이력 최근 셋 · 「회원
  열기」(신고 id 를 들고 간다). 신고한 계정은 닉네임 · 상태 · 「회원 열기」 한 줄. 분리 보관 한 줄.
- **처분 폼**(처리 필요일 때, 「처분 바꾸기」를 눌렀을 때)
  - 결과 넷을 고르는 칸(조치 없음 · 추가 확인 필요 · 경고 · 이용 정지 결정)
  - 경고 · 이용 정지 결정을 고르면 제재 대상 마디 둘(신고받은 계정 · 신고한 계정, 기본은 앞의 것). 경고면 갈래 고르기(기본 = 신고
    사유)와 「현재 신고 기준 이번이 N회째 경고입니다」 — 3회째부터 「이용 정지 결정을 검토하세요.」
  - 판단 근거(필수, 500자, 남은 글자 수, 칸 아래 「이메일 · 실명 · 연락처는 적지 않습니다.」)
  - 단추는 결과를 말한다 — 「조치 없음으로 처리」 · 「추가 확인으로 남기기」 · 「경고」 · 「이용 정지」.
  - 확인 창은 경고 · 이용 정지에만: **「<닉네임> 님에게 경고할까요?」** 본문 「이용자에게 갈래와 안내번호가 갑니다.」 /
    **「<닉네임> 님을 이용 정지할까요?」** 본문 「대화방이 닫히고 모든 이용이 막힙니다.」(단추 위험).
- **반영 결과**(처리한 뒤 · 이미 처리된 신고) — 처분 칸이 결과로 바뀐다: 「처리 완료 · 경고」 · 안내번호 · 제재 대상과 그 계정의
  **지금 상태** · 이용자 확인(확인 전 / 시각) · 판단 근거 · 실행자 · 시각. 단추 「다음 신고」(처리 필요 중 급한 순의 다음) · 「회원
  열기」. 이미 처리된 신고에는 「처분 바꾸기」(글자 단추) — 누르면 폼이 다시 서고(지금 버전을 들고), 확인 창이 「이미 적힌 결과를
  바꿉니다.」를 덧붙인다. 정지 결정을 다른 결과로 바꾸면 「계정은 여전히 이용 정지입니다 — 해제는 회원 화면에서.」
- **실패** — 폼 아래 실패 줄: 「탈퇴를 신청한 계정이라 정지할 수 없습니다.」 · 「운영자 계정은 정지할 수 없습니다.」 · 「판단 근거를
  적어 주세요.」 · 「처분을 적지 못했습니다. 다시 시도해 주세요.」. 버전이 달라 거절되면 「다른 운영자가 먼저 처리했습니다.」와 함께
  지금 결과를 다시 그린다.

### 화면 사이의 길

신고 목록 → 신고 상세 → (처분) → 「다음 신고」 또는 「회원 열기」 → 회원 상세 → (지급 · 정지 · 해제) → 처분 이력의 「신고 내용 보기」
→ 신고 상세. 회원 상세의 구매 줄 · 주문 번호 → 주문 화면(`/ops/orders?order=`, #727). 운영 머리의 「회원」은 #729 가 세운다.
