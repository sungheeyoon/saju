# 위임 규약 — 결정 점검표

색인은 `docs/agents/delegation.md` 다.

## 결정 점검표 — 무엇이 바뀌면 결정인가 (2026-09-28)

**아래 여섯 중 하나라도 바뀌면 그 변경은 결정이다.** PR 의 「문서」 칸 첫 줄
(「결정 여부」)에 「있음」과 어느 줄인지 적고, 조율자가 **머지 전에** 운영자에게 표로 묻는다(맨 끝의 화면 문구만은 사후 확인 — 그 줄) — 에이전트가 「판단 없이
고쳤다」고 적어도 조율자가 이 여섯으로 다시 본다. #292 는 실패 갈래 하나를 고쳤는데
가입 전 계정까지 `/me` 로 들이는 정책 변경이었다(`docs/notes/2026-09-28-overnight-audit.md`).

- **누가 무엇을 볼 수 있는가 · 할 수 있는가** — 허용과 거부의 경계(RLS · 관문 · 문의 grant · 화면의 갈래)
- **실패했을 때 열리는가 닫히는가** — fail-open / fail-closed. 읽기 · 외부 호출이 실패한 갈래가 어느 문으로 보내는가(#292)
- **데이터의 보존 · 삭제 · 보관 기간**
- **비용 · 요금 · 외부 서비스** — 플랜 · 한도 · 새 제공자 · 토큰이 나가는 호출의 수
- **검증 · 배포의 문턱** — CI 계획기가 어떤 변경에 무엇을 건너뛰나, 배포가 무엇을 기다리나. 이 줄의 PR 은 독립 검토가 끝나기
  전에 `--auto` 를 걸지 않는다(#572, 2026-10-09)
- **화면 문구** — ADR 급 결정은 아니고 **운영자 사후 확인이 드는 것**이다 — 머지 전에 묻지 않는다(ADR 0196, 운영자 결정 2026-10-22).
  넣는 법 · 확인받는 법은 `docs/agents/code-rules/screen-copy.md` 「화면 문구」가 든다. 문구가 위 다섯 줄 가운데 하나(권한 · 보존 · 삭제 ·
  비용 · 요금 · 환불)에도 걸리면 그 줄 때문에 결정이다 — 이 줄이 사후 확인이 된 것과 무관하다

문구 말고는 ADR 을 같은 PR 에 쓴다. 운영자가 이미 답한 결정이면 PR 에 그 답(날짜 · 문장)을 옮겨 적는다.
**문구는 운영자가 글자를 정해 주었으면(맡길 때 불러 주었거나 표에 답했으면) 확인까지 끝난 것이다** — 그 글자 그대로 넣고 답을 PR 에
옮겨 적은 뒤 머지까지 간다(`--auto`). 정해진 문구는 바로 낸다(2026-10-09). 정한 글자에서 한 자라도 벗어나면 그 글자는 「확인 전」이다
(`docs/agents/code-rules/screen-copy.md` 「화면 문구」).

**안 정한 것은 간극 대장에만 둔다(2026-10-05).** 「아직 안 정했다 · 맞출지 모른다」는 ADR 덧 · 노트 · 코드 주석에 두지 않고
`docs/product/gaps.md` 의 `G-nn` 줄로 올린다 — 거기 없으면 아무도 묻지 않는다. 비로그인 홈 입력폼이 승인될 때 「로그인 뒤
폼도 맞출지 안 정했다」가 ADR 0132 덧과 노트에만 있어, 그 물음이 한 번도 운영자에게 가지 않았다(2026-10-05).

**한쪽 뜻을 바꾸면 반대쪽 상태까지 걷는다(2026-10-05).** 한 주소 · 한 부품의 한쪽 상태(로그인 전/뒤, 해시 있음/없음 등)의
뜻을 바꾸면, 반대쪽 상태가 여전히 맞는지 걸어 보고 PR 증거에 상태표(누가 · 주소 · 기대 · 실제)로 남긴다. 비로그인 `/` 를
로그인 전 결과의 관문으로 바꿀 때 ADR 0131 이 「회원 쪽은 그대로」라고만 적고, 회원 쪽 `/` 가 그 자리에 아직 맞는지는
아무도 걷지 않았다(2026-10-05). **주소나 상태의 뜻을 바꾸는 PR 은 코드 호출처뿐 아니라 현재 문서(`docs/product/prd/` · `docs/context/` ·
`docs/product/copy-ledger.md`)와 주석에서 옛 뜻을 검색해 함께 고친다** — #477 이 회원의 계산 자리를 `/saju` 로 옮긴 뒤에도 PRD 두
줄과 주석 셋에 「회원의 `/`」가 남았다.
