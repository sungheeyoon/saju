# 위임 규약 — 끝났다는 것

색인은 `docs/agents/delegation.md` 다.

## 끝났다는 것 — PR 이 드는 칸

PR 틀(`.github/pull_request_template.md`)의 칸이다. 칸 이름은 이 표와 같고, **안 한 것은 안 했다고
적는다** — 「안 돌린 것을 통과로 적지 않는다」(ADR 0079).

| 칸 | 무엇을 적나 | 왜 |
| --- | --- | --- |
| **무엇이 참이 되는가** | 이슈의 첫 칸 그대로. 재어 보니 달랐으면 **잰 값으로 다시 쓴 문장** | 이슈 문장은 가설이다 |
| **잰 값** | 고치기 전에 잰 수와 그 방법. 후보 문장과 어디가 달랐나 | 값 없이 「정리했다」는 다음 사람이 다시 잰다 |
| **돌린 것** | `docs/agents/test-map.md` 의 명령과 결과(수까지) — 공개 출시 전의 최소는 단위 · 타입 · 린트와 예외 넷이고, 그 밖에 무엇을 더 돌리나는 `docs/agents/test-map/what-to-run.md` 「무엇을 고쳤으면 무엇을 돌리나」를 따른다. 프롬프트 본문이면 실호출(운영자가 돌린다 — 명령은 「사람이 할 걸음」에), 마이그레이션이면 `db:types` diff. **안 돌린 것과 그 까닭** | 단위 시험은 화면이 사라진 것을 모른다 |
| **잠금이면 일부러 어긴 것** | 린트·시험·pgTAP 을 새로 세웠으면 **옛 상태를 되살리거나 일부러 어긴 파일**로 빨개지는 것을 본 기록. 같은 뜻의 다른 표기(별칭/상대경로, 정적/동적, `.ts`/`.jsx`)까지 | 「규칙을 넣었다」와 「규칙이 건다」는 다른 문장이다(ADR 0085·0086) |
| **문서** | 역할 문서(`docs/roles/`)의 「끝날 때 고치는 것」을 옮겨 적는다. 첫 줄은 **결정 여부** — `docs/agents/delegation/decisions.md` 「결정 점검표」에 걸리면 「있음」과 어느 줄인지, 운영자가 답했는지. 결정이 있으면 ADR(같은 PR). 낱말이 생기면 `docs/context/` 의 그 영역 파일(색인 `GLOSSARY.md`), 모양이 바뀌면 `docs/product/prd/` 의 그 영역 파일과 changelog(`docs/product/prd-changelog.md` 맨 끝 목록에 `- **YYYY-MM-DD** — **무엇이 참이 됐나**(절 · ADR · 결정 출처). 한두 줄` 을 덧붙인다 — 열 필요 없이 끝에 쓴다), 틈이 생기거나 닫히면 `docs/product/gaps.md`, 돌리는 것이 바뀌면 `docs/agents/test-map.md` | 문서와 코드가 어긋나면 시험이 있는 쪽만 산다 |
| **사람이 할 걸음** | 등급 3 — `db push` · 실호출 · 문구 확인 · 운영 SQL. **앱 배포 ≠ DB 마이그레이션**(`docs/ops/runbook/deploy.md` 「배포」) | 앱은 묶음 배포로, DB 는 그보다 먼저 따로 간다 |

**전후 그림은 저장소에 커밋하지 않는다(운영자 지시 2026-10-10 「필요없잖아」).** 에이전트는 같은 로컬 상태에서 찍은 전후를
저장소 밖의 제 폴더(스크래치패드의 고유 하위 폴더)에 두고 경로를 보고한다 — CLI 로는 PR 본문에 GitHub 첨부를 못 올린다.
조율자가 이번에 고친 화면만 아티팩트 한 장으로 운영자에게 보이고, 운영자가 확인하면 아티팩트와 그림을 함께 지운다.
그날 운영자가 그때까지 커밋된 그림(약 33MB)을 모두 걷게 했다 — 옛 노트 · ADR 이 가리키는 그림 경로는 그날의 기록으로 남는다.

**임시 파일(커밋 · PR 본문 · 스크립트)은 제 워크트리 안에 쓴다** — 스크래치패드는 한 세션의 에이전트들이 함께 쓴다. 두 에이전트가
거기에 같은 이름(`commit.txt` · `pr.md`)을 써서 서로 덮었다(#209, 2026-10-18 #750 · #751). 워크트리 안의 임시 파일은 커밋하지 않는다 —
`git add` 는 파일 이름으로 하고 PR 전에 지운다. 그림은 크고 커밋하면 안 되니 위대로 스크래치패드에 두되 **제 이름의 하위 폴더**에 둔다.

**커밋과 PR 제목**은 `type(scope): 한국어 문장 (ADR NNNN)` 이다(`docs/agents/code-rules/locks.md` 「커밋과 PR」).
squash 본문은 PR 본문이 아니라 **커밋 메시지들을 이어 붙인 것**이라(저장소 설정
`COMMIT_MESSAGES`) 커밋을 하나로 두거나 머지 화면에서 다듬는다. 원격 가지는 머지되면 GitHub 가
지운다(`delete_branch_on_merge: true`, 2026-10-12 에 봤다). 로컬 가지만 남는다 — 머지 뒤 `git fetch --prune` 하고 `git branch -d <가지>` 로
걷는다(라운드 끝은 `docs/agents/delegation/coordinator.md` 「라운드 끝 정리」).

## 읽기량 예상치는 보고다

`npm run read-budget` 의 표(역할마다 손대기 전에 읽는 바이트의 보수적 예상치)에는 천장이 없다 — CI 를 붉히지 않는다(ADR 0177).
읽기량에 걸린 붉음은 둘뿐이다 — 역할 문서 한 장이 한 화면(8,000 바이트)을 넘었거나, 역할 문서 · 입구가 가리킨 파일 · 「절」 ·
앵커가 없다(`scripts/code-rules.test.ts` 「역할 문서」). 앞의 것은 원본으로 옮길 것을 옮겨 적고 있다는 뜻이고, 뒤의 것은 가리키는
쪽을 원본의 지금 자리로 고친다.

- **역할 문서의 가리킴을 바꿨으면** 그 역할의 전후 예상치를 PR 의 「잰 값」에 적는다 — 판단의 재료이고 문턱이 아니다.
  `npm run read-budget -- <역할>` 은 고정 파일과 센 절을 찍는다. 백틱 경로 **바로 뒤**에 `「절」` 이 아닌 글이 오면 셈은 파일
  전부다(`scripts/read-budget.mjs` 머리).
- **바이트를 맞추려고 문장을 지우거나 줄이거나 파일을 쪼개지 않는다.** 파일을 나누는 것은 한 원본이 여러 작업의 것을 한데 들어
  한 일이 남의 것까지 읽을 때다 — 문장은 옮기기만 하고 색인 · 링크를 남기며, 큰 옮김은 문서 PR 로 따로 낸다.
- **「먼저 읽는 것」과 「닿을 때 여는 것」 사이로 줄을 옮기는 까닭은 일의 쓰임뿐이다** — 그 역할의 일 대부분이 손대기 전에
  쓰나(ADR 0147 「무엇을 옮기는가의 기준」). 바이트는 까닭이 아니다.
