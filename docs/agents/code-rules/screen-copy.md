# 코드 규칙 — 화면 문구

색인은 `docs/agents/code-rules.md` 다.

## 화면 문구

규칙은 여기 없다 — **`docs/context/copy.md` 「화면 문구 규칙」**(해요체가 기본 · 되돌리기 어려운 결과의 고지는 합니다체를 쓸 수 있다 · 결과가 드러나는
동작명 버튼 · 「~ 중…」 · 문장일 때의 마침표 · 한 사실 한 표기 · 한 화면 한 이름 · 늘 참인 문장은 안 세운다)과
**`docs/product/prd/screens.md` §3.2**(상품 이름 넷, 버튼은 동사로 갈린다)가 답이고, ADR 0025 · 0026 · 0027 · 0135 가 그 근거다.

에이전트에게는 규칙이 하나 더 있다. **한글 문구를 지어내지 않는다.** 새로 쓰거나 고칠 문구는
코드에 넣기 전에 **표로**(지금 글자 / 바꿀 글자 / 그 자리가 하는 일) 보여주고 답을 기다린다.
문법이 맞아도 제품이 쓰는 말이 아닌 문장이 연달아 퇴짜를 맞았다. 사용자가 문안을 불러 주면
줄바꿈까지 그대로 쓴다. 문구만 바뀐 라운드는 시험을 안 돌린다. **예외 하나** — `/ops/**` 에서 운영자에게만 보이는
설명 · 제목 · 빈 상태 문구는 표 승인 없이 쓰고 PR 에 모아 보고한다. 개인정보의 이용 · 보관, 운영자의 권한, 제재 결과,
사용자에게 전달되는 문구는 여기 안 든다(`docs/agents/delegation/working.md` 「사용자와」, ADR 0103).

**UI 변경 요청이 오면 문구는 먼저 `docs/product/copy-ledger.md` 에서 찾는다.** 있으면 그 문구를 쓴다. 없으면
추천 문구를 표(자리 · 지금 · 제안 · 까닭)로 운영자에게 보이고 답을 받은 뒤에 넣는다. 시안 · 외부 리뷰 · 에이전트의
문구는 확정이 아니다. 문구가 말하는 상태 전이(누르면 무엇이 되나 · 실패 갈래 · 처음/다시)는 코드에서 확인한다.
확정되면 그 PR 이 대장에 줄을 더한다. 2026-09-29 — 브리프가 「시안에 있던 문구는 확정」이라 적어 시안의 자리표시
문구(평서체 · 옛 이름)가 제품에 들어갔고, 「답하면 궁합이 열린다」(거절도 답이다 — 궁합은 수락해야 열린다)가
제안됐다. 대장이 저장소 밖에 있어 아무도 안 읽었다.

문구는 그 화면(`.tsx`)에 산다. 여러 화면이 같은 사실을 적으면 상수 하나(`HOUR_UNKNOWN_LABEL`)로
든다 — 화면마다 다시 적지 않는다.
