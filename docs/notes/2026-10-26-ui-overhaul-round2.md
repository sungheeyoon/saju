## 조율자의 판단과 까닭

- **에이전트마다 화면 하나, 같은 에이전트를 끝까지 이어 씀** — 홈 · 설정 · 공통 부품 셋을 처음 맡긴 에이전트에게 열 몇 번의 피드백을
  `SendMessage` 로 이어 보냈다. 맥락이 남아 「왜 그렇게 했나」를 다시 설명하지 않아도 됐다.
- **머지 순서가 충돌을 만든다** — PR 이 열을 넘으니 하나가 들 때마다 나머지가 다시 붉었다(문구 대장 번호 · changelog · e2e). 마지막엔
  「시험 통과 → 바로 머지 → 남은 것 다시 들이기」를 되풀이했다.
- **캡처 비교 페이지는 승인한 것만 남기며 줄였다** — 차수가 쌓이자 운영자가 「헷갈린다 · 다 지워라」고 했다. 마지막엔 PR 별 「승인하신 것」
  상자와 최종 그림만 두었다(아티팩트는 세션 끝에 운영자가 지웠다).

## 배운 것 · 헤맨 것

- **물음을 지시로 읽었다** — 「줄 표시는 굳이 있어야 하나」를 걷으라는 뜻으로 전해 구분선을 걷었다가 크게 되돌렸다. 물음은 두 안을
  캡처로 보이고 고르게 한다.
- **CI 를 기다리느라 보고를 미뤘다** — 「머지 승인했나? 고쳤으면 아티팩트에 올리고 승인받을 생각을 해야지」. 캡처가 나오면 CI 와 상관없이
  먼저 보인다. 머지 직전에만 CI 를 기다린다.
- **화면에 나올 수 없는 시험 글** — 줄바꿈을 보겠다고 빈 화면 설명에 가짜 URL 을 넣은 캡처를 그대로 보였고, 그 캡처를 근거로 전역
  `overflow-wrap: anywhere` 까지 넣었다(뒤에 걷음). 시험 데이터는 실제 문구 · 실제 최대 길이로만.
- **레퍼런스를 겉모양만 봤다** — 설정 2차의 레퍼런스가 TDS 문서 · FAQ 뿐이고 실제 앱 설정 화면이 없어 여백 · 대비를 놓쳤다.
- **데스크톱을 늦게 봤다** — 폰만 찍다가 운영자가 짚었다. 폭이 다섯 벌(1152 · 928 · 896 · 768 · 736)이었고 #841 로 두 벌이 됐다.
- **로컬 스택 자리 아홉이 다 찼다** — 머지된 워크트리가 자리를 쥔 채 남아 에이전트마다 남의 자리 · 꾸민 데이터 · 열 번째 포트로 우회했다.
  `docs/agents/delegation/local-env.md` 에 「자리가 다 찼을 때」가 없다. 라운드 끝에 워크트리 · 가지 · 스택을 모두 걷었다.
- **CI 의 흔들림 둘** — `authed` 차선이 Docker Hub `toomanyrequests: Data limit exceeded` 로 20분 만에 떨어졌다(실패 job 만 다시 돌려 통과).
  pgTAP `99_database_size_alert` 가 운영 DB 크기를 두 번 재는 사이에 값이 바뀌면 떨어진다. 둘 다 어디에도 적혀 있지 않다.
- **전후 그림을 둘 곳이 문서끼리 어긋난다** — 기억 · 지시는 `docs/notes/shots/<날짜>-<PR>/`, `done.md` 는 「커밋하지 않는다」.
  에이전트들은 두고 커밋하지 않았다.
- **에이전트 워크트리의 명령 거절** — heredoc · `for` · `gh -q` 가 이번에도 거절돼 다들 스크립트 파일로 돌았다(`local-env.md` 에 이미 있다).
