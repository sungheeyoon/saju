## 배운 것

- **감사 후보로 브리프를 쓰기 전에 같은 노트의 뒤쪽 정정을 본다.** 조율자가 후보 목록만 읽고 「죽은 `refresh_discovery_summary`

  운영자가 붙여 넣은 외부 검토가 잡았다.
- **저장소 전역을 건드리는 정리(export)는 병렬에 넣지 않는다** — 다른 PR 이 다 든 뒤 순차로. 멈췄다가 다시 재니 133 → 152 였다.
- **병렬 라운드는 `--auto` 를 걸지 않고 조율자가 `merge:sim` 뒤에 들인다** — 각 에이전트가 제 PR 을 따로 머지하면 모의 합치기가
  머지 전에 설 자리가 없다.
- **strict 로 하나씩 들이면 PR 마다 7~8분이다.** 스물다섯을 차례로 들이다 멈추고, 남은 열일곱을 가지 하나에 머지 커밋으로 합쳐
  (`round/2026-09-30-batch`, #385) CI 를 한 번 돌렸다. **머지 커밋**으로 들이면 각 PR 의 머리 커밋이 main 에 들어가 GitHub 가
  PR 열일곱을 각각 머지됨으로 닫는다(squash 면 안 닫힌다). 겹쳐 쌓인 가지(#364 ← #363)는 앞의 것이 squash 로 들어가 충돌 —
  main 의 파일이 뒤 가지의 바탕 커밋과 같은지 보고 뒤 쪽을 썼다.
- **`db push` 는 머지와 따로 먼저 해도 된다** — 새 마이그레이션이 지금 Production 앱이 부르는 서명을 안 바꾸면. 조율자가 둘을
  한 덩어리로 보고 DB 에이전트를 머지 줄 끝에 세워 두었다.
- 두 에이전트가 pgTAP 번호 74 · 75 를 함께 썼다 — 머지 직전 73~77 로 다시 매겼다.
