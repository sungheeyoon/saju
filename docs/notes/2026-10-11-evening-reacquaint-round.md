# 2026-10-11 저녁 UX 라운드 — 대화하면서 상대를 다시 알아볼 수 있나

> **세션 기록이다.** 요구사항도 규칙도 아니다 — 코드와 어긋나면 코드가 맞다. 머지 목록은 PR(#645 ~ #651), 남은 일은
> `docs/product/gaps.md`(G-89 · G-102 ~ G-106)가 원본이다. 같은 날 앞 라운드는 `2026-10-11-day-ux-round.md` 다.

## 무엇이 시작이었나

운영자가 UX 점검의 범위를 「화면이 있느냐」에서 **「다음 행동을 할 수 있나 · 앞에서 본 정보를 다시 볼 수 있나」**로 넓혔다.
핵심 물음은 「대화하면서 상대를 다시 알아볼 수 있나」.

조율자가 코드를 읽고 외부 사례(Tinder · Bumble · Hinge · Coffee Meets Bagel 공식 도움말)를 조사했다. 코드에서 확인한 것:

- 채팅 머리의 사진 · 이름은 인연 궁합으로 갔고, 그 화면에는 상대 사진 · 소개가 없었다 — 소개는 `result.ts` 가 읽고 그리지 않았다.
- 매칭이 선 뒤에는 상대 프로필을 다시 열 길이 없었다.
- 「수락하고 궁합 열기」가 수락만 하고 이동하지 않았다.

외부: 「채팅 머리를 누르면 프로필」은 네 앱 모두 공식 출처를 찾지 못했다. 한국 앱은 공개 FAQ 가 없어 견주지 않았다.

## 운영자 결정 (2026-10-11 저녁)

「추천대로 진행」 · 「머지되면 배포까지」.

- **상대 프로필은 바텀시트(lg 는 가운데 대화상자)** — 방의 스크롤 · 이전 말 · 쓰던 초안이 그대로 남는 것이 까닭이다.
  상대의 지금 사진 · 소개를 보이고, 닫힌 방에서는 열지 않는다.
- **수락하면 인연 궁합으로 간다.**

## 판단과 그 까닭

- **충돌 영역 둘로 나눴다** — 채팅 · 프로필 시트(#645)와 요청 흐름(#646). 두 갈래가 같은 파일을 건드리지 않아 나란히 뒀다.
- **#645 는 PRD chat 에 적힌 결정(방 머리 → 인연 궁합)을 바꾸는 일이라 머지 전에 이 대화를 모르는 reviewer 를 붙였다.**
  reviewer 가 「닫힌 방에서도 상대 사진의 장 수 · 보일 자리가 RSC payload 로 실려 간다」를 찾았고 머지 전에 고쳤다 —
  사진 바이트는 문이 404 로 막지만 장 수와 바뀜 여부가 샜다. 같은 검토에서 쓸기 뒤 첫 탭이 버려지는 것 · Avatar 의 실패 표시가
  남는 것도 함께 고쳤다.
- 배포는 묶음 한 번이다(값은 배포 기록이 원본).

## 헤맨 것 — 다음 `/retro` 거리

- 전후 스크린샷에 「사진 있는 상대 · 차단으로 닫힌 방」 상태를 짓는 법이 `scripts/ui-shots.mjs` 의 PLAN 에 없어 일회성 스크립트를 썼다.
- 워크트리 격리가 git · gh 가 든 복합 명령을 막는다 — 앞 라운드와 같다.
- DB 함수의 지금 모양을 마이그레이션 grep 으로 찾으면 옛 정의가 먼저 나온다. `src/lib/db/database.generated.ts` 부터 보면 덜 헤맨다.
- `check-match.mjs` 하나만 돌리는 법이 test-map 에 없다.

## 뒷부분 — 수락하면 대화 · 방 머리의 점수 · 디자인 검수 (#648 ~ #651)

### 운영자 결정

- **수락하면 채팅방으로 간다**(앞의 「인연 궁합으로 간다」를 같은 날 뒤집었다). 운영자가 붙인 시나리오: A 요청 → B 수락 → 방 →
  A 의 소식도 그 방 → 둘은 바로 대화, 궁합풀이는 동시에 만들어지고 상태는 작게. 단추는 「수락하고 대화하기」.
  까닭: 연결은 이미 끝났으니 대화가 중심이다. 그림(로컬 실패 상태의 「궁합풀이 받기」)이 운영자를 헷갈리게 한 것이 계기였다.
- **방 머리의 궁합 단추가 상태를 든다 — 만드는 중 · 「72점」 · 「다시 받기」, 폰에도 선다.** 「궁합 보기」는 애매하다는 운영자 의견으로
  점수가 됐다. **하트 대신 하단 탭 「궁합」의 음양 아이콘** — 데이팅 느낌을 줄이려고. 이모지를 안 쓴 까닭은 앱에 이모지가 0 이고
  오행 색 · 다크 · 보조기기 이름을 따라가지 못해서다. 「인연」 낱말 전체는 G-104 로 미뤘다.
- 「다시 받기」는 누른 사람의 풀이권을 쓴다(확인 창 뒤) — 숨기지 않는 것으로 두고 그대로 갔다.
- **docs 읽기량 천장 70,000 은 그대로 둔다**(#649 가 올린 것을 운영자가 확인, ADR 0147 「2026-10-11 덧」).
- **인연 궁합 머리 · 상대 프로필 시트의 배치는 운영자가 로컬에서 직접 고쳐 승인했다**(#650, 대장 matching-01) — 머리 한 줄,
  「두 분 모두 같은 글과 같은 점수를 봐요.」 걷음, 시트는 이름 곁 궁합 단추 · 카드 없는 소개.
- 그 배치를 조율자가 디자인 체계(ADR 0109)로 검수하고 다섯을 맞췄다(#651) — 이름은 고운돋움, ← 는 대화방과 같은 공용 단추
  (`ICON_BUTTON_GHOST` 로 합침), 소개는 본문색, 사진 모서리는 카드 단, 보조 글자 단.

### 판단과 그 까닭

- 시안을 머지 전에 그림으로 보였다 — 운영자가 「보고 판단이 달라질 것」이라 해서 #648 은 PR 만 열고 멈췄다.
- #648 도 머지 전 reviewer 를 붙였다 — 막을 결함은 없었고, 말 한 통마다 글 본문 전체를 읽는 낭비 · 겹친 여백 클래스 · 옛 문구 문서를 #649 로 고쳤다.
- 승인된 배치(#650)는 모양을 바꾸지 않는 것만 그 PR 에 더했다(두 줄 제목을 한 heading 으로 — 보조기기 이름 「{닉네임} 님 궁합 결과」).
  눈에 보이는 어긋남은 따로 그림으로 보이고 확인을 받은 뒤 #651 로 냈다.

### 헤맨 것

- **워크트리에서 `npx next dev` 를 바로 띄우면 `.env.development.local`(운영 접속값)을 읽어 로그인 쿠키가 안 맞고 운영 DB 를 본다** —
  로컬 스택에 붙이는 길은 `UI_PORT=<포트> node scripts/ui-dev.mjs` 다(`docs/agents/delegation/local-env.md` 에 한 줄 더함).
  이번에는 로그인 화면만 열려 운영에 쓴 것은 없다.
- 배포 판정(`deploy-range.mjs`)이 「green」이어도 HEAD 가 막 든 커밋보다 앞일 수 있다 — main 의 `verify` 가 그 커밋에서 끝났는지 보고 올렸다.
- 출력을 버린 `vercel deploy --prod` 가 배포를 만들지 않고 끝난 적이 있다(까닭 미확인) — 출력을 보며 다시 돌려 섰다. 판정은 늘 `vercel ls` · 배포의 SHA 로.
- 에이전트가 만든 전후 아티팩트에 「안 바뀐 것을 확인하는 칸」이 설명 없이 섰다 — 운영자가 무엇이 바뀌었는지 찾았다. 전후 그림은 바뀐 자리만, 잘라 키우고 표시한다.
