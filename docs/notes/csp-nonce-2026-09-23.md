# CSP 에서 `'unsafe-inline'` 을 빼는 값 (2026-09-23, G-23 ②)

**지금은** — CSP 는 강제다(`next.config.ts`). `script-src` · `style-src` 의 `'unsafe-inline'` 만 남았고, 그것을
빼는 결정은 G-23 ② 가 든다 — 2026-09-24 에 「지금은 둔다」로 정했다(끝 절). 이 노트는 그 결정에 쓸 값을 잰 날의 기록이다. 요구사항이 아니다.

## 잰 방법

가지 하나에서 두 변형을 짓고 버렸다. 둘 다 로컬 스택(자리 4)에 붙인 **운영 빌드**(`next build` → `next start`)를
Playwright 가 재사용하게 두고 잰다 — e2e 기본은 `next dev` 라 `'unsafe-eval'` 이 열려 있어 운영 정책을 못 잰다.

- **nonce** — `proxy.ts` 가 요청마다 `crypto.randomUUID()` 로 nonce 를 짓고 `script-src 'self' 'nonce-…' 'strict-dynamic'`
  을 요청 · 응답 헤더에 싣는다. matcher 를 `/((?!api|_next/static|_next/image|favicon.ico|brand).*)`(prefetch 제외)로
  넓히고, 로그인 관문 밖 경로는 Supabase 를 안 부르고 헤더만 싣는다. 루트 레이아웃이 `await headers()` 한다.
  `style-src` 는 `'unsafe-inline'` 그대로.
- **SRI** — `experimental.sri: { algorithm: 'sha256' }` 과 `script-src 'self'`(nonce 없음).

## 값

| | 지금(`'unsafe-inline'`) | nonce | SRI |
| --- | --- | --- | --- |
| 정적(○) 경로 | 4 — `/` · `/_not-found` · `/auth/denied` · `/me/discovery` | **0** — 넷 다 ƒ | 4 그대로 |
| `/` 의 응답 | `x-vercel-cache: PRERENDER`, `public, max-age=0, must-revalidate` | `private, no-cache, no-store` | 그대로 |
| 스크립트 태그 | — | 19 전부 nonce(인라인 4 · 외부 15) | 외부 14 중 `integrity` 6, 인라인 4 는 해시 없음 |
| e2e 전부의 CSP 위반 | 0 | **0** — 익명 61 · 로그인 · 관문 126 통과 | 홈 · 처리방침 · 로그인만 열어도 **8**(`script-src-elem` 인라인) — 화면이 수화되지 않는다 |

**SRI 는 대안이 못 된다.** Next 가 페이지에 심는 인라인 스크립트(RSC 조각 `self.__next_f.push`)에 해시를 안 주므로
`'unsafe-inline'` 없이는 막힌다. 문서도 「실험적 · 빌드 때 스크립트만」이라 적는다
(`node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`).

**nonce 는 돈다.** 비용은 넷이다.

1. **홈 `/` 가 CDN 에서 내려오던 것이 요청마다 그려진다.** 운영에서 잰 첫 바이트(9번씩, 중앙값): 정적 `/` 63ms,
   동적 `/privacy` 118ms — 차이 약 55ms, 콜드 스타트 한 번은 1.35초. 홈은 사람이 가장 먼저 여는 화면이다.
2. **proxy 가 모든 화면 요청에 돈다.** 지금 matcher 는 로그인 경로 다섯뿐이다. 넓히면 공개 화면 · 공유본까지 함수
   호출이 하나씩 붙는다(Vercel 의 Edge/함수 호출 수 · 시간 과금). 공유본 링크가 퍼질수록 는다.
3. **PPR 과 ISR 을 못 쓴다**(Next 문서). 지금은 둘 다 안 쓴다.
4. `style-src` 까지 빼려면 따로 잰다 — 이번에는 안 쟀다. 인라인 `style` 속성이 곳곳에 있다.

## PG · 본인인증이 부를 출처 (목록만)

PortOne V2 브라우저 SDK `1.36.1`(`https://cdn.portone.io/v2/browser-sdk.js`)의 소스에서 읽은 주소다. 공식 문서에
CSP 목록은 없다 — **샌드박스로 결제창 · 인증창을 한 번 열어 위반을 재야 확정이다.**

| 지시어 | 출처 | 근거 |
| --- | --- | --- |
| `script-src` | `https://cdn.portone.io` | SDK 본체와 PG 별 드라이버(`/drivers/…`, `integrity` 를 붙여 부른다). nonce 를 쓰면 `'strict-dynamic'` 이 SDK 가 부른 스크립트를 따라 허락한다 |
| `frame-src` | `https://checkout-service.prod.iamport.co` | 결제창 · 인증창 iframe(`imp-iframe`), `postMessage` 의 origin 도 이것 |
| `connect-src` | `https://service.iamport.kr` · `https://checkout-service.prod.iamport.co` · `https://tx-gateway-service.prod.iamport.co` · `https://coretelemetry.prod.iamport.co` · `https://payment-bridge.prod.iamport.co` | SDK 의 서버 상수(`CORE_SERVER` · `CHECKOUT_SERVER` · `TGS_PUBLIC_URI` · `CORETELEMETRY_SERVER` · `PAYMENT_BRIDGE_URL`) |
| `form-action` | 미정 — 모바일 결제는 창을 띄우지 않고 이동한다. SDK 가 최상위 창에서 폼을 PG 로 보내면 `form-action 'self'` 가 막는다 | 샌드박스에서 모바일 폭으로 잰다 |

- **KCP 휴대폰 본인확인(PASS 포함)** 은 PortOne 을 거치면 인증창이 `checkout-service.prod.iamport.co` 안에서 열린다 —
  KCP 쪽 주소(`cert.kcp.co.kr`)는 그 틀 안의 일이라 우리 CSP 에 안 걸린다. KCP 관리자에 인증 결과 URL 로
  `checkout-service.prod.iamport.co` 를 적는다(PortOne 「KCP 본인인증」 문서).
- 서버에서 확인하는 `https://api.portone.io` 는 서버가 부르므로 CSP 와 무관하다(G-23 ⑥⑦).

## 정한 것 (2026-09-24, 운영자)

**ⓒ — `'unsafe-inline'` 은 지금 유지한다.** 결제 · 본인인증(PortOne V2 + KCP)을 **샌드박스로 연동한 뒤** nonce 전환(ⓐ)을
다시 검토한다 — 위 표의 출처와 `form-action` 이 그때 재어져야 nonce 와 `'strict-dynamic'` 의 모양이 정해지고, 정적 넷이 동적이
되는 값(첫 바이트 중앙값 63 → 118ms)을 그 연동과 한 번에 치른다. `next.config.ts` 는 바꾸지 않았다. G-23 ② 가 든다.
