# SEO 점검으로 연 세션과 그 `/retro` — 2026-10-08

> 요구사항이 아니다 — 지금 규칙은 각 원본이 든다. 이 라운드의 PR 은 #519 · #520 과 이 노트의 PR, 그리고 ci-plan 의 주석 판정 PR 이다.
> 결정은 ADR 0151 · 0152 가 든다.

## 시작한 까닭

운영자가 SEO 점검과 첫 화면 문구 보고를 맡겼다. 운영 HTML 을 긁어 robots · sitemap · 대표 주소 지정이 없는 것을 찾았고, SEO 작업은
운영자가 뒤로 미뤘다. 같은 대화에서 운영 주소 정정(#519)과 바닥글의 사업자 정보 걷기(#520, ADR 0151), 배포 한 번이 나왔다.

## 헤맨 것

- **운영 주소를 낡은 주석에서 읽었다.** `app/site-url.ts` 의 「아직 자기 도메인이 없다」와 `app/layout.tsx` 의 옛 별칭을 믿고 운영
  주소를 옛 별칭으로 보고했다. `docs/ops/runbook/domain.md` 는 열지 않았고, 그 문서도 운영 주소를 옛 별칭으로 적고 있었다. 「원본」 표에
  운영 주소 줄이 없었다 → ADR 0152 의 1.
- **운영자의 집 주소가 공개 저장소에 있었다.** ADR 0149 의 세션이 바닥글 값으로 적었다. 저장소가 공개라는 사실을 적은 문서가 없었다 →
  ADR 0151 · 0152 의 2.
- **문서 정정 PR 에 주석 두 줄을 섞어 CI 전부(약 11분)를 돌렸다.** `app/layout.tsx` 는 공용 위험이라 주석 한 줄도 전부다. 운영자가
  안 (가) — ci-plan 이 diff 를 보고 주석만 바뀐 파일을 정책 단계로 센다 — 를 골랐다.
- **지시받은 정정에 다시 허락을 물었고, 배포가 상관없는 PR 의 머지를 기다렸다** → ADR 0152 의 3 · 4.
- **대화 중에 온 운영자의 말에 답이 다른 보고에 묻혔다** — 운영자가 같은 말을 다시 해야 했다. 중간에 온 말은 다음 응답의 맨 앞에서 답한다.
