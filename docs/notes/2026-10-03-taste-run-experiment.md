# 개인별 맛보기 · 가입 뒤 이어쓰기 — 실험 설계와 짝 견본 도구 — 2026-10-03

> **세션 기록이다. 요구사항도 결정도 아니다 — ADR 이 아니다.** 운영자와 이날 합의한 설계를 옮겨 적었고, 이 노트와 함께 든
> PR 은 그 설계를 **실호출 짝 견본으로 재 보는 도구**(프롬프트 · 검사 · 실호출 시험)뿐이다. ADR · PRD · DB · 화면 · 운영 경로는
> 고치지 않았다. 지금 제품의 로그인 전 결과는 여전히 ADR 0131(720칸 공용 표 · `taste_passage` · `taste-maker.ts`)이다.
>
> **순서:** 실호출 짝 견본(운영자가 돌린다) → 사람의 짝 검토(아래 여섯 질문) → ADR(0131 을 대체할지). 그 전에 이 노트의
> 어느 값도 운영에 들지 않는다. 낱말 「맛보기」는 여기서 내부 이름(`taste`)으로만 쓴다 — 화면에서는 「로그인 전 결과」다(`CONTEXT.md`).

## 흐름 (합의한 모양)

1. 로그인 전 생년월일시 → **우리 서버**가 엔진으로 명식 계산(입력 원문은 저장 안 함)
2. 맛보기용 근거 — 자기 풀이 근거(`RedactedEvidence`)에서 해 · 나이 · 날짜를 드러내는 값을 뺀 것(아래 「근거 줄이기」)
3. 근거 지문 — 여덟 글자 · 성별 · 시간 앎 · 엔진 판의 해시
4. DB 예약(아래 「비용 · 남용」) → 맛보기 모델 → 규칙 검사 → tasteRun 저장 → 화면에 맛보기
5. [더보기] → 가입 — **tasteRunId 와 httpOnly 묶음 쿠키만** 들고 간다
6. 「이 사주가 내 사주 맞나요?」 → 확정 입력으로 지문을 다시 계산
7. DB 함수 한 번에 원자적 귀속 — `id` · 브라우저 HMAC 일치, 주인 없음 또는 나, 지문 일치. **지문이 다르면** 그 tasteRun 은 버림
   표시하고 이어쓰기 없는 보통 풀이로 간다. 이미 내게 붙어 있으면 재시도해도 같은 맛보기로 이어 쓴다
8. 기존 자기 풀이 프롬프트에 **저장된** 맛보기 원문 · 질문 · 답의 방향을 그대로 싣는다(표를 다시 읽지 않는다)
9. 결과에 tasteRunId → 화면 맨 위 「아까 보던 내용」(저장 원문) → `continuationAnswer` → `markdown`

## 1. 맛보기 출력 계약 (구조화)

`{ previewMarkdown: string; continuationQuestion: string; answerDirection: string; supportingClaims: string[] }`

- `previewMarkdown` — 300~500자 · 2~4문단 · 해요체 · **핵심 주제 하나** · 장점과 그 장점이 만드는 문제를 잇고, **해결책 직전에서
  완결된 문장으로** 멈춘다. 문장 중간에서 자르지 않는다. 해결책은 말하지 않는다
- `continuationQuestion` — 멈춘 자리의 물음. 가입 뒤 전체 풀이가 맨 먼저 답한다
- `answerDirection` — 그 답의 방향 한 줄(사용자에게 안 보인다)
- `supportingClaims` — 질문과 답의 방향이 기대는 근거 경로(`analysis.structure` · `analysis.johu` …)
- 근거 없는 과장 금지 — 「하나뿐」 · 「아껴 써야」 같은 단정을 자료에 없이 만들지 않는다

코드: `src/lib/reading/taste-run.ts` 의 `TASTE_RUN_SHAPE` · `tasteRunPromptOf`.

## 2. 전체 풀이 출력 계약

tasteRun 이 **있을 때만** `{ continuationAnswer, score, metaphor, markdown }` — `continuationAnswer` 가 **맨 앞 속성**이다(구조화
출력은 속성 차례로 짓는다). 없으면 지금 모양 그대로.

- 첫 절 「먼저 볼 핵심 세 가지」 지시는 안 바꾼다. `markdown` 에서 답을 되풀이하지 말라는 줄 하나만 더한다
- 이어쓰기 블록의 지시 — 이 사용자는 아래 원문을 이미 읽었다 / 이 질문에서 멈췄다 / `continuationAnswer` 가 그 질문에 바로
  답하고 거기서 완결한다(미루지 않는다) / 이미 읽은 내용을 다시 설명하지 않는다 / 앞 내용과 다른 성격으로 규정하지 않는다 /
  `answerDirection` 과 `supportingClaims` 에 기대어 답한다

코드: `src/lib/reading/continuation.ts` 의 `continuationBlockOf`. 블록은 `readingPromptOf` 의 결과 **뒤**에 붙는다 — 정적인 지시가 앞,
자료가 뒤인 지금 차례를 안 깨므로 캐시가 잇는 앞부분이 그대로이고, `readingPromptOf` 의 기본 출력은 한 글자도 안 바뀐다(프롬프트
판 · 캐시 시험이 그대로 초록). 모양은 `app/me/reading/model.ts` 의 `CONTINUATION_SHAPE`(운영 모양 셋 앞에 한 칸).

## 3. 기계 검사

**`continuationAnswer`** — 하나라도 걸리면 실패(`checkContinuation`): 있음 · 120~400자(시키는 값은 150~300) · 해요체 / 미루는 말
(「아래에서」 · 「뒤에서」 · 「이어서 풀」 · 「더 알아보」 …) / **맛보기 원문과의 4글자 조각 겹침이 0.25 이상** / `markdown` 첫 절에 같은
답이 또 있음(같은 자, 0.25) / 분류명 · 한자(`plainTermsIn` 재사용).

**겹침 검사는 보조다.** 글자 조각이 겹치는지만 보므로 말을 바꾼 반복은 못 잡는다. 「질문에 맞는 답인가」 · 「한 글로 이어지는가」는
**사람의 짝 검토가 판정한다.** 문턱 0.25 는 재지 않은 첫 값이다 — 손 견본 짝은 맛보기와 0.014(4글자), 맛보기 문장을 그대로 옮기면
1 에 가깝다. 실호출 짝으로 다시 잰다.

**맛보기** — `checkTasteRun`: 네 칸이 비지 않음 · 250~600자(시키는 값 300~500) · 2~4문단 · 해요체 · 완결된 문장으로 끝남(말줄임 ·
문장 중간 끊김 금지) · 「AI」 없음 · 마크업 없음 · 분류명 · 한자 없음 · `supportingClaims` 1~6개가 경로 꼴이고 **맛보기 근거에 실제로
있는 경로**(빠진 `now` · `daeun` 을 가리키면 걸린다). 막는 값을 시키는 값보다 넓힌 까닭은 `verification-discipline.md`(2026-09-07 —
지시에 없는 상한이 글을 통째로 떨어뜨렸다)이고, 손 견본이 280자라 300 으로 막으면 견본이 떨어진다.

## 4. 맛보기 전용 모델 설정

- 추론 `none` / `low` 비교(기본으로 둘 후보는 `low`), 출력 토큰 상한 1,500(추론 포함), 시간 상한 20초, 동기 호출
- 지금 `callModel` 은 추론 세기를 안 보내 provider 기본(공식 문서상 `medium`)으로 돈다 — **바꾸지 않았다**
- 옵션 이름은 `@ai-sdk/openai` 4.0.50 의 Responses 선택값 `reasoningEffort`(그 패키지 문서 03-openai.mdx: GPT-5.6 은 `none` · `low` ·
  `medium` · `high` · `xhigh` · `max`). `none` 이 아니면 provider 가 추론 요약을 `detailed` 로 켜므로 실험에서는 `reasoningSummary: null`
  로 끈다. 출력 상한은 `maxOutputTokens`(Responses `max_output_tokens`), 시간은 `timeout`
- `callModel` 은 **기본값을 그대로 두는 선택 인자**로만 넓혔다 — `shape` · `continuation` · `reasoningEffort` · `maxOutputTokens` ·
  `timeoutMs`. 안 넘기면 모양 · 세기 · 상한이 전과 같다. 모델을 부르는 자리는 여전히 `model.ts` 하나다(ADR 0047). `callModel` 을
  부르는 것은 실호출 시험 셋뿐이고 운영 제출(`submitBackgroundReading`)은 손대지 않았다

## 5. 비용 · 남용 (설계만 — 코드 없음)

**공식 단가** gpt-5.6-luna — 입력 $0.20 · 캐시 입력 $0.02 · 캐시 쓰기 1.25배($0.25) · 출력 $1.20 /1M
(https://developers.openai.com/api/docs/models/gpt-5.6-luna, 2026-10-03 확인).

**자기 풀이 실측**(2026-10-01 `.reading-live/kinds/self-…`) — 캐시 쓰기 24,689 · 출력 6,560 → $0.0140 ≈ 19.7원(1,400원/$ 가정).

**맛보기 추정** — 입력 ~11,000 토큰 → `none` ≈ 4.6원, `low` ≈ 5.5~6.3원, `medium` ≈ 9~10.6원. **추정이다** — 실호출 사용량으로 다시 센다
(실호출 시험의 `summary.md`).

- **전체 하루 상한 2,000**(80% 에 경고, 닿으면 맛보기를 건너뛰고 가입 안내로) — `low` 기준 하루 1.1만~1.3만원, 월 33만~38만원
- 같은 (브라우저, 지문)은 재사용(비용 0). 브라우저당 **새 지문 시간당 5**, **IP 당 하루 20**
- **DB 함수 하나가 한 트랜잭션으로 모델 호출 전에 예약한다** — 전체 칸 `used < cap` 조건부 증가 → 브라우저 · IP 한도 → taste_run
  「예약됨」. 한도를 넘으면 같은 트랜잭션이라 되돌려진다. 모델이 실패해도 칸은 쓴 것이다. 시간을 넘긴 「예약됨」은 정리 작업이
  실패로 닫는다
- 같은 요청의 중복은 (브라우저 HMAC, 지문) 유일 제약 + 화면 요청 id
- **IP** 는 날짜별 키(`HMAC(서버비밀, 날짜)`)로 HMAC 하고 24시간 뒤 지운다
- **브라우저 묶음** — 쿠키 원문은 고엔트로피 무작위 값, 그것을 **24시간 넘게 유지되는 안정적 비밀키**로 HMAC 한다. 날짜별로 돌리지
  않는다 — 자정을 넘겨 가입한 사용자가 다른 브라우저가 되지 않게
- **미가입 기록 보존 24시간** — 입력이 탭 저장소에 있어 탭 수명보다 길게 둘 이득이 없다. 행 ~2KB, 근거 원본은 저장 안 하고 지문만
- 회원에 붙은 기록은 그 회원의 풀이 자료 — `forget_user` 와 함께 지운다
- **덧붙여 확인한 것** — 운영 백그라운드 경로의 `usageOf`(`app/me/reading/model.ts`)는 캐시 쓰기를 `null` 로 남긴다. 그래서
  `reading_spend_daily` 로 추정하면 입력 비용이 최대 25% 낮게 나온다(청구의 원본은 대시보드). 기다리는 길(`callModel`)은 AI SDK 가
  `cache_write_tokens` 를 읽어 주므로 받을 수 있다 — 이번 PR 은 운영 경로를 안 고쳤다

## 7. 법무 (설계만 — 변호사 검토 대상)

- **모델 제공자(OpenAI, 국외)에 가는 것** — 여덟 글자 · 성별 · 분석값
- **안 가는 것** — 생년월일시 원문 · 출생지 · 이름 · 연락처 · IP · 해 숫자 · 나이 · 절기 날짜
- 다만 **여덟 글자는 60년 주기 안에서 날짜와 2시간 범위로 역산된다** — 「원문은 안 나가지만 출생 날짜 · 시간대에 준하는 값이 식별자
  없이 나간다」. 근거 지문 해시도 경우의 수가 적어 대입으로 풀린다(지문은 비밀이 아니라 열쇠다)
- 지금 회원 풀이 근거에는 해 숫자(1992)와 나이(34)가 들어 있다(아래 「잰 값」)
- 로그인 전 생년월일시가 **우리 서버로 오는 것은 새 일**이다 — 지금 `/` 는 브라우저가 계산한다(ADR 0131 · G-66)
- **G-66 을 대체할 변호사 질문 셋** — ① 국외 이전 고지 대상인가 ② 화면 고지로 충분한가, 처리방침 개정이 필요한가 ③ 미가입 기록
  24시간 보관을 고지해야 하는가
- 화면 고지 후보 — 운영자 2026-09-29 결정 「화면에 AI 를 새로 세우지 않는다」와 부딪친다. 권고안: 「입력한 생년월일시는 우리
  서버에서 사주를 계산하는 데만 쓰고 저장하지 않아요. 풀이를 쓰는 OpenAI에는 정확한 생년월일시와 출생지 대신, 계산된 사주와
  분석값만 보내요.」 **최종 문구는 변호사 검토와 문구 표 확인 대상이고 코드에 넣지 않았다**

> 그래서 책임과 기대가 몰리는 자리에 서기 쉽고, 그 압박을 혼자 버티는 쪽을 자주 택해요. 다만 그 단단함을 받쳐 주는 힘은
> 쇠의 양만큼 크지 않아서, 오래 버틸수록 안에서 먼저 지칠 수 있어요. (돕는 힘 40% 신약 쪽 · 년주 뿌리 충으로 얕음)
>
> 이 사주 안에는 그 열기를 덜어 낼 방향도 함께 보여요. 그 방향을 알면, 같은 압박을 버티는 대신 다르게 다룰 수 있어요.
> (식신제살 조건 · 조후표 임수 참고 · 년간 壬)

- `continuationQuestion` — 「이 사주에서 압박의 열기를 덜어 내는 방향은 무엇이고, 어떻게 쓰나」
- `answerDirection` — 「안에 쌓지 않고 생각을 밖으로 꺼내는 것」
- `supportingClaims` — `analysis.structure` · `analysis.johu` · `pillars.year.stem` · `analysis.strength` · `analysis.rootQuality`

**continuationAnswer**

> 그 방향은 '안에 쌓아 두지 않고 꺼내는 것'이에요. 이 사주에서는 생각과 기준을 밖으로 내보내는 힘이 불의 열기를 누그러뜨리는
> 쪽으로 읽혀요. 그래서 부담이 몰릴 때 혼자 정리를 끝내고 내놓기보다, 덜 다듬어진 채로라도 말로 먼저 나누고 결과물을 일찍 보여
> 주는 편이 맞아요. 버티는 시간이 줄면 같은 책임도 지치는 일보다 실력을 보여 주는 일에 가까워져요.

## 남은 걱정

- 맛보기 근거가 여전히 큰 편이다(대부분이 `analysis`). `none` 으로 20초 안에 드는지, `low` 가 출력 1,500 상한에 걸리지 않는지는 실호출이
  말한다 — 상한에 걸리면 `model-no-output` 으로 남는다
- 짝의 전체 풀이는 지금 운영 기본값(추론 `medium` · 240초)으로 부른다 — 이어쓰기 블록이 붙어 출력이 길어지는 만큼 시간도 는다

결과 원문은 워크트리의 `.taste-run-live/` 에만 있다(커밋 안 함). 쓴 돈은 1차 약 205원 · 2차 약 46원.

### 1차 — 한 꼴(장점 → 문제 → 해결 직전) · 본보기 멈춤 문장 있음

| | 부름 | 검사 지남 | 시간 중앙값 / 최댓값 | 한 번 |
| --- | --- | --- | --- | --- |
| 맛보기 · none | 6 | 5 | 4.8초 / 6.0초 | 약 3.6원 |
| 맛보기 · low | 6 | 3 | 7.9초 / 10.7초 | 약 4.1원 |
| 전체 풀이 + 이어쓰기 | 8 | 8 | 70초 / 92초 | 약 19.5원 |

- **이어붙이기 장치는 섰다** — 이어쓰기 8/8 이 검사를 지났고 미루는 말 없이 행동으로 답했다.
- **미끼는 실패했다** — 명식이 달라도 거의 다 「능력이 있다 → 혼자 책임진다 → 버틴다 → 부담된다 → 나눠라」로 모였다. 원인 셋:
  본보기 멈춤 문장(1987 남은 그대로 베꼈다) · 모든 사주를 한 꼴로 쓰게 한 지시 · 글을 먼저 쓰고 근거를 뒤에 끼우는 출력 차례.
- 검사 실패 넷은 모두 근거 경로 꼴(`chart.` 접두 · 없는 `analysis.relations`)이었다. `low` 는 느리고 비싸고 덜 지나 버렸다.
- 「먼저 볼 핵심 세 가지」의 1번이 이어쓰기 답의 요지를 다시 말하는 일이 있었다(겹침 검사는 의미 반복을 못 잡는다 — 예상한 한계).

### 2차 — 숨은 판단을 먼저(topic · distinctivePattern · supportingClaims · 질문 · 답의 방향 → 글), 꼴 여덟, 경로 enum

- **주제가 갈렸다** — 맛보기만 6개를 돌리니 꼴 다섯(관계에서 반복되는 장면 · 서로 반대되는 두 성향 ×2 · 힘이 빠지는 조건 ·
  겉과 속의 차이 ×2). 「압박 · 혼자 버팀」 줄거리는 사라졌다. 근거 경로 실패는 0 이다.
- **새로 보인 실패** — 9건 중 3건이 마지막 「다음을 예고하는」 문장에서 합니다체로 미끄러졌다(「…핵심이 됩니다」 ·
  「…먼저 보입니다」 · 「…가장 먼저 이어집니다」). 그 문장은 「다음 이야기 · 다음 풀이」를 말해 가입을 에둘러 가리킨다 —
  지시(「가입을 말하지 않는다」)의 빈틈이다. 「명식」이 한 번 본문에 나왔다(검사가 잡았다).
- 대표 셋의 짝은 맛보기가 하나만 지나 **한 쌍**만 나왔다(1987 남, 겉과 속의 차이). 이어쓰기 답은 구체적이었다(「하룻밤 둔 뒤
  다시 읽는 습관 · 숫자와 일정으로 확인하는 절차」). **첫 절 반복은 남았다** — 1번이 「추진력 옆에 멈춤과 검증을 붙이는 일」로
  답을 다시 말했다. 지시 한 줄로는 안 막힌다는 것을 1 · 2차가 같이 보였다.
