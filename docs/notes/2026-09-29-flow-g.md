# 흐름 시안 g — e 화면 + d 흐름 (2026-09-29)

운영자가 라우팅 · 첫 화면 · 탭 구성이 이상하다고 짚었다. 두 라운드로 풀었다.

1. **의견 다섯**(읽기만): 그로스 · IA · UX 리서처 · 시장 분석 · 반론/비용. 공통 결함은 셋이었다 — 풀이 목록에서 연 궁합(`/me/compat`)이 홈 탭에 불을 켠다,
   로그인으로 보내는 약 19곳이 `next` 를 안 든다(가입 관문도 버린다), `/` 에서 이어 온 풀이가 「내 사주」가 아니라 「저장한 사람」으로 저장된다
   (`app/save-for-reading.tsx` → `savePersonForReading`, 조율자가 확인).
2. **흐름 시안 일곱**(`/preview/flow?variant=`, 커밋 안 함, 역할별 에이전트가 파일 하나씩): a 지금 그대로 · b 최소 수정 · c 주소 재정리 · d 맛보기 퍼널 ·
   e 동사 탭(나 · 궁합 · 인연 · 채팅) · f 사람 카드 → 운영자가 **e 의 화면 + d 의 기조**를 골라 g 로 합쳤다. a~f 는 지웠다.

## 운영자가 정한 것

- **기준은 일반 공개 서비스다.** 「테스터를 생각하는 건 어리석은 짓」 — 가입 코드 · 베타 사정으로 흐름을 깎지 않는다.
- **탭은 나 · 궁합 · 인연 · 채팅.** 주소는 그대로 두고 탭 이름과 소속만 바꾼다(조사: 주소를 옮기면 e2e · revalidate · 알림 링크를 다 고치고 얻는 것은 이름뿐).
- **비로그인 첫 화면은 e 의 모양**, 단추는 「무료로 내 사주 보기」. 입력하면 맛보기를 일부 보여 주고 나머지는 잠근다 — 「보고 싶으면 가입하고 무료 풀이 받기」.
- **화면에 「AI」라는 말은 필요 없다.** 일간은 「병화」 글자보다 **지금 쓰는 천간 그림 열**(`app/ui/stem-symbol.tsx`)로.
- **가입 화면은 지금 모양.** 「이 사주가 내 사주 맞나요?」와 풀이 생성 중 화면은 **기존 내 사주 카드**를 쓴다.
- **생성 중에 목차가 하나씩 「완료」되는 화면**을 가장 좋게 봤다 — 꾸며 낸 진행이 아니라 서버 진행에 기댄 것이어야 한다(`app/me/reading/panel.tsx` LoadingState 주석).
- 로그인 주소의 겹친 `next`(`next=/me/onboard/self?next=…`)는 시안의 흉이었다 — `next` 는 최종 목적지 하나만 든다.

## 조사로 잰 것 (백엔드 조사 에이전트, 코드 대조)

- **진행 표시는 조건부 가능.** 제출은 `background: true` 한 번이고 완성본을 통째로 검사한다. 같은 응답을 스트림으로 읽어 절 머리가 나올 때마다 **번호만**
  DB 에 적으면 검사 전 글을 내보내지 않고 토큰도 안 는다. 끝에 「마지막 검토」 칸을 두어 검사가 실제로 끝날 때 닫는다. 궁합은 소제목을 모델이 정하므로
  「n번째 이야기」까지만 — 고정 목차를 되돌리는 것은 프롬프트 실험 보류를 푸는 일이라 운영자 몫으로 남겼다.
- **비로그인 맛보기는 조건부 가능.** 풀이 파이프라인과 섞지 않는 별도 문 · 별도 표. 열쇠를 「일주 × 월지」(720칸)로 거칠게 잡고 **미리 만들어 검사까지 끝낸 표**를
  쓰면 비용 상한이 구조로 막히고, 방문자가 입력할 때 밖으로 나가는 것이 없다(처리방침 부담이 준다). 운영자 확정 전 — 조율자 권고.
- **인연 탭의 「받은 요청」 목록**은 지금 종(`/me/requests`, 제목 「소식」)에 받은 요청 · 보낸 요청 · 새 소식으로 산다. 매칭 탭(`/me/matching`)은 궤도 지도와 덱뿐이다.
  g 는 받은 요청을 인연 탭 맨 위로 옮긴 모양이다. 종에는 풀이 실패 알림도 섞여 있어 통째로 옮기지 않는다.

## 1라운드 (워크트리 셋, 나란히)

- **A 탭** — 나 · 궁합 · 인연 · 채팅, 주소 유지.
- **B 진행 표시** — 스트림으로 절 번호만 적는 칸 + 목차 「완료」 화면. 이 라운드의 마이그레이션은 B 만.
- **D 로그인 · 가입 흐름** — `next` 도우미로 입구 전부, 가입 관문이 목적지를 들고 감, `/` 에서 이어 온 사주를 「내 사주」로 저장할 수 있게.
- 다음 라운드: 맛보기(표 · 미리 만들기 스크립트 — 실호출은 운영자가 돈다) + 첫 화면 · 궁합 맛보기, 받은 요청을 인연 탭으로.

## 프롬프트에 쓸 만한 목차 예시 (운영자: 「어디다가 저장해 두고 싶다」)

시안 g 의 생성 중 화면에 쓴 가짜 목차다. 절 이름 뒤에 **그 사람에게 맞춘 부제**를 붙이는 모양을 운영자가 좋게 봤다.
프롬프트 실험은 보류 중(2026-09-15)이라 지금 프롬프트에 넣지 않는다 — 실험을 다시 열 때의 후보다. 지금 절 이름은 `src/lib/reading/prompt.ts` 가 든다.

사주풀이(병화 일간 예):

1. 타고난 기질 — 한낮의 해
2. 일과 돈 — 드러나야 힘이 나는 사람
3. 연애와 관계 — 먼저 데우는 쪽
4. 지금의 시기 — 2026 병오년
5. 건강과 쉼
6. 앞으로 10년의 흐름

궁합풀이: 두 사람의 첫인상 · 서로를 채우는 오행 · 부딪히는 자리와 푸는 법 · 함께할 때의 시기.

부제가 목차에 서면 생성 중 화면이 절 이름만이 아니라 「그 사람의 이야기」를 미리 보인다 — 다만 부제는 모델이 쓰는 글이라 검사 전에 보이면 안 된다.
진행 화면에는 고정 절 이름만 서고, 부제는 풀이가 검사를 지난 뒤에 선다.

## 아직 안 정한 것

- **이번 달 흐름**(나 탭, 시안 g): 운영자가 「있으면 좋겠지만 어떻게 만들지 모르겠다 — 한 달치를 미리 해 두고 그날그날 꺼내나」.
  조율자 의견: 날마다의 일진(日辰)과 내 일간의 관계(십신 열 가지)는 엔진이 계산으로 바로 낸다 — 미리 만들어 둘 것이 없다. 문장은 십신별 규칙 문장(열 벌)이면
  비용이 0 이고, AI 문장이 필요하면 「일간 10 × 일진 60 = 600칸」을 맛보기처럼 미리 만들어 표에 둔다. 만들지는 운영자 결정 뒤.
- 맛보기 열쇠의 거칠기(일주 × 월지 권고), 궁합 진행 표시(「n번째 이야기」 vs 고정 목차).
