# 문구 CI · 배포 대기 라운드 (2026-10-09~10)

운영자가 「화면 문구만 바꿨는데 CI 를 다 돈다」고 짚은 데서 시작했다. 결정과 규칙은 ADR 0159 가 원본이고, 머지는
#572 · #573 이다. 이 노트는 거기 없는 것만 든다.

## 조율자의 판단과 까닭

- **원인은 문서 규칙이 아니라 계획기였다.** #570 의 문구 상수가 `src/lib/consent/notice.ts` 에 들어가 공용 위험(관문)에 걸렸다.
  그리고 묶음 배포 0 번이 main 의 전체 초록을 한 번 더 기다렸다. 이 둘째 대기는 조율자가 처음에 놓쳤고 외부 검토가 짚었다.
- **「정적 화면 표현」을 빼고 문구로 좁혔다.** `className` · `href` · `aria-*` 도 문자열이라, 문자열로 판정하면 동작 변경이 샌다.
- **배포 범위는 PR 하나가 아니라 묶음 전체로 본다**(ADR 0110). 그래서 커밋마다 가르고, 근거는 GitHub 에서 읽은 마지막
  전체 초록뿐이다.
- **문구 판정은 차선을 좁히기만 한다.** 넓게 켜는 정규식 규칙(쓰임 자리로 가름 · 판별 불가는 켬)을 넣자 문구 한 줄이 전부를
  불렀다. 입구가 아닌 컴포넌트는 #572 전보다 나빠졌다. 운영자가 「좁히기만」을 골랐고, 「좁은 쪽」은 개수가 아니라
  부분집합으로 견준다(운영자 덧).
- **결과 — PR CI 절감은 거의 없고, 이득은 배포 대기다**(ADR 0159 「얻는 것」). 도우미 `e2e/birth-form.ts` ·
  `e2e/second-factor.ts` 를 spec 차선으로 세는 수정은 이득이 작아 하지 않았다.

## 배운 것

- **운영자가 승인한 결정이라도 검증 · 배포 문턱을 바꾸는 PR 은 검토 전에 `--auto` 를 걸지 않는다.** #572 브리프에
  「gate 뒤 `--auto`」를 적어, 독립 검토가 끝나기 전에 머지됐다. 검토에서 `--from` 이 근거를 대신하는 결함, 끝과 끝만
  보는 범위 판정, 최신이 아닌 gate 가 나왔다. 그래서 결정 점검표에 「검증 · 배포의 문턱」 줄을 더했다(#573).
- **판별기를 고치면 검토가 매 라운드 새 구멍을 찾는다.** 검토를 세 번 돌았다. 한 번은 고친 쪽(정규식 위치 추측)이
  새 누락을 만들었다. 추측을 파서로 바꾸니 닫혔다.
- **안전 쪽 규칙은 효과를 0 으로 만들 수 있다.** 「판단이 안 서면 켠다」를 시험 전체에 걸면 문구 좁히기가 사라진다.
  규칙을 넣기 전에 실제 저장소로 실측하고 넣는다.

  `local-env.md` 에는 있는데 역할 문서에서 그 줄로 가는 길이 없다.
- 읽기량 천장 — 이 라운드 뒤 여유가 ui 2 · reviewer 29 · ops 38 바이트다. 공용 원본(`decisions.md` · `deploy.md`)에
  한 줄을 더해도 넘는다. `feature.md` 에는 「공용 원본을 고치면 `npm run read-budget`」 안내가 없다.
