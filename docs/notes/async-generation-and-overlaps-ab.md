## 끝났고 배포된 것 — 생성이 요청을 떠났다 (ADR 0020)

자기 풀이 호출 넷 중 **둘이 240초를 넘겼다.** `after` 가 라우트 `maxDuration` 안에서
도니 화면만 비동기였고, Vercel 상한이 300초라 문턱을 올릴 여지가 없었다.

이제 이렇게 돈다. **프로덕션에서 실제로 완주했다**(02:40 누름 → 02:41:14 webhook →
02:41:15 저장, 75초, 본문 10,398자).

```
누름 → reading_job 에 얼림 → OpenAI background 제출(metadata.reading_run_id) → 즉시 응답
        ├ 정상: webhook → 도착만 적고 2xx → after 가 회수·검사·저장
        └ 유실: Supabase pg_cron 1분 → /api/cron/reading → 같은 회수 경로
화면 3초 폴링 = 표시용 · Vercel 하루 cron = 최후 청소
Supabase 복구 1분 < 우리 deadline 8분 < DB 실행 만료 10분
```

- 열쇠(service_role)에 열린 함수가 **열하나**가 됐다. 13번 pgTAP 이 ACL 로 그 집합을
  센다 — 문을 열면 그 시험을 함께 고쳐야 한다.
- **`OPENAI_WEBHOOK_SECRET`(Vercel)과 `CRON_SECRET`(Vercel + Supabase Vault)은 다른 값**
  이고 둘 다 넣어져 있다. Vault 이름은 `reading_recovery_url`·`reading_recovery_secret`,
  들어 있는지는 `reading_recovery_configured()` 로 묻는다.
- **`supabase db push` 로 원격에 일곱 개 적용됨.** `config push` 는 여전히 쓰면 안 된다.
- 하네스만 `callModel(prompt, timeoutMs)` 로 긴 문턱을 쓴다. 기본값은 운영값 그대로다.

## 결정났다 — overlaps B 는 **보류**다 (2026-09-01)

브랜치 **`overlaps-v2`**(main 위에 다시 쌓았다, `8abe1d7`·`9cd3d3f`). 머지 안 했다.

15회 A/B 를 돌렸다(`$0.1913`). 기계가 답할 수 있는 것은 다 나왔다.

- **15/15 프로덕션 검사 통과**, 본문 6,979~8,734자(주문 5,000~9,000 안), 57~144초
- hard gate 실패는 **C 군만 2건** — `target-오조인`(현침살 × 묘오파) ·
  `반합-단서`(신유 반방합 단정). A·B 는 0건
- **환각 0건.** 6개 flag(이름 9개)를 원문에서 다 읽었다 — 넷은 부정문(「자료에 없으니
  안 쓰겠다」), 하나는 `sinsal.twelveSpirits` 인용, 하나는 월운에서 온 역마살이다.
  **게이트가 팔을 못 가른다** — 지금 가장 시끄러운 열이다
- **A 도 hard gate 를 하나도 안 틀렸다** — 「overlaps 지시가 오조인을 막는다」는 이번
  자료로 확인되지 않았다. 남은 물음은 「글이 더 이 사람 것 같은가」 하나다

블라인드 페이지: https://claude.ai/code/artifact/49ead318-80b6-4431-a977-b6bdc94abc74

**사용자가 블라인드로 골랐고 결론은 「A 유지, B 보류」다.** 배포 가능한 둘만 보면
A 3승 B 2승 — 동전 던지기와 구별되지 않는다. `overlaps-v2` 는 지우지 않고 둔다.

값이 있는 것은 그 뒤에 나온 세 가지다.

- **비용 논거는 성립하지 않는다.** 재 보니 건당 A \$0.01278 · B \$0.01275 로 B 가
  **더 싸다** — 입력 +1,232 토큰을 B 의 짧은 출력(-281)이 갚는다. 「2.5k자를 더 보낼
  값」이라는 저울은 한쪽이 비어 있었다
- **진짜 발견은 A vs C 다.** A 는 overlaps 없이도 hard gate 를 다 통과했고, hard 실패
  2건은 전부 C(자료는 있고 예산 절만 없음)다. **B 의 예산 절은 B 자신이 만든 위험을
  되사는 세금**이다. 그리고 오조인을 막은 것은 `target` 정합표가 아니라 **적게 쓰게 한
  예산**이다 — 적게 쓰는 것은 A 가 공짜로 한다
- **다시 잰다면** 이긴 명식만 반복하지 마라(결과로 표본을 고르는 것이다). 게이트 수리
  → 팔 분리(B 는 규칙 다섯 묶음이다) → 같은 5명식 × 3~5회, 채점은 전체 선호가 아니라
  `manifest.asks` 하나. 75콜이 \$1 밑이라 n=1 로 판정한 것이 이번의 실수였다

## 같은 날 main 에 배포한 것 셋

전부 프롬프트/화면이라 **새로 생성해야** 보인다 — 저장된 풀이는 안 바뀐다(ADR 0013).

- `35f8953` **자기 풀이 9번 절** — 닫힌 메뉴 7개에서 고르게 하니 서로 다른 5명식 ×
  3팔 15건에서 **1번 질문이 14건 같았다**(이직/독립·공부자격). 메뉴만 여는 것으로는
  안 된다 — 「답이 가장 뚜렷한」이 명식이 아니라 **자료 분포**를 고르기 때문이다
  (직업·재성은 어느 명식에나 두껍다). 대운 전환·십성 편중·충형 걸린 궁·무근으로
  바꿨다. **나이(`now.age`)는 주제가 아니라 장면에만** — 나이로 주제를 고르면
  「서른넷이니 결혼」이 되어 명식이 아니라 인구 통계를 읽는다. 성별은 프롬프트에 안
  실린다(대운 방향에만 쓰인다)
- `ad7823b` **궁합 3번 절이 관계를 탄다** — ADR 0018 이 관계 블록을 세웠지만 절 목록은
  관계를 몰라서 「연애로 읽지 마라」 다음 줄에서 「처음에 끌리는 지점」을 시키고 있었다.
  **규칙과 낼 것이 부딪히면 낼 것이 이긴다**(절 제목은 채울 빈칸, 규칙은 추상). 가족·
  친구·모름은 물음 자체를 갈았고 연인·match 만 그대로다
- `4c0b9e4` **궁합 결과 화면에서 사이를 고친다** — `ReadingPanel` 의 `ask` 슬롯. 그리고
  **고르는 칸이 답을 지우고 있었다**: 늘 `null` 로 시작 → `set_pair_relation(null)` →
  행 delete. 화면은 저장값을 읽어 세우고(`pairRelationFor`), 쓰기는 `undefined` 를 안
  적는다 — 「모른다를 골랐다」와 「이 누름에서 안 정했다」는 다른 일이다. 못 읽은 것도
  「모른다」로 안 세운다(`{ ok }` 를 낸다)
