# 개인정보 처리방침 v7 — 공개 출시판 완성본 (변호사 검토 전)

**화면의 처리방침은 여전히 `notice-v6` 이다.** 이 문서는 공개 출시에 올릴 v7 의 **완성본**이고, 운영 화면을 바꾸지 않는다.
화면 원문은 `src/lib/consent/notice.ts` 의 `noticeFor` 와 `app/privacy/page.tsx` 에 살고, 확인 기록은 `app_user.notice_version`
에 판본 이름으로 남는다(ADR 0024 · 0095). v7 을 화면에 올리는 일 — `NOTICE_VERSION` · `NOTICE_ACK_FLOOR` 를 `notice-v7` 로 올리고
확인한 사람 전원이 한 번 다시 읽는 내용 개정 — 은 **변호사 검토 · 한글 문구 승인 · 아래 빈칸이 다 찬 뒤**의 일이고 G-25 가 든다.
v6.1 은 내지 않는다(운영자 결정 2026-09-24).

2026-09-24 에 에이전트가 썼다(처음 초안을 같은 날 다시 썼다). 이 문서가 드는 모든 사실은 **설정 · CLI · 코드 · 마이그레이션 ·
공식 문서로 확인한 값**이고, 어디서 확인했는지는 끝의 「부록 A — 구현 대조」가 든다. 변호사 검토 묶음의 입구는
`docs/legal/README.md` 다.

## 표지 — 넷뿐이다

| 표지 | 뜻 | 누가 채우나 |
| --- | --- | --- |
| `[사업자등록 후 기입: …]` | 사업자등록 · 통신판매업 신고 뒤에만 알 수 있는 값 | 운영자 |
| `[계약 후 기입: …]` | 본인확인기관 · 연동 대행사(PortOne) · PG 와 계약한 뒤에만 알 수 있는 값 | 운영자 |
| `[변호사 검토 필요: …]` | 법률 판단이 필요한 문장. 괄호 안이 정확한 질문이다 — 번호는 `docs/legal/counsel-request.md` | 변호사 → 운영자 |
| `[출시 전 운영자·변호사 확인]` | 법 판단과 운영 결정이 함께 드는 자리. 문장은 지금 구현대로 적었다 | 운영자(필요하면 변호사) |

**조사해서 알 수 있는 값은 빈칸으로 두지 않았다.** 빈칸 전부의 목록은 「부록 D」다.

## v7 본문

화면에 서는 문장이다. **승인된 문구가 아니다** — 화면에 넣기 전에 운영자에게 표로 보인다(`docs/agents/code-rules.md` 「화면
문구」). 말투는 v6(합쇼체 · 「받습니다」 · 「파기합니다」)을 따랐다. 절 뒤의 `(v6 그대로)` · `(새로)` · `(고침)` 은 화면에 서지
않는 표시다.

### 머리

`[사업자등록 후 기입: 상호]`(이하 「회사」)는 만세력 서비스를 제공하면서 이용자의 개인정보를 아래와 같이 처리합니다. (고침 —
v6 의 「초대받은 분만 쓰는 비공개 베타」를 걷는다)

### 1. 무엇을 받고 무엇에 쓰나요 (고침)

**서비스를 쓰는 데 꼭 필요한 것**(이용계약의 이행, 개인정보 보호법 제15조①4)

| 무엇을 | 언제 | 무엇에 |
| --- | --- | --- |
| 구글 계정 이메일 | 로그인할 때 | 계정을 만들고 알아봅니다. 다른 이용자에게 보이지 않습니다 |
| 닉네임 · 소개 · 프로필 사진(올리셨을 때) | 가입 · 프로필을 고칠 때 | 인연 찾기와 채팅에서 나를 보여 줍니다 |
| 내 생년월일과 태어난 시각, 태어난 지역, 사주 계산에 쓰는 성별 | 내 사주를 저장할 때 | 명식과 궁합을 계산하고 결과를 저장합니다 |
| 직접 저장하신 가족 · 지인의 같은 정보와, 그분을 부르는 이름 · 나와의 사이 | 사람을 저장할 때 | 그분의 명식과 궁합을 계산하고, 궁합풀이에서 두 사람을 부릅니다 |
| 만든 사주풀이 · 궁합풀이의 글과 점수, 풀이권을 쓴 기록 | 풀이를 만들 때 | 풀이를 다시 보여 주고, 남은 풀이권을 셉니다 |
| 인연 찾기의 참여 · 궁합 요청 · 수락 · 거절 · 차단 | 그 기능을 쓸 때 | 인연 찾기와 함께 보는 궁합을 운영합니다 |
| 채팅 메시지 | 보낼 때 | 대화를 전달하고 보관합니다 |
| 신고의 사유와 적으신 설명, 신고할 때 고르신 메시지와 앞뒤 다섯 건의 사본 | 신고할 때 | 신고를 검토하고 이용 정지 등 조치를 합니다 |
| 로그인 상태의 마지막 활동 시각 | 로그인해 쓰는 동안 1분에 한 번 | 활동 상태를 표시합니다. 다른 이용자에게는 정확한 시각이 아닌 ‘지금 활동 중’, ‘최근 24시간 내 활동’, ‘24시간 이전 활동’ 구간으로만 표시됩니다 |
| 본인확인 결과 중 만 19세 이상인지와 확인한 시각, 연계정보(CI)로 만든 식별값 | 가입할 때 | 가입 자격을 확인하고, 한 사람이 계정을 하나만 두게 합니다 — 2절 |
| 풀이권 주문 · 결제 · 환불 기록 | 풀이권을 사실 때 | 결제를 확인하고 풀이권을 드리며, 청약철회 · 환불과 법령이 정한 거래기록 보존에 씁니다 — 3절 |
| 문의 · 환불 요청 · 불만의 내용과 처리 기록 | 문의하실 때 | 답하고 분쟁을 처리합니다 |

- 이 정보가 없으면 사주를 계산하거나 서비스를 제공할 수 없습니다.
- **주민등록번호와 카드번호는 받지 않습니다.**
- 사주풀이 · 궁합풀이의 글은 생성형 인공지능이 씁니다(4절).

**선택하신 경우에만**(동의, 제15조①1) — 아래 「선택 항목」.

**무료 풀이권 기록**(새로) — 무료 풀이권은 한 사람에게 평생 한 번 드립니다. 그래서 탈퇴하신 뒤에도 연계정보(CI)로 만든
식별값과 무료 풀이권을 받은 사실 · 처음 받은 시각을 따로 남깁니다. 이름 · 전화번호 · 생년월일 · 성별 · 계정 번호는 이 기록에
들지 않습니다. `[변호사 검토 필요: G-25 ⑧ · B-1 — 이 기록을 탈퇴 뒤에도 두는 근거가 제15조①6(정당한 이익)인가, 약관의 무료
조건에 따른 ①4 인가]`

### 2. 본인확인 — 받는 것과 남기는 것 (새로)

가입할 때 휴대폰 본인확인을 합니다. `[계약 후 기입: 본인확인기관 이름]`이 확인한 결과를 `[계약 후 기입: 연동 대행사 이름 —
후보 PortOne]`를 거쳐, 회사 서버가 그 기관에서 다시 받아 확인합니다. 화면이 보낸 값은 믿지 않습니다.

| 본인확인기관에서 받는 것 | 남기는가 | 무엇에 |
| --- | --- | --- |
| 생년월일 | **남기지 않습니다** — 만 19세 이상인지 판정하고 버립니다 | 나이 확인 |
| 만 19세 이상인지(판정 결과)와 확인한 시각 | **남깁니다** — 계정과 함께 파기 | 가입 자격을 확인한 기록 |
| 연계정보(CI) | **원문은 남기지 않습니다.** 회사만 가진 비밀키로 바꾼 값(HMAC)만 남깁니다 | 한 사람 한 계정 · 무료 풀이권 한 번 |
| 이름 · 휴대폰 번호 · 통신사 · 성별 · 내외국인 구분 · 중복가입확인정보(DI) | **남기지 않습니다** | — |

- 사주 계산에는 본인확인의 생년월일이 아니라 직접 입력하신 출생 정보를 씁니다.
- **CI 로 만든 식별값도 개인정보로 다룹니다.** 같은 사람인지 대조할 수 있기 때문입니다. 서비스 화면과 앱 서버는 이 값을 읽지
  못하고, 비밀키는 서버의 비밀 저장소에만 둡니다. 비밀키가 새면 곧바로 바꿉니다. `[출시 전 운영자·변호사 확인]` — 비밀키를
  바꾸면 옛 키로 만든 값과 대조가 끊긴다(CI 원문이 없어 새 키로 옮길 수 없다, ADR 0101). 교체 뒤 옛 식별값을 어떻게 처분하는지는
  G-20 구현 PR 이 G-25 ⑧ 과 함께 정한다
- 본인확인기관이 실제로 넘기는 항목은 계약서로 확인해 표를 고칩니다. `[계약 후 기입: 본인확인기관이 넘기는 항목 — 위 표의
  첫 칸]`
- `[변호사 검토 필요: B-1 — CI 와 그 HMAC 값이 개인정보 보호법 제24조 · 시행령 제19조의 고유식별정보인가. 그렇다면 별도
  동의(제24조①1) · 암호화(③) · 운영자 접속기록 2년(안전성 확보조치 기준 제8조①2)이 따르는가]`
- `[변호사 검토 필요: B-7 — 본인확인 결과를 두고 다툼이 생겼을 때(명의 도용 주장 등) 회사가 증빙으로 가져야 할 최소 거래
  식별자는 무엇인가. 지금 안은 「확인 시각 + 본인확인기관의 거래 번호」이고, 거래 번호를 남길지 정하지 않았다]`

### 3. 풀이권을 사실 때 — 결제 기록 (새로)

- **받는 것:** 회사의 주문 번호, 결제 대행사에 건넨 가맹점 주문 번호와 결제 대행사의 거래 번호, 산 묶음(1 · 3 · 5 · 20회)과
  금액, 주문 · 결제 · 취소 · 환불 시각, 환불한 금액 · 회차 · 사유의 종류(청약철회 · 안 쓴 몫 · 중복결제 · 제공 장애 · 그 밖) ·
  결제 대행사의 환불 번호, 결제 대행사가 보낸 결제 알림(알림 번호 · 종류 · 금액 · 받은 시각 · 반영했는지 거절했는지), 그리고 **어느 풀이 · 인연 요청이
  무료 · 예외 · 어느 묶음의 풀이권을 썼는지**.
- **받지 않는 것:** 카드번호 · 유효기간 · 카드 비밀번호 같은 결제수단 정보는 받지 않습니다. `[계약 후 기입: 결제 대행사 이름 —
  후보 NHN KCP]`가 직접 처리하고, 거래 주체의 확인은 그 거래 번호로 결제 대행사에 되짚습니다. **결제 기록에는 로그인
  이메일을 넣지 않습니다.** 카드사 · 승인번호는 회사가 따로 적지 않고 결제 대행사의 거래 번호로 조회합니다.
- 쓰는 곳: 결제를 확인하고 풀이권을 얹고, 청약철회 · 환불을 처리하고, 전자상거래법이 정한 거래기록을 보존합니다.
- 풀이권은 무료 → 예외 → 먼저 산 묶음의 차례로 썼다고 봅니다. 이 차례는 남은 수에는 영향이 없고 환불 금액을 정할 때만 씁니다.

### 4. 풀이를 만들 때 밖으로 나가는 것 (고침)

사주풀이 · 궁합풀이의 글과 점수는 외부 인공지능 서비스(OpenAI, 미국)가 씁니다. 사주풀이 받기 · 궁합풀이 받기를 누르셨을 때,
그리고 인연 궁합 요청이 수락되어 궁합풀이가 자동으로 만들어질 때 보냅니다.

| 보내는 것 | 보내지 않는 것 |
| --- | --- |
| 계산된 여덟 글자와 그 위에서 나온 사실(오행 · 관계 · 기준 시각에 도는 운 등) | 생년월일 · 태어난 시각 · 분 단위 시각 · 태어난 지역 · 성별 |
| **궁합풀이에서 두 사람을 부르는 이름** — 저장하신 사람의 이름(예: 「엄마」), 인연 궁합이면 두 분의 닉네임 | 이메일 · 프로필 사진 · 소개 · 채팅 메시지 |
| **궁합풀이에서 고르신 두 사람의 사이**(가족 · 친구 등) | 신고 · 결제 · 본인확인 정보 |
| 회사가 결과를 되찾는 데 쓰는 요청 번호(무작위 번호, 이용자를 가리키지 않음) | |

- 정확한 출생 정보는 규칙으로 막는 것이 아니라 보내는 자료에서 빼고 보냅니다.

### 8. 안전하게 관리하는 방법 (새로)

- **접근을 운영자로 한정합니다.** 이용자 자료는 운영자 화면으로만 열람하고, 화면은 이메일 · 출생 정보를 보여 주지 않습니다.
  운영자가 개인정보를 데이터베이스에서 직접 조회하는 것은 장애 · 수사기관의 적법한 요청 때로 한정하고 그 목적과 대상을 따로
  기록합니다.
- **운영자 계정에 2단계 인증을 씁니다.** `[출시 전 운영자·변호사 확인]` — G-23 ⑨. 운영자 계정 다섯(Supabase · Vercel ·
  GitHub · PortOne · AWS)의 2단계 인증 확인 날짜가 runbook 에 서야 이 줄이 참이다
- **운영자가 개인정보를 처리한 기록(접속기록)을 1년 이상 보관하고 매월 점검합니다.** 기록에는 운영자 계정의 내부 번호, 일시,
  한 일(신고 목록 · 신고 상세 · 대화 사본 열람 · 환불 셈 조회 · 데이터베이스 질의), 대상 신고 번호나 주문 번호, 목록을 거른
  조건, 성공 · 거절이 남습니다. 데이터베이스 질의는 질의 원문 대신 목적과 질의의 요약값(SHA-256)을 남깁니다. **기록은 지우거나
  고칠 수 없게 두고, 매일 한 번 Amazon Web Services 의 서울 저장소에 고칠 수 없는 사본을 400일 보관합니다.** 사본에는 이용자의
  이름 · 이메일 · 메시지 본문이 들지 않습니다.
  - 이용자가 5만 명을 넘거나 고유식별정보 · 민감정보를 처리하게 되면 **2년 이상**으로 올립니다(같은 조 ①1 · 2).
    `[변호사 검토 필요: B-2 — CI 가 고유식별정보라면(B-1) 공개 출시 첫날부터 2년인가]`
  - `[출시 전 운영자·변호사 확인]` — 데이터베이스 안의 원본은 지금 지우는 길이 없다(추가만 되는 표). 사본은 400일 뒤 풀린다.
    원본의 파기 시점(예: 2년 뒤)을 출시 전에 정한다
- **비밀키는 서버에만 둡니다.** 결제 · 본인확인 · 무료 풀이권 식별값의 비밀키와 데이터베이스 열쇠는 서버 환경변수와 비밀
  저장소에만 두고, 브라우저로 가는 파일에 들지 않는지 배포 때마다 검사합니다. 새면 먼저 바꿉니다.
- **전송 구간을 암호화(HTTPS)합니다.** 브라우저가 다른 사이트의 스크립트와 화면 끼워 넣기를 막도록 보안 정책(CSP)을 씁니다.
- **필요 없는 정보를 받지 않습니다.** 출생 정보는 풀이 생성에 보내지 않고(4절), 본인확인 정보는 판정 뒤 버리며(2절), 결제
  기록에는 이메일을 넣지 않습니다(3절).

### 9. 신고 기록은 따로 둡니다 (고침 — 한 줄)

- 신고가 접수된 뒤 신고하신 분이나 신고된 분이 탈퇴하셔도, 그 신고 기록은 탈퇴 처리일부터 6개월 동안 다른 정보와 분리해
  보관합니다.
- 보관 목적은 신고 처리와 재발 대응, 그리고 수사기관의 적법한 요청에 대한 협조입니다.
- 보관 항목은 신고 사유와 적으신 내용, 신고 시각과 처리 상태, 신고 당시 대화 일부의 사본, 두 계정의 내부 식별번호와 로그인
  이메일, 가입일과 탈퇴일, **검토 결과와 조치**입니다. (고침 — 검토 결과 · 판단 근거 · 제재를 받은 쪽이 함께 옮겨진다,
  ADR 0105)
- 권한 있는 운영자만 열람하며, 신고하신 분께도 상대의 신원과 검토 결과를 알려 드리지 않습니다.
- 수사기관이 법령이 정한 절차에 따라 요청할 때만 보관한 범위 안에서 제공합니다. **신고 기록에는 실명 · 주민등록번호 ·
  전화번호가 들지 않습니다.** (고침 — v6 의 「받지 않습니다」는 본인확인으로 이름 · 번호를 **받게** 되므로 참이 아니다. 2절대로
  남기지 않으므로 이 문장은 참이다)
- 6개월이 지나면 자동으로 파기합니다. 그 안에 수사기관의 적법한 보존 요청이 있으면 그 사유가 끝날 때까지 파기를 미룹니다.

### 11. 파기 절차와 방법 (고침)

- 보유기간이 지나거나 처리 목적이 끝나면 지체 없이 파기합니다. 기간은 7절입니다. (고침 — v6 의 「이 베타에서는 ○○이 그
  기한입니다」를 걷는다)
- 전자적 파일은 데이터베이스에서 삭제하며, 복구할 수 없습니다. 종이로 출력한 기록은 만들지 않습니다. (v6 그대로)
- 앱에서 탈퇴를 신청한 때부터 3일 이내에 같은 방법으로 자동으로 지웁니다. (v6 그대로)
- 함께 보기로 한 궁합이 있다면 그 관계와 결과는 상대 화면에서도 함께 사라집니다. (v6 그대로)
- 대화방에서 보내신 메시지는 삭제를 요청하셔도 상대의 대화방에 남고, 그 대화방이 닫힌 날부터 90일이 지나면 매달 한 번의 정기
  삭제 때 지웁니다. (고침 — 7절과 같다)
- 법령에 따라 보존하는 결제 · 분쟁 기록과 따로 두는 신고 기록은 다른 정보와 분리해 두고, 기간이 지나면 같은 방법으로
  파기합니다. (새로 — 제21조①단서 · ③ · 제30조①3의2)

### 12. 인연 찾기에서 상대에게 보이는 것 (v6 그대로)

### 선택 항목 (v6 그대로, 이름 하나 확인)

- 풀이 개선에 답변 활용 — 설문 답변과 생성 기록을 서비스 개선에 활용합니다. 동의를 끄면 지금까지 남긴 설문 답변을 삭제합니다.
- 다음 테스트 소식 받기 — `[출시 전 운영자·변호사 확인]` 운영 베타의 항목이다. 공개 출시에서 「새 기능 소식 받기」 같은
  이름으로 바꾸면 광고성 정보 수신 동의(정보통신망법 제50조)가 되는지 함께 본다. 끄거나 수집 후 1년이 지나면 이메일을 더 쓰지
  않는다는 줄은 그대로다.
- 원할 때만 선택해 주세요. 서비스 이용에는 영향이 없습니다. (v6 그대로)
