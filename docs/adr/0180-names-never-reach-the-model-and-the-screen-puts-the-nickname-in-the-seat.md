# 이름 · 닉네임은 모델로 안 나가고, 화면이 자리 호칭을 지금의 닉네임으로 바꾼다

> **운영자 결정 2026-10-15**(조율자가 옮김) — 「궁합풀이에 사람 이름 · 닉네임을 OpenAI 로 보내지 않는다」. 정정: 「이름은 갈래를
> 나누지 않는다 — 가족을 「어머니」로 등록해도 그것이 그 사람의 닉네임이다. 프롬프트에는 어떤 갈래든 닉네임을 싣지 않고 자리 호칭
> 둘로 통일하고, 결과를 보여 주는 중간 층에서 그 자리의 닉네임으로 바꿔 넣는다. 호칭은 「첫번째님」 · 「두번째님」」. 추가: 「모든
> OpenAI 호출 경로에서 참이어야 한다」.

ADR 0058 의 「공유 풀이가 사람을 부를 때는 두 계정의 공개 닉네임을 쓴다」를 걷는다. 그 ADR 의 나머지(같은 처리 방식 · 다른 허용 근거)는 그대로다.

## 정한 것

- **프롬프트는 두 사람을 늘 `SEAT_NAMES`(「첫번째님」 · 「두번째님」, `src/lib/reading/display.ts`)로 부른다** — 내 궁합 · 인연 궁합,
  누름 · 수락 뒤 자동 생성 모두. `ReadingAbout` 에서 `names` 를 걷어 파이프라인이 넘길 자리가 타입에 없다. 사이(relation)는 그대로 간다.
- **DB 는 그대로다.** 시도를 열 때 `reading_about` 이 이름을 여전히 얼리지만(우리 DB 안이다) 파이프라인은 읽지 않는다
  (`app/me/reading/pipeline.ts` 의 `FrozenJob`). 마이그레이션은 없다.
- **화면이 바꾼다 — `withNicknames`.** 본문 · 한 줄 요약, 모델 글이 서는 자리에서 호칭을 지금의 닉네임으로 바꾸고 `calledName` 으로
  님을 붙인다(받침 없는 이름이면 조사를 옮긴다). 옛 호칭 「첫 번째 분」 · 「두 번째 분」도 받는다 — 2026-10-15 전 글도 같은 자리로 선다.
  이름이 박힌 옛 글은 바꿀 호칭이 없어 그대로다. 이름표를 고치면 이미 받은 글도 새 이름으로 선다.
  - 내 궁합 — 두 사람의 이름표(`local_label`, 나도 내 이름표). `charts.a` 는 Person id 가 작은 쪽이다(`pairSeatsOf`, DB 의 `least`).
  - 인연 궁합 — 내 닉네임과 상대 닉네임, 누가 첫 자리인지는 글이 든다(`viewer_is_first`). 앞서 나를 「나」로 바꾸던 것이 내 닉네임이 된다.
  - 공유본(내 궁합) — 공유할 때 얼린 두 이름표(`reading_share.name_a` · `name_b`).
  - 풀이 목록 · 홈 지도의 한 줄 요약(내 궁합) — `my_readings` 의 두 이름표.
- 프롬프트 판은 궁합 둘이 `reading-prompt-v18` 로 오른다. 개인 풀이 지시는 그대로다(v15).

## 남는 것

- **풀이 목록의 인연 궁합 한 줄 요약은 못 바꾼다.** `my_readings` 가 상대 닉네임 한 칸만 주고 내가 어느 자리인지를 안 준다. 결과
  화면은 바꾼다. 목록까지 바꾸려면 `my_readings` 에 `viewer_is_first` · 내 닉네임을 더하는 마이그레이션이 든다(간극 대장).

## 고르지 않은 것

- **이름을 보내고 화면에서 걷기** — 보내는 순간이 문제다. 지우는 쪽은 경로마다 다시 짓게 된다.
- **새 호칭 대신 「첫 번째 분」 유지** — 운영자가 「첫번째님」을 골랐다. 님이 붙어 있어 바꾸지 못한 자리도 사람을 부르는 말로 읽힌다.
