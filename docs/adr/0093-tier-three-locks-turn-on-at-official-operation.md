# 등급 3 의 잠금은 공식 운영에 들어간 뒤에 켠다

ADR 0090 은 권한 등급 3(사람이 답한 뒤에)의 명령 스물하나를 `.claude/settings.json` 의 `ask` 에
옮겼다 — `db push` · `db query --linked` · 실호출 환경변수 · Vercel 변수와 배포 · `gh pr merge` ·
원격 가지 삭제. 2026-09-23 에 사람이 그 잠금을 **공식 운영에 들어간 뒤로** 미뤘다.

## 재어 본 것

- **`ask` 는 어느 모드에서도 묻는다.** delegation.md 는 「`ask` 는 묻는 모드에서만 묻는다」고 적었는데
  공식 문서는 「Tools matched by an explicit ask rule」을 어느 모드도 자동 승인하지 않는 목록의 첫째로
  든다. bypass 모드로 도는 세션에서 서브에이전트가 `db push` 와 `gh pr merge` 마다 물은 까닭이
  그것이다. `allow` 는 bypass 에서 효력이 없고 `ask` 가 `allow` 를 이기며, `cd x && …` 안에 묻혀
  있어도 잡는다. 문서의 그 문장은 틀렸었고 고쳤다.
- **지금은 운영 베타다.** 실제 사용자가 없고(PRD §7.0 의 공개 출시 전), 운영 DB 와 배포를 되돌려도
  다치는 사람이 없다. 등급 3 이 지키려던 것은 「되돌릴 수 없는 피해」인데 그 피해가 아직 없다.
- **등급 4(`deny`)는 다르다.** main 에 force push · `supabase config push` · Vercel 변수 삭제는 운영
  베타에서도 되돌릴 수 없다(원격의 구글 설정이 지워진다). 그대로 둔다.

## 정한 것

- **`ask` 를 비운다.** 등급 3 의 잠금 칸은 「없음 — 공식 운영 전」이다. 에이전트는 `db push` · 실호출 ·
  `gh pr merge` · 운영 SQL 을 묻지 않고 밟되, **밟고 나서 본 값을 적는다** — 그 규약은 그대로다.
- **켤 목록은 delegation.md 가 든다.** 「공식 운영에 들어가면 켜는 잠금」 절에 스물하나를 그대로
  옮겼다. 그날 `ask` 에 되돌리고 등급 3 의 잠금 칸에 옮겨 적는다 — 간극 대장 G-50.
- **시험은 셋을 잰다.** 등급 3 의 잠금 칸과 `ask` 가 같은 목록인 것(지금은 둘 다 빔), 켤 목록이 열을
  넘고 `deny` 와 안 겹치는 것, `ask` 에 든 것은 전부 켤 목록에서 온 것.
- **마이그레이션의 순서는 안 바뀐다.** 「마이그레이션이 먼저, 앱이 나중」은 사람이 아니라 에이전트가
  밟을 뿐이다. runbook 「배포」 규약 넷은 그대로다.

## 언제 되돌리나

공식 운영 — PRD §7.0 의 공개 출시 — 에 들어가는 날. 그 전이라도 실제 사용자의 자료가 운영 DB 에
들어오면 그때가 그날이다.

## 한 번 켰다가 다시 껐다 (2026-09-23)

같은 날 에이전트가 「G-50 을 진행하라」를 「지금 켜라」로 읽어 `ask` 를 되돌렸다(#134). 사람의 뜻은 공개 출시
전까지 묻지 않는 것이었고, 이 ADR 대로 다시 비웠다. 켜 있던 동안 잰 것 둘은 delegation.md 「잠그지 않은
것」에 옮겼다 — 사용자의 `settings.local.json` 에 쌓인 넓은 `allow` 가 `ask` 를 이겼고(「재어 본 것」의
「`ask` 가 `allow` 를 이긴다」는 이 저장소에서 참이 아니었다), `deny` 는 앞에 `cd` 가 붙은 force push 를
막지 않았다. 그날 켤 때는 넓은 `allow` 를 함께 걷고 창이 뜨는지 재 본다(G-50).
