# 한 사람의 명식과 풀이는 각각 주소를 가진다

궁합 결과 화면에는 읽을 글이 먼저 서고, 계산 근거는 「두 원국을 맞대어 본 표」 안에 접혀
있다. 한 사람 화면은 반대였다. `/me`와 `/me/people/[id]` 아래에 명식 전체와 긴 풀이를 함께
쌓아서, 사람 목록에서 「사주풀이 보기」를 눌러도 명식을 지나 맨 아래로 내려간 뒤 다시
「자세히 보기」를 눌러야 했다.

## 명식 보기와 사주풀이는 탭이지만 주소도 둘이다

한 사람을 보는 화면에는 `명식 보기`와 `사주풀이`가 나란히 선다.

- 내 명식: `/me`
- 저장한 사람의 명식: `/me/people/[personId]`
- 내 풀이: `/me/readings/self`
- 저장한 사람의 풀이: `/me/readings/[personId]`

탭은 한 화면 안에서 숨기고 보이는 클라이언트 상태가 아니라 링크다. 사람 목록과 만든 풀이
목록이 결과로 곧장 들어갈 수 있고, 새로고침과 뒤로가기가 지금 보고 있는 자리를 잃지 않는다.
`self`의 실제 Person id로 들어온 옛 주소는 `/me/readings/self` 한 자리로 모은다. 같은 명식에
`self`와 `person` 풀이가 둘 서지 않게 하던 DB 규칙은 그대로다.

## 풀이 화면에는 풀이만 선다

`/me/readings/[subject]`는 카드 안에 긴 글을 다시 접지 않는다. 풀이 본문과 설문이 바로 서고,
명식 전체를 다시 싣지 않는다. 이미 나란히 선 `명식 보기` 탭이 별도 명식 화면으로 가므로,
접힌 명식은 같은 내용을 향하는 세 번째 길이었다. 사람 목록 카드에서도 별도 `사주 상세 보기`
버튼을 걷고 풀이 화면의 두 탭을 단일 전환점으로 삼는다.

## 풀이권 경고는 처음과 다시 만들기 모두에 선다

ADR 0028은 현재 풀이가 사라지는 재생성에만 확인 창을 두었다. 그러나 풀이권은 처음 만들 때도
같이 줄어드는 한정 자원이다. 따라서 모든 수동 생성은 먼저 네이티브 `<dialog>`를 연다.

- 처음 만들기: 풀이권 1회 사용과 실패 시 복구를 말한다
- 다시 만들기: 위 사실에 더해 현재 풀이와 점수가 교체됨을 말한다
- 인연 요청: 풀이권 1회가 예약되고 거절·거둠·무효·만료 때 풀림을 말한다

취소는 시도나 요청을 만들지 않는다. 확인 뒤의 서버 규칙과 원자적 교체는 ADR 0013·0038을
그대로 따른다.

## 목록에서 빼기도 확인한다

저장한 사람을 목록에서 빼면 접근 엣지와 그 사람의 풀이가 사용자 화면에서 함께 사라진다.
관리 모드의 중간 문장만으로는 실제 누름 직전에 이 결과가 읽히지 않으므로, 빼기 버튼은
네이티브 `<dialog>`를 열고 이름·사라지는 것·되돌릴 수 없음을 말한다. 취소하면 사람과 풀이를
그대로 둔다.

## 앞선 결정과의 관계

- ADR 0028의 「처음 만들 때는 안 묻는다」와 `/me`에 풀이가 함께 선다는 부분을 이 결정이
  대신한다
- ADR 0033의 결과 주소 중 `self`·`person`은 이 결정의 풀이 전용 주소로 바뀐다. 목록이
  본문을 싣지 않는 규칙은 그대로다

## 재는 자리

- 단위 시험은 네 kind의 결과 주소를 가른다
- e2e는 두 탭의 현재 위치, 풀이 화면에 명식이 반복되지 않음, 풀이 본문의 직접 노출,
  확인 창 취소 후 무변경을 잰다
- 흐름 검사는 화면을 여는 것만으로 시도가 생기지 않고 저장된 결과가 전용 주소에 서는지 잰다
