# 관리자 화면 1차판은 신고와 그 스냅샷을 읽기만 하는 열람대다

G-24(확장된 관리자·제재 화면)는 「신고 근거 스냅샷을 읽는 자리가 화면으로 선다」만 적고 크기를 안 정했다.
채팅 안전 베타까지 신고를 읽는 길은 runbook 의 SQL 이었다 — 운영 DB 의 SQL Editor 에 들어가 `jsonb_array_elements`
로 스냅샷을 펴는 질의를 손으로 쳤고, 그 질의는 문서에만 있어 아무도 재지 않았다. ADR 0061 이 설문에서 푼 것과 같은
문제다. 2026-09-24 에 사람이 1차판의 사양과 문구 표를 승인했다.

## 정한 것

- **1차판은 「신고 증거 열람대」다.** `/ops/reports`(목록, 최신부터 30건씩, 검토 상태 · 사유 · 대화 근거로 거른다)와
  `/ops/reports/[reportId]`(신고 내용과 불변 스냅샷) 둘. 현재 계정에 연결된 신고와 스냅샷만 읽는다.
- **경계는 `/ops/survey` 와 같다**(ADR 0061). 비로그인은 `/auth`, 운영자가 아니면 404, 메뉴에 안 선다, 화면은
  「나는 운영자인가」를 따로 안 묻는다. 판정은 DB 의 운영자 전용 문 셋(`operator_reports` · `operator_report` ·
  `operator_report_snapshot`)이 각자 `is_operator()` 로 한다. 표를 직접 읽는 권한은 안 열고 `service_role` 에도 문을 안 준다.
- **엄밀히 읽기 전용이다.** 데이터를 바꾸는 누름이 없다 — 거르기와 쪽 넘기기도 링크다. 검토 완료(`reviewed_at`)는
  당분간 runbook 의 SQL 한 줄이다.
- **근거는 사본뿐이다**(ADR 0091). 실제 대화방이나 현재 메시지를 다시 읽지 않고, 방으로 가는 링크가 없다 — 문이
  `match_id` · `message_id` · 보낸 사람의 UUID 를 아예 안 내준다. 보낸 쪽은 「신고한 사용자」 · 「신고받은 사용자」로
  부른다. 고른 메시지는 정확히 하나만 강조한다. 두 계정의 **지금** 상태는 상단에만 서고 스냅샷에 섞지 않는다.
- **내리지 않는 것** — 이메일 · 출생정보 · 사주 입력 · 풀이 · 저장한 사람 목록. 두 계정은 닉네임과 내부 UUID 로 가른다.
  UUID 는 반복 신고를 가리는 내부 식별자로만 쓴다. 반환형에 그 칸이 없다는 것을 pgTAP `45_operator_reports` 가 잰다.
- **떠난 사람의 신고(`retention.report`)는 화면에 안 나온다**(ADR 0098 의 경계). 그 스키마의 권한을 열지 않는다 —
  runbook 의 SQL 로만 읽는다.
- **G-24 의 끝 조건을 좁혔다** — 「운영자는 현재 계정에 연결된 신고를 목록에서 찾고, 신고 당시 저장된 불변 대화
  스냅샷에서 사용자가 고른 메시지와 앞뒤 문맥을 화면으로 읽는다. 탈퇴한 사람이 든 분리 보관 신고는 기존 runbook
  SQL로 읽는다.」

## 운영자 화면 문구의 예외

`/ops/**` 에서 **운영자에게만 보이는** 설명 · 제목 · 빈 상태 문구는 사전 표 승인을 생략하고 PR 에 변경 문구를 모아
보고한다. 개인정보의 이용 · 보관, 운영자의 권한, 제재 결과, 사용자에게 전달되는 문구는 이 예외에 들지 않는다.
운영자 화면은 사용자가 읽지 않고, 필터 라벨 · 열 제목처럼 자리가 많은 말을 하나씩 물으면 화면 하나가 문답 몇
바퀴가 된다 — 그 비용이 사용자 문구의 승인과 같은 무게일 까닭이 없다. 예외의 문장은 `docs/agents/delegation.md`
와 `docs/agents/code-rules.md` 에 한 줄씩 있다.

## 일부러 넣지 않은 것

이용 정지 · 해제, 신고 기각 · 승인, 메모, `reviewed_at` 변경, 계정 삭제, 차단 현황, 전체 대화 열람, 사용자 검색,
저장한 사람 개별 목록, 출생정보 · 명식 · 풀이 열람, 보존 보류 설정, 집계 「운영 현황」 화면. 쓰는 누름이 드는
날은 접속기록(G-25 ③, G-23 ⑩)과 함께 본다 — 운영자가 무엇을 바꿨는지 남는 자리가 먼저다.

## 잠그지 않은 것

- 한 쪽의 수(30)는 `operator_reports` 만 안다. 화면은 쪽 수(`pages`)만 받는다 — 두 자리에 적지 않는다.
- 쪽은 `offset` 이다. 신고가 수만 건이 되면 키셋으로 바꾼다 — 그때는 검색이 먼저 필요하다.
