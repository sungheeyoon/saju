# 문구만 바뀐 파일은 core 에 옛 글자를 찾는 시험의 차선만 더하고, 문구 · 문서뿐인 묶음은 main 의 전체 CI 를 기다리지 않고 배포한다

> **운영자 결정 2026-10-09**(대화에서, CI 범위 · 배포 대기). PR #570 은 확인 창의 문구 한 줄(G-86)이었다. 그런데 상수가
> `src/lib/consent/notice.ts` 에 들어가 공용 위험(관문)에 걸렸고, PR 에서 e2e 열 차선과 `flow` 를 다 돌았다. 그 뒤 묶음 배포
> 0번이 main 의 전체 CI 초록을 한 번 더 기다렸다. 운영자가 아래 다섯을 정했고, 「정적 화면 표현」을 빼고 **문구**로 좁히는 데
> 동의했다.

ADR 0097(공개 출시 전 PR 은 빠른 검사, 전체는 머지 뒤 main) · 0119(공용 위험은 전부) · 0153(주석만 바뀐 코드 파일은 정책) ·
0154(문서만 바뀐 main 푸시는 `policy` 만) · 0110(묶음 배포)에 한 갈래씩 더한다. 규칙의 원본은 `scripts/ci-plan.mjs` 머리의
「문구만 바뀐 파일」과 `deployRangeOf`, 배포 절차는 `docs/ops/runbook/deploy.md` 「묶음 배포」의 0 이다.

## 정한 것

1. **화면 전용 문구 상수를 관문 모듈 밖으로 옮긴다.** `REQUEST_OPENS_CHAT_NOTE` 는 `src/lib/matching/copy.ts`,
   `BETA_SIGNUP_CODE_NOTE` 는 `src/lib/account/copy.ts` 로 갔다. 글자는 그대로다. 둘 다 화면만 불렀고 관문 · 가입 폼 · 고지문은
   안 불렀다. 도메인 lib 의 새 파일이고 import 가 없어 층 표(`docs/architecture.md`)의 방향은 늘지 않는다.
   `MATCH_PILLARS_DISCLOSURE` 는 `src/lib/consent` 에 남긴다. 확인 창에도 서지만 처리 안내 본문(`noticeFor`)의 한 줄이기도 해서다.
   그 글자가 바뀌면 안내 판본(`NOTICE_VERSION`)의 일이다. 가입 폼 · 안내가 쓰는 말(`NOTICE_ACK_LABEL` · `SIGNUP_CODE_NOTE` …)도 남는다.
2. **CI 계획기가 「문구만 바뀐 파일」을 diff 의 구문 나무로 가른다.** 파일 위치나 PR 설명으로 가르지 않는다. ADR 0153 과 같은 파서로
   base 와 HEAD 를 읽고, 화면 문구 자리의 잎만 글자를 가린 채(`종류:<문구>`) 나무 · 뜻이 있는 주석이 같아야 한다. 그리고 그 자리의
   글자가 하나 이상 달라야 한다(`copyOnlyChanged`). 판정은 `app/**` · `src/**` 의 시험 아닌 코드 파일에서만 한다.
   - **인정하는 자리는 둘뿐이다.** ① JSX 글자(요소 사이의 글자). `option` · `textarea` · `style` · `script` 안은 뺀다. 그 글자는
      값(`option` 은 `value` 가 없으면 글자를 보낸다)이거나 코드다. ② **용도가 확인된 문구 상수**의 문자열 값이다.
   - **용도 확인은 이름이 든 목록으로 한다.** 계획기의 `COPY_FILES` 가 문구 상수만 모은 파일을 이름으로 든다. 지금은
     `src/lib/*/copy.ts` 셋이다(대화방 `src/lib/chat/copy.ts` 는 2026-10-10 화면 점검 C4 에서 더했다). 그 파일이 모양을 지킬 때만 상수 값이 문구 자리다. 모양은 문마다 `export const 이름 = '글자'` 하나다.
     따옴표나 식 없는 백틱이고, 타입 표기 · import · 함수 · 식은 없다(`copyConstantsShape`). `scripts/ci-plan.test.ts` 가 셋을 잰다.
     `src/lib/*/copy.ts` 와 목록이 짝인가, 모양을 지키는가, 그 이름을 부르는 파일이 화면(`app/**/*.tsx`)과 시험뿐인가다.
     「상수의 문자열 값」이라는 까닭만으로는 인정하지 않는다. 경로 · 설정값 · 키 · 정규식 · 환경 변수 이름이 들 수 있어서다.
   - **인정하지 않는 것(지금 규칙 그대로).** JSX 속성 값 전부(`className` · `href` · `src` · `aria-*` · `role` · `data-*` …)가
     그렇다. 조건식 · 이벤트 핸들러 · 식별자 · 구조 변경(요소 · JSX 주석 `{/* */}` 을 새로 세우는 것 포함)도 그렇다. 템플릿 리터럴은
     식 부분도 글자 조각도 인정하지 않는다. `COPY_FILES` 밖의 문자열도, 모양을 벗어난 `COPY_FILES` 의 문자열도 그렇다.
   - **판별이 불확실하면 기존 검사를 유지한다.** 파서 없음 · base 를 못 읽음(추가 · 삭제 · 이름 바꿈 · 실행 비트) · 파싱 실패 ·
     앱 밖 파일 · 시험 파일이면 문구로 세지 않는다. 문구와 동작이 한 파일에 섞여도 세지 않는다.
   - **차선.** 문구만 바뀐 파일은 `core` 를 기본으로 탄다. 바뀌기 전 글자가 `e2e/**` 나 `scripts/check-*.mjs` 에 나타나면 그 시험의
     차선을 더 켠다(`copyLanesOf`). 「나타난다」는 둘 중 하나다. 옛 글자가 소스에 통째로 있거나, 시험의 따옴표 · 백틱 · 정규식 리터럴
     글자(공백 빼고 넉 자 이상)가 옛 글자의 조각이다. spec 이면 그 spec 의 차선, 흐름 검사면 `flow` 다. spec 이 아닌 `e2e/**`
     (여러 spec 이 부르는 도우미)나 차선을 못 찾는 spec 이면 전부다.
     **이 검색은 검사를 더하는 근거일 뿐이다.** 시험이 글자를 동적으로 조합해 찾으면 여기 안 걸린다. 그 구멍은 머지 뒤 main 의 전체 CI 와 `ci-main-red` 가 잡는다.
   - **공용 위험 자리에 있어도 문구만이면 공용 위험으로 세지 않는다.** 판정이 확실할 때만이다. 까닭은 이렇다. 문구 자리를 가린 나무가
     같으면 import · 조건 · 주소 · 속성 · 액션이 하나도 안 바뀌었다. 그래서 관문이 누구를 들이는가, 어느 주소가 열리는가, 레이아웃이
     무엇을 감싸는가는 base 와 같다. 바뀐 것은 화면에 서는 글자뿐이고, 그 글자를 찾는 시험은 위 검색이 켠다. 관문의 판단이 쓰는 문자열은
     `COPY_FILES` 에 들 수 없다. 화면만 부른다는 잠금 때문이다.
   - **운영 베타의 PR 에서만 좁힌다.** 공개 출시면 지금처럼 화면 하나도 전부다. main 푸시 · 일정 · 손으로 켠 실행은 문구만이어도
     전부다 — 머지 뒤의 전체 검증은 그대로다.
3. **묶음 배포의 대기 예외.** 마지막으로 전부를 잰 main 의 초록(`main-red.mjs` 의 `lastFullGreen`)부터 올릴 SHA 까지를 본다. 그 범위의
   변경이 전부 문구 · 문서(정책 파일 · 주석만 바뀐 코드 파일 포함)뿐이어야 한다. 그리고 범위의 커밋마다 그 PR 의 `gate` 가 초록이어야
   한다. 그때만 main 의 전체 CI 완료를 배포의 대기 조건으로 두지 않는다. 동작 변경이 하나라도 섞였으면 지금처럼 기다린다. 배포는
   묶음이라(ADR 0110) 「이 PR 이 문구만」이 아니라 범위 전체를 본다. 판정은 사람이 눈으로 하지 않는다. `node scripts/deploy-range.mjs` 가
   위 2 의 판정 함수를 그대로 써서 `green` · `docs-only` · `copy` · `wait` 를 답한다(`deployRangeOf`). 마지막 초록을 못 찾음 · diff 를
   못 읽음 · 파서 없음 · PR 검사를 못 읽음은 `wait` 다. 문서만 바뀐 범위는 앱을 배포하지 않는다. main 의 CI 는 뒤에서 계속 돌고,
   붉으면 `ci-main-red` 로 대응한다.
4. **에이전트 규칙(운영자 원문).** 「사용자가 확인한 문구 변경은 필요한 PR 검사가 통과하면 재승인 없이 squash-merge 하고 배포한다.
   동작 변경이 없다고 판별된 경우 main 전체 CI 완료는 배포의 대기 조건으로 두지 않는다. 문서만 변경한 경우 앱을 배포하지 않는다.」
   여기서 「문구」는 위 2 의 판정 범위다. 원본 자리는 `docs/agents/test-map/ci.md` 「CI」다. CI 와 배포의 기다림을 함께 말하는 절이라 거기 둔다.

## 다른 결정과의 관계

- **ADR 0097** — 전체 검증은 그대로 머지 뒤 main 에서 돈다. 이 결정은 PR 의 차선과 배포의 기다림만 바꾼다.
- **ADR 0119** — 공용 위험은 전부다. 다만 문구만 바뀐 파일은 공용 위험으로 세지 않는다(위 2). 일부 대체다.
- **ADR 0153** — 같은 파서와 같은 닫힘(판별이 불확실하면 지금 규칙)을 쓴다. 주석만 바뀐 파일은 먼저 정책으로 빠진다. 주석과 문구가
  함께 바뀐 파일은 문구만으로 센다.
- **ADR 0154** — main 푸시는 바뀌지 않는다. 문구가 섞인 main 푸시는 전부를 돌고, 그 초록이 다음 배포 범위의 「마지막 초록」이 된다.
- **ADR 0110** — 「main CI 초록」을 배포 0번의 조건으로 두던 것에 예외 하나를 둔다(위 3). 일부 대체다. 묶음 · 손으로 한 번 · 마이그레이션
  먼저는 그대로다.
- **ADR 0152** — 「올리라고 한 변경은 그 PR 이 main 에 들면 올린다」는 그대로다. 그 배포가 main 의 CI 를 기다리는가를 이 결정이 정한다.

## 얻는 것 — PR CI 는 거의 안 준다, 이득은 배포 대기 (2026-10-10 실측)

**지금 저장소에서는 PR CI 절감 효과가 거의 없다.** 덧 10 의 「좁히기만」 아래에서 검색 계획은 지금 규칙의 부분집합일 때만
채택되는데, 아무 글자(`가나다라마바사`)를 넣어도 시험 35 개 중 18 개가 켜지고 그 안의 도우미 둘(`e2e/birth-form.ts` ·
`e2e/second-factor.ts`)이 「전부」를 불러 좁히기가 채택되지 않는다. 입구가 아닌 컴포넌트의 문구는 이 결정 전에도 `core` 였다.
PR 쪽에서 실제로 바뀐 것은 정한 것 1(문구 상수가 관문 밖으로 나가 #570 같은 변경이 공용 위험에 안 걸린다)뿐이다.
**주된 이득은 문구 · 문서뿐인 묶음이 배포 때 main 의 전체 CI 를 다시 기다리지 않는 것이다**(정한 것 3, `deploy-range`).
도우미를 그것을 부르는 spec 의 차선으로 세는 수정은 하지 않았다 — 두 도우미를 taste · match · chat · saju · signed-in spec 이
함께 불러 켜지는 차선이 거의 그대로라서다(운영자 2026-10-10).

## 남는 구멍과 치르는 값

- **동적으로 조합한 selector.** 시험이 글자를 변수 · 함수 · 다른 상수로 지어 찾으면 옛 글자 검색에 안 걸린다. 넉 자보다 짧은
  조각으로 찾을 때도 그렇다. 그 붉음은 PR 에서 안 보이고, 머지 뒤 main 의 전체가 잡는다. 배포는 그 붉음을 기다리지 않을 수 있다.
  운영 베타에는 실제 사용자가 없다(ADR 0093) — 붉으면 `ci-main-red` 를 먼저 고치고 다시 묶어 올린다.
- **옛 글자 검색은 넓게 건다.** 넉 자 조각도 다른 문장의 일부일 수 있다. 그때는 차선이 더 설 뿐이다(안전 쪽). 2026-10-09 에
  「지금은 비공개 베타라 … 테스트 코드가 필요해요 …」를 넣었다. 흐름 검사 `check-share` 와 함께 가입 폼의 「테스트 코드」를 적은
  spec 셋이 걸렸다.
- **#570 그대로의 diff 는 문구만이 아니다.** 새 상수와 새 `<p>` 를 더했기 때문이다. 이 결정 뒤에는 상수가 관문 밖에 살아, 같은 PR 이
  `core` 를 탄다(공용 위험 아님). 입구가 아닌 컴포넌트라 문구 판정 전에도 `core` 였다 — 아래 「얻는 것」.
- **`COPY_FILES` 에 화면 글자가 아닌 값을 넣으면** 그 값이 바뀌어도 동작 검사가 안 선다. 아래 덧의 쓰임 자리 잠금이 화면 안의
  쓰임까지 보지만, 글자 자리에 선 값이 화면 밖에서 뜻을 가지는 것(그 글자로 다른 화면이 무엇을 찾는 것)은 못 막는다.
- **조각 검색은 고친 뒤에도 근사다.** 분석하지 않는 정규식은 기호 사이의 글자 조각으로 관련을 본다. 조각이 길고 바뀐 글자와 안
  겹치면 켜지 않는데, 그 정규식이 다른 갈래로 바뀐 글자를 잡으면 PR 에서 안 보인다. 새 글자도 찾지만 시험이 글자를 변수로 지어
  찾거나(정규식이 아닌 문자열 조합) 화면의 다른 글자와 이어 붙여 찾으면 안 걸린다. 그 붉음은 배포 뒤 main 의 전체가 잡는다.
- **검색은 넓게 켜고, 계획은 좁히기만 한다.** 글자 없는 정규식을 정리 자리 밖에서 모두 켜므로 2026-10-09 저장소에서는 검색만
  보면 문구 한 줄이 전부를 부른다 — spec 이 아닌 도우미 `e2e/birth-form.ts`(`.exec`) · `e2e/second-factor.ts`(`.test`)가 그런
  정규식을 들어서다. 그래도 계획은 그 파일의 지금 규칙보다 넓어지지 않으므로(아래 덧 10) 입구가 아닌 컴포넌트의 문구는 `core`
  그대로이고, 넓던 파일(`page` · `layout` · 공용 위험)은 검색이 전부면 지금 규칙 그대로다 — 그만큼 좁히는 효과가 준다.
  `scripts/ci-plan.test.ts` 「실측」이 둘을 잠근다.
- **배포 전 검증은 준다.** `copy` · `docs-only` 로 기다리지 않고 올리면 main 의 전체 CI 는 배포 **뒤에** 끝난다. 위 구멍의 붉음은
  운영에 선 뒤에 보인다 — 붉으면 `ci-main-red` 를 먼저 고치고 다시 올린다.

## 덧 — 근거는 마지막 전체 초록뿐이고, 범위는 커밋마다 가르고, 최신 gate 만 센다 (2026-10-09, 외부 검토 · 조율자)

#572 가 독립 검토 전에 자동 머지됐고, 같은 날 외부 검토가 위 2 · 3 의 구현에서 열린 자리를 들었다. 고친 것과 까닭이다.

1. **`--from` 은 근거가 아니다.** `--from` 이 마지막 초록 자리를 대신해 `--from X --head X` 가 아무 검증 없이 `green` 이었다.
   이제 기다리지 않을 근거는 언제나 GitHub 에서 읽은 마지막 전체 초록(`lastFullGreen`)이고, `green` 은 그것이 HEAD 일 때뿐이다.
   `--from`(운영 SHA)은 「앱이 운영과 달라졌나」만 답한다 — `--from` 을 준 답은 `docs-only`(앱을 안 올린다) 아니면 `wait` 이고,
   그것도 마지막 초록부터 HEAD 까지가 위 3 을 채울 때만 `docs-only` 다. **운영 배포 SHA 와 마지막 전체 CI 성공 SHA 는 다른 것이다.**
2. **제외 요소는 조상 전체로 내려간다.** 바로 위 요소만 보아 `<option><span>allow</span></option>` · `<option><>월</></option>` 의
   글자가 문구로 통과했다. `next/script` 의 `Script` 도 뺀다. 이름 모르는 대문자 컴포넌트(`Button` …)의 글자는 그대로 문구다.
3. **범위는 커밋마다 가른다.** 끝과 끝만 견주면 동작 변경 → 되돌림 → 문구 변경이 문구로 보였다. 운영자가 승인한 조건은 「범위 안
   모든 커밋이 문구 · 문서」라, 커밋마다 그 부모와 견주고 하나라도 동작이면 `wait` 다(머지 커밋은 동작으로 센다).
4. **`gate` 는 최신 실행 하나만 본다.** 끝나지 않은 실행 · 취소 · 건너뜀을 무시해 예전 `success` 하나로 참이었다. 이제 PR head 의
   `gate` 중 가장 최근 것(`started_at`, 같으면 `id`)이 끝났고 성공일 때만 참이다. 실행 없음 · API 실패 · 모르는 모양은 거짓이다.
5. **main 이 붉으면 기다린다.** 범위의 SHA 에 붉게 끝난 verify 실행이 있거나 `ci-main-red` 이슈가 열려 있으면, 또 그것을 못 읽으면
   `wait` 다 — 불확실하면 기다린다(조율자, 운영자에게 보고).
6. **문구 상수는 글자 자리에서만 쓰인다.** 「화면만 부른다」 잠금은 `src/lib/*/copy.ts` 에 경로를 두고 `<a href={PATH}>` 로 써도
   초록이었다. 이제 시험이 쓰임 자리를 잰다 — JSX 자식 `{NAME}` 이나 글자 속성(`aria-label` · `title` · `alt` · `placeholder`)의
   값만 된다(`copyConstantMisuses`). 훑는 범위에 뿌리의 `*.ts` · `*.mjs` 도 넣었다.
7. **새 글자도 찾는다.** 새 글자가 「없어야」 하는 글자(`toHaveCount(0)`)나 `getByRole({ name })` 과 겹칠 수 있어 앞뒤 글자를 다
   찾는다. JSX 엔티티(`&nbsp;` …)는 풀어서 견준다.
8. **정규식은 파서로 찾고, 기호를 지워 견주지 않는다**(운영자 2026-10-09). 시험 파일을 TypeScript 파서로 읽어 정규식 리터럴과
   `new RegExp('…')` 의 문자열 인자를 모은다(`regexUsesIn`) — 「식이 설 자리」를 글자로 짐작하던 것은 주석 속 `/…/` 를 읽고 `=>`
   뒤를 놓쳤다. 그날 훑는 시험 파일의 리터럴은 315 개였다. 파싱이 실패한 시험 파일은 판별 불가라 그 차선을 켠다.
   - **글자가 있는 정규식** — 확실히 풀 수 있는 모양(통째 리터럴 · 기호를 이스케이프한 것 · 맨 위 `|` 갈래, 맨 앞 `^` · 맨 뒤 `$`
     는 걷는다)은 글자로 풀고(`regexShape`), 그 밖(`.*` · 문자 갈래 · 수량자 · 무리 · `\s` 같은 글자 갈래)은 기호 사이의 글자 조각만
     본다. 조각 하나라도 앞뒤 글자 안에 있으면 켠다 — 한글은 두 자부터, 한글 없는 것은 넉 자부터(Playwright 의 정규식은 부분 일치라
     `/채팅/` 도 「채팅방이 열려요」를 찾는다), `\d` · `\s` 류에 붙은 한글(`/\d+개/`)은 한 자도, `i` 깃발이면 대소문자를 접어.
     **관련 판정이 안 서면 켠다** — 글자 있는 조각 가운데 견줄 만큼 길지 않은 것이 있을 때다(`/명.*/`).
   - **글자가 없는 정규식 · 글자를 모르는 `RegExp(변수)`** — 쓰임 자리로 가른다(`regexTurnsOn`). 문자열 정리(`.replace` ·
     `.replaceAll` · `.split` 의 첫 인자)면 그것만으로 켜지 않고, 화면 요소를 찾거나 재는 자리(`getByText` · `getByRole` 의
     `name` · `filter({ hasText })` · `toHaveText` · `toContainText` · `toHaveTitle` …)와 그 밖 · 판별 불가(`.test` · `.match` ·
     변수에 담음)면 켠다. 「글자 없는 정규식은 무관」이던 앞의 판단은 버렸다.
   남는 한계와 치르는 값은 위 「남는 구멍」.
9. **같은 날 독립 검토가 더 든 것.** 문구 상수의 자식 식도 값 · 코드 요소(`option` · `textarea` · `style` · `script` · `Script`)
   안이면 오용이다. 별칭(`import { NOTE as X }`) · 네임스페이스(`C.NOTE`)도 같은 상수로 재고, 다시 내보내기는 오용이다.
   `next/script` 를 다른 이름으로 받으면 그 이름도 빼고, 이름 붙여 · 네임스페이스로 받거나 `require` · 동적 `import()` 로 부르면
   그 파일은 문구로 세지 않는다. 문구 파일을 동적 `import()` · `require` 로 들이는 것도 오용이다. 표에 없는
   엔티티(`&rarr;` …)가 바뀐 글자에 있으면 그 파일도 세지 않는다. `gate` 실행은 `filter=all` 로 다 받는다 — 기본 `latest` 는
   `completed_at` 으로 하나를 골라 진행 중인 재실행을 숨길 수 있다. 머지 커밋(부모 둘 이상)은 동작으로 센다 — 첫 부모와의 차이가
   다른 가지의 동작 → 되돌림을 뭉친다. runbook 의 1 · 2 는 `main` 이 아니라 0 이 판정한 `head` 를 올리고 견준다.

결정 점검표(`docs/agents/delegation/decisions.md`)에 「검증 · 배포의 문턱」 줄을 더했다 — 이런 변경은 독립 검토 전에 `--auto` 를
걸지 않는다.
10. **문구 판정은 차선을 좁히기만 하고 넓히지 않는다**(운영자 2026-10-09). 문구만 바뀐 파일마다 두 계획을 견준다 — 그 파일을 문구로
    안 셌을 때의 지금 규칙, 그리고 `core` + 바뀐 글자 · 정규식 검색으로 켠 차선. **뒤의 것이 앞의 것의 부분집합일 때만** 뒤의
    것을 쓴다(지금 규칙이 전부면 무엇이든 부분집합이다). 검색이 전부를 부르거나, 지금 규칙에 없는 차선이 하나라도 섞이면(차선
    수가 적어도) 지금 규칙 그대로다 — 차선을 빼고 다른 차선으로 바꿔치지 않는다(`narrowedCopyOf`). 그래서 입구가 아닌
    컴포넌트(지금 규칙으로 `core`)의 문구는 #572 전처럼 `core` 다. 여러 파일이 섞인 PR 은 파일마다 정한 계획의 합이라, 동작이 바뀐
    파일(공용 위험 · `supabase/**` · 다른 `page`)의 차선은 문구 파일 때문에 빠지지 않는다. 정규식의 쓰임 자리 규칙(덧 8)은 좁힐 때의
    근거로만 쓰인다. 배포의 대기 예외(위 3)는 바뀌지 않는다.
