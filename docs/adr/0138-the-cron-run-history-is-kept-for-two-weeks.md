# 크론 실행 이력은 14일만 남긴다 — 소식 · 노출 기록은 아직 지우지 않는다

> **운영자 결정 2026-09-30** — 「크론 실행 이력만 14일로 지운다. 알림(notification) · 노출 기록(discovery_impression)은
> 지우지 않는다 — 공개 출시 전에 법무 · 안전 정책과 함께 다시 정한다.」 에이전트의 첫 안(노출 기록 180일 · 소식 90일 · 크론
> 이력 14일)에서 크론 이력만 받았다. 남은 둘은 간극 대장 G-67(`보류`)이다.

## 잰 것 (2026-09-30)

- 셋 다 지우는 자리가 없었다(밤샘 감사 DB 5 · 7 · 11, `docs/notes/2026-09-28-overnight-audit.md`). 다른 보존은 크론이 든다 —
  신고(6개월, ADR 0098) · 거절된 결제(`payment-retention-purge`) · 탈퇴 처분(`account-disposal`).
- 운영의 크기(집계만, `npm run db:remote`): `cron.job_run_details` **30,160줄 5 MB**(2026-09-10 부터, 하루 약 1,500줄 — 매분
  도는 복구기가 대부분) · `discovery_impression` 241줄 384 kB · `notification` 10줄. 지금 자라는 것은 크론 이력뿐이다.
- 크론 이력을 읽는 자리는 감시기(`watch_cron`, 지난 한 시간)와 runbook 의 점검 질의(24시간)뿐이다. 사람의 기록이 아니다.

## 정한 것

- **크론 실행 이력은 14일.** 크론 하나(`cron-run-retention-purge`, 매일 04:37 UTC)가 `retention.purge_old_cron_runs()` 를 돈다.
  여러 번 돌아도 안전하고, 실패는 `cron-watch` 가 알린다. 기간은 `retention.cron_run_period()` 한 줄이다.
- **소식 · 노출 기록은 지우지 않는다.** 노출 기록은 요청 · 넘김이 「내가 본 그 카드」로 읽고(`request_match` ·
  `discovery_shown_to_me`), 신고할 수 있는 범위의 근거 하나다(`report_user` — 내게 선 적이 있는 사람). 기간을 두면 신고할 수
  있는 사람이 줄어든다 — 보존 기간이 곧 안전 정책이라 법무 검토(G-25)와 함께 정한다.

## 치르는 값

- 14일 넘은 크론 실패를 이력으로 되짚을 수 없다 — 알림(`ops_alert`)은 남는다.
- 소식 · 노출 기록은 공개 출시 전까지 계속 쌓인다. 베타 동안은 종료 뒤 파기(처리방침)가 먼저 온다.

## 고르지 않은 것

- 첫 안의 **노출 기록 180일(덱에 선 카드는 남김) · 소식 90일** — 운영자가 법무 · 안전 정책과 함께 정하기로 미뤘다(G-67).
