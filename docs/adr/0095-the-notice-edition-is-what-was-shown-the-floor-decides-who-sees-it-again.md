# 판본은 보인 것을 적고, 다시 보여 줄지는 기준이 정한다

`NOTICE_VERSION` 하나가 두 일을 하고 있었다 — 확인 기록에 남는 **무엇을 보여 줬나**의 열쇠이자,
**다시 보여 줄지**의 문턱. 그래서 처리방침의 낱말 하나(「사주풀이 만들기」 → 화면 버튼의
「사주풀이 받기」, ADR 0027)를 맞추려 해도 확인한 사람 전원이 가입 폼으로 돌아와야 했다(G-05).
2026-09-23 에 사람이 정책을 정했다.

## 재어 본 것

- **판단은 앱에만 있고, 세 곳이 따로 견줬다.** `src/lib/consent/gate.ts`(관문, `proxy.ts` 가 부른다) ·
  `app/signup/page.tsx`(가입 화면이 같은 조건을 한 벌 더 적었다) · `app/me/settings/page.tsx`(「안내가 새로
  바뀌어 다시 보여 드립니다」) — 셋 다 `!== NOTICE_VERSION` / `=== NOTICE_VERSION` 이었다.
- **DB 는 판본을 견주지 않는다.** `complete_signup` 은 앱이 보낸 `p_version` 을 `app_user.notice_version`
  에 적기만 하고, 첫 쓰기 둘이 묻는 것은 가입(`signed_up_at`)이다. 판본을 읽는 정책·함수는 0 이다.
  그래서 이 결정에는 마이그레이션이 없다.
- **확인 기록의 칸** — `notice_version`(보인 판본) · `notice_schedule_id`(본 일정 줄) · `notice_ends_on` ·
  `notice_ack_at`. 판본과 줄을 함께 든다(일정 줄은 이 결정과 무관하게 그대로 견준다 — 날짜와 운영자가
  바뀌면 새 줄이고, 그것은 내용이다).
- **판본에는 차례가 없었다** — 문자열이다. 운영 기록(2026-09-23, `db query --linked`)은 `notice-v4` 열넷과
  빈칸 하나였고 지난 판본 넷(`v1`~`v4`)이 모두 `notice-v<수>` 모양이다. 글자째 견주면 `notice-v10` 이
  `notice-v9` 보다 앞서므로 **꼬리의 수로 센다**(`noticeEdition`). 모양이 다르거나 비었으면 확인하지
  않은 것이다.
- **처리방침의 「만들기」는 한 번**이다 — 국외 이전 OpenAI 줄의 「사주풀이 만들기를 누르셨을 때만」.
  「풀이를 만들 때 밖으로 나가는 것」 · 「풀이를 만들지 않으면」은 버튼 이름이 아니라 하는 일이라 둔다.

## 정한 것

- **판본과 기준을 떼어 둔다.** `NOTICE_VERSION` 은 화면에 보인 판본이고 확인 기록에 지금처럼 남는다.
  `NOTICE_ACK_FLOOR` 는 「이 판본 이상을 확인했으면 유효하다」를 든다. 둘 다 `src/lib/consent/notice.ts`
  에 산다.
- **판단 자리는 하나다** — `noticeAckHolds(version)`. 관문은 `signupDone` 을 통해 그것을 부르고, 가입 화면은
  조건을 다시 적지 않고 `signupDone` 을 부르며, 계정 관리도 같은 함수를 부른다. 셋 중 하나만 옮겨지면 관문은
  들여보내는데 계정 관리는 「다시 보여 드립니다」라고 말한다.
- **표현만 고친 개정은 판본만 올린다. 내용이 바뀐 개정은 기준까지 올린다** — 처리 항목 · 목적 · 보유기간 ·
  국외 이전 · 상대에게 보이는 것이 달라지면 내용이다.
- **확인 기록은 고치지 않는다.** 기준 이상을 본 사람은 지나가게 둘 뿐이고, 그 사람의 기록은 원래 본 판본
  그대로 남는다. 기존 사용자를 새 판본을 본 것으로 일괄 갱신하는 길은 금지다 — 누가 어떤 문구를 봤는지가
  남아야 한다. 다시 확인하는 사람만 그때 본 판본으로 새로 적힌다.
- **유효 판본 목록은 안 쓴다.** 개정마다 길어지고, 하나를 빠뜨리면 그 판본을 확인한 사람만 조용히 다시
  불려 온다.
- **시연 — `notice-v4` → `notice-v5`.** OpenAI 줄의 「사주풀이 만들기」를 「사주풀이 받기」로 맞췄다. 표현만
  고친 개정이라 기준은 `notice-v4` 에 둔다. 확인자 열넷은 다시 안 보고 기록은 `notice-v4` 로 남는다.

## 잠근 것

- `src/lib/consent/gate.test.ts` 「재확인 기준」 — 기준 이상은 안 보낸다 · 기준보다 낮으면 보낸다 · 판정이
  기록을 고치지 않는다 · 차례는 수로 센다 · 기준이 화면의 판본을 넘지 않는다(넘으면 방금 확인한 사람도 못
  지나가 가입 폼이 끝없이 돈다).
- `app/notice-version.boundary.test.ts` — `app` · `src` · `proxy.ts` 에서 판본(`NOTICE_VERSION` ·
  `NOTICE_ACK_FLOOR` · `notice_version` · `noticeVersion`)을 `===`/`!==` 로 견주는 자리가 `notice.ts`
  밖에 0 이다. 옛 세 자리를 되살리면 그 세 파일을 대며 빨개진다.
- `e2e/notice.spec.ts` 「재확인 기준」 — 기준 판본으로 기록된 계정이 `/me` 와 계정 관리를 지나가고 DB 의
  값이 그대로인 것, 기준보다 낮은 계정은 다시 확인하고 그때 본 판본이 적히는 것.

## 잠그지 않은 것

- **무엇이 「표현만」인가는 사람이 가른다.** 시험은 기준이 판본을 넘지 않는 것까지만 잰다. 내용을 바꾸고
  기준을 안 올리면 아무것도 빨개지지 않는다 — 개정하는 PR 이 `NOTICE_VERSION` 주석에 어느 쪽인지 적는다.
- **처리방침의 OpenAI 줄은 아직 사실보다 좁다.** 「사주풀이 받기를 누르셨을 때만」이라고 적지만 「궁합풀이
  받기」와 수락 뒤 자동 생성(ADR 0038)에도 나간다. 바로잡는 것은 내용 개정이라 기준이 오른다 — G-54.
