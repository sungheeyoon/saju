# 세 운 표는 같은 자리에서 읽는다

## 후보 문장이 또 반쯤 틀렸다 (2차 라운드에서 네 번째)

이슈 #88 후보 4는 이렇게 적혀 있었다.

> 운 셋이 한 칸을 세 번 적고, 조립 순서가 암묵 지식이다. 세운·월운의 칸 만드는 블록
> 19줄 동일. 가짜 단일 기둥 명식 4벌. `index.ts:178-243` 의 여섯 걸음 순서가 주석에만
> 있다. 시계가 셋인데 타입은 전부 `Date`·`number`.

재어 보니 넷 중 **하나만 맞고 하나는 과소평가, 둘은 틀렸다.**

| 적힌 것 | 잰 것 |
|---|---|
| 「19줄 동일」 | **아니다.** 세운↔월운의 공통은 15블록 76줄로 흩어져 있고 가장 큰 덩어리가 9줄이다. 그런데 **그 9줄은 세 파일에 글자까지 똑같다**(`daeun:300`·`saeun:203`·`wolun:167`) — 둘이 아니라 셋이다 |
| 「가짜 단일 기둥 4벌」 | **5벌이다.** 변수 이름(`annualPillar`)에 기대어 세면 `wolun:134` 를 놓친다 |
| 「한 칸을 세 번 적는다」 | **`now/` 는 일부러 재사용한다.** `saeunEntryOf`·`wolunEntryOf` 가 `computeSaeun`·`computeWolun` 을 그대로 부르고 「다른 함수로 뽑지 않는 것이 요점」이라고 적어 두었다 |
| 「조립 순서가 암묵 지식」 | **컴파일러가 잡는다.** `daeun` 이 `const` 이고 세운·월운 호출이 그것을 참조하므로, 순서를 뒤집으면 선언 전 사용으로 오류다 |
| 「타입이 전부 `Date`·`number`」 | **`CivilDate` 가 이미 있다**(`civilTime.ts`). 세운·월운이 그것으로 받는다 |

**진짜는 하나였다** — 칸 안에서 하는 일이 셋 다 같은데 **그 사실을 아무것도 붙들고
있지 않았다.**

## 무엇을 옮겼나

`src/lib/saju/fortune/` 에 둘을 세웠다.

- **`fortuneReadingsOf(natal, pillar, stages)`** — 그 기둥을 일간과 원국에 대고 읽는다
  (십성·12운성·12신살). 세 파일의 9줄이 여기 한 벌로 모였다.
- **`fortuneChart(chartId, seat, pillar)`** — 기둥 하나짜리 명식. 다섯 자리가 한 벌이 됐다.

`now/` 는 손대지 않았다. 이미 세 표의 함수를 그대로 부르고 있어서다.

## 무엇을 잠갔나

복사를 지우는 것만으로는 아무것도 안 잠긴다(ADR 0074 의 교훈). 그래서 **세 표가 같은
방식으로 센다**를 값으로 세웠다(`fortune.test.ts`).

- 대운·세운·월운의 **모든 칸**이 공용 자리가 내는 것과 같은 십성·운성·신살을 든다
- **같은 간지는 어느 표에 서든 같은 읽기를 받는다.** 위 셋을 각각 통과시키면서도 세 표가
  서로 어긋날 수 있다 — 표마다 다른 기준을 넘기면 그렇게 된다. 겹치는 간지가 하나도
  없으면 아무것도 안 잰 것이므로 **비교한 수가 0이 아닌 것까지 잰다**
- 운 칸의 **빈 세 자리**가 언제나 비어 있다

**리뷰가 한 자리를 걸렀다.** 「12운성 계통이 실제로 값을 바꾼다」는 시험이 **안 바뀌는 것
둘**(십성·신살)만 단언하고 있었다 — `stages` 인자를 통째로 지워도 통과했다. 이름이 말하는
것을 안 재던 시험이고, **이 ADR 이 인용한 바로 그 함정(0074)에 내가 다시 빠진 자리**다.
이제 두 계통에서 **갈리는 칸을 세어 `> 0`** 을 잰다(`daeun.test.ts` 와 같은 모양).

한 자리에서 신살 기준을 년지에서 월지로 옮기면, 전에는 나머지 둘이 옛 기준으로 남고
빨개지는 자리가 없었다. 세 표는 한 화면에 나란히 서므로 그 어긋남은 사용자가 먼저 본다.

## 타입 검사가 한 자리를 잡아 줬다

처음에 `fortuneReadingsOf` 가 `Pillars` 를 통째로 받게 썼더니 세운·월운에서 막혔다.
그 둘은 원국을 **`meta` 없이 다섯 칸으로 좁혀** 들고 다닌다(`SaeunInput`·`WolunInput`).
즉 **통째로 달라는 쪽이 더 달라고 한 것**이었다.

읽는 데 실제로 드는 것은 **일간과 원국의 년지·일지 셋뿐**이라 거기까지 좁혔다
(`Pick<Pillars, 'year' | 'day' | 'dayMaster'>`). 계산마다 필요한 만큼만 받는 것은 이
저장소가 이미 여러 자리에서 하는 일이다(`StructureInput`·`RootednessInput`·`EffectiveInput` …).

좁히고 나니 세 파일에서 `const dayMaster` 세 줄과 `Stem` import 둘이 함께 죽었다.

## 안 한 것

- **D 의 나머지 절반(후보 3, 마이그레이션)** 은 별도 변경이다. 재어 둔 값은 거기서 쓴다.
- **조립 순서에 시험을 걸지 않았다.** 이미 컴파일 오류가 되는 자리에 시험을 더하면
  같은 것을 두 번 잠그는 일이다.
