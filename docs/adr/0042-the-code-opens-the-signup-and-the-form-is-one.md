# 가입은 한 폼이고, 문을 여는 것은 코드다

테스터 한 명을 부르는 데 세 걸음이 필요했다 — 주소를 받고, SQL 로 명단에 넣고, 됐다고
알려 준다. 그리고 그 사람은 화면 넷을 지나야 사주를 넣을 수 있었다.

```
구글 로그인 → /welcome(안내 확인) → /me → /me/profile(이름) → /me → 내 명식 등록
```

관문이 셋이고 튕김이 넷이다. 이 줄에서 이미 한 번 고장이 났다 — 튕김이 둘 겹치면서
**화면이 비었다**(ADR 0041, 커밋 `2cbb31f`).

## 정한 것

**하나. 이메일 명단을 걷고 코드로 바꾼다.**

`invite` 표와 `gate_signup_by_invite` 훅을 지운다. 대신 `signup_code` 를 세운다. 운영자가
코드를 하나 만들고 그 문자열만 전하면 받은 사람이 스스로 들어온다.

**둘. 코드에는 「하루 · 최대 N명」이 붙는다.**

기한 없는 코드는 새면 영원히 열린 문이다. 수 없는 코드는 한 사람이 퍼뜨리면 정원이 없다.
둘을 함께 두면 새어도 **오늘 N명**까지다. 하루의 경계는 서울 자정이다 — 운영자가 「오늘
열 명」이라고 말할 때의 오늘과 같은 날이어야 한다.

**셋. 쓴 수는 세지 않고 센다.**

코드 행에 `used` 를 두고 올리지 않는다. 계정 쪽에 `signup_code` 를 적고 정원은 그 수를
세어 답한다. 어차피 **어느 계정이 어느 코드로 왔는지**를 남겨야 하고, 그 값이 있으면
따로 세는 자리는 두 번째 진실이 된다(`reading_credits_used` 와 같은 규율).

**넷. 가입은 한 폼이다.**

`/signup` 하나에 코드 · 닉네임(중복 확인) · 안내 확인이 선다. 셋이 `complete_signup` 한
문으로 한 트랜잭션에 적힌다.

```
구글 로그인 → /signup(코드 · 닉네임 · 동의) → /me → 내 명식 등록
```

**사진과 소개는 폼에서 뺀다.** 필수가 아닌 것을 첫 화면에 세우면 사용자는 그것도 채워야
하는 줄 안다. 둘 다 `/me/profile` 에 그대로 있다.

**다섯. `/welcome` 을 없애고 `/privacy` 는 전문으로 남긴다.**

안내 본문은 `/signup` 안에 절마다 서되 넷은 접는다. 펴 두는 넷은 가려지면 안 되는 것들이다
— 무엇을 받나, 언제까지 두나, 풀이를 만들 때 밖으로 나가는 것, 인연 찾기에서 보이는 것.
접는 넷(위탁 · 국외이전 · 파기절차 · 권리 행사)은 길고, 필요할 때 찾아 읽는 종류이고,
`/privacy` 에 펼친 채로 서 있다. **자료는 한 벌이다**(`noticeFor`) — 따로 적으면 한쪽만
고쳐지고, 그때 사용자가 읽은 것과 우리가 지키는 것이 갈린다.

**여섯. 관문은 둘이다 — 베타가 끝났나, 가입이 끝났나.**

`gateFor` 가 묻는 것이 셋에서 둘로 준다. 안내와 이름이 각자 세우던 문을 「가입」 하나가
든다.

## 값을 하나로 — **가입 완료는 무엇인가**

`signed_up_at` 한 칸이 든다. `notice_ack_at` 이나 `nickname` 으로 대신할 수 있었지만 안
그랬다. 그 둘은 각자 다른 물음에 답한다 — 「안내를 언제 봤나」와 「무엇으로 불리나」.
「가입이 끝났나」를 그 둘의 곱으로 물으면 **묻는 자리마다 곱셈이 한 벌씩 생기고**, 셋 중
하나는 언젠가 다르게 곱한다.

그런데 관문이 보는 「가입 완료」에는 하나가 더 든다: **지금 안내를 확인했는가.**

```
가입 완료 = signed_up_at 있음 ∧ 지금 판본 ∧ 지금 일정 줄
```

안내가 새 판본이 되거나 운영자가 일정을 옮기면 이미 가입한 사람도 `/signup` 으로 돌아온다.
그때 폼은 **코드와 이름 칸을 안 세우고 확인만 받는다** — 두 번째 코드를 어디서 구하라는
말이 될 것이다. 이 조건을 빼면 「11월에 지운다」를 읽고 확인한 사람을 이듬해까지 들고 있게
된다. ADR 0024 가 막으려던 것이 정확히 그것이다.

문은 여전히 둘이다. 늘어난 것은 「가입 완료」의 정의이지 관문의 수가 아니다.

## 무엇을 잃나 — **미완성 계정이 생긴다**

명단이 문을 지킬 때는 `auth.users` 에 아무나 못 들어왔다. ADR 0006 이 관문을 DB 훅에 건
이유가 그것이었다 — 「가입은 됐는데 아무것도 못 하는 계정」을 남기지 않으려고.

**그 계정이 이제 생긴다.** 구글 계정만 있으면 누구나 `auth.users` 행 하나를 만든다.

받아들이는 대신 두 자리에서 막는다. 되돌릴 수 없는 첫 쓰기 둘이 `signed_up_at` 을 묻는다.

- `create_self_person` — 내 출생 정보가 처음 들어오는 자리
- `create_managed_person` — **남의** 생년월일시가 들어오는 자리

둘째는 **안내를 한 번도 안 묻고 있었다.** 화면 관문이 `/me` 를 지키니 닿을 수 없다고
여겼는데, RPC 는 로그인한 사람이 브라우저에서 그대로 부를 수 있다. 미완성 계정이라는
상태가 생기면서 그 구멍이 실제로 밟히는 자리가 됐다 — 이 개정이 찾아낸 것 중 가장 큰
하나다.

그 둘을 지나야만 다른 문이 열린다. 저장한 사람도, 참여도, 풀이도, 요청도 전부 Person
하나를 먼저 요구한다.

## 안 쓰는 문은 지운다

`acknowledge_notice` 를 부르는 자리가 하나도 안 남았다. 처음 확인하는 것도 다시 확인하는
것도 `complete_signup` 이 한다. 둘을 나란히 두면 안내 기록을 쓰는 자리가 둘이 되고, 그중
하나는 이름도 코드도 안 본다 — 가입이 안 끝난 사람이 그 문으로 확인만 남기면 관문의 셈이
흔들린다. **안 쓰는 문을 남겨 두는 것은 살아 있는 문을 하나 더 지키는 일이다.**

## 이미 들어와 있는 사람

코드가 서기 전에 안내를 보고 이름을 지은 계정은 가입이 끝난 계정이다. 마이그레이션이
`signed_up_at` 을 메운다. `signup_code` 는 **비워 둔다** — 없던 것을 지어 넣으면 「어느
코드로 왔나」가 거짓이 된다. 비어 있는 것이 곧 「코드 이전」이라는 사실이다.

## 훅은 두 자리에서 꺼야 한다

`supabase/config.toml` 의 `[auth.hook.before_user_created]` 와 **원격 프로젝트의 설정**
둘 다. 켜 둔 채로 함수만 지우면 GoTrue 가 없는 함수를 부르고, 그때 아무도 로그인하지
못한다 — 로컬에서 실제로 그 빨간불을 봤다.

## 재어 본 것

pgTAP 20건(`01_signup_code`)이 코드가 실제로 문인지 잰다 — 없는 코드 · 지난 코드 · 정원 찬
코드 · 이름 중복 · 대소문자 · 미완성 계정의 두 문 · 다시 지날 때 코드가 두 번 안 세어지는
것 · 코드 표가 안 보이는 것. e2e 는 폼 하나로 코드와 이름과 확인이 끝나 온보딩까지
**튕김 하나로** 이어지는지를 브라우저로 누른다.
