# 틀린 가입 코드는 계정마다 한 시간에 열 번까지다

> **제안**(2026-09-28) — 운영자 결정 대기. 한도 · 창 · 거절 문장이 운영자가 답할 자리다. 밤샘 감사의 보안 후보(「가입 코드 무제한
> 시도」)를 에이전트가 코드에서 다시 재고 적었다. 번호는 머지 직전 main 의 빈 번호로 옮긴다.

## 잰 것

- `complete_signup` 은 `authenticated` 에 열려 있다(`supabase/migrations/20260911090000_the_code_opens_the_signup.sql:268-271`).
  지금 정의(`20261010110000_the_signup_can_be_paused.sql`)는 코드를 `signup_code` 에서 찾고, 없거나 창 밖이면
  「지금 쓸 수 있는 코드가 아닙니다.」로 던진다. **몇 번째 시도인지 세는 자리가 없다.** 구글로 로그인만 하면 PostgREST 로
  코드를 끝없이 넣어 볼 수 있다.
- 코드의 모양은 대문자 4~24자다(`signup_code.code` 의 검사식). runbook 「초대」의 본보기는 `SAJU1001` · `SAJU1002` 다 —
  앞 넷이 정해지면 남는 것은 만 가지다.
- **던지는 문은 틀린 시도를 셀 수 없다.** 던지면 트랜잭션이 통째로 되감겨 그 시도에서 적은 줄도 사라진다. 세려면 틀린 코드에
  던지지 않고 적은 뒤 돌아와야 한다.

## 제안

1. 틀린 시도를 `signup_code_miss`(계정 · 시각)에 적는다. 사용자에게 안 열린 표다. 들어오면(가입을 끝내면) 그 계정의 줄을 걷고,
   틀릴 때마다 창 밖의 옛 줄을 걷는다. 계정을 지우면 함께 지워진다(`on delete cascade`).
2. **창(한 시간) 안에서 열 번 틀린 계정은 맞는 코드도 못 넣는다** — 「코드를 여러 번 잘못 넣었습니다. 한 시간 뒤에 다시 시도해
   주세요.」(새 문장). 맞는 코드를 받으면 열한 번째에 맞히는 것이 그대로 열린다.
3. 틀린 코드는 던지지 않고 `false` 를 낸다 — `complete_signup` 의 반환형이 `void` → `boolean`. 앱(`app/signup/actions.ts`)은
   `false` 에 지금과 같은 문장을 세운다. 없는 코드와 지난 코드를 가르지 않는 것은 그대로다.

수는 두 함수(`signup_code_miss_limit()` · `signup_code_miss_window()`) 한 곳에 있다.

## 값

- **계정마다 센다** — 구글 계정을 여럿 만들면 그만큼 더 두드린다. 만 가지 코드는 열 번 · 한 시간이면 계정 천 개 · 한 시간이다.
  서비스 전체의 한도(모든 계정의 틀린 시도 합)는 안 넣었다 — 넣으면 한 사람이 모두의 가입을 막는다. 더 막으려면 **코드를 길게**
  (예: 무작위 10자) 만드는 것이 싸다 — runbook 의 본보기를 바꾸는 운영 결정이다.
- 오타를 열 번 낸 사람은 한 시간을 기다린다.
- 반환형이 바뀌는 사이(`db push` 뒤 앱 배포 전), 옛 앱은 틀린 코드의 `false` 를 성공으로 읽어 `/me` 로 보내고 관문이
  `/signup` 으로 되돌린다 — 문장 없이 돌아온다. 가입은 일어나지 않는다.
