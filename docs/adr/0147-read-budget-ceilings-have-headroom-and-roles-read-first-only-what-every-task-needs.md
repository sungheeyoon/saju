# 읽기량의 천장은 여유를 둔 눈금이고, 손대기 전에는 그 역할의 일 대부분이 쓰는 것만 읽는다

> 후속 결정(일부): ADR 0162 — 천장을 정할 때의 여유 바닥은 눈금 반(2,500)에서 눈금 하나(5,000)로, 붉어지는 여유는 10,000 에서
> 15,000 으로 바뀌었다. 셈의 수는 「필수 읽기량」이 아니라 「읽기량 예상치」(고정 + 고르는 것의 최댓값)라 부른다. 아래 「잠그지
> 않은 것」의 ui 화면 절은 화면 무리 파일로 나눠 풀었다

> **운영자 결정 2026-10-06**(조율자 브리프로 전함) — 「읽기량 상한에 여유가 없어 PR 마다 올리고 있다 — 진짜로 는 것만 잡게
> 고친다. 그리고 역할마다 손대기 전에 읽는 양을 크게 줄인다. 규칙은 지우지 않는다 — 대부분의 일이 안 쓰는 원본은 「그 일에
> 닿을 때 연다」로 옮긴다. ADR 0145 를 일부 대체하는 ADR 로 남긴다.」

ADR 0145 의 세 대목을 대체한다 — ① 상한은 잰 값 그대로의 회귀 상한이다 ② 원본은 잠근 날의 크기로 센다(`SIZE_AT_LOCK`)
③ 파일은 절을 가리켜도 통째로 센다. 역할 문서는 Router 다 · 「이 저장소의 방식」은 링크로 시작하는 한 줄이다 · 동적 라우트 ·
선택 묶음 · 셈은 `scripts/read-budget.mjs` 한 곳이다는 그대로 선다. ADR 0140 의 칸 넷에는 세지 않는 다섯째 칸을 맨 뒤에 더한다 —
넷째 칸(끝날 때 고치는 것)은 그대로 넷째다.

## 잰 것 (2026-10-06)

- **상한이 아무것도 막지 못했다.** 역할마다 상한이 그날 잰 값과 같았다(여유 0 — coordinator 88,011 · db 128,334 · ui 134,935 …).
  #504 에서 파일 이름 한 글자가 `feature` 177,516 > 177,513 · `ui` 134,935 > 134,934 를 붉혔고, 고침은 같은 PR 에서 상한을 올리는
  것이었다. PR 마다 올리는 상한은 회귀를 잡는 것이 아니라 일을 하나 더 만든다.
- **잠근 날의 크기가 이미 거짓이었다.** `SIZE_AT_LOCK` 의 50 파일 가운데 34 가 지금 크기와 달랐다 — `docs/ops/runbook.md` +484 ·
  `docs/agents/delegation/done.md` +329 · `docs/text/claim-policy.md` +278. 셈이 에이전트가 오늘 읽는 바이트가 아니었다.
- **절을 가리켜도 파일을 통째로 셌다.** `docs/product/prd/foundation.md` 「0. 지금 어디까지 왔나」는 4,009 바이트인데 21,970 을,
  `docs/architecture.md` 「층 넷」 · 「새 것을 놓을 때」는 3,064 인데 13,809 를 셌다. 셈만 절로 바꿔도(역할 문서는 그대로)
  feature 146,215 · reading 115,460 · ui 125,148 · db 102,196 · reviewer 98,016 · ops 86,099 · coordinator 78,017 · docs 70,867 이었다.
- **손대기 전에 읽는 것의 여럿이 「그 일일 때만」 쓰는 원본이었다.** 운영 역할의 `docs/ops/runbook/security.md` 「보안 점검」(25,200)은
  보안 점검을 맡았을 때만이고, feature 의 `docs/agents/delegation/coordinator.md`(9,033)는 이슈와 코드가 어긋날 때만,
  `scripts/secret-env.mjs`(8,339)는 새 비밀을 들일 때만이다. 풀이 역할은 엔진 · 글 · 화면 흐름의 원본을 한꺼번에 읽었다.

## 정한 것

- **천장은 `CEILING_STEP`(5,000)의 배수다.** 정할 때는 그때의 합에서 2,500 이상 남는 가장 작은 배수(`ceilingFor`). 합이 천장을
  넘으면 붉다 — 새 원본 파일 하나 · 큰 절 하나가 늘었다는 뜻이다. 파일 이름 한 글자 · 역할 문서 한 줄 · 대장의 줄 몇은 눈금
  하나를 못 넘는다.
- **천장이 합보다 `MAX_SLACK`(10,000) 넘게 남아도 붉다.** 줄인 PR 이 천장도 내린다 — 남는 여유에 새 원본 하나가 숨지 않게.
- **천장을 바꾸면 ADR 에 줄을 남긴다.** `| 역할 | … | 천장 |`(천장이 마지막 칸) 줄이 `docs/adr/` 의 어느 ADR 에도 없으면 시험이
  붉다. 올리는 PR 은 그 까닭을 그 ADR 줄 곁에 적는다 — 이 ADR 의 덧이나 새 ADR.
- **크기는 모두 지금 크기다.** `SIZE_AT_LOCK` 을 걷는다. 대장(간극 · 노트 차례)이 자라는 것은 눈금의 여유가 받고, 여유를 넘게
  자랐으면 그만큼 역할이 실제로 더 읽는다는 뜻이다 — 가리킴을 절로 좁히거나 원본을 쪼갠다.
- **절을 가리키면 그 절만 센다.** 백틱 경로 바로 뒤의 `「절」`(그 글자로 시작하는 첫 제목) · 링크의 `#앵커`. 절은 그 제목부터 같거나
  높은 다음 제목 앞까지다. 한 파일을 절 없이 한 번이라도 가리키면 통째다. 선택지는 고정이 이미 센 바이트를 다시 세지 않는다
  (고정이 절만 셌으면 나머지만 더한다). 가리킨 절이 없으면 셈이 멈춘다.
- **역할 문서에 다섯째 칸 「닿을 때 여는 것」을 둘 수 있다** — 맨 뒤, 세지 않는다. 줄마다 `- <언제> → [원본](경로) — 무엇` 한
  줄이고 언제가 먼저 선다(시험이 꼴을 잰다). 「넷째 칸」(끝날 때 고치는 것)은 그대로 넷째다.
- **무엇을 옮기는가의 기준** — 그 역할의 일 대부분이 손대기 전에 쓰는 원본은 「먼저 읽는 것」에 남긴다. 특정한 일(보안 점검 ·
  새 비밀 · 무인 라운드 · 머지 직전 · 로컬 스택 고장)에서만 쓰는 원본은 그 일을 「언제」로 적어 옮긴다. 멈출 자리(「하지 않는
  것 · 묻는 것」)는 옮기지 않는다 — 그 칸은 원래 세지 않는다. 역할 문서에 규칙을 옮겨 적어 읽기량을 줄이지 않는다(ADR 0145).
- **고칠 자리가 갈리는 역할은 선택 묶음을 쓴다** — reading 은 엔진 · 글과 프롬프트 · 풀이 화면과 흐름 셋 가운데 고칠 자리의
  원본을 읽는다(걸치면 둘 다).
- **쓰는 자리는 읽을 자리가 아니다** — 「끝날 때 고치는 것」에서 줄만 더하는 파일은 절(「검토 대기」 앞)로 가리키거나, 노트 차례처럼
  백틱 디렉터리로 적는다(ADR 0145 의 쓰는 자리 규칙 그대로).

## 치르는 값

- 에이전트가 「언제」를 잘못 판단하면 열어야 할 원본을 안 연다. 줄마다 언제를 구체적인 일(보안 점검 · 새 비밀 · 머지 직전)로 적어
  판단을 좁힌다. 멈출 자리는 여전히 역할 문서 안에 인라인이다.
- 절만 센 값은 에이전트가 그 절만 읽는다는 가정이다. 파일을 통째로 열면 셈보다 많이 읽는다 — 역할 문서는 절을 가리키고, 큰 원본은
  제목으로 찾아 그 절만 읽으면 된다.
- 대장이 자라 눈금을 넘으면 그 PR 이 기능과 무관하게 붉다. 지금 자람(하루 몇백 바이트)으로는 몇 주에 한 번이고, 그때 할 일은 천장을
  올리는 것보다 가리킴을 좁히는 것이다.

## 잠그지 않은 것

- 「닿을 때 여는 것」에 둔 줄이 정말 「대부분의 일이 안 쓰는」 것인가 — 시험은 꼴만 잰다. 조율자가 라운드 끝에 보고의 「헤맨 것」으로
  본다(ADR 0146) — 「닿을 때」로 옮긴 원본을 매번 열었다는 보고가 쌓이면 「먼저 읽는 것」으로 되돌린다.
- 한 절 안에서 「그 화면의 하위 절」만 읽는 것(ui 의 `docs/product/prd/screens.md` 「3. 화면」 27,710) — 고칠 화면마다 달라 절 전체를 센다.

## 2026-10-08 덧 — 노트 차례는 「최근」 여덟 줄만 센다

조율자의 「먼저 읽는 것」은 노트 차례의 「마지막 줄들」을 읽으라고 했는데 셈은 차례 **전부**(19,741)를 셌다. 차례는 노트마다
한 줄씩 자라므로 라운드 노트 PR 이 천장을 넘었다 — 2026-10-08 의 노트(#540)는 남의 줄 설명을 줄여서 들어갔다. 차례를
「최근」(여덟 줄까지, 시험이 잰다)과 「차례」로 가르고 역할 문서는 「최근」을 가리킨다. 위 「치르는 값」의 셋째 — 천장을
올리지 않고 가리킴을 좁힌다 — 를 밟은 것이다.
