# 문구 대장의 무리 파일은 고칠 자리로 찾아보는 표라 닿을 때 열고, 새 절은 그 파일 이름을 단 번호다

> **조율자 지시 2026-10-11**(운영자 권한 위임 같은 날) — 「ui 역할이 99,944 / 100,000 바이트라 대장에 절 하나만 더해도 붉다. 천장을
> 올리지 말고 고정 읽기를 줄여 대장 절 몇십 개가 더 붙어도 견디게 한다. 대장 절 번호가 화면 무리 전체에 하나로 이어져 나란히 도는
> PR 이 같은 번호를 노려 이번 라운드에 네 번 부딪혔다 — 싸게 들어가면 같이 고친다.」

ADR 0162 의 두 대목을 대체한다 — ① ui 의 「고칠 화면의 무리」 선택지가 PRD 무리 파일과 **대장 무리 파일의 짝**이라는 것 ② 대장의
절 번호가 대장 전체에서 하나라는 것. 화면 문서를 무리마다 한 파일로 두는 것 · 읽기량을 보수적 예상치로 세는 것 · 여유의 바닥과
붉어지는 여유(`HEADROOM` · `MAX_SLACK`)는 그대로다.

## 잰 것 (2026-10-11, main `b1478b87`, `npm run read-budget`)

- **ui 는 56 바이트 남았다** — 고정 76,030 + 무리 최댓값 23,914(첫 화면 · 사주 보기 — PRD 9,039 · 대장 14,875) = 99,944 / 100,000.
  고정의 가장 큰 파일이 대장 머리 `docs/product/copy-ledger.md`(16,337, 전부)였다.
- **자라는 것은 대장 무리 파일이다.** 확정 문구 하나가 무리 파일 끝에 절 하나(1–2 천 바이트)로 서고, 머리의 무리 색인 「절」 칸에
  번호 하나(5–6 바이트)가 붙는다. 무리 파일은 선택 묶음이라 가장 큰 무리가 자라면 ui 의 예상치가 그만큼 자란다 — 천장을 몇 번 올려도
  대장 절 열 개 안팎이면 다시 닿는다. ADR 0164 는 색인 「 · 35」 여섯 바이트로 reviewer 를 넘겼고, ADR 0168 은 ADR 0109 에 덧을 못 달아
  새 ADR 이 됐다.
- **번호가 부딪혔다.** 절 번호가 일곱 무리 파일과 머리 전체에서 하나라, 서로 다른 무리를 고치는 PR 이 같은 「다음 번호」를 노렸다 —
  이번 라운드에 네 번(조율자 보고). 대장 18 은 한 절의 머리가 두 번 서며 빈 번호로 남았다.

## 정한 것

- **대장 무리 파일은 찾아보는 표다 — ui 는 「닿을 때 여는 것」으로 연다.** 화면 글자를 하나라도 바꾸거나 새로 쓰면 고칠 자리(파일
  이름 · 지금 글자)로 그 무리 파일과 머리의 여러 무리에 걸친 줄을 찾고, 있으면 그 문구를 쓴다 — `docs/agents/code-rules/screen-copy.md`
  「화면 문구」의 「먼저 대장에서 찾는다」는 그대로다. 까닭: 대장은 결정 날짜순 표의 더미라 손대기 전에 무리 전부를 읽어도 고칠
  자리의 줄 몇 개만 쓴다. 손대기 전에 꼭 읽는 것은 「어디에 무엇이 사나」와 규칙이다(ADR 0147). 이것은 `docs/agents/delegation/done.md`
  「읽기량 천장에 걸리면」이 막는 「읽어야 할 링크를 닿을 때로 옮겨 맞추기」가 아니다 — 그 일의 뜻을 바꾼 결정이고, 그래서 이 ADR 이다.
- **ui 는 대장 머리의 「무리 색인」 · 「01 규칙」만 고정으로 읽는다.** 여러 무리에 걸친 줄(탭 · 서비스 이름 · 확인창 · 출생 정보 폼 ·
  실패 줄 …)과 「검토 대기」는 위의 찾는 자리에 든다. 선택 묶음은 PRD 무리 파일 하나다 — 화면의 요구와 규칙이라 손대기 전에 읽는다.
- **절 번호 — 01–47 은 대장 전체에서 하나인 채로 멈춘다. 새 절은 그 파일 이름을 단 번호다**: 무리 파일은 `first-01` · `settings-01`
  처럼 그 파일 이름(PRD 화면 파일과 같은 이름, ADR 0162), 머리(여러 무리에 걸친 줄)는 `all-01`. 한 파일 안에서 01 부터 끊기지
  않는다. 서로 다른 무리를 고치는 PR 은 더는 같은 번호를 노리지 않고, 같은 무리를 나란히 고치는 PR 만 부딪힌다. 새 번호는 이름이
  파일을 말하니 무리 색인 「절」 칸에 적지 않는다 — 색인이 더 자라지 않는다. 옛 번호(「대장 26」)로 부르던 자리는 그대로 산다.
- **시험이 잰다**(`scripts/code-rules.test.ts` 「화면 무리」). ① 대장 전체에서 하나인 번호가 01–47 그대로다(`## 48 …` 은 붉다 — 새
  절은 `<파일 이름>-NN`) ② 이름을 단 절은 그 파일의 이름(머리는 `all`)이고 파일 안에서 01 부터 끊기지 않는다 ③ ui 의 선택지는 무리마다
  그 PRD 화면 파일이고, 「닿을 때 여는 것」이 대장 무리 폴더를 든다.
- **reviewer 는 그대로다.** 프런트 관점은 대장 머리 전부와 본 화면의 대장 무리 파일을 읽는다 — 리뷰는 고친 문구가 대장과 맞는지를
  보는 일이라 표를 읽는 것이 그 일이다. 천장(95,000, ADR 0164)을 둘지는 G-94 의 운영자 답이다.

## 다시 정한 천장

## 치르는 값

- ui 가 손대기 전에 대장 무리 파일을 다 읽지 않으니, 고칠 자리와 다른 글자로 적힌 같은 사실(다른 화면의 같은 문구)을 놓칠 수 있다.
  같은 사실은 상수 하나라는 규칙(`docs/agents/code-rules/screen-copy.md`)과 reviewer 의 프런트 관점이 그 자리를 든다.
- 번호가 두 꼴(옛 01–47 · 새 `<이름>-NN`)이다. 옛 번호를 새 꼴로 다시 매기지 않는다 — PR · ADR · 노트 · 코드 주석의 「대장 NN」이
  수백 곳이다.

## 버린 것

- **천장을 올린다** — 운영자 결정(2026-10-10 「천장은 올리지 않는다」, G-94)과 어긋나고, 대장 절 열 개 안팎이면 다시 닿는다.
- **머리의 여러 무리에 걸친 줄을 새 무리 파일로 옮긴다** — 대장 폴더와 PRD 화면 폴더의 무리 이름이 같다는 시험(ADR 0162)을 깨고,
  절을 가리키는 것만으로 같은 바이트가 빠진다.
- **ADR 0109 를 절로 줄여 읽는다** — 위 둘로 목표(85,000 아래)를 넘었고, 디자인 체계의 추기는 화면 일 대부분이 쓴다.
