# 역할 문서는 원본으로 가는 길잡이(Router)다 — 규칙을 줄여 다시 말하지 않는다

> 후속 결정(일부): ADR 0147 — 상한을 잰 값 그대로 박던 회귀 상한은 여유를 둔 천장(5,000 의 배수 · ADR 줄)으로, 원본을
> 잠근 날의 크기(`SIZE_AT_LOCK`)로 세던 것은 지금 크기로 바뀌었다. 「절」 · 앵커만 가리키면 그 절만 세고, 역할 문서 맨 뒤의
> 「닿을 때 여는 것」은 세지 않는다
>
> **운영자 결정 2026-10-05** — 「1·2번을 모두 진행해 주세요. 다만 한 PR 에 섞지 말고 순차 PR 둘로 나눕니다. 첫 PR 은
> `delegation.md` 의 의미를 바꾸지 않는 물리적 분리와 관련 시험 이전만, 두 번째 PR 은 역할 문서 Router 전환 · ADR 0140 부분
> 대체 · `domain.md` 읽기 범위 · 필수 읽기량 시험을 맡습니다. 「하지 않는 것 · 묻는 것」은 짧게 인라인으로 유지합니다. 필수
> 읽기량은 변경 전후를 먼저 보고하고, 변경 후 값을 회귀 상한으로 잠그세요.」 이 ADR 은 그 두 번째 PR 이다(첫 PR 은 #484).

ADR 0140 의 한 대목 — 「「이 저장소의 방식」은 원본이 말하는 것을 한 줄로 줄인 길잡이」와 줄마다 다는 `(원본: …)` — 을 대체한다.
입구 한 장 · 역할 문서 여덟 · 칸 넷 · 얇은 에이전트 정의 · 조율자가 라운드 끝에 고친다는 나머지는 그대로 선다.

## 잰 것 (2026-10-05)

- **요약은 원본보다 늦게 고쳐진다.** 시험이 「이 저장소의 방식」에 줄 넷 이상과 줄마다 `(원본: …)` 을 강제했다(옛
  `scripts/code-rules.test.ts` 의 `toBeGreaterThan(3)`). 출처가 있다는 것까지만 재고 뜻이 같은지는 못 쟀다(ADR 0140 「치르는 값」).
  2026-10-05 에 원본 「세션 기록」이 「노트는 다른 문서에 없는 것만」으로 바뀌었는데 `docs/roles/coordinator.md` · `docs/roles/ops.md`
  의 「끝날 때 고치는 것」은 여전히 노트에 머지 목록 · SHA 를 적으라고 했다(#483 으로 고침).
- **위임 규약 한 장(453줄 · 53KB)을 모든 역할이 통째로 읽었다** — 역할마다 절 몇 개만 가리켰지만 파일이 하나였다. #484 가
  `docs/agents/delegation/` 의 주제 파일 열로 나눴다.
- **필수 읽기량** — 역할 문서와, 그 「먼저 읽는 것」 · 「이 저장소의 방식」 · 「끝날 때 고치는 것」이 가리키는 파일(백틱의
  뿌리 경로 · Markdown 링크, 폴더 빼고 중복 한 번)과 「먼저 읽는 것」이 번호로 부르는 ADR(`ADR NNNN` → `docs/adr/NNNN-*.md`, 2026-10-05 덧 —

## 정한 것

- **역할 문서는 Router 다.** 「이 저장소의 방식」은 원본을 가리키는 **Markdown 링크**와 그 원본이 무엇을 드는지 몇 낱말이고,
  규칙을 다시 말하지 않는다. 줄마다 한 줄이고 링크로 시작한다. 큰 원본은 절의 앵커까지, 한 주제 파일(위임 규약의 조각)은 파일까지.
- **「끝날 때 고치는 것」은 체크리스트를 옮겨 적지 않는다.** 원본의 체크리스트 — PR 칸은 `docs/agents/delegation/done.md`
  「끝났다는 것」, 노트는 `docs/agents/delegation/notes.md` 「세션 기록」 — 를 가리킨다. 그 원본이 안 드는 역할 고유의 「무엇을
  고치나」(화면의 문구 대장 · 운영의 runbook · DB 의 용어집 표)만 짧게 남긴다.
- **「하지 않는 것 · 묻는 것」은 짧은 인라인 금지 목록으로 둔다** — 손대기 전에 멈춰야 할 자리라 링크 너머에 두지 않는다. 대신
  줄마다 출처 링크를 단다.
- **「먼저 읽는 것」은 그대로다** — `` `경로` 「절」 `` 로 읽을 자리를 가리키고, 그 절이 있는지는 전처럼 시험이 잰다.
- **용어집은 역할 문서가 가리킨 절 · 낱말만 읽는다**(`docs/agents/domain.md`) — `CONTEXT.md` 를 통째로 읽으라던 줄을 고쳤다.
- **시험이 잠근다**(`scripts/code-rules.test.ts`): 옛 「줄 넷 이상 · `(원본: …)`」 검사를 걷고 — ① 역할 문서와 `docs/start.md` 의
  Markdown 링크가 있는 파일을, 앵커가 그 파일의 제목(GitHub 의 앵커 규칙)을 가리킨다 ② 「이 저장소의 방식」의 줄은 링크로
  시작하는 한 줄이고 `(원본:` 이 없다 ③ 「하지 않는 것 · 묻는 것」의 줄마다 링크가 있다 ④ 역할마다 필수 읽기량이 위 표의 「이
  결정 뒤」 값 이하다(회귀 상한 — 임의의 절대 상한은 두지 않는다).
- **읽기량의 원본은 잠근 날의 크기로 센다.** 간극 대장 · changelog · runbook 은 PR 마다 자라는데 그것은 길잡이의 회귀가 아니다 —
  지금 크기로 세면 다음 기능 PR 이 changelog 한 줄로 붉어진다. 역할 문서 자신과 잠근 날에 없던 새 원본은 지금 크기로 센다. 원본을
  쪼개 줄였으면 상한도 내리고, 늘리려면 PR 에 까닭을 적는다.

## 치르는 값

- 역할 문서만 읽고는 규칙을 모른다 — 링크를 따라가야 한다. 그 대신 줄인 문장이 원본과 갈라질 자리가 없다.
- 앵커는 제목 글자에서 나온다 — 원본의 제목을 바꾸면 링크가 붉어진다(절을 옮기면 가리키는 쪽도 옮긴다는 ADR 0140 의 값 그대로).
- 읽기량 상한은 파일 단위라 큰 원본 다섯이 대부분이다. 그 다섯을 쪼개기 전에는 크게 줄지 않는다.

## 잠그지 않은 것

- 큰 원본(`docs/ops/runbook.md` · `docs/prd.md` · `CONTEXT.md` · `docs/product/gaps.md` · `docs/product/prd-changelog.md`)을 주제별
  파일로 쪼개는 일 — 경로를 부르는 스크립트와 시험이 있어 따로 한다. 쪼개면 읽기량 상한을 내린다.
- 링크 옆 몇 낱말이 원본이 드는 것과 맞는가 — 시험은 링크가 닿는지까지만 잰다. 조율자가 라운드 끝에 본다.

## 덧 — 동적 라우트를 센다 (2026-10-05, 운영자 결정)

외부 검토가 짚었다 — 위 「필수 읽기량」은 **실제 파일만** 셌다. 「어느 파일인지는 색인이 답한다」로 고르는 파일과 디렉터리는 0 바이트였다.
`docs/roles/feature.md` 는 PRD 색인에서 그 기능의 영역 파일을, 용어집 색인에서 그 영역 파일을 골라 읽게 하는데 셈에는 색인 둘과
`foundation.md` 만 들었다. 그래서 영역 파일이 커져도 시험이 초록이었다.

- **읽기량 = 고정 + 동적 라우트마다 그 후보 가운데 최댓값.** 동적 라우트는 「여러 파일 중 하나를 골라 읽는다」는 가리킴이다.
- **표기는 디렉터리를 가리키는 Markdown 링크 하나다** — `[그 영역 파일](../context/)`. 후보는 그 디렉터리 바로 아래의 `.md`
  (README 와 그 역할이 이미 고정으로 읽는 파일은 뺀다). 백틱 디렉터리(`docs/product/prd/`)는 고르지 않았다 — 역할 문서가 이미
  `src/lib/reading/` · `app/ui/` · `docs/ops/runbook/` 처럼 「어디에 사는가 · 어디에 쓰는가」를 말하는 데 두루 쓰고 있어, 그것을 라우트로
  읽으면 코드 폴더까지 읽기량이 된다. 디렉터리 링크는 이 결정 전에 역할 문서에 한 번도 없었고, 링크 시험이 있는 디렉터리인지 잰다.
- **동적 후보는 지금 크기로 센다.** 고정 원본을 잠근 크기로 세는 까닭은 간극 대장 · changelog · runbook 이 PR 마다 자라기 때문인데,
  PRD · 용어집의 영역 파일은 그런 파일이 아니라 자라는 것이 곧 신호다 — 잠근 크기로 세면 이 덧이 잡으려는 회귀를 못 잡는다.
- **라우트 목록도 잠근다** — 상한 표가 역할마다 라우트를 든다. 디렉터리 링크를 작은 파일 하나로 바꿔치면 값은 줄어도 라우트가 사라진
  것으로 붉어진다.
- **세지 않는 것을 숨기지 않는다.** ① **ADR 본문은 영역마다 달라 세지 않는다** — 「그 영역의 ADR — 색인에서 번호만」은 후보가 영역마다
  다르고 커서 색인(`docs/adr/README.md`)만 센다. 「먼저 읽는 것」이 번호로 부른 ADR 만 고정으로 든다. ② 「끝날 때 고치는 것」의 쓰는
  자리(`docs/ops/runbook/` 의 그 작업 파일 · `docs/text/` 의 그 문서 · `docs/roles/`)는 백틱 디렉터리로 두어 세지 않는다 — 읽을 것이
  아니라 쓸 자리이고, runbook 은 PR 마다 자라는 파일이라 지금 크기로 세면 절차 한 줄이 세 역할을 붉힌다.
- **셈은 `scripts/read-budget.mjs` 한 곳이다.** 시험(`scripts/code-rules.test.ts`)과 `npm run read-budget`(역할마다 고정 · 동적 · 합 ·
  상한의 표)이 같은 함수를 부른다.

## 덧 — 선택 묶음을 센다 (2026-10-05, 운영자 결정)

`docs/roles/reviewer.md` 의 「먼저 읽는 것」은 「받은 관점의 원본」 **하나**를 읽으라면서 코드 규칙 · 층 · 시험 · 문서 · 운영의 원본을 한
줄에 다 적었다. 셈은 그 다섯을 모두 고정으로 셌다(보수적 과대 계산). 관점의 원본은 서로 다른 폴더에 있어 위 덧의 디렉터리 라우트로는
적을 수 없다 — 그렇다고 가짜 폴더를 만들지 않는다.

- **선택 묶음은 「서로 다른 자리의 파일 중 하나를 골라 읽는다」는 가리킴이다.** 표기는 머리 줄 `- 하나를 고른다 — <묶음 이름>` 과, 그
  바로 아래 두 칸 들여 쓴 `  - <선택지 이름> — <파일들>` 줄이다. 들여 쓴 줄 하나가 선택지 하나이고, 선택지는 파일 여럿일 수 있다
  (문서 관점 = PRD 색인 + 간극 대장). 머리 줄의 고정 낱말은 사람이 읽어도 「여기서 하나」라는 뜻이고, 기계는 그 낱말과 들여쓰기만
  본다 — 쉼표 · 「은/는」 같은 문장 꼴을 해석하지 않는다.
- **묶음의 값 = 선택지마다 그 파일들의 합 가운데 최댓값.** 선택지의 파일은 고정과 같은 크기 규칙(잠근 크기 `SIZE_AT_LOCK` · 그 밖은
  지금 크기)으로 센다. 디렉터리 라우트의 후보를 지금 크기로 세는 까닭(영역 파일이 자라는 것이 곧 신호)은 여기 서지 않는다 — 묶음의
  선택지는 고정으로 세던 원본(간극 대장 · runbook 처럼 PR 마다 자라는 파일)이 「받은 것 하나」로 옮겨 앉은 것이다.
- **두 번 세지 않는다.** 묶음 안의 파일은 고정 목록에 들지 않는다. 같은 파일이 묶음 밖의 줄에도 적혀 있으면 고정 쪽에서 세고 그
  선택지의 합에서는 0 이다(reviewer 의 「층」 — `docs/architecture.md` 는 「무엇이 잠겨 있나」 줄이 고정으로 든다).
- **꼴이 틀리면 셈이 멈춘다.** 머리 줄 아래 선택지가 둘 미만 · 선택지 줄의 꼴이 틀림 · 선택지에 파일이 없음 · 선택지가 디렉터리를
  가리킴이면 `scripts/read-budget.mjs` 가 던진다 — 잘못 읽은 채로 초록이 되지 않게.
- **묶음 목록도 잠근다.** `READ_BUDGET` 의 역할 항목이 묶음마다 이름과 선택지 이름의 차례를 든다 — 묶음을 평범한 줄로 되돌리거나
  선택지를 빼면 붉다. `readBudgetOf` 가 묶음(이름 · 선택지별 합 · 최댓값)을 돌려주고 `npm run read-budget` 표에 「묶음」 칸과 선택지별
  합이 선다. 시험과 출력 명령은 여전히 같은 함수다.

## 덧 — 선택지 안의 동적 라우트 · 관점 여덟 (2026-10-05, 운영자 결정)

외부 검토가 위 덧 둘을 다시 짚었다(조율자가 코드에서 확인).

- **선택 묶음이 색인만 셌다.** reviewer 의 선택지는 `docs/agents/code-rules.md` · `docs/agents/test-map.md` · `docs/prd.md` ·
  `docs/ops/runbook.md` **색인**을 가리켰고, 그 색인은 저마다 「고칠 자리에 맞는 주제 파일만 연다」고 한다. 그런데 셈은 선택지 안의
  디렉터리 링크를 오류로 막아 색인 뒤의 주제 파일을 적을 길이 없었다 — 첫 덧이 고친 「색인으로 고르는 파일이 0 바이트」가 선택지 안에서
  되살아난 것이다.
- **관점은 여덟인데 선택지는 다섯이었다.** 역할 문서와 감사 노트(`docs/notes/2026-09-28-overnight-audit.md` 「팀 — 감사(읽기만)」)는
  코드 규칙 · 아키텍트 · 시험 · 보안 · DB · 프런트 · 문서 · SRE 여덟을 말하는데 묶음은 코드 규칙 · 층 · 시험 · 문서 · 운영 다섯이었고
  위 덧이 그 이름과 차례를 잠갔다. 보안 · DB · 프런트를 받은 검토자는 따를 선택지가 없었다.

정한 것:

- **선택지 안에도 동적 라우트를 둔다.** 표기는 묶음 밖과 같다 — 디렉터리를 가리키는 Markdown 링크(`[그 주제 파일](../agents/code-rules/)`).
  **선택지의 값 = 그 선택지의 파일 합 + 그 안 라우트마다 후보 최댓값.** 파일은 고정과 같은 크기 규칙(잠근 크기), 후보는 지금 크기다 —
  첫 덧과 같은 까닭(주제 파일이 자라는 것이 곧 신호다). 중복은 지금 규칙 그대로다: 묶음 밖에도 적힌 파일은 고정에서 한 번, 같은 파일이
  두 선택지에 있으면 선택지마다 한 번, 라우트의 후보에서는 README 와 고정 · 그 선택지의 파일을 뺀다. 묶음의 값은 여전히 선택지 값의
  최댓값이다. 선택지에 파일이 하나도 없으면(디렉터리만이면) 셈이 던진다 — 선택지는 원본(색인)을 들고, 그 뒤에서 고르는 것만 라우트다.
- **`READ_BUDGET` 의 묶음 잠금이 선택지마다 라우트도 든다** — 선택지의 디렉터리 링크를 색인 파일 하나로 바꿔치면 값이 같아도 라우트가
  사라진 것으로 붉다.
- **선택지는 관점 여덟이고 이름은 받은 관점과 같다.** 새 문서를 만들지 않고 이미 있는 원본에서 고른다 — 근거는 감사 노트의 「팀」 절이
  그 관점에 무엇을 보게 했나와 그 영역 역할 문서가 가리키는 원본이다. 같은 원본을 둘 이상이 나눠 가져도 된다.
