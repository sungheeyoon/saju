# 묶음 가격은 상수 하나에 있고, DB 의 가격표는 시험이 그 상수와 묶는다

> **운영자 결정 2026-10-12**(시스템 점검 라운드의 후속, 조율자가 전함): 「가격은 상수 하나 + 시험」.

## 사정

풀이권 묶음의 가격(1회 4,900 · 3회 12,900 · 5회 19,900 · 20회 59,000원, ADR 0100)이 네 곳에 따로 적혀 있었고 서로 묶는
시험이 없었다 — `READING_BUNDLES`(`src/lib/reading/bundle.ts`), 약관 제12조 가격표와 제16조 환불 예시(`src/lib/brand/terms.ts`),
환불정책의 예시(`src/lib/brand/refund.ts`), DB 함수 `reading_bundle_price`(주문 금액을 정한다). 2026-10-12 에 잰 값은 넷이 같았다.
하나만 바꾸면 사람이 읽은 가격과 카드에 걸리는 금액이 갈린다.

## 정한 것

1. **원본은 `READING_BUNDLES` 다.** 약관 · 환불정책의 가격 · 1회당 값 · 할인율 · 환불 예시 금액은 그 상수에서 짓는다
   (`src/lib/brand/bundle-prices.ts`). 문장은 그대로이고 숫자만 끼운다 — 끼우기 전과 끼운 뒤의 글이 글자 하나까지 같음을
   `src/lib/brand/bundle-prices.test.ts` 가 옛 글자로 잰다. 그래서 `brand → reading` 방향이 열린다(`docs/architecture.md`).
2. **DB 의 가격은 그대로 DB 가 정한다** — 결제 금액을 화면이 보낸 값으로 받지 않는다(ADR 0106). 대신
   `app/me/credits/bundle-price.test.ts` 가 마이그레이션에서 `reading_bundle_price` 의 마지막 정의를 읽어 상수와 같은 회차 · 가격만
   드는지 잰다. 가격을 바꾸는 PR 은 상수와 새 마이그레이션을 함께 고쳐야 초록이다.
3. **가격을 바꾸면 약관 시험도 붉다** — 옛 글자를 기대값으로 든 시험이라, 바꾸는 사람이 약관 · 환불정책의 개정(시행일 · 고지)을
   함께 연다.

## 버린 것

- **pgTAP 으로 견준다** — pgTAP 은 상수를 못 읽어 값을 또 한 번 적게 된다. 마이그레이션을 읽는 꼴은 `settle.test.ts` 의 주문 번호
  시험이 이미 쓴다.
- **DB 가 상수를 읽는다(가격 표를 만들어 앱이 읽는다)** — 판매가 닫힌 운영 베타에서 표 · 문 · 마이그레이션을 늘릴 값이 없다.
