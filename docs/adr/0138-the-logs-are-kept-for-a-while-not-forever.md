# 기록 셋은 끝없이 쌓이지 않는다 — 노출 기록 180일 · 소식 90일 · 크론 실행 이력 14일

> **초안 — 운영자 답 대기(2026-09-30).** 보존 기간은 `docs/agents/delegation.md` 「결정 점검표」의 「데이터의 보존 · 삭제 ·
> 보관 기간」이다. 아래 기간과 방식은 에이전트의 제안이고, 운영자가 답하면 이 머리말을 그 답(날짜 · 문장)으로 바꾼 뒤 머지한다.
> 기간을 바꾸면 `retention.impression_period()` · `notification_period()` · `cron_run_period()` 한 줄씩과 pgTAP 75 의 마지막 줄이다.

## 잰 것 (2026-09-30)

- **셋 다 지우는 자리가 없다**(밤샘 감사 DB 5 · 7 · 11, `docs/notes/2026-09-28-overnight-audit.md`). 다른 보존은 크론이 든다 —
  신고(6개월, ADR 0098) · 거절된 결제(`payment-retention-purge`) · 탈퇴 처분(`account-disposal`).
- 운영의 크기(집계만, `npm run db:remote`): `discovery_impression` 241줄 384 kB(가장 오래된 줄 2026-09-11) · `notification` 10줄 ·
  `cron.job_run_details` **30,160줄 5 MB**(2026-09-10 부터, 하루 약 1,500줄 — 매분 도는 복구기가 대부분). 계정 15.
- 노출 기록은 사람이 카드를 받을 때마다 한 줄이다(덱은 여섯 자리 · 떠나면 한 명씩 채움, ADR 0115). 사람 수 × 넘기는 수로 자란다.
- 노출 기록을 읽는 자리는 넷이다 — `request_match`(내가 본 **그** 카드 — 지금 요약이 같은 가장 최근 줄), `discovery_shown_to_me`
  (넘김의 정책, `20261031090000`), `restore_passed_connection`(되돌리면 새 줄을 적는다), `report_user`(신고할 수 있는 사람의
  근거 하나 — 내게 선 적이 있다 · 요청이 오갔다 · Match).
- 종은 최근 50줄만 그린다(ADR 0130 「치르는 값」).
- 감시기(`watch_cron`)는 크론 이력의 지난 한 시간을, runbook 의 점검 질의는 24시간을 본다.

## 제안

| 기록 | 기간 | 방식 | 까닭 |
| --- | --- | --- | --- |
| 크론 실행 이력(`cron.job_run_details`) | **14일** | 매일 지움 | 읽는 자리가 한 시간 · 하루다. 사람의 기록이 아니다. 지금 자라는 것은 이것뿐이다 |
| 소식(`notification`) | **90일** | 매일 지움 | 종은 최근 50줄만 그린다 — 90일 넘은 소식은 대부분 이미 안 보인다 |
| 노출 기록(`discovery_impression`) | **180일**, **지금 덱에 선 카드의 줄은 남김** | 매일 지움 | 요청 · 넘김이 덱의 카드 줄을 찾는다 — 덱은 이어지므로 카드가 몇 달 설 수 있다. 추천의 모양(점수 · 탐색)을 되짚는 기록이라 한 철은 둔다 |

크론 하나(`log-retention-purge`, 매일 04:37 UTC)가 셋을 돈다 — `retention.purge_old_logs()`. 여러 번 돌아도 안전하고, 실패는
`cron-watch` 가 알린다. 날짜로 지우는 둘에 시각 색인을 더했다.

**베타 동안은 종료 뒤 파기(처리방침)가 먼저 온다** — 베타는 2026-10-31 에 끝나므로 이 기간이 뜻을 갖는 것은 공개 출시 뒤다.
기간을 줄이는 것이라 처리방침의 「베타 종료 후 파기 시점까지」와 어긋나지 않는다. 공개 출시의 처리방침(G-25)에 셋의 기간을 옮겨
적을지는 그때 정한다.

## 치르는 값

- **180일이 지나고 요청 · Match 도 없던 사람은 더는 신고할 수 없다** — `report_user` 의 근거 하나(내게 선 적이 있다)가 사라진다.
  「누가 무엇을 할 수 있는가」에도 걸리는 대가다. 덱에 아직 선 사람은 남는다.
- `match_request.impression_id` 가 비는 요청이 생긴다(`on delete set null`) — 요청 · 풀이권 · Match 는 그대로이고 「어느 카드에서
  왔나」만 빈다. 추천 정책을 되짚는 분석은 180일 안에서만 된다.
- 소식이 적은 사람에게는 90일 넘은 소식이 종에서 사라진다.
- 크론이 실패한 날을 14일 넘어서는 이력으로 되짚을 수 없다 — 알림(`ops_alert`)은 남는다.

## 고르지 않은 것

- **지우지 않는다** — 지금 크기로는 몇 해를 버틴다(크론 이력 연 90 MB 안팎). 그러나 Free 의 500 MB 안이고, 노출 기록은 사람 수에
  비례해 자란다. 기한 없는 보관은 「불필요하게 되었을 때 지체 없이 파기」(개인정보 보호법 제21조①, ADR 0098 이 읽은 원문)와 맞지 않는다.
- **노출 기록을 짝마다 가장 최근 한 줄만 남긴다** — 넘길 때마다 새 사람이라 짝의 수가 줄 수와 거의 같다. 줄지 않는다.
- **소식을 읽은 것만 지운다** — 읽지 않은 소식도 50줄 밖이면 안 보인다. 갈래가 늘 뿐이다.
