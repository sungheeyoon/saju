# 모양도 단언한다 — 행동만 재던 자리에

## 후보 문장이 반쯤 틀렸다 (2차 라운드 다섯 번째)

이슈 #88 후보 3은 「**함수의 지금 정의를 저장소에서 못 읽는다**」였다. 딸린 수는 이번엔
**전부 맞았다**: 마이그레이션 81 · `create function` 310 · 이름 160 · `create_self_person`
10벌 · `add_person_revision` 9벌 · pgTAP `policies_are`·`is_definer`·`col_type_is` 0건.

그런데 **문장이 가리키는 곳이 틀렸다.** 정의는 읽을 수 있다 — 그 이름을 마지막으로 적은
마이그레이션을 찾으면 된다. 재서 좁힌 수는 이렇다.

- 이름 160 중 **살아 있는 것 135**, 마지막이 `drop` 인 것 25
- 두 번 이상 다시 적힌 이름 **69**(정의 219개를 차지) · 한 번만 적힌 이름 **91**
- 마지막 정의 160개 중 **`security definer` 121**

진짜 구멍은 **아무도 모양을 단언하지 않는다**는 쪽이다. pgTAP 825건은 전부 **행동**을
잰다(`throws_ok` 133 · `is(` 493 · `ok(` 248). 되쓰기 사고 — 옛 마이그레이션을 베꼈다가
운영자 풀이권 예외와 하루 상한이 통째로 되감긴 그 사고(`20260925180000` 머리말) — 는
**함수가 다시 적히면서 조용히 달라진 권한과 깃발**이었고, 행동을 재는 시험은 그것을 못 본다.

## 잠근 넷 — 전부 재서 골랐다

`supabase/tests/33_function_shape.test.sql`. 값은 2026-09-22 에 **로컬과 운영 양쪽에서** 쟀다.

| 잠근 것 | 로컬 / 운영 |
|---|---|
| PUBLIC 에 실행이 열린 public 함수 | 0 / 0 |
| `anon` 이 부를 수 있는 함수 | **3 / 3** — 이름·인자까지 같다 |
| RLS 가 꺼진 public 표 | 0 / 0 (표는 27개) |
| `search_path` 가 안 걸린 `security definer` | 0 / 0 (definer 는 107 / 108) |

**수를 단언하지 않는다.** 「definer 가 107개」는 함수 하나 늘 때마다 깨지고, 그것은 잠금이
아니라 소음이다. 잠근 것은 **성질**이다 — 늘어나도 참이어야 하는 것.

`anon` 쪽만 집합으로 잠갔다. 셋(`beta_is_over()` · `current_beta_schedule()` ·
`shared_reading(p_token text)`)은 저마다 로그인 앞에 서야 할 까닭이 있고, 하나가 늘면
**이름이 함께 드러나야** 「이 문이 왜 거기 서는가」를 물을 수 있다. 수만 재면 하나 늘고 하나
줄 때 조용히 통과한다.

## 이빨이 있는지 **깨뜨려 증명했다**

넷 다 「0개다」 꼴이라 통과하는 것만 봐서는 이빨을 모른다(ADR 0074 가 같은 함정에서 P1 을
냈다). 롤백하는 트랜잭션 안에서 하나씩 깨뜨려 세는 수가 실제로 움직이는지 봤다.

| 깨뜨린 것 | 세는 수 |
|---|---|
| `grant execute … to public` | 0 → **1** |
| `grant execute … to anon` | 3 → **4** |
| RLS 없는 표를 만든다 | 0 → **1** |
| `search_path` 없는 definer 를 만든다 | 0 → **1** |

롤백 뒤 기준값이 0/3/0/0 으로 돌아왔고 probe 가 남긴 것은 없다.

그리고 **빈 집합에 대고 참이 되는 것**도 막았다(5·6번 단언). 셋이 「0개다」라서, 스키마를
못 읽는 자리에서 도는 날 전부 조용히 통과한다 — definer 가 쉰 개를 넘고 표가 스무 개를
넘는다는 것을 함께 든다.

## 재다가 나온 것 — **운영에만 있는 한 쌍**

운영과 로컬의 `public` 객체를 통째로 견주니 **운영에만 둘이 있었다.**

- `rls_auto_enable()` — `event_trigger` 를 반환하는 `security definer` 함수. `public` 에
  `create table` 류가 돌면 `alter table … enable row level security` 를 걸고, 실패는
  `raise log` 로 삼킨다. 소유자 `postgres`, ACL 도 `postgres` 뿐이라 **밖에서 부를 길은 없다**
- `ensure_rls` — 그 함수를 `ddl_command_end` 에서 쏘는 **켜져 있는** 이벤트 트리거

**저장소 어디에도 없다**(전수 확인). 즉 운영에는 「새 표는 RLS 가 켜진 채로 태어난다」는
그물이 있고 **로컬·CI 에는 없다.**

**지금 이것이 가리는 것은 없다.** 표 27개의 RLS 상태가 양쪽 다 똑같이 전부 켜짐이다 —
마이그레이션이 스스로 켜 왔다. 그물이 걸러낸 적이 한 번도 없다는 뜻이다.

그래도 적어 두는 까닭은 둘이다. **운영을 마이그레이션으로 다시 지으면 그 그물이 조용히
사라진다.** 그리고 반대로, 누가 RLS 없는 표를 만드는 마이그레이션을 쓰면 **로컬·CI 는
빨개지고 운영은 조용히 덮는다** — 같은 코드가 두 환경에서 다른 뜻이 된다. 위 3번 단언이
로컬 쪽 그물 노릇을 한다.

**무엇을 할지는 안 정했다.** 마이그레이션에 넣어 저장소가 아는 것으로 만들거나, 운영에서
걷거나, 일부러 둔다고 적거나 — 운영 DB 에 대한 결정이라 사람이 고를 일이다.

## 안 한 것

- **`supabase db diff --linked` 로 대조하지 않았다.** 그림자 DB 에 마이그레이션 81개를 다
  적용한 뒤 운영 접속에서 막힌다(`SUPABASE_DB_PASSWORD` 가 필요하다). 그래서 **「그 도구가
  이 드리프트를 잡는가」는 모르는 채로 둔다** — 못 잡는다고 적으면 안 재고 말하는 것이다.
  이번에 찾은 길은 양쪽 목록을 손으로 견준 것이다.
- **마이그레이션을 재배열하지 않았다.** 310개를 160개로 접는 일은 이 잠금이 선 뒤에 할
  일이고, 접는 동안 모양이 안 달라졌다는 것을 이 파일이 말해 준다.
