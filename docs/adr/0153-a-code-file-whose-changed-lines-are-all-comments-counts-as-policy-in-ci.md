# 바뀐 줄이 전부 주석인 코드 파일은 CI 에서 정책으로 센다

> **운영자 결정 2026-10-08**(대화에서, CI 범위) — PR #519 가 문서 정정에 `app/layout.tsx` 주석 한 줄이 섞여 공용 위험(`layout`)으로
> 전부(약 11분)를 돌았다. 「md 만 바꿨는데 CI 다 도는 게 말이 되냐」 — `scripts/ci-plan.mjs` 가 diff 를 보고 가리는 안을 골랐다.

ADR 0082(판단은 `ci-plan.mjs` 한 곳) · 0097(공개 출시 전 PR 은 빠른 검사) · 0119(공용 위험은 전부)에 한 줄을 더한다. 규칙의 원본은
`scripts/ci-plan.mjs` 머리 「주석만 바뀐 코드 파일은 정책으로 센다」다.

## 정한 것

- **PR 에서 코드 파일(`.ts` · `.tsx` · `.mjs` · `.js` 와 그 갈래)의 더한 줄과 지운 줄이 전부 주석이거나 빈 줄이면 그 파일은 정책이다.**
  다른 파일이 없으면 PR 이 `policy`(scripts 시험 · 타입 · 린트)다. 주석이 아닌 줄이 하나라도 바뀌면 지금 규칙 그대로다 — 공용 위험이면 전부.
- **애매하면 주석이 아니다.** JSX 주석 · 블록 가운데의 `*` 없는 줄 · 문자열 · 템플릿 속의 `//` · 주석 뒤에 코드가 붙은 줄 · 린트 · 타입 ·
  번들러가 읽는 지시 주석은 주석으로 세지 않는다. 파일 추가 · 삭제 · 이름 바꿈 · 모드 변경도 가르지 않는다.
- **diff 를 못 받으면 지금 규칙 그대로다.** 계획 job 이 `git diff -U0` 를 파일로 넘기고(`--diff`), 못 받으면 빈 파일이다. main 푸시 · 일정 ·
  손으로 켠 실행은 전처럼 계획을 안 보고 전부다. `supabase/**` 는 주석을 가르기 전에 전부다.

## 치르는 값

- 주석 판정은 문법 분석기가 아니라 줄을 따라가는 작은 훑기다(`codelessLinesOf`). 틀리는 쪽이 코드를 코드로 읽게 짰지만, 정규식과
  나눗셈을 헷갈리는 드문 줄은 남는다 — 그 자리의 붉음은 머지 뒤 main 의 전체가 잡는다.
- 정책 단계는 `scripts/` 밖을 린트하지 않는다. 그래서 린트가 읽는 주석은 지시 목록(`TOOL_DIRECTIVE`)으로 뺀다 — 목록에 없는 새 지시는
  주석으로 세어진다.
- 2026-10-08 에 main 의 최근 커밋 300 개를 넣으니 코드 파일 변경 1,600 건 중 194 건이 주석만이었고, 그 바뀐 줄을 훑어 코드는 없었다.
