# 바뀐 줄이 전부 주석인 코드 파일은 CI 에서 정책으로 센다

> **운영자 결정 2026-10-08**(대화에서, CI 범위) — PR #519 는 문서 정정에 `app/layout.tsx` 주석 한 줄이 섞여 공용 위험(`layout`)으로
> 전부(약 11분)를 돌았다. 운영자가 「md 만 바꿨는데 CI 다 도는 게 말이 되냐」고 했고, `scripts/ci-plan.mjs` 가 diff 를 보고 가리는 안을 골랐다.
> 같은 날 두 번째 의견을 받아 판정을 줄 무늬가 아니라 파서의 구문 나무로 하기로 했다.

ADR 0082(판단은 `ci-plan.mjs` 한 곳) · 0097(공개 출시 전 PR 은 빠른 검사) · 0119(공용 위험은 전부)에 한 줄을 더한다. 규칙의 원본은
`scripts/ci-plan.mjs` 머리의 「주석만 바뀐 코드 파일은 정책으로 센다」다.

## 정한 것

- **PR 에서 코드 파일(`.ts` · `.tsx` · `.mjs` · `.js` 와 그 갈래)이 base 와 구문 나무가 같으면, 그 파일은 정책이다.** 나무는 노드
  종류 · 식별자 · 리터럴 · 연산자로 견주고 위치와 트리비아(주석 · 공백)는 뺀다. 다른 파일이 없으면 PR 이 `policy`(scripts 시험 · 타입 · 린트)다.
  나무가 하나라도 다르면 지금 규칙 그대로다. 공용 위험이면 전부다. 줄바꿈이 자동 세미콜론으로 뜻을 바꾸면 나무가 달라진다.
- **판정은 파서로 한다.** 계획 job 이 PR 에서만 `npm ci` 로 `typescript` 를 깔고 merge-base 를 `--base` 로 넘긴다. 옛 소스는 그 커밋에서 읽는다.
- **아래는 지금 규칙 그대로 간다(닫히는 쪽).** 뜻이 있는 주석(`@ts-…` · `eslint…` · `/// <reference` · `@jsx…` · 번들러 · 커버리지 지시)이
  더해지거나 지워지거나 옮은 파일이 그렇다. 파싱 진단이 하나라도 있을 때, 가르지 않는 확장자일 때도 그렇다. 옛 소스를 못 읽을 때(추가 · 삭제 ·
  이름 바꿈 · 실행 비트 변경), 파서를 못 불렀을 때, PR 계획 밖일 때(main 푸시 · 일정 · 손으로 켠 실행)도 그렇다. `supabase/**` 는
  이것보다 먼저 전부다.

## 치르는 값

- 계획 job 이 PR 마다 `npm ci` 를 한 번 더 돈다. 캐시가 받쳐 수십 초다. 설치가 실패하면 판정 없이 지금 규칙으로 간다.
- 정책 단계는 `scripts/` 밖을 린트하지 않는다. 그래서 린트가 읽는 주석은 지시 목록(`MEANINGFUL_COMMENT`)으로 뺀다. 목록에 없는 새 지시는
  주석으로 세어진다.
- 2026-10-08 에 main 의 최근 커밋 300 개를 넣어 보았다. 코드 파일 변경 1,597 건 중 217 건이 주석만으로 세어졌다. 그 217 건의 바뀐 줄 가운데
  `//` · `/*` · `*` 로 열지 않는 줄은 전부 블록 주석이나 JSX 주석 속의 산문이었다.
