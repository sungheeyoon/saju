## 잰 것 (2026-10-03)

- 0131 의 720칸 공용 표는 같은 일주 · 같은 달의 모든 사람에게 같은 글을 세운다 — 「내 얘기」가 되기 어렵고, 가입 뒤 전체
  풀이와 이어지는 자리가 없다.
- 실호출 4회(운영자 허락, 노트 「실호출 결과」) — 추론 `none` 의 맛보기는 한 번 **약 4원**(1차 평균 약 3.6원), 시간 중앙값
  **4~5초** · 최댓값 **6초 안**(1차 4.8 / 6.0초, 4차 4.4 / 5.7초)이었다. `low` 는 느리고(7.9 / 10.7초) 비싸고 검사를 덜 지났다.
- 1차의 한 꼴 지시(장점 → 문제 → 해결 직전)와 「글 먼저, 근거 나중」 차례는 명식이 달라도 같은 줄거리(「혼자 버팀 → 부담 →
  나눔」)로 모였다. **숨은 판단을 먼저 내게 하고 꼴을 여덟으로 둔** 2차부터 주제가 갈렸고 근거 경로 실패가 0 이 되었다.
- 맛보기 끝의 「다음을 예고하는」 문장이 합니다체로 미끄러지고 가입을 에둘러 가리켰다(2차 3/9). 끝을 장면 안의 물음으로
  바꾼 4차는 6/6 이 그 모양으로 멈췄다.
- 전체 풀이의 첫 절 1번이 이어쓰기 답을 다른 말로 되풀이했다(1 · 2차) — 지시 한 줄로는 안 막혔다. 1번을 이어쓰기 답 자체로
  세운 3차는 3/3 이 답을 한 번만 말했다.

## 정한 것

### 1. 맛보기는 사람마다 모델이 쓴다

- 로그인 전 방문자가 생년월일시를 넣으면 **우리 서버**가 엔진으로 명식을 계산하고, 맛보기 근거(자기 풀이 근거에서 해 ·
  나이 · 날짜를 드러내는 칸을 뺀 것, `tasteEvidenceOf`)로 모델을 한 번 부른다. 모델 설정 — 추론 `none` · 출력 상한 1,500 토큰
  (추론 포함) · 시간 상한 20초 · `store: false`. 모델을 부르는 자리는 여전히 `app/me/reading/model.ts` 하나다(ADR 0047).
- **출력 계약은 숨은 판단이 먼저다** — 구조화 출력이 속성 차례대로 짓는다(`tasteRunShapeOf`):
  `topic`(여덟 꼴 중 하나) → `distinctivePattern` → `supportingClaims`(그 사주의 허용 경로 enum — 사람마다 다르다. 모델이 붙이는
  `chart.` 접두만 정규화한다) → `continuationQuestion` → `answerDirection` → **`previewMarkdown` 마지막**. 숨은 칸은 화면에 안 선다.
- **끝은 장면 안의 물음이다.** 맛보기는 `continuationQuestion` 과 같은 궁금증을 그 장면의 말로 묻는 한 문장(「~까요?」)으로
  멈춘다. 다음 글 · 풀이 · 가입을 예고하는 메타 문장은 금지이고 검사가 막는다(`checkTasteRun`).
- **실패해도 엔진 문장으로 바꿔치기하지 않는다.** 0131 의 「표가 비면 엔진의 발화가 선다」는 이 자리에서 걷는다 — 모델이 쓴
  글인 것처럼 보이는 다른 글을 세우지 않는다. 실패한 자리의 모양과 문구는 앱 PR 이 문구 대장으로 든다.

### 2. 가입 뒤 전체 풀이는 맛보기가 멈춘 물음에서 잇는다

- 이어진 맛보기 세션(아래 4)이 **있을 때만** 자기 풀이가 `continuationAnswer` 를 받는다 — 출력의 맨 앞 칸이다. 없으면 지금
  모양 그대로다(`readingPromptOf` 의 기본 출력은 한 글자도 안 바뀐다).
- 프롬프트는 **저장된 맛보기 스냅숏**(원문 · 물음 · 답의 방향 · 근거 경로)을 싣는다 — 다시 생성하거나 표를 읽지 않는다
  (`continuationBlockOf`). 답은 그 물음에 바로 답하고 거기서 완결한다(미루는 말 금지, `checkContinuation`).
- **첫 절 「먼저 볼 핵심 세 가지」의 1번 본문 = `continuationAnswer`, 한 번만.** 모델은 2 · 3 만 쓰고 앱이 1번을 끼운다
  (`continuedMarkdownOf`). 첫 절 항목 번호가 2 · 3 이 아니면 검사에 걸린다.
- 전체 풀이가 만들어지는 동안 화면에는 **「아까 보던 내용」(저장 스냅숏)과 실제 서버 진행만** 선다 — 진행을 지어내지 않는다.

### 3. 남용 방어 — 모델 호출 전에 원자적으로 예약한다

- **전역 artifact 재사용** — 생성 결과는 `UNIQUE(근거 지문, 프롬프트 판, 모델 설정 판)` 한 행(`taste_artifact`)이다. 같은 입력은
  브라우저 · 쿠키 · IP 가 달라도 모델을 다시 안 부른다. 브라우저마다의 기록은 세션(`taste_session`)으로 따로 둔다.
- **원자적 예약** — `reserve_taste` 가 한 트랜잭션으로 재사용 · 기다림 · 한도 · 예산을 가르고 **모델을 부르기 전에** 칸을 쓴다.
  자물쇠 차례는 늘 IP → 브라우저 → artifact → 전체 하루 행이다. 한도에 걸리면 아무것도 늘지 않는다.
- **상한 값**(이름 붙은 상수 함수에 산다 — `taste_daily_model_calls()` 들):

  | 값 | 수 |
  | --- | --- |
  | 서비스 전체 실제 모델 생성 / 하루(서울 날짜) | 2,000 — 80% 에 `taste-budget-warning`, 닿으면 `taste-budget-reached` |
  | 브라우저 하나의 새 근거 지문 / 1시간 | 5 |
  | IP 하나의 모델 생성 | 1분 3 · 하루 20 |
  | IP 하나의 요청(캐시 적중도 센다) | 1분 30 |
  | artifact 하나의 모델 시도 | 3(처음 + 자동 재시도 2) |

- **실패한 호출도 상한에 든다** — 예산은 부르기 전에 쓴다. 날짜 경계는 풀이 예산과 같은 서울 자정이다.

### 4. 귀속 — 가입한 사람에게 세션을 붙인다

- 브라우저 묶음은 **httpOnly 쿠키 + 서버 HMAC** 이다 — 쿠키 원문은 고엔트로피 무작위 값이고, 서버가 안정 비밀
  (`TASTE_BROWSER_SECRET`)로 HMAC 해 DB 에 그 값만 보낸다. 가입 왕복이 드는 것은 세션 id 와 그 쿠키뿐이다.
- 귀속 · 잇기 문(`claim_taste_session` · `link_taste_reading_run` · `taste_continuation_of_run`)은 **열쇠 + 첫 인자 `p_user_id`**
  다 — 사람 id 는 서버가 로그인 세션에서 얻는다(ADR 0136 의 꼴). 판정이 서버가 다시 잰 지문과 서버만 짓는 HMAC 에 기대므로
  로그인 문(`auth.uid()`)으로 열지 않는다. 정지 · 베타 종료 · 가입 미완은 DB 가 여전히 막는다.
- 「이 사주가 내 사주 맞나요?」에서 확정한 입력으로 서버가 지문을 다시 잰다. **지문이 다르면 그 세션은 버린다**(`discarded`) —
  이어쓰기 없는 보통 자기 풀이로 간다.
- **세션 하나 = 풀이 하나.** 이어진 풀이가 성공했으면 다시 눌러도 새로 만들지 않고 그 풀이를 연다. 실패했을 때만 다시 만들고,
  풀이권 규칙(PRD §2 — 누를 때 1개, 실패는 안 쓴다)은 그대로다.

### 5. 보존

- 미가입 세션 · artifact · 한도 사건 기록은 **생성 시각부터 24시간, 연장 없음**(`taste_keep_for()`). 크론 `taste-sweep`(5분마다)이
  지운다 — 시간을 넘긴 시도(60초)도 실패로 닫는다.
- 귀속된 세션은 그 회원의 풀이 자료로 **풀이와 함께** 남고 탈퇴 때 지워진다(`auth.users` → `app_user` → 세션 cascade).
- 날짜별 수(`taste_daily_count`)는 개인을 가리키는 칸이 없어 지우지 않는다.

### 6. 개인정보 — 무엇이 어디로 가나

- **생년월일시 원문은 서버만 계산에 쓰고 저장하지 않는다.** DB 에 원문을 받는 칸이 없다.
- **모델(OpenAI, 국외)에 가는 것** — 여덟 글자 · 성별 · 시간 앎과 허용된 분석값. 해 숫자 · 나이 · 절기 날짜 · 출생지 · 이름 ·
  연락처 · IP 는 안 간다.
- **잠그지 않는 사실 둘을 적어 둔다.** 근거 지문(SHA-256)은 비밀이 아니다 — 경우의 수가 적어 대입으로 풀린다(열쇠이지 가림이
  아니다). **여덟 글자는 60년 주기 안에서 날짜와 2시간 범위로 역산된다** — 원문은 안 나가지만 출생 날짜 · 시간대에 준하는 값이
  식별자 없이 나간다. 이것이 처리방침 · 국외 이전 고지에 무엇을 요구하는지는 변호사에게 묻는다(G-66 `[변호사 검토 필요]`).
- IP 는 서버가 **날짜별 키**(`HMAC(TASTE_IP_SECRET, 날짜)`)로 HMAC 한 값만 DB 에 가고 24시간 뒤 지운다. 쿠키는 안정 비밀의
  HMAC 이다 — 날짜별로 돌리지 않는다(자정을 넘겨 가입한 사람이 다른 브라우저가 되지 않게).
- **화면 고지 문구(운영자가 정했다)** — 「입력한 생년월일시는 우리 서버에서 사주를 계산하는 데만 쓰고 저장하지 않아요. 풀이를
  쓰는 OpenAI에는 정확한 생년월일시와 출생지 대신 계산된 사주와 분석값만 보내요.」(**2026-10-08 화면에서 걷었다 — 맨 아래 덧**) 운영자 결정(2026-09-29) 「화면에 AI 를 새로
  세우지 않는다」의 **예외**로, 받는 곳의 이름(OpenAI)을 적는다. 문구 대장 등록과 화면은 앱 PR 이다. 처리방침 개정이 필요한지는
  G-66 이 든다 — 이 고지가 그 답을 대신하지 않는다.

### 7. 비용

- 공식 단가 gpt-5.6-luna — 입력 $0.20 · 캐시 입력 $0.02 · 캐시 쓰기 1.25배 · 출력 $1.20 /1M 토큰
  (https://developers.openai.com/api/docs/models/gpt-5.6-luna, 2026-10-03 확인).
- 실측 맛보기 한 번 **약 4원 · 4~6초** → 하루 상한 2,000 을 다 써도 **하루 약 8천원 이하**다. 같은 입력의 재사용은 0원이다.
- 금액은 DB 가 내지 않는다 — `taste_daily` 가 토큰까지 내고 runbook 이 단가를 곱한다. 바깥 벽은 그대로 OpenAI 대시보드의 월 예산이다
  (ADR 0039).

### 8. 퍼널 — 여섯 단계, 날짜별 수만

맛보기 생성 성공 → 더보기 클릭 → 가입 시작 → 가입 완료 · 세션 귀속 → 전체 풀이 시작 → 전체 풀이 성공. 이름 · 출생 정보 · 지문
없이 날짜 × 단계의 수만 센다(`taste_daily`). DB 가 스스로 아는 단계(맛보기 성공 · 귀속 · 풀이 시작)는 DB 가, 화면만 아는 단계
(더보기 · 가입 시작 · 가입 완료 · 풀이 성공)는 앱이 `count_taste_step` 으로 센다 — 가입 완료와 귀속은 칸이 따로다. 「하루 2,000 회에
몇 명이 가입했나」를 판단하는 자다.

## 왜 0131 을 대체하나

0131 은 「로그인 전 방문자의 입력이 모델 제공자로 나가지 않는다」와 「방문 한 번의 비용 0」을 얻으려고 글을 미리 만들었다. 실호출이
보인 것은 그 대가였다 — 공용 글은 「내 얘기」가 아니고, 가입 뒤 풀이와 이어지는 물음이 없다. 비용은 하루 상한과 재사용이 위에서
막고(하루 약 8천원 이하), 입력은 원문이 아니라 여덟 글자와 분석값만 나간다. 그 대신 **로그인 전 생년월일시가 우리 서버로 오고,
여덟 글자가 국외 모델 제공자로 간다** — 0131 에 없던 새 처리이고, 그래서 G-66 을 닫지 않는다.

## 대가

- 로그인 전 첫 화면이 모델 장애 · 지연에 묶인다(20초 상한). 실패하면 맛보기 칸에 대신 설 글이 없다.
- 한도에 걸린 방문자(같은 사무실 IP · 하루 2,000 소진)는 맛보기를 못 받는다 — 비용을 위에서 막는 값이다.
- 근거 지문은 가림이 아니다. 지문 · 여덟 글자가 개인을 다시 가리킬 수 있다는 사실을 문서가 숨기지 않는다.
- 옛 표(`taste_passage`) · 만들기 스크립트 · 대체 문장 경로가 앱 전환까지 함께 남는다 — 좁히기는 뒤다(간극 대장).

## 잠그지 않은 것

- 상한 값 · 막는 길이(250 · 600) · 겹침 문턱(0.25)은 운영 표본으로 다시 본다. 꼴 여덟의 분포(4차의 두 무리)도 운영 표본에서 본다.
- 「질문에 맞는 답인가」 · 「한 글로 이어지는가」는 기계가 못 잰다 — 사람의 짝 검토가 본다.
- 운영 백그라운드 경로의 `usageOf` 가 캐시 쓰기를 `null` 로 남기는 것(노트 「비용 · 남용」)은 이 결정이 고치지 않는다.

## 덧 — 앱이 붙고 검토 여덟 줄을 고쳤다 (2026-10-03, #441 · #442 · #443)

위 결정은 그대로 선다. 앱은 #441(`24eddca`)로 main 에 들었고, 읽기 전용 검토 여덟 줄을 코드에서 다시 재 고친 것이 #443
(`48acc88`), 퍼널 문이 #442(`20261119090000`)다. 운영 배포는 「배포」 답 뒤다(G-68). 조율자가 정하고 무인 라운드에 머지까지
맡겼다(2026-10-03) — 1~8 을 뒤집지 않고 좁히거나 뜻을 박는다.

- **회원에게는 맛보기를 만들지 않는다.** 로그인한 요청이면 `requestTaste` 가 예약 · 모델 없이 닫고, 화면은 세션을 알 때까지
  로그인 전 결과를 세우지 않는다 — 토큰을 새로 받는 동안의 회원이 서버로 물음을 보내던 틈(#443 M1)이었다.
- **IPv6 는 /56 하나를 한 IP 로 센다**(`ipSubjectOf`). /64 로 접으면 흔한 VPS 할당(/56) 하나가 IP 하루 한도를 256배로 늘린다.
  /48 은 한 통신사의 이용자 여럿을 한 이름으로 묶을 위험이 커서 /56 에서 멈췄다.
- **맛보기 호출은 SDK 재시도 0**(`maxRetries: 0`). 시도 수는 DB 의 예약(`taste_attempt_limit()` 3)만 센다 — 숨은 재시도가 예약
  하나에 호출 셋을 태우지 않는다. 운영 풀이 길은 그대로 SDK 기본이다.
- **귀속의 지문은 서버에 저장된 내 사주로 잰다**(`claimTaste(sessionId)`). 4 의 「확정한 입력」은 화면이 실어 보낸 값이 아니라
  저장된 값이다.
- **예약한 뒤의 모든 길이 결과를 적는다** — 호출이 던지거나 적기가 실패해도 `taste-internal-error` 로 닫는다(60초 `running`
  으로 남지 않는다).
- **이어쓰기 스냅숏을 못 읽으면 그 시도는 실패다**(`taste-carry-unread`) — 이어쓰기 없는 풀이를 내보내지 않는다. 실패라 풀이권은
  안 쓰이고 다음 누름이 같은 세션으로 다시 잇는다(4 의 「실패했을 때만 다시 만든다」).
- **퍼널 8 의 뜻.** 앱이 세는 셋(`more_clicked` · `signup_started` · `signup_completed`)은 **세션 하나에 단계마다 한 번**이다 —
  `count_taste_step_once(p_session_id, p_browser_hmac, p_step)` 이 세션 id 와 브라우저 HMAC 이 함께 맞을 때만 센다.
  `signup_completed` 는 **가입을 마치고 그 세션을 들고 돌아온 것**이다 — 귀속 결과가 `claimed` · `discarded` · `expired` ·
  `not_ready` 어느 것이든 센다. 「로그인하고 전체 풀이 받기」도 `signup_started` 다. `reading_succeeded` 는 브라우저가 없는 회수
  경로라 옛 `count_taste_step` 이 센다. **배포 전 날짜의 `taste_daily` 줄은 누름 수였다** — 그 날짜와 뒤를 견주지 않는다.

### 받아들인 위험

- **가짜 쿠키로 `readTaste` 를 두드릴 수 있다.** 꼴만 맞춘 쿠키면 서버 액션이 DB 읽기 한 번까지 간다 — 한도가 없다. 남의 세션은
  HMAC 이 안 맞아 안 읽히고 모델은 안 부른다. 잃는 것은 DB 읽기뿐이다.
- **IP 를 많이 쥔 쪽이 전체 하루 상한을 먼저 채우면 그날 문단이 닫힌다.** /56 으로 접어도 남는다. 돈은 하루 2,000 이 막고(하루 약
  8천원 이하) 남는 것은 가용성이다 — 닫혀도 가입 안내는 선다. 서버 액션 POST(`/`)의 Vercel WAF 속도 제한은 운영자 몫이다
  (runbook 「로그인 전 사주 문단 — 비밀 둘 · 상한 · 비용」).
- **CGNAT 로 IP 하나를 나누는 사람들이 IP 하루 20 에 함께 걸릴 수 있다.** 값은 그대로 두고 `taste_daily` 의 `limited_ip` 로
  잰다 — 늘면 값을 다시 본다(위 「잠그지 않은 것」).

## 덧 — 순간 장애에서 약속이 조용히 깨지지 않게 (2026-10-03, #446)

외부 검토가 「맛보기에서 끊긴 물음은 가입 뒤 반드시 그 답부터 이어진다」가 순간 장애에 조용히 깨지는 길 둘과 문구 하나를 찾았고,
조율자가 코드에서 확인해 범위를 정했다(운영자 요청, 2026-10-03). 1~8 을 뒤집지 않는다 — 실패했을 때 여닫는 쪽을 박는다.

- **귀속의 답은 세 갈래다** — `claimed`(붙었고 이을 풀이가 남았다) · `terminal`(답이 났다 — `discarded` · `expired` · `taken` ·
  `not_found` · `not_ready` · id 꼴 틀림 · 비밀 없음 · 이 브라우저의 쿠키 없음 · 이어진 풀이가 이미 섰음) · `retryable`(답이
  안 났다 — 귀속 문 · 로그인 세션 · 열쇠를 그 순간 못 씀, 방금 저장한 내 사주를 못 읽음, 던짐). `not_ready` 가 `terminal` 인
  까닭은 그 사람이 끊긴 물음을 본 적이 없어서다 — 글이 선 세션만 가입 단추가 id 를 싣는다. 탭의 세션 id 는 **답이 났을 때만**
  지운다(`app/carried-taste.ts`). `retryable` 이면 이동하지 않고 「이어오지 못했어요.」와 「다시 시도하기」(붙이기만 다시 한다) ·
  「이어 보지 않고 계속하기」(id 를 버리고 보통 흐름 — 아래 덧이 「전체 풀이만 보기」로 바꾸고 서버 표까지 걷게 했다)가 선다.
- **잇기에 답이 안 나면 그 풀이 시도를 실패로 닫는다**(`taste-link-failed`) — 보통 풀이로 강등하지 않는다. 귀속 표를 다시
  맞추는 답이 안 났을 때(`unreachable`) · 잇는 문이 답하지 않거나 던졌을 때 · 연 시도를 다른 세션이 쥐었을 때(`run_taken`)다.
  풀이권은 안 쓰이고 귀속 표가 남아 다음 누름이 같은 맛보기로 다시 잇는다. 잇기의 정상 답 중 `not_claimed`(세션이 이제 이 회원
  것이 아니다)는 표를 걷고 보통 풀이, `wrong_run`(방금 연 시도가 자기 풀이가 아니라는 모순)은 보통 풀이와 기록 — 실패로 닫으면
  누를 때마다 같은 답이라 영영 못 받는다(아래 덧이 뒤집었다 — 실패로 닫고 알리며, 막히면 「전체 풀이만 보기」). `already_succeeded` · `already_running` 은 그대로다.
- **이어질 글이 없는 가입 단추는 「이어보기」라 하지 않는다** — 모델 실패 · 한도 · 시간 초과로 글이 없을 때 「무료 회원가입하고
  전체 풀이 받기」(운영자 쪽 검토가 정했다). 글이 선 뒤 「더보기」의 「무료 회원가입하고 이어보기」는 그대로다.
- **붙이고 도착한 사람에게는 풀이권 확인창이 스스로 열린다**(조율자 결정) — 여는 것까지이고 누름은 사용자가 한다(ADR 0028).
  「아까 보던 내용」이 뒤에 보이게 좁은 화면에서는 창을 아래에 붙인다. 이을 풀이가 이미 섰거나 도는 중이거나 누를 수 없으면
  안 연다. 「막 도착했다」는 귀속이 `claimed` 일 때 그 탭에만 서는 한 번짜리 표(`TASTE_ARRIVAL_KEY`)이고 처음 그릴 때 지운다 —
  귀속 표 쿠키는 첫 누름까지 남아 새로고침 · 뒤로가기마다 다시 열리게 된다.

## 덧 — 새로고침 · 불변식 위반 · 탈출구 (2026-10-03, 두 번째 외부 검토, #447)

두 번째 외부 검토가 위 덧에 남은 구멍 셋을 찾았고 조율자가 코드에서 확인했다(운영자 요청 · 조율자 범위, 2026-10-03). 위 덧의
「`wrong_run` 은 보통 풀이와 기록」은 이 덧이 뒤집는다 — 나머지는 그대로다.

- **새로고침해도 다시 붙인다.** 다시 시도는 화면의 상태라 새로고침에 사라지고, 내 사주는 이미 저장돼 「이 사주가 내 사주
  맞나요?」가 다시 안 섰다 — 탭에 남은 세션 id 를 붙일 코드가 없어 보통 풀이로 빠졌다. 이제 `/` 의 저장 입구가 **내 사주가 이미
  저장됐고 탭이 id 를 들고 있으면 스스로 다시 붙인다**(`useCarriedTasteResume`, `app/save-for-reading.tsx`). 자리를 `#resume-reading`
  의 복원 단계가 아니라 이 화면으로 고른 까닭은 그 낱말이 첫 복원에서 입력으로 갈아 끼워져 새로고침에는 남지 않기 때문이다 —
  새로고침 · 뒤로가기 · 같은 탭의 재방문이 모두 이 화면을 지난다. `claimed` 면 도착 표를 세우고 내 사주풀이로, `retryable` 이면
  같은 다시 시도 화면, `terminal` 이면 id 를 지우고 보통 흐름이다. 남의 id 를 들고 와도 서버 귀속이 막는다(쿠키 HMAC 과 서버에
  저장된 내 사주로 다시 잰 지문).
- **`wrong_run` 은 실패로 닫고 운영자에게 알린다.** 방금 `self` 로 연 시도가 자기 풀이가 아니라는 답은 정상에서 날 수 없는
  불변식 위반이다 — 보통 풀이로 내면 풀이권 한 번이 이어쓰기 없는 글에 조용히 쓰인다. `taste-link-failed` 로 닫고(풀이권 안 씀)
  기록과 함께 서버 오류 알림 문(`report_request_error`, 종류 `request-error:action:/taste/wrong-run`)으로 알린다 — 앱이 부를 수 있는
  알림 길이 그 문 하나라 마이그레이션은 없다. 확인 질의는 `docs/ops/runbook.md` 「이어쓰기가 막힌 시도」.
- **명시적 이어쓰기 포기 — 「전체 풀이만 보기」.** 같은 실패가 거듭되면 누를 때마다 실패라 사용자가 막힌다. 지난 시도가
  `taste-link-failed` 로 실패했고 「아까 보던 내용」이 다음 누름을 기다리면 그 화면에 「전체 풀이만 보기」가 서고, 누르면 서버
  액션(`skipTasteCarry`)이 귀속 표 쿠키를 걷는다 — 다음 누름은 보통 풀이다. **DB 의 귀속된 세션은 버리지 않는다** — 누름이 세션을
  찾는 길은 그 쿠키 하나이고(`pressCarry` 는 표가 없으면 보통 풀이), 화면의 「아까 보던 내용」도 표가 없으면 그 글을 만든 시도에
  이어진 것만 본다. 탭의 id 는 붙은 뒤 지워졌다. 남은 세션은 붙이고 누르지 않은 세션과 같은 모양이다(회원과 함께 지워진다).
  `not_claimed` 만 표를 걷고 보통 풀이로 가는 지금 동작은 그대로다.
- **탈출구는 서버의 귀속 표까지 걷는다.** 앞서 「이어 보지 않고 계속하기」는 탭의 id 만 지웠다 — `retryable` 은 앞서 붙은 표를
  남기므로 그 표가 있으면 내 사주풀이의 누름이 그대로 이었다. 이제 같은 서버 액션으로 표를 걷은 뒤 이동한다. 이름은 두 탈출구
  모두 「전체 풀이만 보기」다(운영자 쪽 검토 권고 · 조율자 채택 — 모바일 반쪽 폭에서 한 줄).

  가입 뒤 그 절의 1번이 이 문단이 멈춘 물음의 답이라(2), 문단이 읽히는 자리와 답이 이어지는 자리가 한 줄이다. 나머지 절은 이름 +
  자물쇠(둘째 절은 흐린 막대도)로 잠긴 채다. 글 아래에는 문구 대장 10 의 「가입하면 이 물음의 답부터 전체 사주풀이가 이어져요.」가
  옮겨 선다(전에는 「더보기」를 누른 뒤에 섰다).
- **가입 단추는 카드 끝의 하나 — 「로그인하고 전체 풀이 받기」.** 두 칸이 같은 가입 흐름을 「무료 회원가입하고 이어보기」 ·
  「무료 회원가입하고 전체 풀이 받기」 · 「로그인하고 전체 풀이 받기」로 따로 부르던 중복을 걷었다. 글이 섰으면 그 단추가 세션 id 를
  싣는다(4 · `TASTE_SESSION_KEY`) — 왕복은 전과 같다. 위 덧의 「이어질 글이 없는 가입 단추는 이어보기라 하지 않는다」는 그 단추가
  없어져 저절로 선다.
- **「더보기」를 걷는다 — 퍼널 8 의 「더보기 클릭」은 2026-10-09 부터 화면이 세지 않는다.** 서버 액션 · DB 단계(`more_clicked`)는
  그대로 받는다. 이 날짜 앞뒤의 그 칸을 견주지 않는다. 단계와 프롬프트의 「[더보기]」 한 줄을 걷을지는 G-85 다.
- **실패 · 시간 초과 · 한도는 첫 절이 조용히 잠긴다** — **2026-10-10 에 바뀌었다(아래 「덧 — 첫 절은 써지는 글이다」 — 실패 줄과 「다시 시도하기」가 다시 선다).** 둘째 절과 같은 자물쇠 + 흐린 막대다. 「다시 읽기」와 실패 · 시간 초과 · 한도의
  문장(문구 대장 10 의 에이전트 줄)을 걷었다. 1 의 「다른 글로 바꿔치기하지 않는다」는 그대로다 — 못 선 글은 없는 채로 선다.
  기다리는 동안은 첫 절 자리에 글이 설 높이의 막대 넷이 선다.
- **같은 날 함께 — 「무료로 내 사주 보기」를 누르면 결과 머리로 내려간다**(화면 점검 A1). 폼이 결과 위라 누른 자리에서는 결과가 안
  보였다. 제출로 선 결과만 카드로 스크롤하고(줄인 움직임이면 바로) 초점을 옮긴다 — 링크 · 뒤로가기로 선 결과는 움직이지 않는다.
  궁합 입구(`app/compat-picker.tsx`)와 같은 몸짓이다. 회원의 `/saju` 는 그대로다.

화면은 `app/taste.tsx` · `app/saju-calculator.tsx`, 시험은 `e2e/taste.spec.ts` · `e2e/signed-in.spec.ts`. PRD §3.1, 문구 대장 07 · 10.

## 덧 — 퍼널은 다섯 단계다 (2026-10-10, 운영자 결정 · G-85)

8 의 「더보기 클릭」을 걷는다 — 퍼널은 맛보기 생성 성공 → 가입 시작 → 가입 완료 · 세션 귀속 → 전체 풀이 시작 → 전체 풀이 성공이다.
서버 액션 `noteTasteStep` 은 `signup_started` 만 받고, `TASTE_SESSION_STEPS` 는 둘(`signup_started` · `signup_completed`), 두 셈 문
(`count_taste_step_once` · `count_taste_step`)은 `more_clicked` 를 22023 으로 거절하며, `taste_daily` 에서 그 칸을 뺐다
(`20261128090000`). 운영 DB 에 그 단계로 센 줄은 한 번도 없었다(2026-10-10 집계 0). 위 「덧 — 앱이 붙고」의 「퍼널 8 의 뜻」은
앱이 세는 셋이 둘로 줄어든 것 말고 그대로다. 로그인 전 사주 문단 프롬프트의 「[더보기]가 선다」 한 줄은 이번에 안 걷었다 —
본문이 바뀌면 실호출이 들고 실호출은 운영자가 돌린다(G-85 에 남는다).

## 덧 — 첫 절은 써지는 글이다: 기다림 · 실패 · 다시 시도 (2026-10-10, 운영자 결정)

운영자가 로그인 전 결과를 보고 물었다 — 「기다리라는 건가 오류가 난 건가」. 막대 넷은 기다림 · 실패를 같은 회색으로 보였고, 실패는
위 덧대로 말 없이 잠겼다. 시안 셋(실제 단계 · 써지는 글 · 최소 변경)에서 운영자가 **B — 써지는 글**을 골랐다(원문 「b로 적용하자」).
**1 의 생성 · 3 의 예약(세 번까지) · 4 의 귀속 · 5 의 보존 · 서버는 그대로다** — 바뀌는 것은 첫 절의 모양 넷(`tasteFirstSectionOf`,
`src/lib/reading/taste-visit.ts`)이다.

- **기다림** — 막대 넷을 그 자리에 두고 위에 「첫 문단 작성 중…」 한 줄. 빛이 줄마다 0.22초씩 늦게 흘러 위에서 아래로 써 내려가는
  듯하고, 마지막 줄 끝에 커서가 깜박인다(`app/taste.module.css`). 서버는 중간 단계를 주지 않는다 — 차오르는 막대가 아니라 끝을 모르는
  흐름이다. 「작성 중…」은 전체 풀이 목차의 같은 상태(`READING_OUTLINE_STATE.writing`)를 쓴다 — 한 사실 한 표기.
- **성공** — 문단이 0.35초 간격으로 하나씩 떠오른다.
- **실패 · 시간 초과(`retry: true`)** — 첫 절이 둘째 절처럼 자물쇠 + 흐린 막대로 잠기고, 아래에 「첫 문단을 쓰지 못했어요.」와 글자 단추
  「다시 시도하기」. 누르면 같은 입력을 다시 보내고 서버가 같은 artifact 의 다음 시도를 연다(3). **위 「2026-10-09 덧」의 「조용히
  잠긴다」를 이것으로 바꾼다** — 그날 걷은 「다시 읽기」를 이 이름으로 되살렸다.
- **한도 · 세 번 실패 · 서버가 닫음(`retry: false` · `limited`)** — 같은 자물쇠 + 막대에 「지금은 첫 문단을 열 수 없어요.」 한 줄. 단추는 없다 —
  눌러도 같다. 어느 한도인지는 여전히 안 가른다.
- **움직임을 줄인 사람**(`prefers-reduced-motion`)에게는 빛 · 커서 · 떠오름이 멈춘다 — 막대는 멈춘 채, 문단은 바로 선다.
- 「다른 글로 바꿔치기하지 않는다」(1)는 그대로다 — 못 선 글은 없는 채로 선다.

**조율자가 함께 정한 둘** — 「다시 시도하기」의 부활과 「작성 중…」 표기는 운영자에게 추천으로 보였고 운영자가 B 를 그 모양대로
골랐다. 운영자가 다르게 원하면 되돌린다. 문구는 대장 34(`docs/product/copy-ledger/first.md`), 글자는 `src/lib/reading/copy.ts`(ADR 0159).
화면은 `app/taste.tsx`, 시험은 `src/lib/reading/taste-visit.test.ts` · `e2e/taste.spec.ts`. PRD §3.1.
