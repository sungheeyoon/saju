# 정책 파일만 바꾼 main 푸시는 `policy` 차선만 돈다

> **운영자 결정 2026-10-08**(대화에서, CI 범위) — 문서 PR 이 머지되면 main 에서 전부(약 11분)가 돌았다. 재는 것이 없는데 러너만
> 쓰고 `ci-main-red` 를 늦췄다. 운영자가 main 푸시도 범위를 보고 가리기로 정했다.

ADR 0097 의 「main 푸시는 계획을 안 보고 전부 돈다」를 일부 고친다. ADR 0153 의 「PR 계획 밖(main 푸시)은 지금 규칙 그대로」도 같다.
규칙의 원본은 `scripts/ci-plan.mjs` 머리의 「문서만 바뀐 main 푸시는 `policy` 만」이다.

## 정한 것

- **main 푸시는 푸시 전 SHA(`github.event.before`)와 뒤 SHA 사이의 변경 전체로 가른다.** 여러 PR 이 한 푸시에 들어도 그 범위 전부다.
  그 안이 정책 파일과 주석만 바뀐 코드 파일(ADR 0153, base 는 푸시 전 SHA)뿐이면 `policy` 만, 하나라도 그 밖이면 전부다. `audit` 도
  `policy` 만일 때는 건너뛴다 — 새 advisory 는 하루 한 번의 일정이 잡는다.
- **앞 커밋이 초록으로 끝났을 때만 좁힌다.** main 의 concurrency 는 새 푸시가 앞 실행을 끊는다(ADR 0097). 코드 커밋의 전체가 바로 뒤
  문서 커밋에 끊기고 그 문서 커밋이 `policy` 만 돌면, 코드 커밋은 아무도 안 잰다. 그래서 계획 job 이 푸시 전 SHA 의 verify 실행(main 의
  push · 일정 · 손으로 켠 것)을 API 로 읽어, 초록이 하나 이상이고 붉은 것이 없을 때만 좁힌다. 그 초록이 `policy` 만이었으면 그것도 같은
  조건으로 좁혀졌으므로, 사슬 끝에는 전부를 잰 초록이 있다. 붉은 main 위의 문서 푸시도 전부다.
- **닫히는 쪽.** 범위를 못 받음 · 푸시 전 SHA 가 0 · 강제 갱신 · diff 를 못 읽음 · 앞 실행을 못 읽음은 전부다. `supabase/**` 는 전부다.
  일정 · 손으로 켠 실행은 지금처럼 전부다.
- **`ci-main-red` 는 전부를 잰 초록만 센다.** `policy` 만 돈 초록은 이슈를 닫지 않고 「마지막 초록」으로도 세지 않는다
  (`main-red.mjs` 의 `measuredEverything` — `policy` 말고 건너뛴 job 이 없는 실행). 그것을 세면 붉은 e2e 위의 문서 커밋이 이슈를
  닫고, 범위가 문서 커밋부터로 좁아져 거짓이 된다. `policy` 만 돈 실행이 붉으면 지금처럼 연다.

## 치르는 값

- 계획 job 이 main 푸시에서도 `npm ci` 를 한 번 돈다(파서). 캐시가 받쳐 수십 초다. 계획 job 에 `actions: read` 를 준다 — 쓰는 권한은 없다.
- `policy` 만 돈 머리 위에 열린 이슈가 있으면 다음 전부(코드 푸시나 하루 한 번의 일정)까지 이슈가 남는다. 앞 커밋이 붉으면 문서 푸시도
  전부라서 대개 바로 다음 푸시가 닫는다.
