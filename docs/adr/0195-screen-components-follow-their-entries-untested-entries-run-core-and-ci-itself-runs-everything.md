# 화면 컴포넌트는 쓰는 입구의 차선을 타고, 시험이 정말 없는 입구는 core 와 시험 공백이며, 엔진의 DB 쪽 · CI 자체 · 시험 실행 의존성은 전부다

> **운영자 결정 2026-10-22**(CI 갈래 검수, 조율자가 옮김) — 검수(`docs/notes/2026-10-22-ci-lane-audit.md` 「CI 갈래 검수」)의 2번에
> 「조건부 core」: 주소를 확실히 풀었는데 닿는 시험이 0 인 경우만 `core` 로 보내고 그 시험 공백을 간극 대장에 적는다. 해석 불가 · 미분류 ·
> 관문이 부르는 경우는 계속 전부, 다른 파일이 이미 켠 차선은 그대로. 3번에 「코드를 전부로」: `ENGINE_DB_FACING` 은 운영 베타에서도 전부를
> 돈다. CI 자체 변경에 「이번에 전부로」: `.github/workflows/**` 와 시험 실행 의존성(Playwright 등) 변경은 전부, 일반 패키지 버전 변경과는
> 구분한다. 1번(입구가 아닌 화면 컴포넌트)과 4번(시험이 부르지 않는 도구 넷)은 에이전트 몫으로 맡겼다.

ADR 0119 의 「고르지 않은 것 — 입구가 아닌 컴포넌트까지」와 ADR 0178 의 「찾은 입구의 주소에 닿는 시험이 0 인 것도 전부다」를 고친다.
규칙의 원본은 `scripts/ci-plan.mjs` 머리(「CI 갈래 검수의 넷」)와 `docs/agents/test-map/ci.md` 다.

## 잰 것

- **화면 컴포넌트가 샜다.** main 이 붉은 #581(#579 — `anon` · `signed-in`) · #614(#612 — `push`) · #595(#593 — `signed-in`)는 모두 입구가
  아닌 `.tsx` 만 바꾼 PR 이 `core` 만 돌았던 것이다. 지금 계획기에 그 PR 의 파일을 넣으면 #579 는 `signed-in` 둘(`anon` 없음), #612 는
  `live` 하나(`push` 없음)였다.
- **넓어지는 폭**(2026-10-22, 한 파일씩) — 옛 규칙 `core` 이던 화면 컴포넌트 145 개 중 113 개가 좁힌 차선(그중 아홉은 차선 열하나를 다
  켠다), 19 개가 전부(길 위에 layout · 인증 · Next 공용 경계 — `app/ui/**` 의 일곱), 11 개는 그대로 `core`(쓰는 입구에 닿는 시험이 정말
  없다), 2 개는 나머지 입구의 차선이다. `app/ui/**` 의 `.tsx` 열셋은 일곱이 전부, 여섯이 `core` 를 넣어 차선 아홉 ~ 열둘이다 — 공용 부품이라 거의
  다 전부와 같다.
- **닿는 시험이 0 인 입구는 지금 다 「정말 없음」이다.** 글자 그대로의 주소가 0 인 입구 아홉(`/help` · `/terms` · `/refund` · `/me/credits`
  셋 · `/ops/members` · `/ops/orders` · `/ops/today`) 모두 시험 · 도우미가 템플릿 · 이어 붙임 · 정규식으로도 그 주소를 안 적는다. 그 아홉과
  그것만 쓰는 서버 파일 여섯을 바꾼 PR 은 전부(러너 56분)를 돌았지만 그 화면을 여는 시험은 하나도 없었다.

## 정한 것

- **입구가 아닌 화면 컴포넌트는 그것을 쓰는 입구의 차선을 탄다.** `app/**` 의 시험 아닌 `.tsx` 가운데 입구 · 서버 파일이 아닌 것은 ADR 0178
  의 서버 파일과 같은 길(`entriesReaching`)로 그 컴포넌트를 쓰는 입구의 주소에 닿는 차선을 켠다. 안전 문턱도 같다 — 길 위에 공용 위험이나
  메타데이터가 서거나 쓰는 입구를 못 찾으면(고아) 전부다. 지운 컴포넌트는 안 건다(부르던 쪽이 함께 바뀐다). 순수 로직 `.ts` 는 단위 시험이
  재므로 그대로 `core` 다(ADR 0119 추기).
- **닿는 시험이 0 인 입구는 「정말 없음」과 「탐색이 놓쳤음」을 가른다.** 글자 그대로 요청하는 시험이 0 이어도 시험이나 그 도우미(spec 이
  아닌 `e2e/**` · 흐름 검사의 도우미)가 템플릿의 식 · 이어 붙임 · 식 뒤의 경로 · 정규식의 `\/` 경로로 그 주소를 요청할 수도 있으면 전부다
  (「닿는 시험 모름」). 그것도 없으면 그 파일은 `core` 로 세고 까닭에 시험 공백(간극 대장 G-116)을 싣는다. 다른 파일이 켠 차선은 그대로다.
  G-116 의 기록이 계획의 `untestedEntries()` 와 같은 목록을 드는지 시험이 견준다 — 새 page 를 시험 없이 더하면 그 시험이 붉어 대장에 한 줄을
  더하게 하고, 시험을 더하면 지우게 한다. 고아 · 미분류 · 관문이 부르는 파일 · 차선 모름은 그대로 전부다.
- **엔진의 DB 쪽은 운영 베타에서도 전부다.** `ENGINE_DB_FACING`(`src/lib/saju/version.ts` · `pillars/index.ts`)을 공용 위험 「엔진의 DB 쪽」으로
  둔다. 머리말과 `docs/agents/test-map/what-to-run.md` 는 이미 「전부」라 적었고 코드만 공개 출시에서 그랬다.
- **CI 자체와 시험 실행 의존성은 전부다.** 워크플로(`.github/workflows/**`)와 모든 job 이 읽는 Node 판(`.nvmrc`)은 공용 위험 「CI 자체」다.
  의존성 목록은 base 와 견줘 시험 실행 의존성이 바뀌었을 때만 전부다 — Playwright(`@playwright/test` · `playwright` · `playwright-core`)와
  Supabase CLI(`supabase`)의 판 · `overrides` · 잠금 파일의 설치 항목(판 · 출처 · 지문), 그리고 차선 job 이 부르는 스크립트(`test:e2e*` ·
  `test:flow` · `test:db` · `db:start` · `db:types`). 앱이 쓰는 패키지만 바뀌었으면 전처럼 `core` 와 `audit` 이다. base 나 HEAD 를 못 읽으면
  가를 수 없어 전부다. 그 목록이 차선 job 의 `npm run` 과 시험만 들이는 개발 의존성을 덮는지 시험이 잰다.
- **시험이 부르지 않는 도구 넷은 시험 도구가 아니다.** `scripts/pr-title.mjs`(계획 job 이 PR 마다 부르고 제 단위 시험이 있다) ·
  `scripts/deploy-smoke.mjs`(`npm run smoke:deploy`, 사람이 배포 뒤에) · `scripts/brand-icons.mjs` · `scripts/push-vapid-keys.mjs`(사람이 손으로)
  를 `NOT_HARNESS` 에 둔다 — 바꾸면 `core` 다. e2e · 흐름 검사 · Playwright 설정 · 그 도우미가 넷을 import 하거나 실행 인자로 넘기지 않는지
  시험이 잰다(`push-local.mjs` 가 찍는 안내 문장 속 이름은 부르는 것이 아니다).

## 고르지 않은 것

- **화면 컴포넌트가 layout 을 지나면 그 layout 아래 주소로 좁히기** — ADR 0178 이 서버 파일에 고르지 않은 것과 같다. layout 은 공용
  위험이라 그 몫도 같은 문턱에 둔다. 그래서 `app/ui/**` 의 공용 부품 일곱이 전부다.
- **순수 로직 `.ts` 까지 넓히기** — `book.ts` · `buttons.ts` 같은 것은 단위 시험이 잰다. #579 의 `buttons.ts` 는 같은 PR 의 컴포넌트가
  그 차선을 켰다.
- **「닿는 시험 0」을 모두 `core` 로** — 지금 문자열 탐색은 시험이 링크를 눌러 닿거나 주소를 조합하는 화면을 못 본다. 놓쳤을 수 있는
  경우를 가르지 않으면 그 구멍이 차선 하나 없이 `core` 로 떨어진다.
- **`package.json` · `package-lock.json` 을 바꾸면 모두 전부** — Next · sharp 같은 앱 패키지의 판 올림은 `core` 의 빌드와 `audit` 이 재고, 매번
  전부(56분)를 돌 까닭이 없다. 큰 판 올림이면 시험 지도대로 사람이 e2e 를 한 번 더 돈다.

## 치르는 값

- 화면 컴포넌트를 바꾼 PR 이 머지 전에 e2e 를 더 돈다 — 공용 부품(`app/ui/**`)이나 layout 이 부르는 것은 전부다.
- 닿는 시험이 정말 없는 화면을 바꾼 PR 은 `core` 만 돈다 — 그 화면은 머지 뒤 main 의 전체도 재지 않는다(시험이 없으니). 그 공백은 G-116 이
  든다. 링크를 눌러 닿고 주소를 하나도 적지 않는 시험은 여전히 못 본다(ADR 0178 「치르는 값」과 같은 구멍).
- `.nvmrc` 를 바꾼 PR 도 전부다 — 모든 job 이 그 판으로 돈다(`authed` 를 세운 날 Node 20 과 24 의 차이가 로그인 차선에서만 드러났다,
  `verify.yml` 의 `anon` 주석).
- `main-red.yml` 처럼 PR 에서 돌지 않는 워크플로는 전부를 돌아도 그 자체는 재지 못한다.
