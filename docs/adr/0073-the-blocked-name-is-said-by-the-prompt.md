# 검사가 막는 이름은 프롬프트가 같은 표에서 부른다

## 무엇이 갈려 있었나

「무엇을 말해도 되는가」를 아는 자리가 **셋**이었다.

| 자리 | 무엇을 재나 | 어긴 글은 |
| --- | --- | --- |
| `saju/text/policy.ts` + `checkSentence` | **우리가 조립한 문장**(L3) | 안 나간다 |
| `reading/check.ts` + `checkReading` | **모델이 낸 글**, 저장 직전 | 버려진다 |
| `reading/prompt.ts` | 모델에게 **시키는 말** | — |

앞의 둘이 「두 체계」로 적혀 있었지만 **합칠 대상이 아니다.** 둘은 서로 다른 글을 재고,
금지 목록이 둘(`기신`·`희신`)밖에 안 겹친다. `checkSentence` 는 모델 출력에 한 번도
닿지 않는다 — 부르는 곳은 `fragment.ts`·`assemble.ts`·시험뿐이다.

진짜로 갈려 있던 것은 **셋째 자리**다. `prompt.ts` 는 `check.ts` 에서 아무것도 수입하지
않고, 같은 낱말을 **산문으로 다시 타이핑한다.**

그리고 `check.ts` **한 파일 안에서도 두 표가 같은 낱말을 두 번 적고 있었다** —
`PLAIN_FORBIDDEN_TERMS`(93)와 `OUT_OF_SCOPE_TERMS`(35)가 **20개를 겹쳐 든다**.

## 왜 이것이 값을 치르는 모양인가 — 한 번 치렀다

한 줄 요약의 길이가 같은 자리에서 떨어졌다. 검사는 60자를 막고 있었는데 **프롬프트는
길이를 한 번도 말하지 않았다.** 모델이 63자를 쓰자 다 만든 글이 통째로 버려졌다 —
**모델이 지킬 방법이 없는 계약을 검사만 들고 있었던 것**이고, 토큰은 나가고 글은 안
남았다. 그래서 `READING_POLICY.metaphorLength` 가 **시키는 값(`target`)과 막는 값
(`max`)을 한 상수에서** 내주게 고쳤다.

낱말도 같은 모양이다. 표가 늘면 검사는 따라오지만 프롬프트의 산문은 안 따라온다.

## 정한 것

**함께 드는 낱말은 `reading/vocabulary.ts` 의 갈래에서 온다.** 두 표가 그 갈래를 펴서
자기 표를 짓고, 프롬프트가 같은 갈래에서 이름을 읽어 문장에 꽂는다.

```
SAJU_TERMS.strength  신강·신약
SAJU_TERMS.eokbu     억부·용신
SAJU_TERMS.method    격국·조후
SAJU_TERMS.luck      대운·세운·월운
SAJU_TERMS.sinsal    신살·천을귀인·문창귀인·학당귀인·역마·도화·화개·공망·백호·괴강·양인
```

**한 목록으로 합치지 않는다.** 두 표는 겨누는 것이 달라 각자 더 드는 낱말이 있고
(`천덕귀인`·`월덕귀인` / `종격`·`고신`·`과숙`·`통근`·`12운성`), 그것들은 그 표 옆에 남는다.
갈래로 올리면 **다른 표가 조용히 넓어진다** — 저장을 막는 표가 넓어지는 것은 멀쩡한 글이
버려진다는 뜻이다.

## 프롬프트는 표 전체를 부르지 않는다

프롬프트가 읽어 가는 것은 **그 자료에 실제로 실린 판정의 이름**뿐이다. 두 자리다.

- `matchScope` 의 확장형 — 「그 판정의 이름(신강·신약·억부·용신)은 본문에 쓰지 마라」
- `PAIR_DATA.match` — 「대운·세운·월운은 이 자료에 없다」

**금지 낱말 35개를 나열하지 않는다.** 이 저장소가 이미 재어 둔 것이다 — 「모델이 먼저
읽는 것은 목록이다」. 목록을 길게 세우면 규칙과 본보기가 서로 다른 말을 하게 되고, 글이
점검표처럼 굳는다. 고칠 때는 금지어를 늘리지 말고 **지시가 결론의 모양을 시키게** 한다.

그래서 시험이 재는 방향도 한쪽이다 — **프롬프트가 부른 이름이 검사의 표 안에 있는가.**
반대(「표의 낱말을 프롬프트가 다 부르는가」)는 재지 않는다.

## 프롬프트 본문은 한 글자도 안 바뀌었다

낱말 순서까지 지금 나가는 것과 같게 꽂았고, **31벌(kind 넷 × 조립 판 × 호칭 셋)을 고치기
전후로 떠서 `diff` 가 비었다.** 그래서 이 변경은 실호출이 필요 없다 — 모델에 가는 글이
달라지지 않았다. 두 표의 낱말 수도 그대로다(93 · 35 · 겹침 20).

**다음에 이 자리를 고치는 사람에게**: 프롬프트 본문이 바뀌는 순간 그 면제는 사라진다.
`READING_LIVE=1 npx vitest run app/me/reading/call.live.test.ts` 를 한 번 돌리고 올린다.

## 낱말 집합은 같고, 실패 상세의 나열 순서는 달라진다

두 표의 **구성은 한 낱말도 안 바뀌었다**(93 · 35 · 겹침 20). 다만 갈래를 펴면서
`OUT_OF_SCOPE_TERMS` 의 **배열 차례**가 달라졌고, 그 차례를 그대로 쓰는 자리가 하나 있다 —
검사에 걸린 낱말을 `·` 로 이어 적는 실패 상세(`out-of-scope-judgment` 의 `detail`, DB 의
`p_failure_detail` 과 실험 출력 문자열).

**막는 판정도, 사용자가 보는 글도 달라지지 않는다.** 그 문자열을 프로그램이 다시 읽어
갈라 쓰는 자리도 지금은 없다. 그래서 비차단으로 받았다 — 옛 차례를 되살리려고 구조를
복잡하게 만들지 않는다. 다만 **옛 기록과 새 기록의 나열 순서가 다를 수 있다**는 것은
적어 둔다. 그리고 어떤 시험도 이 순서를 안 재므로, **시험은 이 차이를 못 본다.**

## 재는 자리

`src/lib/reading/vocabulary.test.ts` 가 선다.

- **두 표가 겹치는 것과 갈래의 합이 정확히 같다** — 손으로 적은 사본이 다시 생기면 깨진다
- 갈래는 두 표에 다 들어 있다
- **한쪽만 드는 낱말은 하나도 갈래에 없다** — 본보기 몇 개가 아니라 양쪽 전용 낱말 전부를
  본다. 갈래로 잘못 올리는 실수는 한 낱말에서 나므로, 고른 몇 개만 재면 그 몇 개가 아닌
  낱말이 올라간 날에 초록이 뜬다
- **저장을 막는 표만 드는 열다섯을 값으로 든다** — 이쪽이 넓어지는 것은 멀쩡한 글이
  버려진다는 뜻이다. 판을 재는 표만 드는 쪽은 십성·관계 이름이 표에서 지어지므로 수를
  안 박고, 손으로 적은 여섯만 짚는다
- 확장형 프롬프트가 부르는 판정 이름이 `OUT_OF_SCOPE_TERMS` 안에 있다
- 운영 프롬프트가 「이 자료에 없다」고 적은 운 이름도 같은 표에서 온다
