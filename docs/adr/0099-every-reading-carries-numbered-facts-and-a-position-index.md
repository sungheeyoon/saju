# 모든 풀이 프롬프트가 사실에 번호를 달고, 자리 색인은 그 번호만 모은다

2026-09-15 의 「자리가 붙은 사실」 목록(`reading-prompt-v11` · `v12`)은 두 궁합에만 실렸고, 자리별로 묶은
색인은 일부러 안 만들었다 — 9/1 실험이 모델 입력에 색인을 더한 실익을 못 보였기 때문이다(PRD §8.5). 2026-09-23 에
사람이 다시 정했다: **색인을 더하고, 관계 사실이 있는 모든 풀이에 같게 싣는다**(G-33). 이것은 그 실험의 결과가
아니라 **사람의 새 결정**이다.

## 정한 것

- **줄마다 번호** — 관계는 `[R1]`, 신살 · 공망은 `[S1]`. 줄의 나머지는 v11 그대로다(`A 월지 丑 → B 년지 戌 : 축술형`).
- **자리 색인은 번호만 든다** — `- A 월지 巳 : R1 · R4 · S5`. 사실을 다시 적지 않으므로 한 사실은 목록에 한 번만
  선다. 9/1 실험의 색인은 자리마다 사실을 풀어 적었고, 그러면 한 사실이 자리 수만큼 세어진다 — 이번 모양은 그 길을
  안 간다.
- **판정 기준 글자는 색인에 안 선다.** `[기준 …]` 은 판정에 쓴 글자이지 걸린 자리가 아니다(목록이 이미 그렇게 적는다).
- **네 kind 가 다 싣는다** — `self` · `person` 에 목록이 처음 선다. 인연 궁합은 자료가 든 두 사람 사이 관계만 색인에
  선다(`WITHHELD_PATHS` 그대로).
- **새 한글 셋** — 블록 머리 `자리 색인`, 머리 문단의 번호 설명 한 줄, 「같은 번호를 자리마다 되풀이해 세지 마라」 한 줄.
  2026-09-23 에 사람이 승인했다.
- **판본** — `version` v10 → `reading-prompt-v13`, `pairVersion` v12 → `reading-prompt-v13`. v11 · v12 는 궁합이 쓴
  이름이라 개인 풀이는 건너뛴다.

## 재는 법 — 자리 검사

`src/lib/reading/position-check.ts` 가 **사용자가 읽는 본문만**(`readingBody`) 잰다. 운영 파이프라인은 안 부른다 —
문장 안에서 두 낱말이 함께 서는 것은 오조인일 수도 맞는 대비일 수도 있어 막는 계약으로 쓰기엔 거칠다. 실호출 시험
(`call.live.test.ts`)이 부른다.

| 코드 | 무엇 |
| --- | --- |
| `wrong-place` | `월지 巳` 처럼 자리와 글자를 함께 적었는데 그 자리의 글자가 아니다 |
| `number-leak` | 번호나 「자리 색인」이 본문에 샜다 |
| `stem-sinsal-with-branch-relation` | 천간에만 걸린 신살과 같은 기둥 지지의 관계를 한 문장에 묶었다 — 9/1 hard 실패 ① |
| `partial-as-complete` | 시간 미상인데 세 글자 중 일부인 합을 이뤘다고 단정했다 — 9/1 hard 실패 ② |

실호출 시험에 **시간 미상 한 편**(1991-06-02 여, 일부만 선 합이 있는 명식)을 더했다.

  안 나왔다. 검사를 본문으로 좁히고 같은 원문을 다시 재어 0 이 됐다.
- 둘째 차례의 인연 궁합이 **근거 절과 점수 줄에 번호를 34번** 적었다(`relations R4 자축합토 [사실]`, `R8·R9·R10 충 -3`).

  오히려 쉽다 — 막지 않는다. 본문에는 0 이다.
- 본문의 분류명 목표(`plain-terms-exposed`, 「명식」 · 「원국」)는 개인 풀이 열 편 중 셋이 넘었다. **v13 이 연 것이
  아니다** — 이 기계에 남은 09-03 ~ 09-05 개인 풀이 원문 아홉 편은 모두 넘었고(편마다 2 ~ 9번), v13 은 0 ~ 2번이다.
  v10 원문은 이 기계에 없어 그것과 직접 견주지는 못했다.

## 언제 다시 보나

「자리를 잘못 이어서 틀린 글」이 설문과 검산 화면에 쌓이면, 자리 검사의 네 코드가 그 글을 잡았는지부터 본다.

## 추기 — 근거 칸의 사실 번호 (2026-09-23)

근거 칸의 관계 · 신살 인용에 사실 번호가 붙을 수 있다 — `relations R4 자축합토 [사실]`, 점수 줄의 `R8·R9·R10 충 -3`.
번호는 자리가 붙은 사실 목록의 **이미 있는 사실을 가리키는 내부 참조**다. 프롬프트가 시킨 것이 아니다 — 근거 칸의
계약(`parts.ts` 의 `CLOSING`, `prompt.ts` 의 `PAIR_CLOSING`)은 `경로 [층]` 만 말하고, 번호는 v13 실호출에서 모델이 그렇게
적은 것을 기록한 것이다. 프롬프트 본문과 판본은 그대로 둔다(사람의 답).

- 근거 절은 화면에 안 나가므로 번호가 사용자에게 새지 않는다. **사용자 본문의 번호 누설 검사(`number-leak`)는 그대로다.**
- 인연 궁합 입력 평가(`match-input-eval.ts`)가 근거 칸의 관계 인용을 셀 때 `relations 자축합토 [` 만 읽어, 번호가 붙은
  인용을 놓쳤다. 이제 이름 앞의 **`R\d+` · `S\d+` 토큰 하나만** 받아 같은 인용으로 센다. `4` · `R` · `X4` 는 받지 않는다.

## 추기 — 지시문이 쓰는 말을 바꾸고 판본이 v14 로 오른다 (2026-09-23, G-55)

개인 풀이 본문에 남던 「명식」·「원국」은 절 본문이 아니라 **공통 규칙 조각**에서 왔다. 쉬운 말 판은 절 본문만 갈라
두었고(`prompt.ts` 의 「이 사람」·「타고난 자리」), `parts.ts` 의 규칙과 판정 서열 절은 한 벌이라 지시문이 스스로
그 말로 가르쳤다 — 개인 풀이 지시문에 명식 4 · 원국 4. 모델은 그 말을 빌려 「운의 X가 원국의 Y와 만나」·「돈 벌
기회가 없는 명식은 아니에요」로 썼다.

- **정한 것(사람의 문구)** — 금지 목록을 늘리지 않고 가르치는 말을 바꾼다. `natal`(타고난 구조), 「타고난 구조에서
  이미 서로 맞부딪히던 자리」·「올해 새로 생긴 맞부딪힘」(「충」도 뜻으로 푼다), 「운은 타고난 구조 자체를 바꾸지
  않는다」·「원래 가진 무엇과 만나」, 시간 미상 규칙의 「태어난 시각을 모르는 사주」·「네 기둥이 다 선 사주」,
  「남의 사주 이야기」, 「이 사주에 무엇이 필요한지」. 쉬운 말 규칙 §5 뒤에 본보기 한 쌍이 선다. 문구와 본보기는
  한 판본에 함께 든다.
- **판본** — `version` · `pairVersion` 둘 다 v13 → `reading-prompt-v14`. 시간 미상 규칙(`ABSORPTION_RULE`)이 두 궁합의
  읽는 법에도 실리므로 궁합도 v13 으로 저장된 글과 갈라야 한다. 궁합의 다른 지시에 남은 「원국」·「명식」은 이번에
  안 건드린다.
- **`plain-terms-exposed` 는 `target` 그대로다.** 저장 검사(`checkReading`)에 넣지 않고 저장 거절 · 재호출도 만들지
  않는다 — 막으면 풀이권은 안 깎여도(ADR 0038) 토큰과 하루 시도 상한(500)은 나가고, v13 비율이면 개인 풀이 절반이
  다시 불린다. 금지 목록에 「충」을 넣지 않는다(「충분하다」가 걸린다).
- **위 「실호출」 절의 수를 바로잡는다.** 이 검사로 잰 것은 개인 풀이 여섯 편(셋이 넘음)이고 궁합 네 편은 안 쟀다
  (실호출 시험이 궁합에는 `outputDeviations` 를 안 건다). 「v13 은 0 ~ 2번」은 **노출된 낱말의 가짓수**이고
  「09-03 ~ 09-05 아홉 편은 2 ~ 9번」은 **출현 횟수**라 단위가 다르다. v13 원문이 이 기계에 없어 같은 단위로 다시
  세지 못한다. 다음 실호출부터 편마다 둘 다 적는다.
- **v14 실호출과 G-55 의 닫힘은 아래 절이다.**
