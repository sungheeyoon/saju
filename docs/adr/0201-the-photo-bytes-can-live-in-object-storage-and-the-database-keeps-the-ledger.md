# 사진의 바이트는 저장소에 살 수 있고, 장부는 DB 가 든다 — 꺼진 채로 들어온다

> ADR 0040 「얼굴은 Postgres 안에 둔다」를 다시 연다(일부). 저장 자리(AWS S3 서울 — 감사 버킷과 같은 계정 · 다른 버킷 · 다른 권한)는
> 운영자가 정했다(2026-10-23 낮 세션, 나이트 브리프 B). **열람 방식은 이 ADR 이 정하지 않는다** — G-120 의 결정이다.

## 왜 다시 여나

ADR 0040 은 bytea 를 골랐다 — 지우는 일이 FK 를 따라가고(ADR 0023), 저장소의 파일은 `forget_user` 가 못 지우기 때문이다. 그 근거는
그대로 참이다. 다시 여는 것은 **화질**과 **DB 크기** 때문이다 — 긴 변 512px 는 넓은 화면의 인연 카드(약 1,110 장치 px)에도 모자라고,
한 장 512KB 의 바이트가 Free 의 읽기 전용 문턱(ADR 0199)을 같이 쓴다. 그래서 바이트만 밖에 두고, **0040 이 지키려던 것 — 떠나면
사라진다 — 은 DB 가 지울 줄로 든다.**

## 정한 것

1. **DB 는 장부다.** 자리 · 판본 · 보일 자리 · 볼 수 있는가(`may_see_photo`)는 그대로 DB 가 답한다. 한 줄은 바이트 **또는** 열쇠
   (`photos/{user}/{upload}`) 하나를 든다(`20261227090000`).
2. **두 벌** — `card`(긴 변 480px) · `large`(1440px). 셈과 출처는 `docs/product/gaps/records/g-120.md`. 원본은 안 둔다.
3. **열쇠는 DB 가 짓고, 쓰기 전에 표를 적는다.** 앱은 표를 받고(하루 한도가 여기서 깎인다) → 두 벌을 쓰고 → DB 에 적는다. 실패하면
   표를 지울 줄로 넘긴다 — **저장소를 그 자리에서 지우지 않는다.** 「응답만 끊기고 DB 는 적었다」에서 지우면 보이는 사진이 깨지는데,
   넘기기는 표가 남아 있을 때(= DB 가 안 적었을 때)만 지울 줄에 넣으므로 그 경합이 없다. 넘기기마저 못 하면 한 시간 지난 표를 청소기가
   옮긴다. 옛 사진을 옮기는 도구도 같은 표를 받는다(`photo_move_begin`) — 주인 없는 객체는 다음 청소까지만 남는다.
4. **지우는 일은 지울 줄을 따라간다.** 열쇠를 잃는 모든 길(바꾸기 · 지우기 · 계정 삭제의 cascade)에서 트리거가 옛 열쇠를 넣고, 하루
   한 번의 청소 크론(`app/api/cron/photo-sweep`)이 두 벌을 지운다. 못 지우면 다시 하고(청소가 하루 한 번이라 처음 다섯 번은 날마다),
   다섯 번째(닷새째)부터 운영 알림을 낸다. **지워지는 때가 바뀐다** — DB 의 행은 그 자리에서 사라지지만 저장소의 객체는 다음 청소(하루
   안, 못 지우면 더)까지 남고, **열쇠의 접두사가 계정 id 라 지울 줄 · 표에 그 id 도 그때까지 남는다.** 그 객체를 가리키는 줄이 없으므로
   화면 · 주소 어디서도 안 열린다. 둘 다 켜는 날의 확인 거리다(G-120).
5. **꺼진 채로 들어온다.** `PHOTO_STORE_*` 다섯이 모두 비면 올리기는 지금 길(DB bytea)이고 청소기는 DB 에도 안 닿는다. 일부만 있으면
   올리기는 DB 길로 가고 청소기가 실패로 알린다. 운영에는 값이 없다 — 이 ADR 로 운영 동작은 바뀌지 않는다.
6. **열람은 아직 404 다.** 열쇠 줄의 `photo_at` 은 `base64` 가 비고 라우트는 없는 장으로 답한다. 어떻게 내줄지는 G-120 이 정한다 —
   권고(앱 경로가 중계)는 draft PR 에 있다.
7. **옛 사진은 사람이 옮긴다**(`scripts/photo-move.mjs`) — 원본 바이트를 그대로 두 벌로 쓰고, 판본을 안 바꾼다. **화질은 돌아오지
   않는다** — 이미 512px 로 줄여 저장됐다.

## 고르지 않은 것

- **브라우저가 S3 에 바로 올리기(서명된 PUT)** — 함수가 바이트를 안 지나 싸지만, 서버가 두 벌의 머리(형식 · 크기 · 같은 그림)를 못 재고
  버킷에 CORS 를 열어야 한다. 하루 한도 스무 번이라 함수가 지나는 바이트가 작다.
- **서버가 두 벌을 굽기(sharp)** — 서버가 원본(3~5MB)을 받아야 해 본문 한도(1MB)를 올려야 한다. 브라우저가 이미 굽고 있다(`shrink`).
- **버전 관리 켠 버킷** — 지운 객체가 이전 판으로 남아 「떠나면 사라진다」가 깨진다. 버킷은 버전 관리를 끈다(runbook).
- **저장소 목록으로 고아 찾기** — `ListBucket` 권한과 전체 훑기가 든다. 표 · 지울 줄로 고아가 생기는 길을 먼저 막았다.
