# 관문은 현관(`/`)으로 오는 서버 액션에서도 돈다 — 화면을 그리는 요청은 그대로 둔다

> **운영자 결정 2026-09-30.** 「현관 저장 요청에도 로그인 확인」 — 관문을 현관(`/`)으로 오는 서버 액션 POST 에도 돌린다.
> 결정 점검표(`docs/agents/delegation.md`)의 첫 줄 — **누가 무엇을 할 수 있는가** — 에 걸린 결정이다: 다른 기기에서 끊긴
> 세션의 쿠키로는 현관에서 저장할 수 없다. 독립 검토가 기술적으로 이상 없다고 봤고, 짚은 대가 하나는 아래 「정한 것」에 적었다.

## 잰 것 (2026-09-30)

- 화면의 로그인 확인 `signedInUser`(`app/auth/signed-in.ts`)는 쿠키의 **서명**만 확인한다(ADR 0117). 서버에서 막 끊은 세션
  (다른 기기에서 나감 · 지워진 계정)은 같은 요청에서 먼저 도는 관문(`proxy.ts`)의 `getUser` 가 알아채 그 쿠키를 걷는다 —
  둘은 한 벌이고, 머리말은 「이 함수는 `proxy.ts` 의 matcher 안에서만 부른다」고 적었다.
- 주소의 입구에서 값 import 를 따라가 `signed-in.ts` 에 닿는 주소를 재니(`app/auth/signed-in.boundary.test.ts`) 하나가
  matcher 밖이었다: `/ — app/page.tsx → app/saju-calculator.tsx → app/save-for-reading.tsx → app/me/actions.ts →
  app/me/keyed-chart-writes.ts → app/auth/signed-in.ts`. 현관의 「사주풀이로 이어 보기」 저장은 **`/` 주소로** 서버 액션을
  POST 하고(브라우저는 액션을 지금 화면의 주소로 보낸다), 그 액션이 열쇠 모듈에서 `signedInUser` 로 사람을 묻는다.
- 그래서 끊긴 세션의 쿠키가 토큰이 만료될 때까지(한 시간) 현관에서 내 사람 · 저장한 사람을 만들 수 있었다 — 내 사람은 열쇠로
  쓰는 `create_self_person`(ADR 0136)이다. 쓰는 것은 제 자료뿐이라 남의 것이 열리지는 않는다.
- 로컬 dev(자리 2)에서 거절될 토큰을 든 쿠키로 두드렸다: 옛 matcher 는 `POST /`(`next-action` 머리글) 에 `Set-Cookie` 가
  없었고, 이 결정의 matcher 는 `sb-127-auth-token=; Path=/; Max-Age=0` 를 실었다(관문이 돌아 쿠키를 걷었다). `GET /` 와
  `POST /privacy` 는 둘 다 없었다. 빌드 표에서 `/` 는 그대로 `○`(정적)이다.

## 정한 것

`proxy.ts` 의 matcher 에 `{ source: '/', has: [{ type: 'header', key: 'next-action' }] }` 를 더한다. 서버 액션의 표식 머리글이
있는 `/` 요청에서만 관문이 돈다 — 현관을 그리는 GET(로그인 없는 정적 화면)은 그대로 관문 밖이다.

관문이 하는 일은 다른 주소와 같다 — 세션을 갱신하고, 거절된 쿠키를 걷고, 누른 것(GET 이 아닌 요청)이면 활동을 적는다
(ADR 0118). `gateFor` 는 `/` 를 안 보므로 아무 데도 안 보낸다. 대가: 현관의 저장 한 번마다 Auth 왕복 하나와 계정 · 일정 읽기
(관문이 늘 하는 둘)와 활동 적기가 는다. 현관의 저장은 드물다.

**대가 하나 더 — 관문이 던지면 현관 저장이 선다**(독립 검토, 2026-09-30). 이제 관문이 `/` 의 액션에서도 돌므로, 관문 자체가
던지는 실패(예: `supabaseEnv` 가 접속값을 못 찾아 던짐)는 현관 저장을 500 으로 세운다. 전에는 관문이 안 돌아 그 실패가 저장에
닿지 않았다. `getUser` 가 Auth 에 못 닿은 것(네트워크 · 5xx)은 거절이 아니라서 쿠키를 안 걷고 통과시키는 것 — 열린 채 지나가는
갈래(fail-open) — 은 그대로다. 그때는 옛날처럼 화면의 서명 확인만 남는다.

## 고르지 않은 것

- **matcher 에 `/` 를 통째로** — 현관을 여는 모든 요청에 관문이 돈다. 로그인 안 한 방문도 세션 갱신을 지나고, 로그인한 방문은
  Auth 왕복 · 계정 · 일정을 읽는다. 현관은 정적이라 그 비용을 낼 까닭이 없다.
- **열쇠 모듈이 `getUser` 로 묻기** — 서버가 Auth 에 묻는 자리가 둘이 된다(ADR 0117 은 그것을 하나로 줄였다). 홈 · 매칭을
  그릴 때마다 여는 참여 문(`openParticipation`)도 왕복 하나를 더 낸다.
- **이어 보기 저장을 `/me` 아래 액션으로 옮기기** — 액션은 부르는 화면의 주소로 가므로 파일을 옮겨도 주소는 `/` 다.

## 잠금

`app/auth/signed-in.boundary.test.ts` — 입구에서 `signed-in.ts` 에 닿는 주소가 matcher(Next 의 `getMiddlewareMatchers` 로 지은
정규식) 안인지. 화면을 그리며 닿으면 조건 없는 matcher, 액션 파일을 지나서만 닿으면 조건 붙은 matcher 도 센다. 알고 있는
어긋남 목록은 이 결정으로 빈다. 현관 · 공유 · 크론 · webhook 은 화면을 그리는 요청이 관문 밖이라는 표본도 든다.
