# 운영자가 개인정보를 읽는 순간부터 접속기록이 남고, 기록은 매일 지울 수 없는 곳으로 나간다

2026-09-24 에 쟀다(runbook 「운영자 접속기록」, #197): 이용자 자료에 닿는 두 자리 — 앱의 `/ops` 화면과 CLI 로 보내는
SQL — 은 누가 무엇을 읽었는지가 **0일** 남았다. Postgres 는 `log_statement = ddl` 이라 읽기를 안 적고, Vercel 런타임
로그는 1시간이다. 같은 날 `/ops/reports`(ADR 0103)가 섰다 — 운영자가 신고와 대화 스냅샷을 **읽기 시작한 날**이다. ADR
0103 은 「쓰는 누름이 드는 날 접속기록과 함께 본다」고 적었는데, 법이 남기라는 것은 쓰기가 아니라 **접속**이다(「개인정보의
안전성 확보조치 기준」 제8조). 같은 날 운영자(유일한 개발자)가 넷을 정했다.

## 정한 것

**1. 개인정보는 화면으로만 읽는다.** 개인정보 열람은 `/ops/**` 화면으로만 한다. 통계 · 건수 · 마이그레이션 상태처럼
개인을 식별하지 않는 원격 질의는 된다. 개인정보를 읽는 직접 SQL 은 명시된 **break-glass**(장애 · 수사기관의 적법한 요청)
에서만, **사람만** 실행하고, 목적 · 실행자 · 대상 · 시각 · 결과를 저장소 밖의 대장에 적는다(runbook 「break-glass」).
**에이전트는 운영 개인정보를 예외 없이 직접 조회하지 않는다** — 필요하면 질의를 써 주고 사람이 검토해 실행한다
(`docs/agents/delegation.md` 등급 3). CLI(`npm run db:remote`)로 부르는 질의는 SQL 원문이 아니라 **목적과 해시**를
남긴다 — 원문에는 이용자 자료가 섞이고 기록은 지울 수 없는 곳으로 나간다. 빈도가 늘면 `pgaudit` 로 옮긴다.

**2. 접속기록은 1년, 매일 S3 로 나간다.** DB 안의 추가만 되는 표(`audit.operator_access`)가 적고, 크론이 매일 S3 에 JSON
Lines 로 올린다. 버킷은 Versioning + Object Lock — 처음 설정은 Governance 로 재고, 운영 기록은 Compliance, 기본 보존
400일. 객체 키는 첫 줄의 날짜와 최소 · 최대 로그 번호, 파일 머리에 행 수 · 첫/마지막 번호 · 본문 sha256. G-25 법률 검토가
2년이라 하면 만료 전에 이미 있는 객체의 보존을 늘린다(Compliance 는 늘리기만 된다). **Compliance 는 되돌릴 수 없으므로
반출 행에는 운영자 id · 시각 · 대상(신고 id) · 동작(목록 · 상세 · 스냅샷) · 성공/거절만 담는다** — 닉네임 · 메시지 본문
같은 이용자 개인정보 원문은 안 넣는다. git 저장소에도 로그 원문을 넣지 않는다.

**3. 운영 주기는 내부 목표다.** 신고는 영업일마다 미검토 목록을 보고, 접수 뒤 늦어도 3영업일 안에 1차 판단한다 — **이용자에게
공개 약속하지 않는다**(화면 문구를 바꾸지 않는다). 접속기록은 매월 한 번 이상 점검한다(이상 접근 · 대량 열람 · 업무시간 밖
열람 · 연속 거절). 운영자가 3영업일을 넘게 자리를 비우면 **새 가입을 닫는다.** 법령의 말: 「개인정보의 안전성 확보조치
기준」 제8조는 접속기록 보관을 원칙 1년(정보주체 5만 명 이상 · 고유식별정보 · 민감정보 처리 등은 2년)으로 두고, 점검 주기 ·
방법 · 사후조치는 내부 관리계획으로 정하게 한다. **CI 가 고유식별정보에 해당하는지와 그래서 2년인지는 단정하지 않는다** —
G-25 변호사 확인 목록에 넣었다.

**4. Vercel Preview 는 앱이 바뀐 커밋만 빌드한다.** `ignoreCommand`(`scripts/vercel-ignore.mjs`, #199). production 은
건너뛰지 않는다. 문서 · 마이그레이션 · pgTAP · 순수 단위 시험만 바뀌었으면 건너뛰고, 판단 불가 · 비교 실패 · 오류는 빌드한다.
Vercel 은 0 이면 건너뛰고 1 이면 빌드한다 — 시험이 그 반대 의미를 든다.

## 구현이 정한 것

- **기록 표** — `audit` 스키마(API 에 안 나간다). 칸: 번호(identity) · 시각 · 채널(`app` · `cli`) · 운영자 id · CLI 실행자
  이름 · 동작 · 대상 신고 id · 거른 조건 요약 · CLI 목적 · SQL sha256 · 성공/거절. 모든 역할(소유자 `postgres` 포함)에서
  `update` · `delete` · `truncate` 를 걷고 줄 · 문장 트리거가 한 번 더 막는다. 소유자는 트리거를 끌 수 있다 — DB 안에서는 그
  이상 못 지키고, 그래서 밖의 사본이 지워지지 않는 기록이다.
- **문이 적는다** — 운영자 문 셋이 `stable` 에서 `volatile` 로 바뀌고 성공한 읽기를 **같은 트랜잭션에서** 적는다. PostgREST 로
  문을 직접 두드려도 빠지지 않는다.
- **거절은 문 밖에서 적는다** — 운영자가 아니면 문은 `42501` 을 던지고 그 트랜잭션에 적은 줄은 되감긴다. 던지지 않고 빈
  결과를 내면 화면이 404 대신 빈 목록을 세운다. 그래서 앱의 문(`app/ops/reports/read.ts`)이 거절을 받으면 `note_operator_denial`
  을 제 트랜잭션에서 부른다. 운영자가 부르면 안 적고, 한 사람이 한 시간에 서른 줄을 넘게 못 적는다. **한계** — 운영자가 아닌
  사람이 PostgREST 로 문을 두드리고 이것을 안 부르면 거절은 안 남는다(얻는 것은 `42501` 뿐이다). `dblink` 로 트랜잭션 밖에
  적는 길은 접속 비밀을 DB 안에 두어야 해서 버렸다.
- **CLI** — `npm run db:remote -- --purpose "<목적>" "<sql>"`. 목적이 없거나(4~200자) `@` 가 들면 안 돈다. 같은 잠금(ADR 0096)
  안에서 먼저 `audit.note_cli_query` 를 부르고, 적지 못하면 SQL 을 안 보낸다. 실행자는 git `user.name`, 에이전트 세션이면
  `(agent)` 가 붙는다. 대시보드 SQL Editor 는 덮지 못한다 — 그 자리에서 개인정보를 읽지 않는 것이 결정 1 이다.
- **반출** — Vercel Cron `/api/cron/audit-export`(하루 한 번, 서울 03:37 전후 — Hobby 는 프로젝트당 100개 · 하루 한 번 · ±59분,
  기존 크론 하나와 합쳐 둘). `CRON_SECRET` 은 복구기와 같다. 지난 반출의 마지막 번호 뒤를 읽어 올리고, **올린 뒤에** 범위를 적는다.
  적는 문은 앞 반출에서 이어지지 않거나 범위 안의 행 수가 틀리면 거절한다. ~~방금(10분 안) 적힌 줄에서 멈춘다 — 번호를 먼저 받고
  늦게 커밋된 줄을 건너뛰지 않게.~~ → 아래 「정정」. 보존은 객체마다 적지 않고 **버킷 기본 보존**이 정한다 — 반출 키는 `s3:PutObject` 하나면 되고,
  Governance → Compliance 가 코드 배포가 아니다. 켜는 값 넷(`AUDIT_EXPORT_BUCKET` · `AUDIT_EXPORT_REGION` · 접근 키 둘)이
  없으면 「설정 안 됨」으로 200 을 내고 끝난다 — **AWS 계정이 아직 없다.** S3 클라이언트는 `@aws-sdk/client-s3` 하나(설치 25개,
  `npm audit --omit=dev` 0).
- **신고의 검토 기록** — `report` 에 `reviewed_by` · `review_outcome`(조치 없음 · 경고 · 이용 정지 · 추가 확인) · `review_note` ·
  `sanctioned_user_id` · `sanctioned_by`. 채우는 손은 runbook 의 검토 SQL 이다 — 화면에 쓰는 누름은 없다(ADR 0103 그대로).
  「처분은 `app_user.status` 가 든다」(`20260826120000`)는 **지금** 값으로서 그대로다 — 검토 기록은 그 판단의 이력이다. 신고한
  사람은 제 신고를 읽을 수 있으므로 표 단위 `select` 를 걷고 원래 칸 일곱에만 다시 줬다 — 상대가 정지됐는지와 판단 근거가
  새지 않는다. 떠난 사람의 신고(ADR 0098)에도 같은 칸이 옮겨지고, 옮긴 뒤에도 검토 칸은 적을 수 있다.
- **가입 닫기** — `public.signup_pause` 에 열린 줄이 있으면 `complete_signup` 이 **새 사람만** 막는다(이미 가입한 사람의 안내
  재확인은 안 막는다). 막는 문장은 기존의 「지금 쓸 수 있는 코드가 아닙니다.」다 — 닫힌 동안 참이고 새 문구가 없다. PASS 가 가입의
  문이 되는 날(G-20) 코드가 사라지면 이 문장을 다시 본다.

## 정정 (2026-09-24) — 10분 창은 늦은 커밋을 못 막았다 · 거절 한도는 나란히 오면 넘었다

외부 리뷰가 찾았고 로컬 스택에 psql 둘 · 셋을 띄워 재현했다(`scripts/check-db-races.mjs`). 고친 것은 `20261013090000`.

- **반출은 쓰기와 같은 advisory 자물쇠를 나눠 쥔다.** 「최근 10분 안의 줄 앞에서 멈춤」은 커밋 안 된 줄을 못 본다 — 번호 5 를
  받은 트랜잭션이 커밋하기 전에 6 이 커밋되면 반출이 6 만 가져가 커서를 넘겼다. 쓰는 문장은 **문장 트리거**가 번호를 받기 전에
  공유로, 반출은 배타로 쥐고 읽는다. 10분 창은 걷었다. xid 경계(`pg_snapshot_xmin`)는 번호 차례와 xid 차례가 갈릴 수 있어
  같은 구멍이 남으므로 버렸다(까닭은 마이그레이션 머리말) — 그래서 칼럼도 기존 줄을 채울 규칙도 없다.
- **거절 기록의 한 시간 서른 줄은 그 사람의 자물쇠 안에서 센다.** 세고 적는 사이에 나란히 온 두 번째가 같은 수를 봐 31 이 됐다.

## 정정 둘째 (2026-09-24) — 반출 실행의 둘레 (`20261014090000`)

운영자 결정으로 AWS 계정이 서기 전에 반출을 끝까지 다듬었다.

- **한 번에 하나** — 실행은 시작할 때 시도 한 줄과 5분 임대를 적는다. 임대가 살아 있으면 뒤 실행은 「도는 중」으로 적히고
  물러난다. 같은 범위를 두 번 적으면 조용히 받는다.
- **실패는 DB 에** — 실행마다 결과 한 줄(성공 · 실패 · 설정 없음 · 설정 오류 · 도는 중, 오류는 분류만). 집계
  `audit.export_status()`, 운영자 문 `operator_audit_export_status()`(읽으면 남는다), 알림 셋(`audit-export-failed` ·
  `-silent` · `-no-success`)은 `notify_ops` 를 탄다. 위 「잠그지 않은 것」의 「반출 크론의 실패는 Vercel 로그에만 선다」는
  이것으로 닫혔다.
- **켜는 값은 셋으로 갈린다** — 모두 비면 꺼짐(조용히), 하나라도 넣었는데 모자라면 오설정(실패 · 알림). 자격은 **Vercel OIDC →
  IAM 역할(단기)이 기본안**이고 접근 키는 대안이다. 둘을 함께 넣으면 오설정.
- **검증** — `npm run audit:verify` 가 객체를 내려받아 DB 의 반출 기록과 견준다(읽기 역할은 쓰기 역할과 따로).
- **CLI 질의의 결과** — 보낸 뒤 새 줄 `cli.result` 가 앞 줄을 가리키며 성공/실패 · 분류를 든다. 반출 파일은 `version` 2.
- 반출 파일의 운영자 UUID · 신고 id 도 개인정보에 준해 다룬다(runbook 「반출」).

## ADR 0103 을 고친다

「일부러 넣지 않은 것」의 「쓰는 누름이 드는 날은 접속기록(G-25 ③, G-23 ⑩)과 함께 본다」는 **「열람이 시작되는 날부터
접속기록」**으로 고친다. 접속기록은 쓰기의 짝이 아니라 읽기의 짝이다 — `/ops/reports` 가 선 날 이미 늦었다. 이 ADR 이 그 틈을
닫는다. 쓰는 누름(검토 완료 · 제재)이 화면에 없는 것은 그대로다.

## 버린 것

- **`pgaudit` 먼저** — Free 로그는 하루라 크론이 하루 빠지면 그날이 없고, 크론이 Management 열쇠를 들어야 하며, 본문에 이용자
  자료가 섞인 채 밖에 쌓인다. 빈도가 늘면 그때 옮긴다(결정 1).
- **CLI 본문을 적는다** — 위.
- **거절을 빈 결과로 답한다** — 404 대신 빈 목록이 서면 「여기 뭔가 있다」가 된다.
- **객체마다 Object Lock 보존을 적는다** — 반출 키에 보존 권한이 들고, 모드 전환이 배포가 된다.

## 잠그지 않은 것

- 대시보드 SQL Editor 에서의 읽기 — 결정 1 의 규약이지 도구가 막지 않는다. `.claude/settings.json` 도 SQL 의 내용을 못 가른다.
- 반출 크론의 실패는 Vercel 로그에만 선다(`cron-watch` 는 `pg_cron` 만 본다). 월 점검이 마지막 반출 시각을 본다.
- `postgres` 가 트리거를 끄는 것 — 밖의 사본과 월 점검(반출 범위가 이어지는가)이 드러낸다.
