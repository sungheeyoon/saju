# 진입 의식은 한 번 판정하고 화면마다 그린다

`/me` 아래 화면은 모두 같은 것을 먼저 묻는다 — 계정을 읽었나, 정지됐나, 자기 사주를
등록했나. `select('status, self_person_id')` 가 일곱 벌 똑같이 적혀 있고 그 뒤의 세 갈래도
손으로 되풀이됐다.

**아홉 벌이 같은 답을 하지 않았다.** 계정을 못 읽었을 때(`account === null`):

| 화면 | 보여주던 것 |
| --- | --- |
| `me/page.tsx` | 「계정을 읽지 못했습니다. 다시 로그인해 주세요.」 |
| `me/people/[personId]/page.tsx` | **「중지된 계정입니다」** |
| `me/people` · `me/readings` · `me/settings` · `me/compat` | 정상 화면 |

`app_user` 의 select 정책은 `id = auth.uid()` 하나이고 **`status` 를 안 본다.** 정지된
계정도 자기 행을 읽는다. 그러니 「못 읽음」은 「정지」일 수 없고, 저 화면 하나는 아무 일도
없는 사람에게 틀린 말을 하고 있었다. 「한 사실에는 한 표기」(ADR 0027)가 안 지켜진 자리다.

## 게을러서 갈린 것이 아니다

관문은 레이아웃에 못 산다(ADR 0041). 그런데 이것은 **튕기는 일이 아니라 그리는 일**이라
`proxy.ts` 로도 못 올라간다 — 거기서 하는 일은 길을 가리키는 것뿐이고, 접근 판정을 거기
두면 판정하는 자리가 둘이 된다. 갈 곳이 없어서 화면마다 손으로 적혔다.

## 정한 것

**판정은 함수 하나, 그리기는 화면마다.** 계정을 묻는 함수가 다섯 상태 중 하나를 낸다.

- **active** — 다 갖췄다
- **onboarding** — 자기 사주가 아직 없다
- **halted** — 중지다. 우리가 아는 사실이다
- **missing** — 그 자리에 계정이 없다. 다시 들어오라고 한다
- **unreachable** — 지금 물어볼 수 없다. 잠시 뒤에 다시 보라고 한다

컴포넌트로 감싸지 않는다. 화면마다 정지와 온보딩을 다르게 그려 왔고(`/me` 는 온보딩
카드를 펴고 `/me/settings` 는 정지 딱지만 얹는다) 그 자유는 남길 값이 있다. 통일할 것은
**무엇이 참인가**이지 **어떻게 보이는가**가 아니다.

## 다섯째가 오늘 생긴 자리다

`error` 를 보는 화면이 열넷 중 하나였다. DB 가 잠기든 행이 없든 똑같이 `data: null` 로
와서 같은 문구가 섰다. **「다시 로그인해 주세요」는 DB 가 잠겼을 때 틀린 지시다** —
들어올 곳이 없는 데로 보내는 말이고, 사용자는 그 길로 두 번 헛걸음한다.

판정을 한 자리로 모으는 지금이 `error` 를 처음으로 보는 자리다. 함수가 하나라 한 번만
적으면 되고, 열넷에 흩어져 있는 동안에는 열네 번 적어야 했으므로 아무도 안 적었다.
