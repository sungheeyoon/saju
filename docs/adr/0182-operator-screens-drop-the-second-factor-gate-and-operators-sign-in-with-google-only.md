# 운영 화면의 2단계 제한을 걷는다 — 운영자 로그인은 구글 간편로그인만 쓴다

> 후속 결정: ADR 0209 — 운영 화면에 TOTP(aal2)를 다시 걸고, DB 의 `is_operator()` 도 aal2 를 묻는다(운영자 결정 2026-10-28).

> **운영자 결정 2026-10-15**(조율자가 옮김) — 「운영자 로그인은 당분간 구글 간편로그인(OAuth)만 쓴다. 운영 화면의 TOTP(aal2)
> 제한을 걷는다. 기존 운영자 권한 검사(DB `is_operator()` 등 운영자 문)와 접속기록은 그대로 유지한다.」

ADR 0123 을 통째로 걷는다. 그 ADR 은 배포(`a45e34e`) 당일 보류됐고(G-65), 인증 앱은 등록된 적이 없다 — 그래서 운영자도
`/ops/reports` · `/ops/survey` 에서 404 를 받아 왔다.

## 정한 것

- **운영 화면(`/ops/reports` · `/ops/reports/[reportId]` · `/ops/survey`)은 세션의 aal 을 보지 않는다.** 로그인한 세션이면 문은
  곧장 운영자 문을 부르고, 운영자인지는 지금처럼 DB 의 `is_operator()` 하나가 답한다 — 운영자가 아니면 `42501` → 404, 거절 기록
  (`note_operator_denial`)도 그대로다. 운영자면 aal1 세션으로 열리고, 문이 읽을 때마다 접속기록(ADR 0105)이 한 줄을 적는다.
- **`/ops/mfa` 와 `app/ops/second-factor.ts` 를 지운다.** 쓰는 자리가 없어진 등록 화면은 남겨 두면 「쓰는 길」로 읽힌다. 다시 쓰기로
  하면 ADR 0123 과 그 PR(#309)에서 되살린다.
- **DB · Auth 설정은 그대로다.** 마이그레이션은 없다 — `is_operator()` 는 원래 aal 을 묻지 않았다(ADR 0123 「DB 층」은 설계만).
  `supabase/config.toml` 의 TOTP 켜짐은 두며, 운영 Auth 의 TOTP 설정도 건드리지 않는다.

## 이 결정이 말하지 않는 것

- **법적 충족 여부는 확인 전이다.** 「개인정보의 안전성 확보조치 기준」 제6조 제2항(외부에서 개인정보처리시스템에 접속할 때 안전한
  인증수단)을 구글 간편로그인만으로 충족하는지는 정하지 않았다 — OAuth 라는 이유만으로 충족했다고 적지 않는다. 남은 물음은 G-65 가 든다.
- G-23 ⑨ 의 바깥 계정(Supabase · Vercel · GitHub · PortOne · AWS) 2단계 인증은 이 결정과 따로다.

## 값

- 운영자의 구글 계정이 새면 그 세션으로 신고 근거 · 설문 글을 읽을 수 있다 — ADR 0123 「잰 것」의 위험이 화면 쪽에서도 다시 열린다
  (DB 층은 원래 열려 있었다). 막는 것은 구글 계정 자체의 보호와 접속기록 뿐이다.
- 신고 열람대 운영 검증 열네 걸음(G-24)이 2단계 없이 밟힌다.
