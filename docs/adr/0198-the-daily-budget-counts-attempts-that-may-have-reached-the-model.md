# 하루 공용 상한은 모델에 닿았을 수 있는 시도를 센다 — 제출 전에 끝난 예약은 자리를 돌려준다

> **운영자 결정 2026-10-22**(조율자 세션에서 전함) — 권고안 그대로: 물음 1 은 **안 A**(모델에 닿았을 수 있는 시도 + 도는 예약을 센다,
> 제출 전에 끝난 예약만 빠진다), 물음 2 는 **`reading_run.model` · `prompt_version` 을 그대로 둔다**. 점검표의 「비용 · 요금 · 외부
> 서비스 — 한도」 줄에 걸린 결정이다. 이 ADR 은 ADR 0039 의 「실패한 시도도 센다」를 좁힌다 — 실패를 빼지 않고, 모델에 안 간
> 채 끝난 시도만 뺀다.

## 무엇이 문제였나

`reading_spend_today()`(`20260909090000`)는 오늘 연 `reading_run` 을 상태와 상관없이 셌다. 시도를 여는 문(`start_reading_run`)은
로그인한 사람에게 열려 있고, 모델에 보내는 걸음(`prepare_reading_job` → 제출)은 앱이 열쇠로 따로 밟는다. 문만 바로 부르면 모델에 한
번도 안 가는 예약이 생기고, 그것은 복구기(`prepare-timeout`)나 같은 대상의 다음 누름(`expired`)이 닫는다 — 그래도 하루 500 의 자리를
차지했다.

- 계정 하나: 시간당 20(`reading_rate_limit`) → 하루 최대 480. 혼자서는 500 을 못 채운다
- 계정 여럿: 두 계정이면 하루 960 — 채운다. 그날 모든 사람의 풀이가 「오늘 만들 수 있는 풀이를 모두 썼습니다」로 선다
- 돈은 안 나간다(모델에 안 갔다). 막히는 것은 서비스다

운영 값(2026-10-22): 시도 45건 — 성공 43 · 실패 2(둘 다 `non-korean-self-body`, 토큰을 든 채). 지금까지 이렇게 쓰인 적은 없다.

## 정한 것(안)

| 물음 | 답 |
| --- | --- |
| 무엇을 세나 | 오늘 연 시도 가운데 **제출 직전 문을 지난 것**(`reading_run.prepared_at`) + **아직 도는 예약**(`running` 이고 `reading_run_timeout()` 안) |
| 실패는 | 빼지 않는다. 모델이 토큰을 쓴 뒤 실패한 시도(`model-timeout` · 검사 실패)는 제출 직전 문을 지났으므로 센다 |
| 표시는 누가 다나 | `prepare_reading_job` — 열쇠(`service_role`)에만 열려 있다. 모델에 보내는 길은 그 문 뒤의 하나뿐이다(`submitFrozen`). **앱은 그 문이 참을 낼 때만 보낸다** — 전에는 반환값을 버려, 이미 닫힌 시도(거짓)도 보냈고 그러면 표시 없이 모델이 돈다. 이 결정과 함께 고친다 |
| 잠금 차례 | 문은 시도 행을 먼저 잠그고 작업 행을 고친다 — 닫는 쪽(시도 행 → 트리거로 작업 행)과 같은 차례라 엇갈려 교착하지 않는다 |
| 옛 시도 | 모두 `prepared_at = created_at` 로 채워 옛 셈과 같게 센다 |
| 지출 표 | `reading_spend_daily` 끝에 `budget_counted` — 오늘 줄의 그 칸이 상한이 보는 수다. `attempts` 는 연 시도 전부 그대로 |

남는 것 — 도는 예약은 여전히 센다. 계정 하나가 동시에 잡는 예약은 풀이권 잔액 · 대상마다 하나 · 시간당 20 에 묶이므로, 500 을
동시에 잡으려면 수십 계정이 든다.

## 고르지 않은 것

- **실패를 통째로 뺀다** — 모델이 비용을 쓴 뒤 실패한 시도가 빠져 상한이 돈을 못 막는다.
- **사용자 문을 걷고 서버만 연다** — 시도 여는 문을 열쇠로 옮기면 사람 자격(`auth.uid()`)을 문 밖에서 다시 짓게 된다. 크고, 이번 결함보다 넓다.

## 같이 본 것 — `p_model` · `p_prompt_version`

`start_reading_run` 의 두 인자는 부르는 쪽이 정하고 `reading_run.model` · `prompt_version` 에 그대로 남는다. 비용 · 권한에는 안
닿는다 — 모델에 실제로 보낸 값은 열쇠가 적는 `reading_job.requested_model` · `prompt_version` 과 저장 문(`save_reading`)이 든다.
`reading_run` 의 두 칸은 로컬 도구가 제 줄을 알아보는 표식으로 쓴다(`scripts/notice.mjs` 의 `MACHINE_MODELS`). 그래서 이번에는 안
고친다 — 기록만 흐려진다는 것을 운영자 표에 올린다.
