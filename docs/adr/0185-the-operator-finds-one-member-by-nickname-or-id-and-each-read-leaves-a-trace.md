# 운영자는 닉네임이나 계정 id 로 회원 한 명을 찾아 상태 · 풀이권 · 경고 이력만 보고, 읽을 때마다 접속기록에 남는다

> **근거** — 간극 대장 G-110 ③(「정했다」, 2026-10-16 운영자 물음에서 섰다): 「회원을 찾아 상태 · 산 풀이권 · 쓴 풀이권 ·
> 경고 이력을 보고 … 열람은 접속기록에 남는다」. 찾는 열쇠와 칸의 경계는 이 ADR 이 정한다 — 운영자 확인 전이다.

## 잰 것 — 만들기 전에

- 회원을 찾는 화면이 없었다. 풀이권 문의 · 이의 제기 · 환불 요청을 받으면 계정을 runbook SQL 로 찾아야 했고, 이메일로 계정을
  찾는 것은 break-glass 다(`docs/ops/runbook/access.md` 「개인정보는 화면으로만」).
- 운영 화면은 이미 계정을 **닉네임과 내부 UUID 로만** 가른다(`/ops/reports`, ADR 0103). 이의 제기 메일도 닉네임 · 안내번호로
  찾는 것이 절차다(ADR 0108). 닉네임은 유일하다(`app_user_nickname_is_unique`, `nickname_key` — 대소문자 · 앞뒤 빈칸을 안 가린다).

## 정한 것

1. **찾는 열쇠는 닉네임 또는 계정 id 다. 이메일은 문이 받지도 내지도 않는다.** 찾으면 한 명이다 — 목록 · 앞글자 찾기를 두지
   않는다(훑어보는 길이 되지 않게).
2. **보여 주는 칸은 G-110 이 든 넷뿐이다** — 계정 상태 · 산 풀이권(묶음의 산 회차 · 환불로 걷은 회차) · 쓴 풀이권(산 것에서 쓴
   회차 · 몫을 안 가린 확정 쓰임, 예약 중이면 따로) · 경고 이력(경고 · 이용 정지 결정 — 안내번호 · 갈래 · 검토한 때 · 이용자 확인 ·
   12개월 셈에 드는가, 신고 내용으로 가는 길), 그리고 승인된 적 있는 주문의 번호(`rdo_…`) — 주문 화면(`/ops/orders?order=`,
   G-110 ②)으로 가는 길이다. 출생정보 · 풀이 · 저장한 사람 · 이메일 · 주문 금액 · 판단 근거 · 신고한 사람은 안 낸다.
3. **경고 이력은 지금 계정의 신고(`public.report`)에서 제재 대상인 줄뿐이다.** 떠난 사람의 신고로 옮겨진 경고(`retention.report`)는
   떨어진 보관이라(ADR 0098) 앱이 읽는 길을 새로 내지 않는다 — 셈에는 들므로 3회째 검토 때는 runbook 「경고를 적기 전에」의
   질의로 센다. 이의 제기를 인정한 경고는 제재 대상이 비어 안 선다. **화면은 그 범위대로 말한다** — 횟수는 「현재 신고 기준」,
   빈 상태는 「현재 신고에 적힌 경고가 없습니다」이고, 분리 보관 경고는 런북 SQL 로 따로 센다는 한 줄이 늘 선다(조율자 리뷰
   2026-10-16). 보관분까지 센 수를 화면에 주는 제한된 문은 다음 일이다.
4. **문이 적는다** — `operator_member` · `operator_member_warnings` 가 읽을 때 같은 트랜잭션에서 `members.find` ·
   `members.warnings` 한 줄씩. 거른 조건 칸에는 무엇으로 찾았나(`by=nickname|id`)와 찾은 계정 id(`user=<uuid>`, 없으면 `none`)만
   적는다 — **찾은 닉네임은 적지 않는다**(반출본은 지울 수 없다, ADR 0105 결정 2). 거절은 앱의 문이 `note_operator_denial` 로.
5. **찾는 말 없이 연 화면도 문을 부른다** — 그때 문은 운영자인가만 묻고 빈 결과다(적지 않는다). 운영자가 아니면 404 다.

마이그레이션 `20261212090000` · pgTAP `97_operator_member` · 화면 `app/ops/members/`.

## 버린 것

- **이메일로 찾기** — 고객 문의가 메일로 오니 편하지만, 화면이 이메일을 받으면 이메일 → 계정의 짝을 읽는 길이 화면에 선다
  (지금은 break-glass). 답장으로 닉네임을 묻는 지금 절차를 그대로 쓴다.
- **찾은 말을 기록에 적기** — 「누구를 찾았나」는 계정 id 가 든다. 없는 닉네임을 찾은 것까지 남기려면 원문이 들어간다.
