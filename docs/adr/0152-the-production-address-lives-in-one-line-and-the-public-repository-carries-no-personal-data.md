# 운영 주소는 한 줄에만 살고, 공개 저장소는 사람을 가리키는 값을 들지 않으며, 지시받은 일은 PR 까지 묻지 않고 간다

> **운영자 결정 2026-10-08**(대화 세션의 `/retro` 에서 1 · 2 · 4 · 5 를 골랐다). 그날 사정은 `docs/notes/2026-10-08-seo-audit-retro.md` 가 든다.

## 정한 것

1. **운영 주소를 적는 자리는 `docs/ops/runbook/domain.md` 맨 위 한 줄이다.** 코드 주석 · 위임 규약 · 운영 절차 · 역할 문서는 주소를
   글자로 들지 않고 그 줄을 가리킨다. `docs/start.md` 「원본」 표에 줄을 두었고, `scripts/code-rules.test.ts` 가 잰다 — 그날의 글자로
   남는 기록(노트 · ADR · 법무 · changelog · 간극 기록)과 흉내 낸 값(`scripts/check-share.mjs`)은 뺀다.
   까닭: 주석 둘(「아직 자기 도메인이 없다」)이 낡은 채 남아 조율자가 운영 주소를 옛 별칭으로 보고했다.
2. **이 저장소는 공개다 — 사람을 가리키는 값은 적지 않는다.** 집 주소는 시군구까지, 휴대폰 · 주민번호는 적지 않는다. 동 · 호, 휴대폰,
   주민번호 꼴을 추적하는 글자 파일 전체에서 시험이 잰다. 까닭: ADR 0149 의 세션이 운영자의 집 주소를 코드와 문서에 적었다(ADR 0151 이
   걷었다, 기록에는 남는다).
3. **운영자가 특정 변경을 올리라고 하면 그 PR 이 main 에 든 순간 올린다** — 상관없는 열린 PR 은 기다리지 않는다
   (`docs/ops/runbook/deploy.md` 「묶음 배포」 0). 묶음을 닫는 배포는 그대로다.
4. **운영자가 고치라고 한 일은 커밋 · PR · `--auto` 까지 묻지 않는다** (`docs/agents/delegation/coordinator.md` 「조율자 세션」).
   다시 묻는 것은 결정 점검표의 새 줄에 걸릴 때와 배포뿐이다. ADR 0093 의 등급은 그대로다 — PR 과 `--auto` 는 이미 등급 2 다.
