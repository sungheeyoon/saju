# PRD 는 지금 모양만 들고, 틈은 대장 한 장이 든다

## 무엇이 흩어져 있었나

`docs/prd.md` 는 1,265줄이었고 그중 **282줄이 개정 기록**이었다 — §0.3 「재어 본 값」(날짜 넷의
시험 수), §0.4~§0.8 「이번 개정에서 문서를 고친 자리」 다섯 절, §9.2 「이전에 닫은 항목」, §10
「이 문서의 계보」 114줄. 제목 한 줄이 개정 날짜 여섯을 들었다. 무엇을 만드는가를 읽으려는
사람이 그 문서가 어떻게 여기까지 왔는가를 함께 읽어야 했고, 두 종류의 글이 같은 절 번호를
나눠 썼다 — §9 는 「코드를 고쳐야 맞는 것」과 「이전에 닫은 것」을 한 절에 뒀다.

**아직 없는 것 · 안 정한 것 · 어긋난 것은 다섯 자리에 흩어져 있었다.** PRD §7(정했다) · §8(미정,
번호 여덟) · §9(어긋남 둘) · 이슈 #88(구조 후보 7·8 과 「작지만 잰 것」 여섯) · 세션 메모(운영에만
있는 `ensure_rls`, 처리방침 낱말, 긴 각주, 개인 풀이 프롬프트의 말투, 유입 측정, 배포 규약).
그중 메모에 있는 것은 저장소 밖이라 다른 에이전트가 못 본다. 어느 것도 **상태 · 끝났다고 말할
조건 · 언제 닫는가**를 같은 모양으로 들지 않았다 — §8 의 미정과 §7 의 없다는 뜻이 다른데(PRD
머리가 그렇게 적었다) 그 둘과 「어긋남」이 한 표에 선 적이 없다.

위임 준비 6단계(2026-09-22 진단)가 이것을 들었다.

## 정한 것

**PRD 본체는 지금 모양만 든다.** 개정 기록은 `docs/product/prd-changelog.md` 로 갈라 냈다 —
머리말의 「이번 개정은…」 문단, §0.3~§0.8, §7.4.3·§7.4.4(끝난 화면 정리), §9.1·§9.2, §10. **문장은
옮겼을 뿐 고치지 않았다.** 본체에 남은 것은 표시 표, §0.1·§0.2(지금 상태), §1~§8, 그리고 §9 자리의
포인터 한 절이다. 1,265줄 → 973줄. 새 개정은 changelog 에 날짜 순으로 쌓는다.

**틈은 `docs/product/gaps.md` 한 장이 든다.** 서른다섯 줄이고 줄마다 번호(`G-nn`) · 무엇 · 출처 ·
상태 · 끝났다고 말할 조건 · 메모다. **상태는 다섯뿐이다** — `정했다` · `미정` · `어긋남` · `보류` ·
`결정 대기`. 「보류」는 2026-09-15 의 「써 보고 정한다」이고, 「결정 대기」는 사람의 답이 필요한
것이다. **띠는 넷** — 운영 베타에서 닫는다 · 채팅 안전 베타 · 공개 출시 · 정비(위임 준비). 「써 보고
정한다」는 띠가 아니라 상태다. 닫히면 줄을 지우고 changelog 에 날짜와 함께 적는다.

PRD §7·§8 은 그대로다 — 무엇을 만들지와 무엇을 안 정했는지는 요구사항이고 거기 산다. 대장은
그것들을 **가리키며** 상태와 조건을 더할 뿐이다. §9 의 어긋남 둘은 대장으로 갔다(하나는 끝난
기록이라 changelog 로).

**대장과 본체의 가리킴은 시험이 든다** — `scripts/code-rules.test.ts`.

- 줄마다 번호가 하나씩이고 상태가 다섯 중 하나다
- 출처의 `§` 는 PRD 본체에 실제로 있는 절이다. §8 은 절이 아니라 번호 목록이라 `§8.N` 은 그
  목록의 N 번째 줄로 잰다. `CONTEXT §10` 은 용어집의 절이라 뺀다
- PRD 본체에 `## 10.` 도 `### 0.3~0.8` 도 없고, changelog 에 계보가 있다
- 대장이 든 뿌리 경로(`src/lib/reading/parts.ts` · `docs/ops/runbook.md` …)는 실재한다(ADR 0087
  의 입구 문서에 넣었다)

## 옮긴 절을 가리키던 자리

여섯을 손봤다 — PRD 안의 셋(§0.1 의 「§9」, §3.1 의 「§7.4.3」, §5.3 의 「§9」)과 코드 주석 넷
(`scripts/run-checks.mjs` · `run-checks.test.ts` 의 「§0.7」, `check-result.mjs` · `check-match.mjs` 의
「§9.1」), 코드 규칙 문서의 「PRD §9」 둘. 코드 주석이 PRD 의 절 번호를 들고 있던 것은 이번에
알았다 — 절 번호는 옮겨지는 값이라 앞으로는 changelog 의 날짜나 대장의 `G-nn` 을 든다.

## 잠그지 않은 것

- **대장의 항목이 PRD §7·§8 전부를 덮는가.** 손으로 맞췄다(§7.0~7.4 · §8.1~8.8 전부 든다). §7 에
  줄이 늘고 대장에 안 실리면 안 잡힌다 — 반대 방향(대장이 없는 절을 가리킴)만 잰다
- **changelog 의 절 번호.** 옮긴 절은 옛 번호(§0.3 · §10)를 제목에 그대로 든다 — 기록이라 그
  번호가 그때의 자리를 말한다. 고치지 않는다
- **닫힌 줄을 changelog 로 옮기는 일.** 규약만 적었다
