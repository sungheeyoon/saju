# 일은 역할 문서 한 장에서 시작하고, 그 문서의 넷째 칸을 고치며 끝난다

> 후속 결정(일부): ADR 0145 — 「이 저장소의 방식」을 원본을 한 줄로 줄인 길잡이로 두고 줄마다 `(원본: …)` 을 달던 것은
> 원본을 가리키는 Markdown 링크와 몇 낱말의 길잡이(Router)로 바뀌었다. 「끝날 때 고치는 것」은 원본의 체크리스트를 가리키고,
> 「하지 않는 것 · 묻는 것」은 줄마다 출처 링크를 단다

> 후속 결정(일부): ADR 0146 — 「역할 문서는 조율자가 라운드 끝에 고친다」는 조율자가 라운드 끝에 `/retro` 를 도는 것으로 바뀌었다

> **운영자 결정 2026-09-30** — 「에이전트가 바로 손대지 말고, 역할마다 무엇을 읽고 이 저장소가 어떻게 하는지 알고 시작하게.
> 문서 하나가 길면 안 되고 링크로 갈라서. 끝나면 무엇을 고쳐야 하는지도 알아야 선순환이 된다.」 범위는 1단계(입구와 역할
> 문서 · 얇은 에이전트 정의)이고, 큰 문서를 쪼개는 일은 뒤로 미뤘다.

## 잰 것 (2026-09-30)

- 입구는 `CLAUDE.md` 의 「무엇은 어디서 답한다」 네 줄과 `docs/agents/delegation.md`(49KB) 였다. 원본은 넷(`docs/prd.md` 127KB ·
  `docs/ops/runbook.md` 170KB · `CONTEXT.md` 81KB · `docs/product/gaps.md` 52KB)이 가장 크다 — 「화면을 고친다면 무엇을 읽나」에
  답하는 자리는 없었고, 에이전트는 다 읽거나 안 읽고 시작했다.
- 조율자 브리프가 그 빈자리를 메웠다. 브리프가 규칙을 기억으로 다시 써 원본을 뒤집은 일이 있었고(「머지 뒤 `db push`」,
  2026-09-28), 그래서 「브리프는 규칙을 옮겨 적지 않는다 · 브리프 틀 문서는 따로 두지 않는다」가 섰다.
- 끝날 때 고칠 문서는 PR 틀의 「문서」 칸 한 줄에 다섯 문서가 나열돼 있었다 — 어느 일이 어느 문서를 고치는지는 없었다.

## 정한 것

- **입구 한 장 `docs/start.md`** — 모두가 먼저 보는 넷, 역할 고르기, 원본이 무엇을 답하나, 선순환의 네 걸음.
- **역할 문서 `docs/roles/*.md` 여덟** — 화면 · 기능 · DB · 풀이 · 운영 · 검토 · 문서 · 조율자. 칸은 넷으로 같다: 먼저 읽는 것 ·
  이 저장소의 방식 · 하지 않는 것 · 묻는 것 · 끝날 때 고치는 것.
- **역할 문서는 규칙을 옮겨 적지 않는다.** 원본의 절을 `` `경로` 「절 이름」 `` 으로 가리키고, 「이 저장소의 방식」은 원본이
  말하는 것을 한 줄로 줄인 길잡이다. 둘이 어긋나면 원본이 맞다. 이것이 「브리프 틀 문서는 따로 두지 않는다」를 대신한다 —
  진실이 두 벌이 되는 까닭은 규칙을 옮겨 적기 때문이지 역할을 나누기 때문이 아니다.
- **에이전트 정의 `.claude/agents/<역할>.md` 는 얇다** — 역할 문서를 읽으라는 말과 끝날 때의 한 줄뿐이다. Claude Code 만 읽으므로
  다른 에이전트에게는 `docs/start.md` 의 표가 전부다. 조율자는 사람과 말하는 세션 자신이라 정의가 없다. **역할 문서는 도구를
  모르게 적는다** — Claude Code 의 호출법(`subagent_type` · `isolation`)은 `CLAUDE.md` 한 곳에 둔다(2026-09-30 보정).
- **역할 문서는 조율자가 라운드 끝에 고친다.** 에이전트는 헤맨 자리를 보고에 한 줄 남긴다 — 나란히 도는 PR 이 같은 역할 문서를
  고쳐 부딪히지 않게.
- **「이 저장소의 방식」의 줄마다 끝에 `(원본: …)` 을 단다**(2026-09-30 보정) — 출처는 `` `경로.md` 「절」 `` 이나 `ADR NNNN` 만이고
  고정 형식이다. 본문에 경로나 ADR 이 우연히 있어도 그 줄의 출처로 세지 않는다.
- **시험이 잠근다**(`scripts/code-rules.test.ts`): 역할 문서마다 네 칸이 그 차례로 있다 · `docs/start.md` 의 표가 역할 문서 전부를
  든다 · 가리킨 절이 그 파일에 제목으로 있다 · 「이 저장소의 방식」의 줄마다 고정 형식의 출처가 있고 그 ADR 이 있다 · 에이전트
  정의와 역할 문서가 짝이다 · 역할 문서는 한 화면(8KB) 안이다. 역할 문서와
  `docs/start.md` 는 입구 문서라 백틱 경로와 `npm run` 이름도 잰다.

## 치르는 값

- 원본의 절 이름을 바꾸면 역할 문서도 고쳐야 한다 — 시험이 붉혀 알려 준다.
- **시험이 보장하는 것은 자리까지다** — 줄마다 출처가 있고 그 절 · ADR 이 있다는 것. 줄인 문장이 원본의 뜻과 같은가는 못 견준다.
  원본이 바뀌어 뜻이 달라져도 초록이다 — 조율자가 라운드 끝에 본다. 다만 이제 어느 줄을 어디와 대조할지가 줄마다 드러나 있다.

## 잠그지 않은 것

- 큰 원본(`docs/ops/runbook.md` · `docs/prd.md` · `CONTEXT.md` · `docs/agents/delegation.md`)을 주제별 파일로 쪼개는 일 — 경로를
  부르는 스크립트와 시험이 있어 따로 한다. 역할 문서는 절을 가리키므로 쪼갤 때 가리킨 경로만 옮기면 된다.
- 에이전트가 역할 문서를 정말 읽었는가 — 도구로는 못 잰다. PR 의 「문서」 칸이 넷째 칸을 옮겨 적었는지로 본다.
