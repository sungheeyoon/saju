# Match 는 범위가 정해진 접근권이고, 출생 원문은 모델에 넘기지 않는다

## Match 는 상대 Person 에 대한 전체 접근권이 아니다

「궁합을 함께 보자」는 동의에는 **서로의 여덟 글자가 관계표에서 전부 드러날 가능성**이
포함된다(ADR 0012). 그러나 그것이 「정확한 출생 시각과 출생지를 공개하고, 내 원국의 모든
판정을 열겠다」는 동의는 아니다. `Evidence.charts.a` 는 **원국 전체**이고(팔자·십성·오행·신강신약·
억부·조후·격국·종격·신살·대운·지금 도는 운) `Saju.meta.inputTime` 에 **입력한
생년월일시 원문**이 들어 있다. 근거 보기를 그대로 열면 「동의 전 비공개」로 정한 넷 중
셋이 버튼 한 번에 나간다.

**저장은 한 벌, 노출이 두 벌이다.** 전체 Evidence 는 서버에 한 벌로 보존하되
클라이언트가 직접 조회할 수 없게 하고, 서버가 현재 User 를 확인해
`compatibility + limitations + 자기 charts` 만 돌려준다. 상대의 `ChartEvidence`,
`meta.inputTime`, 출생지와 원국 전체 판정은 내려보내지 않는다. Compatibility 의 관계
참가자를 합쳐 상대의 여덟 글자가 모두 드러나는 것은 Match 동의 범위 안이다. **자르는
것은 서버가 한다** —
통째로 내려보내고 화면에서 접으면 개발자 도구 한 번에 다 보인다.

`compatibility.elementSupport.a` 와 `eokbuMatch.a` 는 오행 구성과 억부 후보를 사실상
드러낸다. 그건 궁합 그 자체라 뺄 수 없으므로 **동의 화면이 정확히 적는다** — 상대는
궁합 관계·관계에 걸린 글자와 자리·매칭 지표·AI 해석과 일부 오행 구성을 보게 되고, 그
관계를 모두 합치면 여덟 글자가 전부 드러날 수 있다고. 정확한 생년월일시·출생지와 상대
원국 전체 판정은 공개되지 않는다.

상대 원국 전체 판정이나 `ChartEvidence` 공유가 필요해지면 Match 수락에 묶지 않고 **별도
동의 기능**으로 추가한다. 여기서 여덟 글자와 원국 전체 판정을 같은 말로 부르지 않는다
(ADR 0012).

## 출생 원문은 모델에 넘기지 않는다 — 공유용만이 아니라 언제나

프롬프트 규칙(「입력 원문을 출력하지 않는다」)만으로 막지 않는다. **안 넣은 것은 못
낸다.** AI 입력에서 정확한 생년월일시와 출생지를 제거하고, 그 위에 출력 원문 노출
검사를 둔다. 프롬프트 정책 버전이 올라가는 사유다.

**공유 Reading 에만 적용하지 않고 모든 Reading 에 적용한다.**

1. 규율이 하나가 된다 — `Reading.evidence` 는 언제나 모델에 넘긴 그것과 정확히 같다.
   갈라 두면 어느 Reading 의 근거 보기가 무엇을 보장하는지가 두 갈래가 되고, 그 구분은
   화면에서 보이지 않는다.
2. 모델은 그것을 쓰지 않는다. 해석에 쓰이는 것은 팔자와 그 위의 분석이지
   `1993-05-12 14:30` 이라는 문자열이 아니다 — 절기·자시·경도 판정은 이미 끝나서
   `pillars` 와 `meta.corrections` 로 들어와 있다.
3. 생년월일시가 외부 API 로 아예 나가지 않는다. 프롬프트 규칙이나 출력 검사보다 강한
   성질이고, 「AI 에 무엇을 보냈나」에 한 문장으로 답할 수 있게 한다.

본인이 자기 명식 전체를 보는 자리는 Reading 이 아니라 자기 Person 페이지다. 근거 보기의
구실은 **AI 의 주장을 되짚는 것**이지 명식을 보여주는 것이 아니다 — 오히려 모델이 못 본
사실이 근거 패널에 서면 글이 실제보다 더 단단히 뒷받침된 것처럼 보인다.

## ADR 0001 을 한 군데 고친다

ADR 0001 은 `inputSnapshot` 을 두지 않는 근거로 「evidence 안에 이미 입력이 있다」를
들었다. 원문을 빼면 그 근거가 사라지므로, **`Reading` 이 양쪽 `chartRevisionId` 를
든다**(ADR 0004 가 만든 것). revision 이 입력을 들고 evidence 는 안 든다.
