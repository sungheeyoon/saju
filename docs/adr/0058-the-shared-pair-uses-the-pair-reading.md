# 공유 궁합도 궁합 풀이의 한 처리 방식을 쓴다

공유 궁합은 동의 범위가 좁다는 이유로 비공개 궁합과 다른 프롬프트 구성과 다른 결과
화면을 쓰고 있었다. 그 결과 일반 궁합에서 절 목록을 걷어내고 이름을 고쳐도 공유 궁합은
옛 절 목록과 「첫 번째 분·두 번째 분」을 그대로 썼다. 같은 종류의 풀이가 만들어진 경로에
따라 다른 제품처럼 보였다.

## 결정

공유 궁합과 비공개 궁합은 **같은 궁합 풀이 구성 방식**을 쓴다. 모델에는 정해진 절 대신
다룰 것의 목록을 주고, 소제목·차례·깊이는 모델이 정한다.

자료 범위까지 같게 만들지는 않는다. 공유 궁합은 ADR 0012의 동의 범위를 그대로 지켜,
각 사람 원국의 전체 판정과 운을 보내지 않으며 그 자료가 필요한 물음도 목록에서 제외한다.
같은 것은 처리 방식이고, 다른 것은 허용된 근거다.

공유 풀이가 사람을 부를 때는 두 계정의 공개 닉네임을 쓴다. 닉네임과 판본의 매김은
`match_calculation_inputs`가 함께 내어 앱이 차례를 추측하지 않게 한다. 정확한 출생 입력을
내는 이 함수는 계속 `service_role`에만 열려 있고 브라우저에는 닫혀 있다.

이미 저장된 옛 풀이를 지우거나 다시 만들지는 않는다. 화면에서 「첫 번째 분·두 번째 분」만
현재 보는 사람 기준의 `나`와 상대 공개 닉네임으로 옮겨, 기존 결과도 자리 이름을 그대로
노출하지 않게 한다. 풀이의 판단과 문장 차례는 바꾸지 않는다.

## 화면

성립한 궁합은 소식의 결과 목록이 아니라 풀이 탭에 선다. 결과 화면은 한 문장 결론과 점수,
두 사람의 명식, 궁합 풀이 본문 순서다. 동의가 끝난 뒤에는 요청 때의 긴 범위 카드, 상대 소개
카드, 엔진 중간 관계표를 다시 세우지 않는다. 상세 결과 화면이므로 풀이 본문도 접지 않는다.

받은 요청 카드에서는 결정에 필요한 질문 하나만 직접 묻는다. 내 사주팔자 여덟 글자가
상대에게 공개되고 두 사람이 자세한 궁합을 함께 본다는 내용이다.
