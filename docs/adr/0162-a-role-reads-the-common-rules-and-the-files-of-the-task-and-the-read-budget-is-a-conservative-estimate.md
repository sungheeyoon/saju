# 역할은 공통 규칙과 그 일의 파일을 읽고, 읽기량은 보수적 예상치로 센다 — 화면 문서는 무리마다 한 파일이다

> **운영자 승인 2026-10-10**(조율자 브리프로 전함) — 「역할별 필수 읽기량이 천장에 닿았다. ui 는 15바이트 남았고, PRD 화면 표에
> 한 구절만 더해도 ui · reviewer 가 넘어 필요한 제품 문서를 못 고친다. 문서 PR 하나로 정비한다.」 방향은 여섯이었다 — 늘 읽는 공통
> 규칙과 일마다 읽는 문서를 나눈다 · 검사를 그 구조에 맞추고, 정확히 못 세면 「실제 필수 읽기량」이라 부르지 말고 보수적 예상치라
> 적는다 · 링크만 옮겨 수를 줄이지 않는다 · 결정과 요구는 지우지 않고 옮기기만 하며 길(색인 · 링크)을 남긴다 · 다시 재서 여유를
> 두고 상한을 정한다(80,000 일 필요는 없다) · 라운드 보고가 짚은 빠진 것을 맞는 문서에 넣는다.

ADR 0147 의 두 대목을 대체한다 — ① 천장을 정할 때 남기는 여유의 바닥(눈금 반, 2,500) ② 붉어지는 여유(10,000). 그리고 ADR 0145 ·
0147 이 「필수 읽기량」이라 부른 수의 이름을 「읽기량 예상치」로 바꾼다. 셈의 규칙(고정 · 절 · 동적 라우트 · 선택 묶음 · 「닿을 때
여는 것」은 안 센다)은 그대로다. ADR 0140 의 「역할마다 한 장」도 그대로다 — 역할 문서는 한 장이고, 일마다 갈리는 읽을 거리는 그
한 장 안의 선택 묶음이 든다.

  화면의 한 줄이 자라도 모든 화면 일의 읽기량이 자랐다.

## 정한 것

- **화면 문서는 무리마다 한 파일이다.** 무리는 일곱이고 두 폴더가 같은 이름을 쓴다.

  | 무리 | 파일 이름 | 화면 |
  | --- | --- | --- |
  | 첫 화면 · 사주 보기 | `first` | `/` · `/saju` — 로그인 전 결과 · 이어 보기 확인 · 사주 결과 표 |
  | 로그인 · 가입 · 안내 화면 | `public` | `/auth` · `/auth/denied` · `/signup` · `/closed` · `/privacy` · `/about` · `/help` · `/share/**` · 바닥글 · 오류 · 404 |
  | 홈 · 저장한 사람 · 풀이 | `home` | `/me` · `/me/people` · `/me/readings` · `/me/readings/[subject]` |
  | 궁합 | `compat` | `/compat` · `/me/compat` |
  | 인연 · 채팅 · 소식 | `matching` | `/me/matching` · `/me/matching/history` · `/me/match/[id]` · `/me/chat` · `/me/requests` |
  | 설정 · 프로필 · 설문 | `settings` | `/me/profile` · `/me/settings` · `/me/survey` |
  | 운영 화면 · 작업대 | `ops` | `/ops/**` · `/me/reading/inspect` |

  PRD 는 `docs/product/prd/screens/<무리>.md`(화면 표의 그 줄과 그 화면의 절), 대장은 `docs/product/copy-ledger/<무리>.md`. 공통
  파일은 남는다 — `screens.md` 는 모든 화면의 규칙 · 무리 색인 · §3.2, `copy-ledger.md` 는 머리 · 무리 색인(번호 → 파일) · 01 규칙 ·
  여러 무리에 걸친 줄 · 「검토 대기」.
- **옮기기만 했다.** 줄은 글자 그대로 옮겼다 — 옮긴 스크립트가 대장의 표 줄은 정확히 한 번, 문단 줄은 한 번 나오는지 셌다. 한 절의
  줄이 여러 무리에 걸치면 머리말은 한 곳에 두고, 다른 무리 파일에는 같은 번호의 제목과 「머리말은 … 의 같은 번호다」 한 줄과 그
  무리의 줄만 둔다. 표 머리는 무리마다 되풀이한다. 번호(대장 NN · PRD §3.n)는 그대로다 — §3.1 만 사주 보기 쪽(`first`)과 궁합
  보기 쪽(`compat`) 두 파일에 갈렸고 PRD 색인 `docs/prd.md` 가 그것을 적는다.
- **ui 는 공통 둘을 고정으로 읽고 무리 하나를 고른다.** 「하나를 고른다 — 고칠 화면의 무리」의 선택지는 무리마다 PRD 파일과
  대장 파일의 짝이다(둘에 걸치면 둘 다). reviewer 의 프런트 관점은 대장 머리 전부와, 본 화면의 PRD 무리 파일 · 대장 무리 파일을
  동적 라우트 둘로 든다. 무리 파일 머리는 그 화면의 동작 절(§4 · §5 · §6 · §7.1)을 가리키고, ui 는 동작을 바꿀 때 연다(「닿을 때」).
- **수의 이름은 「읽기량 예상치」다.** 고정은 모든 일이 읽는 바이트 그대로, 동적 라우트와 선택 묶음은 일마다 고르는 후보 가운데
  가장 큰 것 — 실제로 한 일이 읽는 양은 이 수 이하다. `npm run read-budget` 의 표 위에 그 한 줄이 서고 칸 이름이 「예상치」다.
- **천장의 여유는 눈금 하나다.** 정할 때 예상치 위에 `HEADROOM`(= `CEILING_STEP` 5,000) 이상 남는 가장 작은 배수
  (`ceilingFor`). 붉어지는 여유 `MAX_SLACK` 은 15,000 — 바닥 위로 눈금 둘이라, 막 정한 천장에서 눈금 하나만큼 줄어도 붉지 않다.
  까닭: 2,500 의 바닥에서 ui 가 15 바이트를 남기고 막혔고, PRD 한 문단 · 대장 한 절 · ADR 추기 하나가 1–3 천 바이트다. 화면 일의
  여유는 이제 공통 파일만 갉는다 — 가장 크지 않은 무리 파일이 자라면 예상치가 안 움직인다.
- **시험이 구조를 잰다**(`scripts/code-rules.test.ts`). PRD 색인 시험이 `screens/` 까지 들고, 「화면 무리」 시험 셋이 ① 두 폴더의
  무리 이름이 같고 공통 파일의 색인이 무리 파일을 다 든다 ② 대장 무리 색인의 「절」 칸이 그 파일의 번호 절과 같고, 한 번호는 어느
  파일에서나 같은 제목이며 번호가 끊기지 않는다 ③ ui 의 선택지가 무리마다 그 짝을 든다. 무리 파일을 더하면 색인 · 역할 문서에도
  들어야 초록이다 — 셈이 모르는 파일이 생기지 않게.
- **천장에 걸렸을 때 할 일은 한 곳이다** — `docs/agents/delegation/done.md` 「읽기량 천장에 걸리면」. 고치는 역할 일곱의 「끝날 때
  고치는 것」이 그 절을 가리킨다(reviewer 는 고치지 않는다).
- 같은 PR 에 라운드 보고가 짚은 빠진 것 셋을 넣었다 — 워크트리에서 전후 그림 찍기(`docs/agents/delegation/local-env.md` 새 절, ui 의
  「닿을 때」), 반환 칸만 느는 함수 확장은 PR 하나(`docs/agents/delegation/permissions.md`, db 의 「먼저 읽는 것」), 위의 천장 절차.
  ops 의 로컬 환경 링크는 「먼저 읽는 것」이 이미 부르던 절(「로컬 환경의 함정」)로 좁혔다 — 새 절이 ops 의 셈에 들지 않게.

## 치르는 값

- **큰 옮김이라 같은 파일을 고치는 열린 PR 과 부딪힌다** — #586(대장 30) · #589(`screens.md` 의 첫 화면 폭). 이 PR 이 마지막에
  들었고, 이 PR 이 main 을 합치며 그 줄(대장 30 절)을 home · compat · matching 로 갈랐다. 대장의 새 절은 앞으로 무리 파일 끝에 붙는다 — 번호는 대장 전체에서 하나라
  나란한 두 PR 이 같은 번호를 고를 수 있다(시험이 같은 번호 · 다른 제목을 붉힌다).
- **무리의 경계는 판단이다.** 바닥글의 모양은 §3.1(`first`)에, 바닥글의 문구는 `public` 에 있다. 소식(`/me/requests`)의 풀이 실패
  줄은 `matching` 이다. 무리 파일 머리와 색인이 그 화면 이름을 든다.
- **ui 의 예상치가 올랐다**(79,985 → 92,013). 셈이 정직해진 값이다 — 같은 일을 옛 구조로 세면 131,538 이었다.
- **대장 파일의 합이 늘었다**(머지 직전 55,907 → 70,572) — 무리 파일 머리 · 표 머리 · 「머리말은」 줄이 되풀이된다. 한 일이 읽는 양은 줄었다.

## 잠그지 않은 것

- 무리 파일의 줄이 정말 그 무리 화면의 것인가 — 시험은 자리와 번호만 잰다. 조율자가 라운드 끝 보고의 「헤맨 것」으로 본다.
- feature 의 PRD 라우트는 `docs/product/prd/` 바로 아래 파일만 후보다. 화면 영역(`screens.md` + 무리 하나)이 가장 큰 영역 파일보다
  커지면 셈이 작아진다 — 지금은 14,832 < 23,864.
