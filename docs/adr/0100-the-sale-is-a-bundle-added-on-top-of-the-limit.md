# 파는 것은 풀이권 묶음이고, 산 몫은 한도 위에 얹힌다

PRD §8.7 은 공개 출시에서 무엇을 팔지 — 단건 풀이 · 풀이권 묶음 · 구독 — 를 열어 두었다(G-22).
2026-09-23 에 사람이 정했다.

## 정한 것

| 물음 | 답 |
| --- | --- |
| 무엇을 파는가 | **풀이권 묶음** — 1회 · 3회 · 5회 · 20회 넷 |
| 무료로 주는 몫 | **1개** — 지금의 5개에서 줄인다 |
| 산 풀이권의 유효기간 | **없다** |
| 인연 요청 | **지금처럼 같은 풀이권**으로 낸다 — 요청할 때 예약, 동의하면 사용, 거절 · 거둠 · 만료면 풀림 |

값(가격)은 아직 안 정했다. PG 와 함께 G-21 이 든다.

## ADR 0021 · 0038 은 그대로 선다

묶음을 고른 까닭이 이것이다. 산 몫은 **한도에 더해질 뿐**이고, 잔액은 여전히 세는 법이다.

```
이 사람의 한도 = 무료 몫 + 예외 몫(ADR 0043) + 산 몫의 합
남은 것      = 한도 − 성공한 시도 − 도는 시도 − 살아 있는 내 요청
```

- 실패는 여전히 풀이권을 안 쓴다 — `failed` 를 애초에 안 센다(ADR 0021).
- 인연 요청의 예약도 그대로다 — 예약은 `match_request.status` 를 세는 법이다(ADR 0038).
- 유효기간이 없으므로 **어느 몫을 먼저 쓰는가**라는 순서가 셈에 들어오지 않는다.

**단건 풀이를 안 고른 까닭** — 결제 한 건이 시도 하나에 묶이면 실패한 시도의 결제를 되돌려야 하고,
ADR 0021 이 없앤 「반환」이 돈으로 돌아온다. 인연 요청은 결제를 7일 동안 붙잡아야 한다.

**구독을 안 고른 까닭** — 셈이 기간 단위로 바뀌고, 무제한이면 비용이 사람 수에 비례해 열린다.

## 산 몫은 예외 표에 넣지 않는다

ADR 0043 의 `reading_credit_grant` 는 운영자가 SQL 로만 넣고 앱도 `service_role` 도 못 닿는다 —
그 키가 새면 풀이권을 나눠 주는 문이 되기 때문이다. 결제 확인은 서버가 받아 적어야 하므로
**산 몫은 다른 표**가 든다. 예외는 여전히 자료이지 판매가 아니다.

## 남는 것 — 공개 출시 전에 답한다

- **무료 몫을 5 → 1 로 내리면 이미 쓴 사람의 잔액은 그냥 0 이 된다.** 장부가 없기 때문이다(ADR 0043
  첫 문단과 같은 성질). 운영 베타 테스터에게 5 를 남길지는 공개 출시 때 정한다.
- **무료 1개에서는 §2 의 벽이 첫걸음에 온다** — 인연 요청 하나를 띄우면 답이 올 때까지 자기 풀이를
  하나도 못 만든다. 사게 하는 자리인지 막히는 자리인지는 화면에서 정한다.
- **청약철회 · 환불** — 유효기간이 없어도 묶음을 일부 쓴 뒤 물리면 무료 몫과 산 몫 중 무엇을 먼저
  썼다고 볼지 정해야 한다. G-21 · G-25 가 든다.
