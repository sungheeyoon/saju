# 풀에 오르는 요약과 여덟 글자는 열쇠 모듈 하나가 쓴다 — 사용자 경로의 제한된 예외

> **운영자 결정 2026-09-30.** G-64 는 길 ① 로 간다 — 매칭 풀에 요약(`element_summary` · `need_summary`)과 여덟 글자
> (`person.current_chart`)를 올리는 DB 문은 `authenticated` 에서 EXECUTE 를 거두고 `service_role` 로만 부른다. 서버가 저장된
> 입력에서 엔진으로 값을 지어 넘긴다. 조건: 열쇠는 **이 작업 전용 서버 모듈 하나**에 가두고 그 모듈은 이 문들만 부른다.
> 부를 사람의 id 는 세션에서 서버가 얻는다(인자로 받지 않는다). 클라이언트가 보낸 요약 · 여덟 글자를 받지 않는다.
> 일반 허용이 아니다.

## 잰 것 (2026-09-30, 이 결정 전)

- 풀에 오르는 값을 쓰는 문 넷이 `authenticated` 에 열려 있었다 — `create_self_person`(내 사람과 여덟 글자) ·
  `edit_person_input`(고친 입력과 여덟 글자) · `set_discovery_participation` · `ensure_discovery_participation`(요약 둘,
  `20261025160000`). DB 는 모양만 본다 — `is_element_summary` · `is_need_summary` · `reject_bad_chart`(낱자 · 일간 · 시주 유무).
  로그인한 사람이 PostgREST 로 직접 부르면 제 저장된 입력과 다른, 모양만 맞는 값을 풀에 올릴 수 있었다(2026-09-28 보안 감사,
  `docs/notes/2026-09-28-overnight-audit.md` 「안 고친 것 — 보안」).
- 여덟 글자는 풀 밖으로도 간다 — 카드 점수가 일주 · 일지를 읽고(`20261025160000`), 인연 궁합의 풀이 입력이 된다. 요약 둘은
  남의 후보 카드 순서와 점수가 된다.
- 여덟 글자를 받는 문은 하나 더 있다 — `create_managed_person`(가족 · 친구). 그 사람의 여덟 글자는 **등록한 계정에게만**
  보인다. 남에게 사람을 넘기는 문이 없고(`user_person_access` 에 넣는 문은 내 사람 · 대신 등록 둘뿐), 내 사람이 되는 길은
  `create_self_person` 하나라 대신 등록한 사람이 풀로 가는 길이 없다.
- 열쇠(`app/keyed-client.ts`)는 이미 여섯 파일이 들었다 — 풀이 제출 · 회수(사용자가 누른 뒤의 서버 일) · 크론 둘 · webhook
  둘. 누가 드는지 잠근 목록은 없었다.

## 정한 것

1. **문 넷은 `service_role` 에만 연다.** 같은 이름에 첫 인자 `p_user_id` 가 붙은 판을 세우고(`20261106090000`, 넓히기),
   앱이 옮겨 배포된 뒤 인자 없는 옛 판을 걷는다(좁히기). 몸은 옛 판과 같다 — `auth.uid()` 자리만 인자다. 정지 · 베타 종료 ·
   가입 전 · 이름 없음 · 남의 사람 · 껐는가의 판정은 여전히 DB 가 한다. 열쇠로 부른다고 판정을 건너뛰지 않는다.
2. **부르는 자리는 `app/me/keyed-chart-writes.ts` 하나다.** 그 모듈은
   - 첫 줄이 `import 'server-only'` 이고 서버 액션(`'use server'`)이 아니다 — 브라우저가 이 함수를 직접 부를 길이 없다.
   - 사람 id 를 **세션에서** 얻는다(`signedInUser` — 쿠키의 JWT 서명을 서버가 확인한다. PostgREST 가 `auth.uid()` 로 하던 것과
     같은 확인이다). 내보내는 함수는 사람 id 를 인자로 안 받는다.
   - 값을 **서버가 짓는다** — 여덟 글자는 저장할 입력(`Query`)을 엔진이 센 것(`selfPersonArgs` · `personInputArgs`), 요약은
     그 사람의 저장된 입력에서 `app/me/summary.ts` 가 지은 것. 참여를 여는 문만은 화면이 같은 요청에서 이미 지은 요약
     (`SelfSummary`)을 받는다 — 다시 읽으면 탭마다 물결이 하나 늘고(2026-09-30 에 줄인 것), 그 값도 저장된 입력에서 서버가
     지은 것이다.
   - 이 넷만 부르고, 표를 직접 만지지 않고, 열쇠를 밖으로 내주지 않는다.
3. **열쇠를 드는 파일을 이름으로 잠근다** — `eslint.config.mjs` 의 `KEY_HOLDERS` 일곱(크론 둘 · webhook 둘 · 풀이 제출 ·
   회수 · 이 모듈)이 `no-restricted-imports` 로 나머지 `app/**` 를 막고, `scripts/layers.test.ts` 「열쇠를 드는 자리」가 부르는
   파일이 목록과 정확히 같은지 · 린트의 목록과 같은지 · 문 넷의 `.rpc()` 가 이 모듈 밖에 없는지 · 모듈이 넷 밖을 안 부르고 사람
   id 를 안 받는지 잰다. 브라우저로 가는 그래프에 열쇠 둘이 없는 것도 같은 파일이 든다.
4. **시험 넷**
   - pgTAP `71_pool_values_keyed`(좁히기와 함께) — `authenticated` 가 문 넷을 부르면 권한 거절(`42501`)이고, 모양만 맞는 다른
     요약을 사용자 역할로 올리는 시도가 풀의 값을 안 바꾼다. `13_reading` 의 열쇠 허용 목록에 넷이 선다.
   - 단위 `app/me/keyed-chart-writes.test.ts` — 넷 다 세션의 id 를 싣고, 세션이 없으면 열쇠 문을 안 부르며, 여덟 글자는 저장할
     입력을 엔진이 센 값이고, 참여를 켤 때의 요약은 DB 에 저장된 입력에서 지은 값이다(입력이 다르면 요약도 다르다).
   - 기존 pgTAP · 흐름 · e2e 는 세션의 사람으로 열쇠 문을 부르는 손잡이로 옮겼다 — `tests.create_self_person` 등
     (`supabase/tests/00_helpers.sql`), `keyedRpc`(`scripts/checks.mjs` · `e2e/session.ts`).

## 왜 ② 를 버렸나 — DB 가 짓는 길

② 는 저장된 입력에서 SQL 이 여덟 글자와 요약을 계산하는 길이다. 앱이 넘기는 값이 아예 사라진다는 점에서 더 곧다. 버린 까닭은 둘이다.

- **유지비** — 엔진의 절기(태양 황경) · 자시 규칙 · 경도 보정 · 음력 표 · 억부 판정을 SQL 로 한 벌 더 적어야 한다. 엔진은
  `src/lib/saju/` 의 138 파일이고(2026-09-30, 시험 포함), 절기 · 음력만 해도 1900~2100 하루 단위 대조로 잠겨 있다. 그 크기를 한 벌 더 들면 엔진을
  고치는 모든 날이 SQL 도 고치는 날이 된다.
- **두 구현의 불일치** — 한 규칙이 두 언어에 있으면 갈린다. 카드 점수 하나(TS ↔ SQL)에도 대조 시험(`card-score-sql`)을
  따로 세워야 했다. 엔진 전체를 두 벌로 두면 갈린 날 **어느 쪽이 사용자의 사주인지** 답할 수 없다 — 화면은 TS 로, 풀은 SQL 로
  다른 사주를 말하게 된다. 그것은 이 결정이 막으려던 「저장된 입력과 다른 값이 풀에 선다」와 같은 증상이다.

## 대가 — 그리고 왜 일반 허용이 아닌가

「사용자 경로에 `service_role` 을 쓰지 않는다」(ADR 0003 · 0006)는 **무엇을 볼 수 있는가 · 쓸 수 있는가의 답이 정책(RLS ·
grant)에 있어야지 앱 코드에 있으면 안 된다**는 뜻이었다. 이 결정은 그 답의 한 조각을 앱 코드로 옮긴다 — 문 넷에 대해서는
「누가 부르는가」를 DB 가 아니라 이 모듈이 세션으로 정한다. 그래서 **이 한 경로에만** 연다.

- 열쇠가 드는 자리가 사용자 경로에 하나 늘었다. 그 자리의 실수(세션 대신 인자의 id · 넷 밖의 문 · 브라우저 값)가 곧 권한
  우회다. 그 실수를 시험 셋이 막는다(위 3 · 4).
- 새 자리가 열쇠를 들려면 `KEY_HOLDERS` 와 층 시험의 목록을 함께 고쳐야 하고, 그 PR 은 결정 점검표의 「누가 무엇을 할 수
  있는가」에 걸린다 — ADR 이 든다.
- 판정은 DB 에 남는다. 열쇠 모듈이 하는 것은 「누구로 부르는가」와 「무슨 값을 싣는가」 둘뿐이다.

## 기존 데이터

이 결정은 **앞으로의 쓰기**만 바꾼다. 이미 풀에 있는 줄의 요약과 이미 저장된 여덟 글자는 그대로다 — 되짓지 않는다. 운영
베타에서 앱은 늘 서버가 지은 값을 보냈으므로 그 값은 저장된 입력에서 나온 것이다. PostgREST 를 직접 부른 쓰기가 있었는지는
DB 만으로 가를 수 없다(쓴 경로가 안 남는다). 가르려면 모든 참여자의 요약 · 여덟 글자를 저장된 입력에서 엔진으로 다시 지어
견주는 일이 든다 — 지금 그 도구는 필요한 기운 요약의 백필(`need_summary_backfill_targets` · `set_discovery_need_summary`)과
여덟 글자의 백필(`set_person_chart`)이 반쯤 든다. 하지 않았다(운영 개인정보를 읽는 일이라 사람이 돈다, ADR 0105).

## 안 옮긴 것

- `create_managed_person` — 위 「잰 것」대로 그 여덟 글자는 등록한 계정에게만 보인다. 남에게 보이는 길이 생기는 날(사람을
  넘기는 문 · 대신 등록한 사람을 내 사람으로 삼는 문) 이 모듈로 옮긴다.
- 풀의 선호 성별(`discovery_profile.prefer_gender`) — 사용자가 고르는 값이고 엔진이 짓는 값이 아니다. 정책이 열어 준 칸 그대로다.

## 잠그지 않은 것

- 문 넷이 받은 값이 **정말 그 사람의 저장된 입력에서 나왔는지는 DB 가 끝내 못 본다** — ② 를 버린 대가다. 열쇠를 든 쪽이
  틀린 값을 보내면 DB 는 모양만 보고 받는다. 그 쪽이 이 모듈 하나라는 것이 이 결정이 거는 전부다.
- 세션은 서명과 만료만 확인한다(`getClaims`, ADR 0117). 서버에서 막 끊은 세션을 못 알아채는 것은 옛 길(PostgREST 가 JWT 의
  서명으로 `auth.uid()` 를 세운다)과 같다 — 관문의 matcher 안(`/me/**` 등)이면 먼저 도는 `getUser` 가 그 쿠키를 걷고, 밖(첫
  화면의 「내 사주로 저장」은 `/` 에서 부른다)이면 토큰의 만료까지 산다. 정지 · 탈퇴 대기는 DB 가 `app_user.status` 로 본다.
