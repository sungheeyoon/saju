# 결과 화면의 ← 와 켜진 탭은 온 곳을 따른다

> **운영자 결정 2026-09-29(u2).** 「← 는 온 곳으로, 불도 온 곳 기준: 나 탭 홈 · 보관함에서 연 결과는 불 나, ← 는 나 탭 홈 /
> 같은 칩의 보관함. 궁합 탭 · 인연 탭 · 채팅에서 연 결과는 그 탭 불, ← 그 탭. 주소를 직접 연(from 없는) 결과는 결과 종류의
> 탭(사주 → 나, 궁합 → 궁합, 인연 → 인연)과 그 탭 첫 화면으로.」 「풀이 보관함(`/me/readings`, 칩 넷)과 저장한 사람
> (`/me/people`, `/me/people/[id]`)은 나 탭 소속 — 불 「나」. ADR 0133 의 「보관함은 어느 탭도 안 켠다」를 뒤집는다.」
> 「궁합 탭의 「모두 보기」는 `/me/readings?kind=compat&from=compat` 로 — 그 목록은 나 탭 불(운영자 받아들임).」

## 잰 것 (2026-09-29, 이 PR 전)

- 결과 화면은 셋이다 — 사주풀이 `/me/readings/self|[subject]` · 직접 궁합 `/me/compat?a&b` · 인연 궁합 `/me/match/[id]`. 이 셋을
  여는 자리는 여섯이다 — 나 탭 홈 · 보관함 · 궁합 탭 · 인연 탭(과 인연 기록) · 채팅방 · 소식.
- ← 와 켜진 탭은 **글의 종류**로만 정해졌다(ADR 0126 · 0133). 사주풀이의 ← 는 늘 「풀이 보관함」, 궁합의 ← 는 늘 보관함의 궁합풀이
  칸, 인연 궁합의 ← 는 늘 보관함의 인연 궁합 칸이었다. 그래서 궁합 탭에서 연 궁합의 ← 가 보관함으로 갔고, 채팅방에서 연 인연 궁합의
  ← 도 보관함으로 가서 대화로 돌아갈 길이 뒤로 가기뿐이었다. 나 탭 홈에서 연 사주풀이의 ← 도 나가 아니라 보관함이었다.
- 머리글(`app/site-header.tsx`)은 루트 레이아웃의 클라이언트 조각이고 `usePathname` 만 읽었다. `/` 는 미리 그려지는(○) 화면이고
  머리글이 그것을 깨지 않으려고 서버에 안 묻는다(그 파일의 머리말).

## 정한 것

1. **결과 링크가 온 곳을 싣는다 — `?from=`.** 값은 일곱이다: `me`(나 탭 홈) · `shelf`(보관함 — 칩 `kind` 와 함께, 전체 칩은 안 싣는다) ·
   `compat`(궁합 탭) · `matching`(인연 탭) · `history`(인연 기록 `/me/matching/history`) · `chat`(대화방) · `news`(소식). 표 한 벌은
   `app/came-from.ts` 다 — 무슨 값이 있고(`CAME_FROM`), 어느 불을 켜고(`lightOf`), ← 가 어디로 무슨 이름으로 가는가(`backOf`).
2. **켜진 탭 = 온 곳.** `me` · `shelf` → 나, `compat` → 궁합, `matching` · `history` → 인연, `chat` → 채팅, `news` → 탭 없이 종.
   **없거나 모르는 값은 결과 종류의 탭**이다 — 사주풀이는 나, 직접 궁합은 궁합, 인연 궁합은 인연. 결과 화면이 아닌 화면은 `from` 을
   안 읽는다(보관함 목록에 `from=compat` 이 붙어 와도 나다).
3. **보관함 목록 `/me/readings` 과 저장한 사람 `/me/people/*` 은 나 탭이다** — ADR 0133 의 2(「어느 탭도 안 켠다」)를 뒤집는다.
   인연 기록 `/me/matching/history` 는 인연 탭 아래라 인연이다.
4. **← 의 글자는 가는 곳의 이름이다** — 「나」 · 「풀이 보관함」 · 「궁합」 · 「인연」 · 「인연 기록」 · 「대화」(그 Match 의 방) ·
   「채팅」(방을 모르는 결과의 채팅 목록) · 「소식」. `from` 이 없으면 결과 종류의 탭 첫 화면이다(「나」 `/me` · 「궁합」 `/compat` ·
   「인연」 `/me/matching`). 대화방으로 가는 ← 는 **결과가 이미 연 Match id** 로 짓는다 — 방의 주소가 곧 Match id 라 주소에 방을
   따로 싣지 않는다.
5. **← 는 표 밖으로 못 간다 — 열린 리디렉트가 없다.** `from` 은 이름표이지 주소가 아니다. `https://…` · `//…` · `/me` · 대소문자 ·
   공백이 붙은 값은 모르는 값이라 기본으로 떨어진다. 가는 곳은 같은 사이트의 고정 경로와, 서버가 UUID 로 거르고 볼 수 있음을
   확인한 Match id 뿐이다(`came-from.test.ts` 가 적대 값 × 결과 셋 × 칩을 다 돌려 같은 사이트 경로임을 든다).
6. **보관함으로 가는 ← 는 넓은 화면에서 안 선다** — 책장이 이미 옆 칸에 있다. 다른 곳으로 가는 ← (「나」 등)는 넓은 화면에도 선다.
   글 끝의 「다음 풀이」와 넓은 화면이 목록에서 저절로 펴는 한 권은 지금 온 곳을 그대로 들고 간다.
7. **머리글이 쿼리를 읽어도 `/` 는 미리 그려진 채다.** `useSearchParams` 는 미리 그리는 화면에서 가장 가까운 `Suspense` 까지를
   브라우저로 미룬다 — 그래서 탭 불을 그리는 조각 셋(넓은 화면의 탭 · 종 · 폰의 독)만 `Suspense` 로 감싸고, 미리 그릴 때의
   대신 그림은 **`from` 없이(`null`) 그린 같은 조각**이다. 미리 그려지는 화면은 결과 화면이 아니어서 `from` 이 불을 안 바꾸므로 대신
   그림과 붙은 뒤의 그림이 같다. 결과 화면(`/me/**`)은 요청마다 그려져 서버가 쿼리를 알고 첫 HTML 부터 맞는 불이다. 이 PR 뒤
   `next build` 의 ○ 는 그대로 `/` · `/_not-found` · `/icon.svg` 셋이다.
8. **결과 화면은 서버에서 `searchParams` 로 읽는다** — 직접 궁합 · 인연 궁합 페이지는 서버 컴포넌트라 ← 를 서버가 짓는다. 사주풀이의
   ← 는 보관함 레이아웃의 클라이언트 틀(`frame.tsx`)이 칩과 함께 주소에서 읽는다.

## 이 PR 이 싣는 자리와 안 싣는 자리

- 싣는다: 보관함의 표지 · 만드는 중인 인연 궁합 편지(`shelf` + 칩), 대화방의 「인연 궁합」 두 곳(`chat`), 소식의 풀이 실패 줄(`news`).
- 나란히 도는 PR 이 싣는다: 나 탭 홈(`me`), 궁합 탭(`compat`), 인연 탭 · 인연 기록(`matching` · `history`). 싣기 전에는 그 자리에서
  연 결과가 결과 종류의 기본으로 선다 — 사주풀이는 이미 나, 궁합은 궁합, 인연 궁합은 인연이라 틀린 탭은 아니다.

## 안 한 것

- 저장한 사람 화면(`/me/people/[id]`)에서 연 사주풀이의 ← 는 그 사람이 아니라 기본(「나」)이다. 값을 하나 더 두면(`person` + id)
  주소에 사람 id 를 싣고 그것을 다시 걸러야 한다 — 운영자가 정한 값 목록에 없어 두지 않았다.
- 뒤로 가기(브라우저)는 건드리지 않는다. ← 는 링크이고, 브라우저의 뒤로 가기는 늘 직전 화면이다.
