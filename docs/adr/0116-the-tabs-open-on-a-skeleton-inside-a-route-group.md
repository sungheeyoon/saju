# 탭 넷은 누르는 즉시 뼈대로 넘어가고, 뼈대는 무리 폴더 안에 산다

> **섰다**(2026-09-27). 운영자가 「탭을 눌렀는데 늦게 간다」고 했다 — 들어간 뒤의 그리기가 아니라 누른 순간부터 화면이
> 바뀌기까지다.

## 잰 것 (2026-09-27, `origin/main` `310a696`, `next build` + `next start`, 로컬 스택)

- 네 탭(홈 `/me` · 매칭 `/me/matching` · 풀이 `/me/readings` · 채팅 `/me/chat`)은 모두 로그인을 읽는 동적 화면이고
  `app/` 어디에도 `loading.tsx` 가 없었다. Next 16 은 그런 화면을 **미리 받지 않고**(`next-router-prefetch` 요청은 가지만
  관문만 돌고 끝난다), 누른 뒤 서버 응답이 다 올 때까지 **지금 화면에 머문다**(`01-app/02-guides/prefetching.md` 의 표).
- 한 번 누를 때 서버가 DB 를 **차례로** 부르는 물결이 매칭 9~10 · 홈 6~8 · 채팅 6 · 풀이 5 였다. 앞의 넷은 모든 탭이 같다 —
  관문의 로그인 확인(`/auth/v1/user`) → 관문의 계정 · 일정 → 화면의 로그인 확인 → 화면의 계정. 로컬에서도
  `/auth/v1/user` 하나가 25~40ms 다. `app/me/layout.tsx`(경고 안내)는 탭을 옮길 때 다시 안 돈다 — 같은 기록에 그 문이 없다.
- 누름 → 주소가 바뀜(= 화면이 바뀜)의 중앙값은 로컬 그대로 80~120ms, 운영 비슷하게 늦춘 스택(아래)에서 **375~635ms**
  였다. 운영의 익명 `/me` RSC 한 번이 185~250ms(따뜻할 때) · 1.45초(찬 함수)였다 — 로그인한 사람의 탭 이동은 그 위에
  DB 물결이 얹힌다. Vercel 의 경로별 시간(`vercel metrics`)은 Observability Plus 가 없어 못 읽었다.

## 정한 것

**탭 넷에 `loading.tsx` 를 둔다.** 뼈대가 있으면 Next 가 그것까지 미리 받아 두고 누르는 즉시 그 자리로 넘어간다. 뼈대는
글자가 없고 그 화면의 모양만 닮는다(`app/ui/skeleton.tsx` 의 두 조각 · `reading-skeleton` 반짝임 — 줄인 움직임은
`globals.css` 가 멈춘다).

**뼈대는 그 탭 하나만 품는 무리 폴더에 둔다** — `app/me/(home)/` · `app/me/(shelf)/readings/` · `app/me/chat/(rooms)/`, 매칭은
`app/me/matching/` 에 바로(그 아래는 같은 모양의 예시 화면 하나뿐이다). 주소는 그대로다.

- `app/me/loading.tsx` 하나로 두면 `/me` 아래 모든 화면이 그 뼈대로 열리고, **곧바로 연 문서의 상태 코드가 바뀐다** —
  뼈대가 먼저 흘러 나가면 `notFound()` 는 200 + `noindex`, `redirect()` 는 200 + 문서 안의 되돌림이 된다
  (`02-guides/streaming.md`). 흐름 검사가 `/me/compat` · `/me/discovery` · `/me/match/[matchId]` · `/me/chat/[matchId]` 의
  307 · 404 를 잰다. 무리 폴더는 뼈대가 번지는 곳을 그 탭 하나로 줄인다.
- **풀이는 레이아웃이 읽는다**(책장이 레이아웃에 산다). `loading.tsx` 는 같은 폴더의 레이아웃을 감싸지 않으므로
  `readings/loading.tsx` 는 누른 뒤 그 레이아웃이 다 읽힐 때까지 여전히 멈추고, 미리 받기도 그 레이아웃의 DB 를 돌린다.
  그래서 `readings` 를 무리(`(shelf)`)에 넣고 뼈대를 그 바깥에 둔다. 책장 안에서 글을 옮길 때는 레이아웃이 그대로라 안 선다.
- 채팅 방(`[matchId]`)은 없거나 못 보는 방에 404 를 곧바로 보내야 해서 목록만 무리(`(rooms)`)에 넣는다.

**매칭의 덱과 지나친 인연은 나란히 읽는다** — 덱을 채우는 문(`my_discovery_board`)은 `discovery_passed` 를 읽기만 한다.
물결 하나가 준다.

## 잰 값 — 고친 뒤

같은 방법, 데스크톱(Desktop Chrome) · 폰(Pixel 5), 이동마다 세 계정 × (첫 방문 · 다시 방문) 중앙값. 방법은 이 ADR 을 들인 PR 본문에 있다.

| | 누름 → 화면이 바뀜 | 누름 → 본문 |
| --- | --- | --- |
| 운영 비슷하게 늦춘 스택 — 전 | 375~635ms | 380~650ms |
| 운영 비슷하게 늦춘 스택 — 뒤 | **4~23ms**(뼈대) | 360~590ms |
| 로컬 그대로 — 전 | 80~120ms | 85~130ms |
| 로컬 그대로 — 뒤 | **4~21ms**(뼈대) | 310~330ms |

늦춘 스택은 서버의 Supabase 부름마다 +25ms · 요청마다 +150ms · 브라우저 왕복 20ms 다 — 운영의 익명 RSC 시간에 맞춘
가정이지 운영 값이 아니다.

## 잠그지 않은 것 · 대가

- **본문은 뼈대가 선 뒤 최소 300ms 뒤에 선다.** React 가 Suspense 의 대체 화면을 걷는 것을 300ms 로 묶는다
  (`FALLBACK_THROTTLE_MS`, `react-dom-client` 의 `globalMostRecentFallbackTime + 300`). 서버가 300ms 안에 답하는 자리(로컬)에서는
  본문이 전보다 늦다. 운영의 탭 이동은 그보다 길어 대가가 안 보인다 — 운영에서 본문이 300ms 안에 오게 되면 다시 잰다.
- **익명으로 네 탭 주소를 곧바로 열면 307 대신 200 + 문서 안의 되돌림이다.** 로그인 판정은 여전히 화면이 한다(ADR 0041 —
  관문은 판정하지 않는다). `scripts/check-chat.mjs` 의 「로그인 없이는 목록이 안 열린다」는 되돌림의 목적지로 잰다.
  풀이의 `[subject]` 가 없는 사람에게 내던 404 도 200 + `noindex` 가 된다 — 이 상태 코드를 재는 시험은 없었다.
- **자바스크립트가 없으면 뼈대와 본문을 바꿔 끼울 스크립트가 안 돈다.** `<noscript>` 안의 규칙 두 줄이 그때만 뼈대를 걷고
  숨은 본문(`div[hidden][id^="S:"]` — React 의 스트리밍 표식)을 세운다. React 가 표식을 바꾸면 조용히 안 먹는다 —
  `signed-in.spec.ts` 의 「자바스크립트 없이 여는 홈」이 든다(이 규칙 없이 붉었다).
- **관문의 prefetch 판별은 안 걸린다.** `proxy.ts` 는 `next-router-prefetch` 머리로 미리 받기를 가려 활동 기록
  (`touch_activity`)을 건너뛰려 하지만, Next 가 그 머리를 관문에 넘기기 전에 지운다(`server/web/adapter.js` 의
  `FLIGHT_HEADERS`). 미리 받기마다 활동이 적힌다(1분에 한 번으로 묶여 있다). 이 PR 은 관문을 안 건드렸다 — 사람이 정한다.
  → 닫힘(2026-09-27): 활동은 화면이 그려질 때 적는다(ADR 0118).
- 화면의 로그인 확인(`getUser`)이 관문의 것과 겹쳐 두 번 돈다. 네트워크 한 번짜리 물결이다. 줄이려면 판정의 자리를 옮기는
  결정이라 이 PR 밖이다. → 닫힘(2026-09-27): 화면은 쿠키의 서명을 확인한다(ADR 0117).

## 추기 — 톱니가 여는 화면 셋도 뼈대로 연다 (2026-09-30)

밤샘 감사(`docs/notes/2026-09-28-overnight-audit.md` 「안 고친 것」의 화면 줄)가 「탭 밖 동적 화면의 `loading.tsx`」를 남겼다.
머리글의 톱니가 여는 계정 관리(`/me/settings`) · 프로필(`/me/profile`) · 서비스 설문(`/me/survey`)에 뼈대를 둔다 — 셋 다
로그인과 계정을 읽는 동적 화면이고, 제 폴더에 그 화면 하나만 있으며 `notFound()` 가 없다. 대가는 탭 넷과 같다 — 익명으로
곧바로 열면 307 대신 200 + 문서 안의 되돌림이다. 흐름 검사가 이 셋의 상태 코드를 재는 자리는 로그인한 계정의
`/me/settings` 200 하나다.

**안 둔 자리와 까닭.**

- 소식(`/me/requests`) — 뼈대를 두자 「내 사주의 소식 버튼으로 들어오면 도착한 소식을 모두 읽은 것으로 남긴다」(`e2e/match.spec.ts`)가
  데스크톱 · 폰 둘 다 붉었다. 들어오면 읽음으로 바꾸고 `router.refresh()` 하는 부품(`ReadNotificationsOnVisit`)의 새로 그림이
  「읽지 않음」 딱지를 걷지 못했다 — 뼈대를 빼면 초록이다. 까닭을 끝까지 안 갔다. 소식에 뼈대를 둘 때 그 부품부터 본다.
- `/me/compat` · `/me/discovery` · `/me/match/[matchId]` · `/me/chat/[matchId]` 는 위 「정한 것」대로 307 · 404 를 곧바로 보내야 한다.
- 저장한 사람(`/me/people`)은 같은 폴더의 `[personId]` 가 `notFound()` 를 내서, 목록만 무리 폴더로 옮겨야 한다 — 그 화면의 옛 DB
  호출 지문(`scripts/layers.test.ts`)이 파일 경로를 들고 있어 이 라운드 밖이다.
- 공유(`/share/**`)는 로그인이 없고 없는 링크에 404 를 낸다.

## 추기 — 있을지 모르는 띠 · 줄은 뼈대에 두지 않는다 (2026-10-10)

#577(화면 점검 2026-10-09 C6 · C7, 운영자 승인 · 머지)이 이미 이렇게 세웠고, 여기 그 승인을 적는다 — 새로 묻지 않는다. 뼈대는
**늘 서는 덩어리만** 둔다. 사람마다 서거나 안 서는 줄 — 홈의 「만드는 중」 줄(`home/running-band.tsx`) · 받은 사주풀이 둘째 줄,
궁합 탭의 궁합풀이 한 줄(`CompatSummary`) — 은 자리를 두지 않는다. 늘 두면 대부분의 사람에게 빈 띠가 섰다가 걷혀 아래 전부가
올라간다. 근거는 `app/me/(home)/loading.tsx` · `app/compat/loading.tsx` 머리 주석과 #577 의 실측(390 · 1280 에서 본문 높이가 실제와 같다).
그런 줄이 선 사람에게는 다 불러온 순간 그 높이만큼 아래가 내려간다 — 이 값을 치르고 고른 것이다.
