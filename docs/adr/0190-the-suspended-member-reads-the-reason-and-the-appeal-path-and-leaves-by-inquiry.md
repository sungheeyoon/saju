# 정지된 이용자는 제 정지의 사유 갈래와 소명 경로를 읽고, 탈퇴는 문의로 받아 운영자가 탈퇴 대기로 옮긴다

> **근거** — 간극 대장 G-111(`docs/product/gaps/records/g-111.md` 「정한 것 (2026-10-16)」 G-111-8, 「검수에서 남긴 결정 거리」 R-1 ·
> R-2). 운영자가 2026-10-17 에 정지 화면의 본문 문구(후보 C, 이용제한형)와 이용자에게 보이는 갈래 낱말을 확정했고, 같은 날 R-1 을
> 「정지된 사람이 탈퇴(개인정보 삭제)를 원하면 문의로 받아 운영자가 처리한다 — 화면은 지금처럼 막아 둔다」로 정했다. ADR 0188 의
> 공통 함수 · 상태 이력 · 트리거와 ADR 0189 의 회원 화면 위에 선다.

## 잰 것 — 만들기 전에

- 정지 화면은 `/me` 아래 화면마다 `AccountNotice` 가 그린다. 상태는 `readAccount` 가 `app_user` 의 자기 행을 읽어 가른다 — select
  정책이 `id = auth.uid()` 하나라 정지된 사람도 자기 행(닉네임 포함)을 읽는다. 다른 자기 자료는 `is_active_account()` 가 막는다.
- 상태 이력(`account_status_change`)은 RLS 가 켜져 있고 누구에게도 grant 가 없다. 이용자가 제 정지의 갈래를 읽는 길이 없었다.
- 이력 줄의 칸 가운데 이용자에게 가도 되는 것은 갈래뿐이다 — 메모는 「이용자에게 안 간다」(표의 주석), 실행자는 운영자 UUID, 관련
  신고는 신고 id 다(G-111 「모두에 걸리는 것」).
- 정지된 사람은 `request_account_deletion` 이 `42501` 로 거절하고, 공통 함수는 정지 → 탈퇴 대기를 모른다. 정지에 기한이 없으므로
  (G-111-8) 정지된 사람이 지워질 길이 없었다. 탈퇴 대기의 해제(`deletion_withdrawn`)는 언제나 `active` 로 갔다 — 정지에서 온 탈퇴
  대기를 풀면 정지까지 풀렸을 것이다.

## 정한 것

1. **본인의 문 하나 — `my_suspension()`.** 지금 `suspended` 인 사람만 한 줄(닉네임 · 갈래)을 받고, 아니면 빈 결과다. 인자가 없어 남의
   것을 물을 길이 없다. `authenticated` 에만 열고 anon · 서버 열쇠에는 안 연다. `is_active_account()` 를 묻지 않는다 — 정지된 사람이
   읽는 문이다. **갈래만 나간다** — 메모 · 실행자 · 관련 신고 · 시각은 나가는 칸에 없다.
2. **갈래는 정지로 들어온 마지막 줄의 것이다** — 이력에서 `to_status = 'suspended'` 이고 탈퇴 대기의 해제(정지로 되돌아온 줄)가 아닌
   마지막 줄. 그 갈래가 정지 갈래 다섯이 아니면(공통 함수 밖의 변경) 비고, 그런 줄이 없으면(ADR 0188 전의 정지) 빈다. 풀린 앞 정지의
   갈래가 새 정지에 묻어오지 않는다.
3. **화면은 정지된 사람만 한 번 더 묻는다.** `readAccount` 가 `status` 가 `suspended` 일 때만 문을 부르고 그 값을 상태
   (`AccountState` 의 `halted`)에 싣는다. 부속 정보다 — 못 읽으면 닉네임 · 갈래 구를 빼고 문장이 선다. 정지라는 사실과 소명 경로는
   그대로다.
4. **문구는 운영자 확정 그대로**(대장 `all-03`) — 본문 「{닉네임}님은 {갈래} 사유로 이용제한 중이에요. 저장된 자료는 그대로 있어요.
   이의가 있으면 {고객 문의 이메일}로 소명해 주세요.」. 갈래 낱말은 `report` 신고 검토 결과 · `policy` 운영정책 위반 · `payment` 결제
   부정 이용 · `eligibility` 이용 자격(만 19세 이상) 미충족 · `other` 운영 정책에 따른 조치. 갈래가 없으면 「{갈래} 사유로 」만 뺀다.
   **신고로 정지된 사람도 같은 안내다**(R-2). 제목 「이용이 정지된 계정입니다」와 운영 화면의 「이용 정지」는 이 판에서 안 바꾼다 —
   운영자가 아직 답하지 않았다. 문장은 `src/lib/account` 가 들고 이메일은 화면이 `SUPPORT_EMAIL` 을 넘긴다(경고 안내와 같다).
5. **정지 → 탈퇴 대기는 공통 함수로**(R-1). 갈래 `deletion_request`(이용자 스스로의 신청과 같은 갈래 — 실행자가 운영자라는 것이
   가른다), 메모 필수. 이용 정지인 계정만 받고 이용 중 · 이미 탈퇴 대기는 `55000`. 탈퇴 대기 시각을 지금으로 적고,
   `request_account_deletion` 과 같은 자리에 선다 — 인연 찾기 노출을 끄고 답을 기다리던 요청을 정리한다(대화방은 정지 때 이미
   닫혔다). 처분은 지금처럼 크론(`account-disposal`)이 하루 뒤에 한다. 트리거는 정지 → 탈퇴 대기를 공통 함수의 변경으로 받는다 —
   이용 중 → 탈퇴 대기는 여전히 이용자 스스로의 신청으로만 적힌다.
6. **탈퇴 대기의 해제는 그 앞의 상태로 돌아간다.** 탈퇴 대기로 들어온 마지막 줄이 정지에서 왔으면 `suspended` 로만(`active` 로 풀면
   `22023`), 아니면 지금처럼 `active` 로만(`suspended` 로 풀면 `22023`). 탈퇴를 거두는 것이 정지를 푸는 길이 되지 않는다. 정지로
   돌아오면 앞 정지의 갈래가 다시 읽힌다(2).
7. **이력의 시각은 줄이 적히는 순간이다** — `account_status_change.at` 의 기본값을 `now()`(트랜잭션 시작)에서 `clock_timestamp()` 로
   바꾼다. 2 와 6 은 「마지막 줄」을 `at` 으로 고르는데, 한 트랜잭션(런북의 `do` 블록 · 시험) 안의 바뀜 둘이 같은 시각을 받아 무작위
   id 가 차례를 정했다(pgTAP 이 세 번에 한 번 붉었다). 이미 적힌 줄은 그대로다.
8. **화면은 지금처럼 막아 둔다.** `request_account_deletion` 의 `42501` 은 그대로이고, 탈퇴 대기로 옮기는 것과 그 해제는 런북만이다
   (`docs/ops/runbook/erasure.md` 「정지된 계정의 탈퇴 요청」). 본인 확인 · 처리 기한 · 신고 기록 보존과의 관계는 런북이 든다.

마이그레이션 `20261217090000` · pgTAP `99_my_suspension` · `74_authenticated_doors`(문 집합) · 코드 `src/lib/account/index.ts` ·
`app/me/account.ts` · `app/me/account-notice.tsx`.

## 버린 것

- **상태 이력 표에 이용자의 select 정책을 연다** — 메모 · 실행자 · 관련 신고가 같은 행에 있다. 칸마다 가리려면 뷰가 하나 더 들고,
  문 하나가 더 좁다.
- **`app_user` 에 정지 갈래 칸을 둔다** — 같은 사실이 두 자리에 산다(이력과 칸). 이력이 원본이다.
- **정지 갈래를 `readAccount` 의 select 에 붙인다** — 상태 이력은 `app_user` 의 칸이 아니고, 이용 중인 사람까지 묻게 된다.
- **정지된 사람도 화면에서 탈퇴를 신청하게 한다** — 운영자가 R-1 에서 막아 두기로 정했다. 정지를 피하는 길이 되지 않는지 사람이 본다.
- **정지 → 탈퇴 대기에 새 갈래를 둔다**(`deletion_by_inquiry` 같은) — 같은 일(이 사람의 탈퇴 요청)이고 실행자가 가른다. 검사식 ·
  운영 화면의 갈래 이름을 바꾸지 않는다.
- **해제가 언제나 `active` 로 가게 둔다** — 정지 중에 받은 탈퇴 요청을 거두는 순간 정지가 풀린다.

## 물을 거리로 남긴 것

- 본문은 「이용제한」, 제목 · 운영 화면은 「이용 정지」다 — 한 사실 한 표기(`docs/context/copy.md` §8)로 맞출지는 운영자가 정한다.
- 확정 문구의 「{닉네임}님」은 대장 01 의 「이름 뒤 「님」은 띄어 쓴다」와 다르고, 「…com로」는 저장소가 쓰는 「{SUPPORT_EMAIL}으로」
  (`app/help` · `app/closed` · 경고 안내)와 다르다 — 글자 그대로 넣고 PR 에 물었다.
