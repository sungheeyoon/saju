# L3 말뭉치 — 조각이 실제로 들어앉는 곳

코드는 `src/lib/saju/text/corpus.ts`, 나온 문장은
[`text.snapshot.txt`](../../src/lib/saju/text/text.snapshot.txt).
스키마([`fragment-schema.md`](./fragment-schema.md))가 "무엇을 몇 개 만들어야 하는가"를
적어 준 지시서라면 여기는 그 지시서를 채운 **내용물**이다.

파일을 나눈 이유는 **바뀌는 이유가 다르기** 때문이다. 스키마는 계약이 바뀔 때 바뀌고,
말뭉치는 문장을 더 쓸 때마다 바뀐다. 나중에 생성기가 붙어도 손대는 파일은 이쪽 하나다 —
생성기는 런타임 줄의 다음이 아니라 **옆**이라, 이 상수를 빌드 타임에 만들어 넣는 놈으로
바뀔 뿐 `renderFragment` 아래는 그대로다(`runtimeAi: 'none'`).

## 왜 이 세 주제부터인가

`rootedness` · `strength` · `eokbu` 는 **강도 사다리 네 칸을 전부 지나가는 가장 작은
묶음**이다.

```
rootedness.rooted    fact      derived
rootedness.rootless  fact      (시간 미상은 침묵)
strength.verdict     derived   candidate
eokbu.candidate      candidate reference
```

칸을 많이 채우는 것이 목적이 아니라 **사다리가 실제로 작동하는지 보는 것**이 목적이었다.
특히 `reference` 는 출처 의무를 강도에서 떼어 낸 뒤로(`ATTRIBUTION_PATHS`) 한 번도
문장이 되어 본 적이 없던 칸이다. 관계 22칸을 먼저 돌았다면 규칙이 흔들릴 때 22칸을 두 번
만졌을 것이다 — 실제로 그 셋을 쓰는 동안 규칙이 세 개 생겼다(아래).

## 강도마다 표지가 하나다

`REQUIRED_HEDGES` 는 "이 중 하나는 품어라"는 **하한**이다. 하한만 있으면 같은 후보
강도의 문장이 어떤 것은 '여지', 어떤 것은 '가능성', 어떤 것은 '검토'로 갈려 **읽는
사람에게 사다리가 보이지 않는다.** 보이지 않는 사다리는 유지할 이유도 없어진다.
그래서 칸마다 하나를 골라 고정했다.

| 강도 | 표지 | 예 |
| --- | --- | --- |
| `fact` | (없음) | 갑 일간은 월주 자리에 같은 글자로 뿌리를 둡니다. |
| `derived` | `으로 봅니다` | 일간을 돕는 세력이 38% 정도라 신약 쪽으로 봅니다. |
| `candidate` | `후보로 봅니다` | 억부 관점에서는 … 재성 자리의 화 쪽을 후보로 봅니다. |
| `reference` | `참고할 수 있습니다` | … 인성 자리의 수 쪽을 참고할 수 있습니다. |

**사실은 표지가 없는 것이 표지다.** 사실 문장이 "…쪽으로 봅니다"로 끝나면 근거보다
약하게 말하는 것이고, 그것은 안전해 보이지만 강도 체계를 장식으로 만든다. 테스트가
양쪽을 다 잡는다 — 제 강도의 표지를 품어야 하고, 다른 칸의 표지를 품으면 안 된다.

**`reference` 의 '참고'는 출처 표시가 아니다.** 이 칸에 앉는 것은 조후가 아니라
**시간 미상의 억부**이고 억부에는 인용할 표가 없다. 출처 의무는 강도가 아니라 읽은
근거에 걸려 있다([`claim-policy.md`](./claim-policy.md)의 "출처 의무" 항목).

## 한 칸 내려앉은 벌은 시주를 밝힌다

주제마다 조각이 두 벌인 것은 시간 미상 때문이고, 약한 쪽은 **시주 두 글자를 빼고 센
값**이다. 그 사실을 문장이 스스로 밝히지 않으면 독자에게는 그냥 말끝이 흐린 문장으로
보인다. 경고는 `meta.warnings` 로 따로 나가지만 **경고는 문장 옆에 붙어 있지 않다** —
강등을 하기로 한 이유가 애초에 그것이었다.

```
fact       갑 일간은 월주·일주 자리에 같은 글자로 뿌리를 둡니다.
derived    시주를 빼고 세면 갑 일간은 월주·일주 자리에 같은 글자로 뿌리를 둔 것으로 봅니다.
```

## 변종은 갈릴 근거가 있을 때만 가른다

억부 다섯 자리에 같은 문장을 다섯 벌 넣으면 `{role}` 슬롯 하나로 충분했다는 뜻이 된다.
그래서 조각이 더하는 것은 **그 자리가 일간과 맺는 방향** 한 마디다.

```
比劫  일간과 한편에 서는        印星  일간을 받쳐 주는
食傷  일간이 기운을 내보내는    財星  일간이 기운을 쓰는
官星  일간을 누르는
```

십성의 정의라 명식마다 달라지지 않는다 — 그래서 슬롯이 아니라 변종에 얹힌다.
역할이 하나 늘면 `EOKBU_GLOSS`에서 컴파일이 깨진다.

**거꾸로, 나눌 근거가 없는데 나누면 없는 구별을 지어내는 것이다.** 관계 열한 종류는
문장 여덟 벌을 나눠 쓴다(`RELATION_WORDINGS`).

| 문장 | 종류 |
| --- | --- |
| 두 천간이 … 짝을 짓습니다 / 서로 맞섭니다 | 천간합 · 천간충 |
| 두 지지가 … 짝을 짓습니다 / 서로 맞섭니다 | 지지육합 · 지지충 |
| 지지가 … 한 무리를 이룹니다 | 삼합 |
| 지지가 … 한 계절에 모입니다 | 방합 |
| 지지가 … 서로 물립니다 | 형(순환한다) |
| … 관계가 성립합니다 | **해 · 파 · 원진 · 귀문** |

마지막 줄이 요점이다. 이 넷에 대해 엔진이 아는 것은 **두 지지의 짝이 성립한다**는 것뿐이고
길흉도 기전도 판정하지 않는다(`RELATION_POLICY`). 문장을 넷으로 갈라 쓰면 엔진이 모르는
차이를 산문이 지어내는 것이 된다. 그래서 넷이 한 줄에 모여 있고, **나눠 쓴다는 사실이
코드에서 한 줄로 보인다.** 겹친 문장의 수가 선언한 벌 수와 어긋나면 테스트가 건다.

합에서 오행을 말하지 않는 것도 같은 규율이다 — 글자가 모인 것과 합화한 것은 다르고
화(化) 판정은 하지 않는다. 주제가 선언한 슬롯이 `name`·`positions`뿐이라 말할 길도 없다.

## 41/41 은 할 말을 다 했다는 뜻이 아니다

지시서에 빈칸이 없다. 그런데 조후·종격·신살·대운은 여전히 침묵한다 — 조각이 없어서가
아니라 **주제가 없어서**다. 둘은 다른 자리에 적힌다(`UNCOVERED_FACTS` ↔
`missingFragmentsOf`). 섞으면 "안 중요해서 뺐다"가 조용히 들어온다.

다음 일은 칸을 채우는 것이 아니라 **주제를 더하는 것**이고, 그때 분모가 늘어난다.
생성기는 그 뒤다 — 41칸이 손으로 채워지는 동안 규칙이 세 번 바뀌었고(표지 고정,
시주 표시, 공유 문장), 규칙이 흔들리는 동안 생산 자동화를 붙이면 흔들림이 그대로
41벌로 복제된다.
