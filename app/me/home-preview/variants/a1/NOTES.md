# A1 · 통합 홈 요약형

**한 줄 요약** — 나는 요약 카드 한 장(일주 표식 · 이름 · 여덟 글자 한 줄 · 오행 개수 한 줄 + 풀이 · 상세 두 길),
저장한 사람은 작은 카드 격자(모바일 2열 · 태블릿 3열 · 데스크톱 4열), 끝에 「사람 추가」 칸, 맨 아래 보조 행동 한 줄.

**이 시안이 답하는 질문** — 「홈 한 화면에 나와 저장한 사람이 함께 서려면 내 자리를 얼마나 줄여야 하는가」.
명식 표 · 오행 막대 · 출생 정보는 기존 상세(`/me/people/<내 id>`)로, 관리(수정 · 빼기 · 메모)는 기존 `/me/people` 로
남긴다. 홈은 **목차**가 된다.

위에서 아래 차례: 제안 메뉴 모형 → 경고(있을 때) → 제목 → 새 소식 띠(있을 때) → 내 요약 → 저장한 사람 격자 → 보조 행동.

## 장점

1. 폰 첫 화면에 나와 사람 두세 명이 함께 들어온다 — 「나는 기준, 사람들은 그 곁」이 한눈에 읽힌다.
2. 새로 만든 것이 거의 없다. 일주 표식 · 여덟 글자 칸 · 일간 타일 · 풀이 띠가 전부 기존 모양이라 구현할 때 옮기기 쉽고,
   관리 화면(`/me/people`)을 그대로 두므로 서버 액션을 새로 홈에 끌어올 일이 없다.
3. 사람 0 · 3 · 10명에서 모양이 같다 — 격자가 늘기만 하고, 「사람 추가」 칸이 자리 수(n/10)와 함께 늘 끝에 선다.

## 단점

1. 사람 카드에 여덟 글자와 메모가 없다 — 그 사람을 알아보는 단서가 일간 한 글자와 이름뿐이다(메모는 `전체 관리` 에서만 보인다).
2. 사람 풀이로 가는 길이 한 겹 깊어진다 — 저장 목록 카드에는 풀이 띠가 바로 섰는데, 여기서는 「풀이 있음」만 알리고 상세를 거친다.
3. 사람을 「추가」하는 일이 홈 안에서 끝나지 않는다 — 빈 칸을 누르면 `/me/people` 로 가서 한 번 더 「사람 추가」를 눌러야 폼이 열린다.

## 핵심 여정 클릭 수 (홈에서 출발)

| 여정 | 클릭 | 길 |
| --- | --- | --- |
| 내 사주 상세 | 1 | 요약 카드 「사주 자세히 보기」 |
| 내 사주풀이 | 1 | 요약 카드 「사주풀이 보기 / 받기」 |
| 사람 상세 | 1 | 사람 카드 아무 곳 |
| 사람 풀이 받기 | 2 | 사람 카드 → 상세의 사주풀이 탭 |
| 사람 추가 | 2 | 「사람 추가」 칸 → `/me/people` 의 「사람 추가」 (폼이 열림) |
| 나와 그 사람 궁합 | 1 (+1) | 카드의 「나와 궁합」 → 두 칸이 채워진 궁합 첫 화면 (결과는 「궁합 보기」 한 번 더) |
| 모르는 사람 사주 보기 | 1 | 보조 줄 「다른 사람 사주 보기」 |
| 새 소식 확인 | 1 | 새 소식 띠, 또는 메뉴의 종 |
| 매칭 가기 | 1 | 메뉴 「매칭」 또는 보조 줄 |
| 서비스 설문 | 2 | 메뉴의 톱니 → 「서비스 설문」 |

## 상태별 한 줄

- **사람 10명** — 격자가 모바일 5줄 · 데스크톱 3줄로 늘고, 끝 칸은 「등록할 수 있는 10명을 다 채웠습니다.」로 바뀐다. 할머니(못 읽는 판본)는 `?` 타일과 사유 한 줄이 서고 「나와 궁합」이 빠진다. 열두 자 이름은 두 줄로 접힌다.
- **내 사주 없음** — 요약 카드 자리에 온보딩 머리를 흉내 낸 「내 사주 등록」 카드와 「내 명식 등록」 버튼이 서고, 저장한 사람 격자는 그대로 서되 「나와 궁합」은 빠진다(기준인 내가 없다).

## 확인

- `npm run typecheck` · `npx eslint app/me/home-preview/variants/a1` · `npx vitest run scripts` 통과.
- 화면은 로그인이 필요해 브라우저로는 못 봤다. 대신 `react-dom/server` 로 내 사주 있음/없음 × 사람 0 · 3 · 10 여섯 상태(소식 · 경고 켬)를 렌더해 깨지지 않음을 확인했다. 360px 가로 스크롤은 눈으로 확인하지 못했다 — 넓이를 고정한 칸은 없고(격자 `minmax` 없음, 요약 카드의 `minmax(20rem,…)` 은 `md` 이상에서만) 긴 이름은 `break-all` 로 접힌다.
