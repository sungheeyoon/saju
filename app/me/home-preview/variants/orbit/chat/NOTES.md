# 3차 · 관계 지도의 채팅 (orbit / chat)

역할: orbit 홈을 만든 인터랙션 디자이너가 이어서 그렸다.

## 콘셉트

홈에서 저장한 사람이 나를 돌았듯, 채팅에서는 **대화방이 열린 상대가 한 궤도를 돈다.** 목록 머리의 궤도 띠
「지금 대화 중인 인연」은 가운데 내 일간 글자(홈의 가운데 점과 같은 모양) 둘레에 열린 방의 상대 얼굴을 앉힌다.
최근에 말이 오간 방이 앞(아래 가운데)에 서고 좌우 · 뒤로 돈다 — 자리는 **대화의 순서일 뿐** 가깝다는 판정이 아니다.
지금 활동 중인 상대는 고리가 빛나고(`motion-safe` 에서만 숨 쉼) 나와 점선으로 이어진다.

띠는 머리일 뿐이고 주인공은 목록과 방이다. 데스크톱(lg)은 목록 22rem + 방 두 칸, 폰은 한 화면 안에서 목록 → 방으로
바뀌고 방 머리의 「← 채팅」이 돌아간다. 닫힌 방은 목록 아래 「닫힌 방」 구역으로 내려가 흑백 얼굴 · 자물쇠 · 닫힌 까닭
한 줄로 선다. 방 안은 날짜 구분선 · 「대화방이 열렸습니다」 · 「새 메시지」 줄 · 연달아 보낸 말 묶기 · 입력창(0 / 1,000)이다.

## 홈 시안에서 이어받은 것

- 타입 스케일 그대로: D1 화면 제목 40/32 · D2 방 제목 22(홈의 사람 이름 판과 같음) · D3 띠 제목 20 · B 본문과 말풍선 15 ·
  S 이름표 13 · C 시각 · 날짜 · 범례 12. 11px 는 안 읽음 수 딱지뿐이다.
- 단추 세 단(`../ui.tsx` 의 `BUTTON`): 주 = 「보내기」 · 빈 상태의 「매칭에서 오늘의 인연 만나기」, 작은 보조 = 「함께 보는 궁합」,
  셋째 = 「그만두기」. 메뉴는 `../menu.tsx` 사본(`menu.tsx` — 지금 자리를 `current` 로 받는 것만 다르다).
- 가운데 점: 오행 soft 판 + 30% 테두리 + 일간 글자, 다크에서 글자만 밝기 1.45. 내 사주가 없으면 점선 원 안의 「나」.
- 궤도 규율: 실선/점선이 뜻을 나눈다 — 접속 상태도 **색이 아니라 고리 모양**(빛나는 실선 · 실선 · 점선)으로 가른다.

## 새로 정한 것

- 접속 상태를 방 안 한 줄에 더해 **목록 · 띠의 얼굴 고리**로도 세웠다(아래 약점 1).
- 신고 여정: 방 머리 「⋯」 → 「신고할 메시지 고르기」 → 상대 말풍선이 고를 수 있게 테두리를 두름 → 누르면 입력창 자리에
  신고 판(고른 말 인용 · 기존 신고 안내 · 사유 · 덧붙일 말 · 「신고합니다」). 실제 화면은 메시지마다 11px 「신고」 글자가
  있어 44px 를 못 채웠다 — 여기서는 신고를 한 손잡이로 모으고 메시지를 고르는 뜻(PRD §7.1)을 살렸다.
- 차단: 같은 「⋯」 안의 빨간 줄 → 방 머리 아래 경고 띠에 기존 `BLOCK_NOTE` + 「차단합니다」(되돌릴 수 없는 누름 직전에만 선다).
- 떠난 상대는 사진 · 이니셜 대신 사람 윤곽, 신고 · 차단 손잡이와 궁합 길이 사라진다. 닫힌 방은 입력창 자리에 닫힌 까닭.
- 말풍선: 내 말 = accent 채움(오른쪽), 상대 말 = 옅은 판 + 테두리(왼쪽, 덩어리 첫 줄에만 얼굴). 3분 안에 이어 보낸 말은 묶고
  맞닿는 모서리를 줄이며 시각은 덩어리 끝에만. 한글은 `keep-all` 로 낱말 가운데서 안 끊는다.

## 핵심 여정 클릭 수

| 여정 | 폰 | 데스크톱 |
| --- | --- | --- |
| 안 읽은 방 열어 읽기 | 1 (띠의 얼굴 또는 목록 줄) | 0 (첫 방이 열려 있음) · 다른 방 1 |
| 함께 보는 궁합으로 | 2 (방 → 궁합 단추) | 1 |
| 메시지 신고 | 방 + 3 (⋯ → 고르기 → 말풍선) + 신고합니다 | 3 + 신고합니다 |
| 차단 | 방 + 2 (⋯ → 차단) + 차단합니다 | 2 + 차단합니다 |
| 빈 상태에서 매칭으로 | 1 | 1 |

## 가짜 값에 대해

`screens.ts` 는 첫 방(서연)의 대화만 든다. 다른 방은 목록의 마지막 한 줄을 **상대가 보낸 말 하나**로 세웠다(`index.tsx` 의
`messagesOf`) — 방 안 모양을 견주려는 것이고, 실제로는 읽는 문이 방마다 내준다. 경고 안내 띠는 홈의 것이라 여기 세우지 않았다.

## 스스로 본 약점

1. **접속 상태를 목록과 띠에도 세웠다 — PRD §7.2 는 「대화방 안과 후보 카드」만 적는다.** 목록의 읽는 문(`my_chat_rooms`)이
   이미 구간을 내주므로 새 정보가 새지는 않지만, 자리가 는 것은 결정이 필요하다. 띠 자체가 이 결정에 기대 있다 — 안 된다면
   띠는 「안 읽은 수가 붙은 얼굴 궤도」로 줄고, 그러면 목록과 겹쳐 값어치가 약하다.
2. **띠와 목록이 같은 방을 두 번 세운다.** 홈의 지도 + 목록과 같은 중복이고, 폰에서 띠가 목록을 약 250px 밀어낸다.
   궤도에는 여섯 방까지만 앉고 그 뒤는 목록에만 선다. 신고 여정이 세 번 눌러야 하는 것도 한 번 더 누르게 된 값이다.
