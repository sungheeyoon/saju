# 3차 · 관계 지도의 풀이 (orbit / readings)

역할: orbit 홈을 만든 인터랙션 디자이너가 이어서 그렸다.

## 콘셉트

풀이 목록도 **지도의 문법으로 읽는다.** 홈에서 사람은 일간 글자가 선 점이고, 이미 본 궁합은 두 점을 잇는 실선과 점수였다.
여기서는 그 모양이 목록 줄 앞에 표식으로 선다 — 사주풀이 = 점 하나, 궁합풀이 = 두 점과 실선(+ 오른쪽 큰 점수),
함께 보는 궁합 = 두 점과 점선(만드는 중). 제목을 읽기 전에 「몇 사람의, 누구의 글인가」가 보인다.

목록 위의 「글이 있는 관계」는 **글이 하나라도 있는 사람만** 앉힌 작은 궤도다. 책 딱지 = 사주풀이 있음, 실선 + 점수 =
궁합풀이, 점선 = 만드는 중. 점을 누르면 아래 두 구역이 그 사람이 든 글로 좁혀지고(「엄마의 글 2편 · 전체 보기」),
관계 없는 점과 선은 흐려진다. 둘레에 앉을 사람이 없으면(비어 있음 · 내 풀이만) 지도를 세우지 않는다.

줄을 누르면 글 칸이 열린다 — 데스크톱은 목록 오른쪽 두 번째 칸(처음부터 맨 위 글이 열려 있다), 폰은 목록 자리를
바꿔 끼우고 「← 만든 풀이 목록」으로 돌아오면 방금 누른 줄 위치로 돌아온다. 주소는 안 바꾼다(브라우저 상태).

- **한 사람 풀이 글**: 일간 점 + 이름(32px) → 사주 / 사주풀이 분할 탭 → 글 판. 판 안은 「○○의 사주풀이」 →
  **비유 한 줄 32px(폰 26) · 왼쪽 accent 막대** → 생성 시각 + 공유 링크 복사 · 사주풀이 다시 받기 → 차례(소제목 앵커, 44px 줄)
  → 본문(17px(폰 16) · 행간 1.85 · 한 줄 34em 제한 · 소제목 22px 앞에 accent 점 · 목록은 테두리 상자) → 줄 뒤 맺음 15px.
  이전 명식이면 판 맨 위에 경고 상자(승인 문구 `READING_STALE_NOTE`)가 서고, 「사주풀이 다시 받기」가 그 상자의 주 단추로 옮겨 간다.
  글 아래 「이어진 글」은 이 사람이 든 궁합풀이 줄이다.
- **궁합 글**(목록에 섞여 있어 누르면 무엇인가는 서야 한다): 두 점(72px)을 실선으로 잇고 한가운데 점수 40px,
  제목 · 비유 · 생성 시각, 주 단추 「궁합풀이 보기」(실제 궁합 화면으로), 아래 「각자의 사주풀이」.

## 홈 시안에서 이어받은 것

- 메뉴 모형(분할 단추 · 종/톱니 44 원 · 폰 하단 막대) — `../menu.tsx` 를 `menu.tsx` 로 복사하고 켜진 탭만 prop 으로 받게 했다.
- `BUTTON` 네 단(`../ui.tsx`) 그대로: 주 = 「함께 보기」 · 「궁합풀이 보기」 · 이전 명식의 「다시 받기」 · 빈 상태의 「사주풀이 받기」,
  작은 보조 = 공유 · 다시 받기 · 전체 보기, 셋째 = 목록으로.
- 타입 스케일: D1 화면 제목 40/32 · D2 판 이름 28~32 · D3 구역 제목 20 · 본문 15 · 보조 13 · 캡션 12, 11px 는 눈썹 · 칸 딱지 · 점수 딱지뿐.
- 점의 옷: `ELEMENT_TONE` soft 바탕 + 테두리 + 글자색, 다크에서 글자만 밝기 1.45. 지도 판의 radial accent-wash, 모서리 32/24/16.
- 궤도 점선 · 선 두께 · 점수 딱지 모양, 두 사람 사이 휜 선은 `../placement.ts` 의 `arcBetween` 을 import 해서 쓴다.

## 새로 정한 것

- **줄 앞 표식(`Mark`)** — 폭 72px 고정이라 점 하나 줄과 두 점 줄의 제목이 한 세로줄에 선다. 궁합 줄은 점수가 오른쪽에 24px 로 선다.
- **읽기 타이포 단** — R0 비유 32/26 · 700 · 1.35 / R1 소제목 22/20 · 700 / R2 본문 17/16 · 400 · 1.85 · 34em / R3 맺음 15 · secondary.
- 지도의 뜻이 홈과 조금 다르다: 홈의 두 궤도(본 적 있음/없음) 대신 **한 궤도**다 — 여기 앉은 사람은 모두 글이 있는 사람이라 가를 것이 없다.
- 인연 상대(서연)는 일간을 모르므로 점 대신 사진이 선다.

## 스스로 본 약점

1. **목록의 궁합 줄이 두 번 누르게 한다.** 궁합풀이의 실제 글은 궁합 화면에 살아서, 줄을 누르면 먼저 요약 판(두 점 · 점수 · 비유)이
   서고 「궁합풀이 보기」를 한 번 더 눌러야 한다. 줄 모양은 같은데 한쪽만 글이 바로 열리지 않는 것이 어색할 수 있다 — 실제로 옮기면
   궁합 글도 이 칸에서 읽게 하거나, 궁합 줄은 바로 떠나게(→ 표시를 바꿔서) 갈라야 한다.
2. **지도가 사람 수만큼 커지지 않는다.** 한 궤도에 7명까지는 폰(328px)에서 이름표가 안 겹치지만, 글 있는 사람이 열 명이 되면 이웃
   이름표가 붙는다(홈은 두 궤도로 나눠 버텼다). 또 데스크톱에서 지도(5:4)가 목록 칸 폭 400px 을 다 먹어, 글이 두세 편뿐일 때는 지도가
   목록보다 무겁다.
