# A3 · 통합 홈 전체 사람형

**한 줄 요약** — `/me/people` 을 통째로 홈에 들인다. 맨 위에 강조한 「나」 요약 카드 한 장이 서고, 그 아래에
저장한 사람 카드가 원본 그대로 열 장까지 선다(머리 · n/10명 · 사람 추가 · 궁합 보러 가기 · 여섯부터 찾는 칸 · ⋯ 메뉴 자리).

**이 시안이 답하는 질문** — 사람 화면을 따로 둘 필요가 있나? 가설: 저장 자리가 열이라 전부 한 화면에 들어간다.

**답(보고 느낀 것)** — 들어가긴 한다. 다만 카드가 커서(휴대폰 약 330px) 열 명이면 홈이 휴대폰에서 약 4,000px 이 넘고,
홈 끝의 매칭 띠 · 「저장하지 않고 사주 보기」가 목록 뒤로 밀린다. 사람 화면을 없애도 되지만, 그러려면 카드가 작아지거나
(A1 · B 쪽) 목록 뒤의 길을 위로 올려야 한다.

## 차례

제안 메뉴 모형 → 경고(`WarningBanner`) → 새 소식 띠(`UnreadStrip`) → h1 「나의 사주와 인연」 → **나**(요약 카드) →
**저장한 사람**(원본 `/me/people` 의 머리 · 추가 · 찾는 칸 · 카드) → 매칭 띠(원본 홈 그대로) → 「저장하지 않고 사주 보기」.

## 장점 3

1. **화면 하나가 줄어든다** — 메뉴에서 「사람」과 모바일 전체 메뉴의 「사람」이 빠지고, 홈 = 나와 내 사람들 전부라는 모형이 단순하다.
2. **원본을 거의 그대로 쓴다** — 카드 · 찾는 칸(`PeopleFinder` 실제 동작) · 문구가 이미 승인된 것이라 구현 위험이 가장 작다. 옮기는 일에 가깝다.
3. **나와 남이 한 눈금으로 읽힌다** — 내 카드의 여덟 글자 표가 사람 카드의 표와 같은 모양이라 견주기 쉽고, 강조 테두리 · 「나」 표식으로 기준점은 분명하다.

## 단점 3

1. **길다** — 10명이면 휴대폰에서 스크롤이 길고, 목록 뒤의 매칭 · 모르는 사람 사주로 가는 길이 사실상 안 보인다.
2. **궁합이 멀다** — 원본 카드에는 「나와 궁합」 길이 없어서, 그 사람과의 궁합은 「궁합 보러 가기」 → 궁합 화면에서 두 사람 고르기다. 통합 홈이라면 카드에 한 줄이 있어야 할 자리다(카드를 그대로 두는 이 시안의 제약).
3. **홈의 읽기가 무거워진다** — 지금 `/me/people` 이 하는 읽기(`my_person_slots` · `user_person_access` · `myReadings` · 입력 여럿)가 홈에 더해진다. 로그인할 때마다 도는 자리다.

## 상태별 모양

- **사람 10명** — 머리가 「10/10명」, 「사람 추가」 대신 한도 다 참 문장(원본 그대로), 그 아래 찾는 칸이 서고 카드 열 장. 휴대폰에서 매우 길다.
- **내 사주 없음** — 「나」 자리에 온보딩 머리를 흉내 낸 카드와 「내 명식 등록」 링크. 저장한 사람 목록은 원본처럼 그대로 선다.
- 폭 360px 에서 여섯 상태(기본 · 10명 · 0명 · 내 사주 없음 · 10명+소식+경고 · 없음+10명) 모두 가로 넘침 0 을 쟀다.

## `/me/people` 을 `/me` 로 잇는 경우의 영향

`/me/people` 을 가리키는 자리를 2026-09-24 에 셌다(이 폴더 밖).

- **메뉴** — `site-header.tsx` 의 `MEMBER_LINKS` 「사람」과 모바일 전체 메뉴의 「사람」을 걷는다. `isNavigationActive` 는 `/me/people/<id>`(사람 상세)를 「홈」으로 밝혀야 한다 — `site-header.test.ts` 두 줄이 바뀐다.
- **주소** — `/me/people` 은 `/me` 로 영구 이동(북마크 · 옛 링크). 사람 상세 `/me/people/[personId]` 는 주소를 그대로 둔다(링크 · 시험이 많다). 상세의 돌아가기(`[personId]/page.tsx` 의 `mine ? '/me' : '/me/people'`)는 둘 다 `/me` 가 된다.
- **본문 안의 링크** — `save-for-reading.tsx` · `me/compat/not-found.tsx` · `me/readings/page.tsx` 가 `/me/people` 로 보낸다 → `/me`.
- **새로 고침** — `app/refresh.ts` 의 `person-list-changed` 가 `/me/people` 만 다시 그린다 → `/me` 를 더한다(`refresh.boundary.test.ts` 도).
- **읽기** — 홈이 `my_person_slots` · 목록 · `myReadings` · 입력 여럿을 더 읽는다. `/me/people/page.tsx` 에 잠긴 화면 DB 호출 지문 둘(`layers.test.ts`)이 홈으로 옮겨 가거나, 이참에 문으로 옮긴다.
- **관문** — `gateFor` 는 `/me` 아래를 같이 보므로 바뀌지 않는다(시험의 `/me/people` 예시는 다른 주소로 바꿔도 된다).
- **시험 · 도구** — e2e `signed-in.spec.ts` 의 `/me/people` 진입 열 곳과 「사람은 전체 메뉴에 둔다」, `match.spec.ts` 한 곳, 흐름 검사 `check-managed.mjs` · `check-match.mjs`, `ui-shots.mjs` 세 장면.
- **문서** — `/me/people` 을 이름으로 부르는 PRD 절, 찾는 칸 ADR(ADR 0102)의 「사람 목록」 자리.
